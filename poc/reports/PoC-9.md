## 4. 관찰

1. **패널을 접으면 바와 대화 열이 170 DIP 어긋났다.** 바 위치는 ADR-021대로 패널 폭을 늘 빼고 계산하는데, 렌더러는 패널을 접으면 대화 열을 가운데로 옮겼기 때문이다(1280 DIP 창). 렌더러 규칙을 하나 더했다: **승인 대기 중에는 패널을 접어도 그 폭을 비워 둔다.** 이후 어긋남 0(스크린샷 11). 렌더러 배치 규칙이라 보안 판정과는 관계없다.
2. **입력창이 1줄일 때 바와 입력창 사이가 54 DIP다.** 바 위치를 입력창 예약 높이(3줄)로 정하고 입력창은 제자리에 두기 때문이다. 이 간격이 습관 클릭을 줄이는 쪽이지만, 바가 입력창에서 떨어져 보인다. 시연에서 어색한지 사용자 확인이 필요하다.
3. **스크롤 막대 폭만큼 대화 카드가 바와 어긋났다**(7 DIP). 타임라인 스크롤 영역에 `scrollbar-gutter: stable both-edges`를 줘 맞췄다. Windows는 스크롤 막대가 늘 폭을 차지하므로 Windows에서 다시 본다.
4. **습관 클릭(판정 로직 수준)**: 입력창에서 바로 올라와 150ms 안에 누른 클릭은 머무름으로 거부되고 "마우스를 조금 움직인 뒤 눌러 주세요"가 뜬다. 앞 게이트를 바 안에서 승인한 뒤 나감 없이 다음 게이트가 떠도 같다. 입력창 Enter·바의 Enter·Space는 승인이 아니다. 렌더러 영역(간격·입력창)에 보낸 클릭은 바 판정에 들어가지 않았지만, 이것은 main이 메인 화면에 넣은 이벤트라 **OS가 어느 뷰로 보내는지(hit-test)는 시험하지 않았다**. **사람의 실제 습관 클릭도 시험하지 않았다**(§5).
5. `BrowserWindow.capturePage`는 자식 뷰를 담지 않는다. 스크린샷은 메인 화면과 바를 따로 찍어 합쳤다. 바 페이지를 바꿔 불러오는 순간에는 캡처가 실패해 다시 시도한다(`UnknownVizError`).

## 5. Windows에서 확인할 것

- [ ] `pnpm demo`로 흐름 전체를 한 번 돌린다(Malgun Gothic 렌더링, 금액·사업자번호 고정폭 정렬, 다크 모드).
- [ ] 배율 100·125·150%에서 바가 렌더러가 비운 자리와 맞는지, 클릭 판정 위치와 그려진 위치가 같은지(사람 클릭).
- [ ] 스크롤 막대가 있는 상태에서 카드·입력창·바가 같은 폭으로 정렬되는지.
- [ ] **습관 클릭 시험(ADR-021 조건)**: 승인 대기 중에 입력창에 글을 쓰다 입력창 위쪽을 누르는 동작을 사람이 20회 해 보고, 바가 승인한 횟수와 거부 문구가 뜬 횟수를 센다. 문제가 되면 간격을 늘리거나 작업 패널 하단으로 되돌리는 것을 사용자와 다시 정한다.
- [ ] 좁은 창(화면 반쪽 배치)에서 바가 창 오른쪽 끝까지 넓어질 때 Windows 알림과 겹치는지.
- [ ] 창을 다른 창 뒤에 두었다가 바를 바로 눌러 앞으로 가져올 때(클릭 활성화 예외) 한 번에 승인되는지, 실패로 보이지 않는지.
- [ ] 바를 가린 알림 창이 사라지는 순간의 클릭이 머무름으로 거부되는지.
- [ ] 작업 표시줄 깜빡임(창이 뒤에 있을 때)과 포커스 비탈취.
- [ ] 배율이 다른 모니터 두 대에 창이 걸쳤을 때 `screen.getCursorScreenPoint()`와 `getContentBounds()`의 DIP 변환이 같아 "멈춘 커서" 판단이 맞는지.
- [ ] 바를 숨겼다가 다음 게이트로 다시 보일 때 앞 게이트의 마지막 프레임이 잠깐 비치는지(로드 완료가 곧 그려짐은 아니다. 무장 600ms 전이라 승인은 안 됨).
- [ ] 렌더러가 띄울 수 있는 네이티브 모달(`window.print()` 인쇄 대화상자, 파일 선택 창)이 바를 덮는지. `disableDialogs`는 JS 대화상자만 막는다(PoC-6 확인 목록에 추가 권고).
- [ ] 1줄 입력창과 바 사이 54 DIP 간격이 시연에서 어색한지.

## 6. PoC-6 실발급과 연결할 것

- 목업 실행기(`shell-mock.ts` `MockRuns`)를 엔진 H-01 플레이북 이벤트(단계, `WaitingGate`, 발급 확정·승인번호)로 바꾼다. 셸 main(`shell-app.ts`)에 `main.ts`의 금고·엔진 기동을 옮긴다.
- 바 요약을 엔진 게이트 요청 `fields`로 받고 main이 D03 `cardHash`·`actionHash`를 다시 계산한다. 근거는 `LocalApproval` v2(`reqId`·`approvalNonce`·`presence`)로 main↔엔진 전용 포트에 보낸다.
- "처음 거래"·"처음 보내는 주소"를 원장 `committed` 행의 HMAC 열로 판정하고, 중복 경고(`$dup.*`)를 바에 올린다.
- 프로필·거래처를 DB(`db.query.*`, PoC-5)로, 문서함을 PoC-8 보관함으로 바꾼다.
- 내 차례(간편인증 폰 승인, 인증서 비밀번호 직접 입력, [브라우저로 가기])를 엔진 `human:*` 단계에 잇는다.
- OS 수준 입력 시험(ADR-021 "조건"의 PoC-6 목록)을 셸에서 한다.

## 7. 하지 않은 것

- 서체 파일(IBM Plex·Noto Serif)을 앱에 넣지 않았다. 렌더러에 네트워크가 없어 대체 서체로 보인다.
- 렌더러 확대·축소는 막았다(바 자리가 DIP 고정). 접근성 배율은 Phase 1.
