# H-01 실제 홈택스 캡처: 꼭 얻어야 할 것 (2026-11-11)

목적: 게시본 `hometax.invoice.issue@2.1.1`과 조회 패키지(`hometax.invoice.lookup`·`hometax.invoice.email_status`)는 실제 홈택스 화면에 맞춘 적이 없다(건조 실행·캡처 대조, 리허설 보고서 §7-11). 이 목록을 다 채우면 새 판(셀렉터·URL·스텝·commitEndpoints·문구)을 쓸 수 있다. 서명·게시는 대표가 한다.

## 0. 캡처하는 법 (모든 화면 공통)

- 화면마다 세 가지를 남긴다.
  - **접근성 트리**: Chrome DevTools > Accessibility, 또는 기존 `<접두>-form.json` 방식. 요소마다 역할(role), 접근성 이름(name), 태그, `id`, `title`, `aria-*`, iframe 안이면 그 iframe의 id·src.
  - **가린 스크린숏**: 사업자번호·상호·이름·전화·이메일·금액을 가린다.
  - **HAR**: 요청 주소·메서드·`actionId`만 본다. 본문 값은 저장하지 않거나 가린다.
- 주소는 그 화면의 실제 URL 전체를 남긴다(`websquare.html?w2xPath=…&tmIdx=…&tm2lIdx=…&tm3lIdx=…`). 같은 URL을 새 탭에 직접 넣어도 그 화면이 뜨는지도 본다(goto로 갈 수 있는가).
- 화면이 뜰 때 덮는 것도 적는다: 전체 화면 스피너, 공지 팝업, NetFunnel 대기, 보안 프로그램 설치 안내. 무엇이 사라져야 조작할 수 있는지 적는다.
- **Mac과 Windows 둘 다** 본다. 고객 PC가 둘 다라서다. 특히 공동인증서 창·보안 프로그램 안내·인쇄 경로는 OS마다 다를 수 있다.
- 패키지 셀렉터는 역할·이름 후보가 1순위이고 css(`#id`)가 2순위다. 그래서 같은 요소의 **역할·이름과 id를 둘 다** 적는다. `wq_uuid_<숫자>`처럼 매번 바뀌는 id는 "바뀜"이라고 적는다.

## 1부. 되돌릴 수 있는 구간 ([발급하기]를 누르기 전까지)

이 구간에서는 아무것도 발급되지 않는다. 대표 로그인만 있으면 순서대로 다 본다.

### 1-1. 첫 화면, 로그아웃 상태 (s0·s1·s2)
- [ ] 로그인 전에도 뒤에도 늘 있는 요소 하나: 역할·이름·id. 패키지는 지금 link "홈"을 보고(`hometax.nav.home`, s0 expect) 있는데 캡처에 없다. 머리말 로고 링크나 `#mf_wfHeader_*`가 후보다.
- [ ] 페이지 전체를 감싸는 영역(landmark)의 역할·이름. 패키지는 main "홈택스"(`hometax.page.root`)인데, 로그인·서명 셀렉터가 전부 이 아래에 있다고 가정한다. main이 없으면 무엇으로 바꿀지(`#mf_txppWframe`, body)를 정한다.
- [ ] 로그인 상자: 공동·금융인증 `…loginboxFrame_anchor22`, 개인용 간편인증 `…_anchor23`, 아이디 로그인 `…_anchor24`(11-09 캡처). 각각의 역할(링크 a인지 button인지), 접근성 이름, 로그인 상자 전체의 역할·이름.
- [ ] **사업자용 간편인증 입구가 따로 있는지**("개인용"만 있다면 사업자 로그인은 무엇으로 하는지).
- [ ] 로그인 전 머리말 글(지금 "로그인")과 로그인 뒤 글("로그아웃"). s5의 성공 표지가 "로그아웃" 글자라서, 로그인 전 화면 어디에도 "로그아웃"이 없어야 한다.

### 1-2. 간편인증 로그인 (s3·s4·s5·s6)
- [ ] [간편인증]을 누르면 무엇이 뜨는지: 같은 페이지의 레이어인지, iframe인지(id·src), 새 창인지.
- [ ] 제공자 고르기(카카오·네이버·PASS·토스 등), 이름·전화·생년월일 입력, 약관 동의, [인증 요청] 버튼. 사람이 하는 칸이라 셀렉터는 필요 없고 **순서와 걸리는 시간**만 본다. s5는 지금 120초를 기다린다.
- [ ] 폰에서 승인한 뒤 화면이 저절로 넘어가는지, **[인증 완료]를 사람이 한 번 더 눌러야 하는지**(버튼 이름).
- [ ] 로그인 실패·취소·시간 초과 때의 문구와 요소(역할·id).
- [ ] 로그인 뒤 첫 화면에서 로그인 유형이 보이는 곳("○○님 · 개인사업자" 등). 개인 로그인과 사업자 로그인을 구분할 수 있는가.
- [ ] 화면 판단(s2·s6, screen_state_v2)에 쓸 표지: 로그인됨, 로그인 필요, 자동입력방지, 인증 대기, 오류 각각이 화면에서 무엇으로 구분되는지.

### 1-3. 공동인증서(사업자 인증서) 로그인 (공동인증서 고객용, 패키지 문제 P1)
- [ ] [공동·금융인증] 뒤 인증서 창이 웹 레이어(DOM)인지, iframe인지, 별도 프로그램(보안 모듈 창)인지. **금고 비밀 창이 암호 칸에 직접 넣을 수 있는지가 여기서 갈린다.**
- [ ] 저장 위치 고르기(하드디스크·이동식·브라우저), 인증서 목록, **암호 칸**(역할·이름·id·frame), [확인] 버튼.
- [ ] Windows에서 보안 프로그램(AnySign·Veraport 등) 설치 안내가 뜨는지. 뜬다면 문구와 요소.
- [ ] 암호를 틀렸을 때 문구, 시도 횟수 제한.

### 1-4. 세션 (sessionRequired·재진입)
- [ ] 자동 로그아웃 시간과 그 전에 뜨는 "로그인 연장" 알림창(문구·요소·버튼). 승인 대기(최대 10분) 중에 뜨면 실행이 멈추거나 다시 로그인해야 한다.
- [ ] 로그아웃된 채 발급 화면 주소로 가면 어디로 가는지(로그인 화면? 알림?).

### 1-5. 발급 화면으로 가기 (s10·s11)
- [ ] 메뉴 경로(전체메뉴 > … > 전자(세금)계산서 건별 발급)와 그 화면의 URL 전체(w2xPath, tmIdx, tm2lIdx, tm3lIdx).
- [ ] 그 URL을 로그인된 새 탭에 직접 넣었을 때 같은 화면이 뜨는지. 안 뜨면 메뉴 클릭 경로(각 메뉴 a의 id `grpMenuAtag_…`와 이름).
- [ ] 화면이 뜰 때 덮는 공지·안내 레이어와 닫는 버튼.
- [ ] 폼 전체 틀의 역할·이름(패키지: form "전자세금계산서 건별 발급", 실제는 `#mf_txppWframe` 아래일 것).

### 1-6. 발급 폼 칸 (s12~s19e, 되읽기 13칸)
칸마다 **id, 역할, 접근성 이름(label·title), 입력 종류, readonly 여부, 미리 채워진 값의 형식**을 적는다.

| 패키지 키 | 지금 가정(역할 · 이름) | 실제에서 볼 것 |
|---|---|---|
| supplierBizNo | textbox · 공급자 등록번호 | 로그인 사업자로 자동 채워지는지, 하이픈 형식, 입력 칸인지 표시 글인지 |
| supplierName | textbox · 공급자 상호 | 같음 |
| counterpartBizNo | textbox · 공급받는자 등록번호 | 한 칸인지 세 칸(3-2-5)인지, 하이픈 |

- [ ] 칸을 채우고 **[발급하기]를 누르지 않은 채** 화면에 뜨는 검증 문구(빈 칸, 형식 오류). form_ready 판정과 실패 신호에 쓴다.
- [ ] [발급하기] 버튼의 실제 이름·id. 그 앞에 [미리보기]나 [임시저장] 같은 단계가 있는지.

### 1-7. 발급목록 조회 (s30 verify 조회 패키지, 지난 발급 건으로 미리 볼 수 있다)
- [ ] 메뉴 URL 전체(w2xPath·tm3lIdx). 지금 패키지는 `/invoice/list` 자리표시다.
- [ ] 검색 칸: 기간(시작~끝, 형식, 1일·1주 단추), 거래처 사업자번호 칸이 있는지, [조회] 버튼(이름·id).
- [ ] 결과가 `<table>`인지 WebSquare 그리드(div)인지. 열 이름과 순서: 승인번호, 작성일자, 공급받는자 등록번호, 공급가액, 세액, 상태. "총 N건" 표시 요소.
- [ ] 결과가 없을 때 문구.
- [ ] 조회의 HAR actionId(커밋 아님 확인, knownEndpoints).

### 1-8. 메일발송목록 (s33, 지난 건으로 미리)
- [ ] 메일 발송 상태를 보는 곳이 따로 있는 화면인지(URL·tm3lIdx), 발급목록의 열인지.
- [ ] 승인번호로 찾을 수 있는지, 상태 글자 그대로("전송완료"·"발송완료"·"미전송"·"실패" 등). 지금 문구 사전은 `^(전송|발송)완료$`과 `실패|미전송|대기|오류|중$`이다.

## 2부. 되돌릴 수 없는 구간 ([발급하기]부터. 대표의 명시 승인, 실제로 낼 건 한 건으로)

여기부터는 실제 세금계산서가 나간다. 미리 할 것:
- HAR 기록을 켠다.
- [발급하기]부터 완료 화면까지 화면을 녹화한다.
- 클릭은 한 번씩만 한다. 실패해도 다시 누르기 전에 발급목록을 먼저 본다.

### 2-1. 발급 확인창 (s21 expectConfirm)
- [ ] **브라우저 기본 confirm 창인지, WebSquare 레이어(`.w2window`)인지.** 엔진의 expectConfirm은 지금 브라우저 대화상자를 받는 구조다. 레이어라면 엔진 고침이 필요하다.
- [ ] 문구 그대로. 패키지 정규식은 `^(전자)?세금계산서를 발급하시겠습니까\?$`다.
- [ ] 버튼 이름(확인·취소)과 id.

### 2-2. 전자서명 창 (s21 signFlow)
- [ ] **간편인증으로 로그인했을 때 발급 서명을 간편인증으로 할 수 있는지, 공동·금융인증서를 요구하는지.** 패키지는 간편인증이면 `wait:push`(폰 승인), 공동인증서면 `human:secret`(금고 비밀 창)으로 갈린다.
- [ ] 서명 창이 레이어인지, iframe인지, 별도 프로그램인지. 역할·이름. 패키지는 dialog "전자서명"(`hometax.invoice.sign.root`)이다.
- [ ] 암호 칸(역할·이름·id·frame)과 [서명]이나 [확인] 버튼(`hometax.invoice.sign.confirmButton`, 패키지: button "서명").
- [ ] 폰 승인 방식이면 승인 뒤 저절로 진행되는지, 버튼을 한 번 더 누르는지.
- [ ] 서명 취소·시간 초과 때 문구와 요소. 패키지 실패 신호 자리표시는 `#signRejected` "전자서명을 취소했습니다"다.

### 2-3. 발급 요청 (commitEndpoints, 원장의 근거)
- [ ] HAR에서 [발급하기]부터 완료까지 나간 **모든 POST**의 경로·`actionId` 순서. 지금 패키지는 `POST /wqAction.do actionId=ATEETBDA001R01` 하나를 발급으로 본다. 확인한 적은 없다.
- [ ] 그 가운데 실제로 발급을 만드는 요청이 어느 것인지. 앞서 나가는 중복 확인·서명 원문 요청이 있는지(maxRequests 1과 맞는지).
- [ ] actionId가 쿼리에 있는지 본문에 있는지, 본문 인코딩(XML·JSON·form).
- [ ] 이게 확인되면 "POST 0번이면 발급 안 됨" 규칙(B2, 지금은 in_doubt 유지)을 다시 정할 수 있다.

### 2-4. 발급 완료 화면 (s30 이전, s32 save_pdf)
- [ ] 완료 안내의 요소·문구. 승인번호가 화면에 보이는지(어느 요소).
- [ ] 같은 탭에 남는지, 새 창·팝업(세금계산서 보기)이 뜨는지. save_pdf는 지금 **실행 탭을 그대로 인쇄**한다. 세금계산서 본문이 팝업에 뜨면 그 창을 인쇄해야 한다.
- [ ] [인쇄]·[PDF 저장] 버튼이 있는지, 누르면 브라우저 인쇄 대화상자인지 보안 인쇄 프로그램인지(Mac·Windows 각각).
- [ ] 발급 실패 때 문구와 요소(s30 failSignals, 지금 자리표시 `#errorDialog`).

### 2-5. 발급 뒤 조회 (s30·s33)
- [ ] 발급 뒤 발급목록에 그 건이 몇 초·몇 분 만에 보이는지(verify 대기 상한 300초 안인지).
- [ ] 메일발송목록에 "전송완료"가 몇 분 만에 뜨는지(s33 상한 50초 안인지, 넘으면 completed_with_issues).
