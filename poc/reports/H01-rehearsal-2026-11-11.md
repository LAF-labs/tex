# H-01 사람 속도 리허설 (2026-11-11)

부장 지시(2026-11-11): 사용자가 실제 홈택스에서 H-01을 하기 전에, 사용자가 밟을 구간을 가짜 홈택스에서 사람 속도와 사람 실수로 먼저 밟는다. 0.1.5~0.1.8에서 자동 시험이 놓친 막힘(이메일 코드 3초, profile_missing 노출 등)과 같은 종류를 찾는 것이 목적이다.
기준 커밋은 main `294bdfe`(설치본 0.1.8)다. 이 문서는 찾은 것을 보고만 한다. 고치는 일은 팀장이 배분한다.

## 1. 어떻게 밟았나

- **재현 e2e**: `apps/desktop/e2e/shell-rehearsal-e2e.ts`(새 파일, 수동 실행, CI 아님)
  - 실제 렌더러, preload, main 처리기, 엔진(utilityProcess), 승인 카드 뷰를 쓴다. 가짜 H-01 페이지(127.0.0.1)에 붙는다. DB는 빈 상태로 시작한다(견본 사업장·거래처·서류를 넣지 않는다).
  - 동작 사이에 `SAX_REH_PACE`(기본 6000ms)의 0.3~1.7배를 쉰다.
  - 값은 `insertText`로 붙여 넣는다. 키 입력 사건이 없으므로 ⌘V·IME 확정과 같다.
  - 클릭은 버튼 가운데에 실제 mouseDown·mouseUp을 보낸다(숨은 창이라 DOM 클릭이 안 되면 같은 순간에 대신 누른다). 제출은 칸에서 Enter로 한다.
  - 승인은 승인 카드 뷰에 실제 마우스 입력으로 한다. 승인 전에 창 blur → 4초 → focus를 넣어 "홈택스 Chrome을 보고 돌아옴"을 흉내 낸다.
  - `SAX_REH_PHASE=main`: 승인 대기 상태에서 정리 없이 앱을 끈다. 이어서 `SAX_REH_PHASE=restart SAX_REH_ROOT=<같은 루트>`로 다시 켜서 재시작 뒤 상태를 본다.
  - 찾은 문제는 `REPRO <id>` 줄로 찍는다. 고쳐지면 같은 자리에 `FIXED <id>`가 찍힌다.
- **CI에서 도는 재현**: `tests/h01-rehearsal.test.ts`. 고쳐야 할 모습을 단언하고 todo로 둔다. 지금은 todo 실패로 찍히지만 스위트는 깨지지 않는다. 고치면 통과로 바뀌므로, 그때 todo를 뗀다.
- 실행 방법(`poc/`에서):

```bash
pnpm build && SAX_REH_PACE=6000 node_modules/.bin/electron apps/desktop/e2e-dist/shell-rehearsal-e2e.js
```

```bash
SAX_REH_PHASE=restart SAX_REH_ROOT=<위에서 찍힌 root> node_modules/.bin/electron apps/desktop/e2e-dist/shell-rehearsal-e2e.js
```

## 2. 실제 H-01을 막는 것

### F-01 품목 없는 거래처로는 발급이 시작되지 않고, 화면이 고칠 길을 말하지 않는다 — **막음**

- **재현**: 경로 4→5. e2e `REPRO F-item-empty-card`·`F-item-missing-block`, 시험 `F-01 …`(todo 2건)
- **보이는 것**
  - 확인 카드: `추정 값 2개 · 부가세, 품목 · 아직 아무것도 보내지 않았어요`. 품목 줄이 빈 칸이다. 카드 버튼은 [홈택스에서 준비]·[부가세 포함하기]·[금액 수정]·[취소]뿐이다.
  - [홈택스에서 준비] 뒤: `확인 필요 · 품목이 비어 있어 시작하지 않았어요. 아무것도 발급하지 않았어요.` 그다음 할 일이나 버튼이 없다.
- **왜**
  - 제품 해석은 문장의 품목을 뽑지 않는다(`parseRegex` item: null). 그래서 품목은 거래처의 [저장 품목]에서만 온다(`shell-runs.ts createDraft` `item || cp.item`).
  - 그런데 [저장 품목]은 선택 칸이다(placeholder "발급 때 후보로 채워요"). [등록증으로 채우기]도 품목을 채우지 않는다(등록증의 종목도 후보로 오지 않는다). 온보딩도 품목을 묻지 않는다.
  - 처음 쓰는 사용자가 거래처를 등록증이나 번호로 넣으면 첫 H-01이 거의 반드시 여기서 멈춘다.
- **고칠 자리**: `static/shell/shell-views.js` taskCard(초안 품목 칸 편집), `src/shell-runs.ts` updateDraft(item 받기)·NOTE.item_missing 문구, `static/shell/shell.js` cpEditPanel·`src/counterparty-book.ts`(등록증 종목 → 저장 품목 후보)
- **제안**: 초안 카드의 품목 줄을 [금액 수정]처럼 고칠 수 있게 하고, 비어 있으면 [홈택스에서 준비]를 막고 그 칸으로 보낸다. 최소안은 item_missing 문구에 "거래처 화면에서 [저장 품목]을 넣고 다시 요청해 주세요" + [거래처 열기]를 붙이는 것이다.

## 5. 실제 입력 규칙 전수 점검 (`needGesture`·`needTyping`)

규칙: main이 메인 창에서 본 마지막 mouseUp, 또는 수식키 없는 Enter·Space(`needTyping`은 아무 keyDown)가 ms 안에 있어야 한다. 판정은 처리기 첫 줄에서 한다. 그래서 처리기 안의 대화상자·조회 대기는 시간에 들어가지 않는다.

## 7. 가짜 페이지로는 못 본 구간 (실제 홈택스에서만)

1. **홈택스 로그인(IR s0~s6)**
   - 간편인증은 폰 승인을 기다린다(핸드오프 상한 30분).
   - 공동인증서는 금고 비밀 창에서 비밀번호를 받는다(TTL 120초, 창이 홈택스 Chrome 뒤에 뜨면 못 볼 수 있다).
   - 보안 프로그램 설치 안내, 로그인 실패 문구, 세션 만료가 있다.
   - 가짜 페이지는 `login.session_assumed`다.
2. **로그인한 사업자와 프로필 번호 대조(s19c)**: 내 사업장 번호를 바꿨거나 대표자 개인 인증서로 로그인하면 `assert.supplier_mismatch`로 멈춘다. 문구가 맞는지 실제로 볼 것.

4. **되읽기 13칸 셀렉터**: 레지스트리 `hometax.invoice.issue@2.1.1`의 실제 화면 대응. 작성일자 KST(s19e).
