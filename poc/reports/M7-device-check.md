# M7 실기기 점검: 증빙 촬영·현금매출 (2026-11-06)

**결과: 통과.** 페어링부터 보안 확인까지 모두 실제 iPhone에서 됐다. 점검 중 화면 버그 두 개를 찾아 고쳤다(아래).

- **기기:** iPhone 16 Pro, iOS 26.7.2(사용자 기기). 우리 앱 하나만 설치했다. 기기 설정, 다른 앱, 사진 보관함은 바꾸지 않았다.
- **빌드:** 개발 빌드 `com.lafco.tex.dev`(Debug).
  - 팀 JA55KTZH34에 생긴 것은 네 가지다: 이 iPhone 등록, Apple Development 인증서 1개, App ID `com.lafco.tex.dev`, 개발 프로필 1개. 사용자가 허락했고, 빌드는 사용자가 직접 실행했다.
  - 릴리스 번들 ID `com.lafco.tex`는 그대로다.
- **맥:**
  - 실제 계정·릴레이 서비스(`dev/stack.ts`, `STACK_HOST=<이름>.local:8787`, 라이브 끔, 큐만)를 띄웠다.
  - Metro는 `EXPO_PUBLIC_TEX_DEV_HOST`로 띄웠다.
  - 페어링 QR은 맥 브라우저의 `/dev/qr.html`로 띄우고 폰 카메라로 찍었다.
- 실제 영수증 이미지, 금액, 상호, 번호는 이 보고서에 넣지 않는다. 받은 사진은 SHA-256만 대조했고 열어 보지 않았다.

## 찾아서 고친 것

1. **연결 화면(P-06)이 스크롤되지 않았다.** 계정·PC 이름 줄(#124)이 늘어 보호 상태 보고가 화면 밖으로 밀렸다. `ScrollView`로 바꿨다.
2. **보호 상태 목록의 React key가 겹쳤다.** 경로를 `<id>`로 가려 보여 주다 보니 같은 키가 생겼다(개발 경고). 순번을 키에 더했다.
3. 개발 도구 `dev/stack.ts` QR 페이지:
   - 6자리 입력 칸을 더했다(PC 앱 입력 대역).
   - 시간이 지나면 [새 QR] 버튼을 보인다. 저절로 다시 만들지 않는다. 릴레이는 페어링 룸을 계정당 시간당 5개까지만 받고, 더미 PC는 폰을 30초만 기다리기 때문이다. 처음에 저절로 바꾸게 했더니 `429 policy.rate_limited`가 났다.

## 개발 빌드에서만 나는 것

- 비행기 모드에서 앱 프로세스가 새로 시작되면 빨간 "No script URL provided"가 뜬다. 개발 빌드는 시작할 때 Metro에서 코드를 받기 때문이다. 릴리스 빌드는 번들을 앱 안에 넣으므로 해당하지 않는다.
- 이때 찍던 사진은 저장 전이라 남지 않았다. 앱을 닫지 않고 다시 한 시험(위 표)은 통과했다.
