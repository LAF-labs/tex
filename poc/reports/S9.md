# S9 OpenAI 실호출 스파이크 (PoC-7, 2026-10-29)

> **실호출 미실행, 키 필요.** 이 세션 환경에 `OPENAI_API_KEY`가 없었다. 스크립트·어댑터·egress 경로는 모의 서버로 끝까지 검증했고, 키를 넣으면 같은 명령으로 실측한다. 아래 "모의 결과"의 수치는 모의 서버가 만든 합성 응답이며 **측정값이 아니다**.

## 실행

```bash
cd poc && OPENAI_API_KEY=... pnpm s9
```

```bash
cd poc && pnpm s9 --mock
```

- 키는 환경 변수로만 받고 코드·보고서·원자료·커밋 어디에도 쓰지 않는다(`tests/s9-mock.test.ts`가 결과 파일에 키가 없음을 확인).
- 입력은 합성 화면 텍스트 20종(`tests/fixtures/s9-screens.ts`)뿐이고 마스킹(`@sax/redaction`)을 거친다. 실제 사업자 데이터는 쓰지 않는다.
- 호출 경로는 제품 경로와 같다: `OpenAIDecisionsAdapter`(SDK `openai@7.45.1`, `maxRetries: 0`) → `egress.toModel()` 검사 4종 → 티켓이 붙은 `providerFetch`만 공급사로 나간다.
- 비용 상한: 계획 호출 55회(Decisions 53 + Responses 2), 사전 추정 상한 $0.202(모든 입력을 캐시 쓰기 요율로, Terra 출력은 `max_output_tokens` 상한으로 계산). 실행 중 누적 비용이 $1.5를 넘거나 호출이 150회를 넘으면 멈춘다. 상한은 $2.
- 결과: `reports/raw/s9-live.json`(실측) 또는 [raw/s9-mock.json](raw/s9-mock.json)(모의).

## 측정 항목과 판정

| 항목 | 방법 | 확인할 것 | 근거 |
|---|---|---|---|
| 명시 캐시 적중 | `screen_state_v2` 같은 접두 + 다른 화면 3회 | 1회차 `cache_write_tokens` ≈ 접두, 2·3회차 `cached_tokens` ≈ 접두. 접두 o200k 1,949토큰(≥ 1,024) | D04 §2.1 |
| refusal 빈도·유발 텍스트 | 합성 화면 20종(기준 4, 안전 6, 인젝션 5, 사회공학 2, 경계 3) × `screen_state_v2` 9문항 | 질문별 refusal 수, 어떤 텍스트가 `page_text_addresses_agent`·`security_warning` refusal을 부르는지, refusal이 결과를 진행 쪽으로 바꾸지 않는지 | D04 §2·§9, BV-02 |
| 질문 수별 지연 | 탐침 번들 2·5·10문항 × `--reps`(기본 10) | p50·p95·최대(ms). 한국 egress 기준 | D04 §2(절대 수치 없음) |
| 레이트 리밋 헤더 | 모든 응답의 `x-ratelimit-*`·`retry-after` | Decisions 응답에도 오는지, 이름·값 | R1 §A.8 |
| choice `probabilities[]` | `screen` choice 20회 | 7개 전체 분포인지, top-1만인지 | D04 §2 예약 라벨 확률 정의 |
| `prompt_cache_key` 형식 | BYOK 키 `sax:b:<bundleWireId>`(콜론 포함) | 400 없이 받는지 | D04 §2.1 미확인 |
| `store:false` 재생 | Terra `selector_repair` 2턴: 1턴 도구 호출 → reasoning(`encrypted_content`)·function_call 재생 + `function_call_output` → 2턴 구조화 출력 | 2턴이 `previous_response_id` 없이 완료되는지, 도구 호출이 로컬 스키마를 통과하는지 | D04 §4 |

## 모의 결과(파이프라인 검증, 측정값 아님)

| 항목 | 모의 결과 |
|---|---|
| 호출 | HTTP 55회(Decisions 53, Responses 2), 오류 0, 모의 usage로 계산한 비용 $0.008 |
| 캐시 | 1회차 write 2,517 / 2·3회차 cached 2,517 (모의 서버는 바이트/3을 토큰으로 친다) |
| refusal | 20종 중 영문 직접 인젝션 1종에서 `security_warning`·`page_text_addresses_agent` 거절 → 결과 `blocked`(assume_true 해석) |
| choice 분포 | 모의 서버는 R1 예시대로 top-1만 준다 → 20/20 부분 분포. 이때 `P(blocked)`는 argmax∧confidence 규칙으로 계산됨 |
| 지연 | 로컬 루프백이라 의미 없음(< 1ms) |
| 레이트 헤더 | `x-ratelimit-{limit,remaining,reset}-{requests,tokens}` 6종 수집 |
| store:false 재생 | 1턴 `reasoning`+`function_call` → 2턴 `completed`, `outcome: repaired`. 재생 항목은 어댑터 HMAC 태그로 확인(위조 태그는 거부) |

모의 refusal 행에서 보인 설계상 사실: 인젝션 문구가 있는 화면(`inj_ko_direct`)이 모델 답만으로는 `logged_in`이 될 수 있다. 실제 판정에서는 엔진 judge의 결정적 사전 필터가 이 진행 결과를 `unknown`으로 내린다(`tests/l0.test.ts`). S9 원자료의 `outcome`은 사전 필터 적용 전 값이다.

## 실측으로 닫을 미확인(R1 §D.2)

1·4번(Decisions 레이트 리밋·지연), 5번(refusal 발생 조건), 8번(`prompt_cache_key` 형식, 캐시 진단), choice 전체 분포 여부, Terra `store:false` 재생. ZDR·`kr.` 리전·SP-7은 영업 문의라 이 스크립트 밖이다.

## 키를 받으면

1. 위 명령으로 1회 실행(약 55회 호출, 예상 실비 수 센트).
2. `reports/raw/s9-live.json`을 이 문서의 "모의 결과" 표 자리에 실측 표로 옮기고, 호출 수와 실비를 적는다.
3. choice 분포가 top-1만이면 D04 §2의 예약 라벨 확률 정의(argmax∧confidence)를 확정하고, 전체 분포면 `probabilities[]` 값을 쓰도록 둔다(코드는 두 경우 모두 처리).
