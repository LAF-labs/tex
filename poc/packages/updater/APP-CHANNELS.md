# 앱 채널 규칙(데스크톱·폰 공통, ADR-028)

> D14 M7-1 선행(M4-9). 폰 빌드·서명·스토어 제출은 폰 트랙이 한다. 이 문서는 두 앱이 함께 지키는 **채널 규칙**만 정한다. 근거: ADR-028 결정 1~5, D09 §8.2·§8.3·§8.6, D11 §4 자동 업데이트·모바일 행, D08 §3.

## 1. 신뢰 뿌리

| | 데스크톱(Windows) | 폰(iOS·Android) |
|---|---|---|
| 배포 경로 | 레지스트리 `/releases/{channel}/latest.json` + 설치본 | App Store·Google Play(스토어가 배포·설치) |
| 앱이 설치 전에 보는 서명 | `latest.json` Ed25519 릴리스 키(하드웨어 토큰, 비운영자 1인) + 뿌리 변경이면 루트 2-of-3 | 없음(스토어 서명·OS 검증) |
| OS 코드서명 | Artifact Signing(Microsoft 보관 외부 단일 키, 정직 고지) | Apple 배포 인증서·Play 앱 서명(스토어 보관 외부 키, 정직 고지) |
| 원격 코드 갱신 | 없음(설치본 단위) | **OTA(JS 번들 원격 갱신) 쓰지 않는다**. 쓰게 되면 자체 키(오프라인) 코드 서명 필수, 프로토콜·암호 모듈은 네이티브 빌드에만(D11 §4 모바일 행) |
| 빌드 장소 | 자체 Windows 러너(서명 시크릿은 보호 환경) | 자체 러너. 서명 키를 외부 빌드 서비스(EAS Build 등)에 올리지 않는다(D11 §4) |

## 2. 채널

- 이름: `stable`, `beta`(레지스트리 채널 목록의 부분집합, `hotfix`는 플레이북 전용이라 앱에 쓰지 않는다).
- 한 기기는 한 채널만 구독한다. 채널 바꾸기는 설정에서 사용자가 하고, 바꾼 뒤에도 **설치본보다 낮은 버전은 받지 않는다**(beta → stable로 옮기면 stable이 따라올 때까지 그대로).
- 폰은 스토어 트랙으로 대응한다: `beta` = TestFlight·Play 내부/비공개 테스트, `stable` = 프로덕션.
- 버전: `x.y.z`(사전 릴리스 표기 없음). 같은 채널 안에서 늘기만 한다. 데스크톱·폰 버전 번호는 따로 센다.

## 3. 뿌리를 바꾸는 릴리스(ADR-028 결정 3)

핀 키(`keyEpoch`)·내장 허용 목록(eTLD+1, 금고 origin)·앱 내장 상한(`PORTAL_MODE_CEILING`)을 바꾸는 릴리스는 루트 2-of-3 서명을 남긴다.

- 데스크톱: `latest.json` `rootChange`(`@sax/updater` README).
- 폰: 스토어가 설치를 막을 수 없으므로 **릴리스 노트와 투명성 로그 항목**에 같은 2-of-3 서명(내용 = `{platform, version, changes, keyEpoch, buildDigest}`의 JCS)을 남긴다. 페어링된 PC는 폰 `hello`의 앱 버전을 그 로그와 대조해 서명 없는 뿌리 변경 버전이면 경고한다(Phase 2 `hello.registryHeadHash`와 함께, D08 §5).

## 4. 설치·적용 시점

- 데스크톱: 실행 중·커밋 구간·데몬 실행 중에는 설치하지 않는다(`installGate`).
- 폰: 스토어 업데이트는 OS가 하지만, 앱은 **페어링 프로토콜 버전이 PC와 맞지 않으면** 승인·전송을 하지 않고 "앱을 업데이트해 주세요"만 보인다(낮은 쪽에 맞추지 않는다, 다운그레이드 협상 없음).

## 5. 실패와 롤백

- 공통: 앱은 내려가지 않는다. 문제 릴리스는 이전 코드로 버전을 올려 다시 낸다(앞으로 롤백). 확산 멈춤은 데스크톱 `rolloutPercent`, 폰 스토어 단계적 출시 일시 중지.
- 검증 실패 문구는 하나다: "업데이트를 확인하지 못했습니다"(ADR-028 UX 영향). 지금 설치본으로 계속 쓴다.
- 14일 동안 업데이트 확인 성공이 없으면 알린다(데스크톱 D11 §4). 폰은 스토어가 맡는다.

## 6. 키 보유자(역할당 1인 1키, ADR-028 결정 5)

릴리스 키(데스크톱 `latest.json`)·Apple 배포 인증서·Play 업로드 키는 서로 다른 사람이 갖는 것을 목표로 한다. 5인 팀에서 겹치면 겹친 것을 ADR-013 결과 절 배정표에 적는다. 어느 키도 CI 러너 디스크·레지스트리 호스팅 권한자에게 두지 않는다.
