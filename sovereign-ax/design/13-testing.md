## 2. 테스트 데이터와 머리 규칙

- **머리 규칙 1**: 운영 수준이 `postprocess`인 포털(정부24·SMINFO·4대보험)에는 스파이크·리플레이 녹화·코퍼스 수집을 포함해 **어떤 자동화도 하지 않는다.** 사람이 조작하고 하네스는 파일 감시·기록만 한다. 정부24 탭에 CDP를 붙이지 않는다.
- **머리 규칙 2**: 전자세금계산서는 발급 후 취소가 없고(수정세금계산서로만 상쇄), 공급 없는 발급은 조세범처벌법 제10조 위험이 있다. 따라서 **"0원·취소 가능 발급"은 없다.** 실발급은 관계사 간 **실거래 소액 용역**(실제 공급이 있는 건) 2~3건으로 제한하고, 그 적법성은 법률 질의 5번째 항목으로 확인한 뒤에만 한다. 나머지 측정은 **게이트 직전까지의 자동 구간**(실발급 없음)으로 한다. 리플레이 녹화는 그 실거래에서만.
- 테스트 사업자(법인 1, 개인사업자 1)는 창업자의 실제 영업 법인이 아닌 **테스트 전용 법인**이어야 한다(차단·정지 시 실제 업무 계정 보호). 조달 일정·계정 정지 시 대응은 D18에 적는다.
- 테스트 코드는 사용자 기본 앱 루트(`%LOCALAPPDATA%\SovereignAX`)를 쓰지 않는다. Electron 스모크도 임시 루트로 띄우고, 실 루트에 `db\db.sqlite`가 있으면 시작하지 않는다(ADR-022, D-38(N-57)).
- 합성 식별자 생성기(체크섬 유효)로 마스킹·파서 테스트.
- 화면 스냅샷 코퍼스: 스파이크에서 수집, 마스킹 후 라벨링(S7용 300장+).

## 3. 포털 리플레이 하네스

- 녹화: 스파이크 실행 중 네트워크(HAR)·DOM 스냅샷(스텝 경계)·접근성 트리를 저장. 비밀 입력 단계는 녹화 제외, 개인 식별자는 저장 전 마스킹. HAR은 저장 전에 인증 경로 바디·`Cookie`·`Set-Cookie`·`Authorization`을 제거하고 암호화해 보관한다(A-32).
- 화면 영상은 로그인·비밀 창 활성 구간·인증서 선택·비밀번호 화면을 찍지 않는다(로그인은 녹화 밖에서 하고 세션을 이어 쓴다). 영상·스크린숏·HAR은 `%LOCALAPPDATA%\SovereignAX\spikes\`(사용자 전용 DACL, OneDrive 밖)에만 두고 누출 스캐너 대상에 넣으며 12-31에 지운다. HAR은 `recordHar({content:'omit', urlFilter: 조회 경로})`로 바디·쿼리를 처음부터 뺀다(ADR-022, D-08(N-05)).
- 재생: Playwright `routeFromHAR`로 네트워크를 재생하고, 비밀·간편인증·캡차 스텝은 **스텁 핸들러**(즉시 성공/실패 시나리오 선택)로 대체.
- 시나리오: 정상, 세션 만료, 안내 팝업, 입력 검증 오류, 캡차 등장, 차단 안내, 셀렉터 drift(후보 1 제거), 제출 후 결과 지연.
- 수용: 모든 시나리오에서 엔진이 명세된 상태(완료/핸드오프/쿨다운/InDoubt)에 도달하고 비가역 스텝이 2회 실행되지 않음.
- 실패 시퀀스 회귀(REVIEW-A §B): ① 클릭 후 결과 렌더 전 단절 ② 포털 이중 제출(Enter+클릭, confirm 재표시) ③ 클릭~verify 사이 크래시 ④ 제출 뒤 human TTL 초과 → Paused → 재개 ⑤ 리모트 명령 지연 재전달 ⑥ 데스크톱 2대 ⑦ 정당한 동일 거래 2건 ⑧ 핸드오프 중 사용자가 직접 발급 → 재개(B-04) ⑨ 발급목록 반영 지연 중 `not_committed` 판정 시도(B-07) ⑩ 같은 `intent_id`로 다른 입력의 `cmd.run` 재수신(B-10). 기대: ①~⑤·⑧~⑩ 중복 0건(InDoubt·committed 재사용·거부), ⑦ 차단 없이 경고. ⑥ 데스크톱 2대는 **온라인이고 백업 스위치가 켜져 있으면 경고**(서버 `biz_key_marks`의 `committed`·`in_doubt`·`armed`, B-30·E-13), **오프라인·동시 게이트(수 초 창)·백업 꺼짐이면 중복 가능**(잔여 위험, D03 §4.1, D19 §8).
- `decide`는 저널의 기록값으로 스텁해 재생한다(판정 결과는 재질문하지 않는다).

## 8. 운영 수준별 고정 테스트

- `postprocess` 모드 실행 중 Chrome 기동 0회, CDP 연결 0건, 포털 요청 0건(네트워크 캡처)임을 자동 테스트로 고정한다. 포털은 `shell.openExternal` 호출 1회만(비 https·허용 밖 호스트는 거부). docparse 샌드박스의 네트워크 요청 0건, 비밀 단계의 복사 버튼 0개.
- `assisted` 변환 IR이 검증기를 다시 통과하는지, `human_commit`이 토큰·원장·verify를 거치는지 리플레이로 고정한다.
- 서명 없는 `gate.response`, 챌린지 불일치 `sealed`, 과거 봉인문 재생, 소프트웨어 키 서명의 비가역 승인, `consent.response`를 게이트 승인으로 제출, 서명 없는 기기 목록은 모두 거부되어야 한다(프로토콜 회귀).
- 리모트·클라우드 회귀(감사 C): PAIR_OK의 AIK 불일치 중단, 24시간 이내 등록 데스크톱 경고, 비가역 카드에서 `ed25519` 응답 거부, 폰 `actionHash` 재계산 불일치 시 승인 비활성, 큐 6번째 의도 거부, 시작 게이트 전 무조작, 만료 `Q_D` 봉인 거부, `rev` 롤백·위조 레코드 거부, 라이브 `cmd.run` 중복 `cmdId` 거부, 깨우기 속도 제한, 복구 72시간 보류, 즉시 삭제는 AIK 서명만, 레지스트리 `+1001` 버전·폐기 키 서명·헤드 해시 불일치·status 48/72시간.
- 로컬 승인은 main 소유 승인 바(`WebContentsView`)에서 main이 관찰한 클릭으로만 성립함을 고정한다(A-15, E-06, ADR-021).
  - 승인이 아닌 것: 키보드 입력(Enter·조합키), 바가 보이거나 옮겨지거나 요약·동작이 바뀐 뒤 600ms 안의 입력, 창이 옮겨지거나 다시 보이거나 활성화된 뒤 600ms 안의 입력(앱이 연 비밀 창·전용 Chrome·Hello에서 120초 안에 돌아와 바를 눌러 활성화한 경우만 예외, ADR-024), 바 안에서 실제로 움직인 뒤 150ms 안의 mouseDown, 대화 화면 커서가 숨겨지거나 바뀐 동안의 입력, 대화 렌더러가 보낸 승인 신호, 렌더러 명령 중계 경로로 온 `answerGate`.
  - 무장 전 mouseDown은 600ms를 다시 시작한다. 상태 문구("잠시 뒤 다시 눌러 주세요", "마우스를 조금 움직인 뒤 눌러 주세요")만 바뀌면 재무장하지 않는다.
  - 멈춘 커서 아래에 바가 뜬 경우(대기열의 다음 건 등) 마우스를 움직이지 않은 클릭도 600ms 뒤에는 승인된다. 알림 창이 바를 덮었다가 사라진 뒤의 클릭은 실제 이동 뒤 150ms가 지나야 승인된다.
  - e2e: 외부 창에서 돌아온 첫 바 클릭은 거부되고 0.6초 뒤 승인된다. 앱이 연 핸드오프(비밀 창·전용 Chrome)에서 돌아온 클릭은 바로 승인된다(ADR-024, D-31(N-48)).
  - 중복 경고(`$dup.*`)가 있으면 바의 동작 글자가 "같은 건 기록을 확인했고 발급"(원장에 `committed`가 있으면 "발급된 기록을 확인했고 한 번 더 발급", 주의 색, ADR-024)이고, 이 클릭 없이는 게이트를 통과하지 않는다. `$first.*`·`$dup.*`를 뺀 `fields`로는 `cardHash`가 맞지 않는다.
  - InDoubt 증언의 `LocalAttestation.summaryHash`가 증언 바에 보인 건과 다르면 거부된다. 바 자리 우선순위(게이트 > 증언 > Hello 설정)가 지켜진다.
  - 렌더러의 `window.moveTo`·`resizeTo`와 `alert()`는 막힌다.
  - 이 판정 로직은 `sendInputEvent` e2e로 고정하고, 배율·모니터 이동·머무름·알림 창 사라짐·클릭 활성화는 OS 수준 입력(별도 프로세스의 `SendInput` 또는 사람의 클릭)으로 따로 시험한다.
  - 바 위치는 렌더러 보고와 무관하고, 창 크기 변경 뒤 다시 배치·재무장된다. 승인 대기 중 렌더러의 숨김 요청은 무시된다.
  - `trigger=local`이 아닌 실행에서는 바가 자동으로 뜨지 않고, 폰이 먼저 결정하면 바가 내려간다.
  - InDoubt 증언은 `LocalAttestation`으로만 받고 승인 근거로는 거부된다. 앞 게이트의 `LocalApproval`은 같은 실행의 다음 게이트에서 거부된다.
  - Hello를 켠 경우 `Verified` 밖의 결과로는 `LocalApproval`이 발급되지 않고, 쓸 수 없을 때의 면제는 `presence: click+waiver`와 알림을 남긴다.
