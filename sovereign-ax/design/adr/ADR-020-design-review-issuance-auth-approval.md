# ADR-020. 화면 디자인 검토 결정: 발급 인증 고정, 카드 승인, 응답 끊김 자동 조회, 부가세 토글, 새 PC 복구

> 상태: 채택(2026-10-30), 결정 4의 버튼 위치와 승인 근거는 ADR-021(2026-10-31) · **결정 3·7은 ADR-026·029로 개정(2026-11-03)**: 결정 3의 저장 방식(통째 JSON·DPAPI·Hello 기본 꺼짐)은 [ADR-026](ADR-026-human-secret-device-bound-session-vault.md)(칸 단위·TPM 결박 KEK·Windows 세션 추종 금고·엄격 모드 Hello)으로 대체, 결정 2의 완전 위임은 유지. 결정 7의 PASS 범위 미결은 [ADR-029](ADR-029-remote-recovery-data-minimization.md) 결정 1(PASS는 계정만, 백업은 연결된 폰으로만)로 닫음 · 관련: ADR-005, ADR-014(§2 대체), ADR-016(복구 문구 경로 대체), ADR-019, 02 §2·§4·§7, 08 §3·§4·§6·§9·§11
> 근거: 디자인 캔버스 [소버린 AX 화면 디자인](https://claude.ai/artifact/Fyc1UUSuZs3e9y6tydeSL3) 댓글 검토(2026-10-30), research/R2 §1·§2

## 맥락

- 화면 디자인 캔버스를 검토하면서 사용자가 다섯 가지를 바꿨다. 금액 해석 카드, 별도 승인 창, 사람에게 결과 확인을 넘기는 예외 처리, 12단어 복구 문구가 모두 사용 흐름을 끊는다는 이유다.
- 홈택스 전자세금계산서 발급의 전자서명 수단은 공동인증서(사업자범용·전자세금계산서용), 금융인증서(전자세금용), 보안카드, 사업자용 간편인증(2026-04, 카카오뱅크·IBK·KB)이다(R2). 2026-04 기준 발급 사업자 비중은 공동 83%·보안카드 14%·생체 2%·금융 1%다. 보안카드는 아이디 로그인 때만 전자서명 창에서 고를 수 있다.
- 공동·금융인증서 비밀번호는 가상키패드·키보드보안(nxKey 계열)으로만 받는다. 앱이 넣으려면 이 장치를 우회해야 하는데, 05 문서와 R3는 우회를 하지 않기로 정했다.

## 결정

1. **발급 인증은 한 번 고르면 고정한다.** 온보딩(08 O-03)에서 보안카드·사업자 간편인증·공동인증서·금융인증서 중 하나를 고르고, 모든 발급에 같은 방법을 쓴다. 바꾸려면 설정 > 발급 인증에서만 바꾸며 다음 발급부터 적용한다. 진행 중인 작업은 원래 방법으로 끝낸다. 작업 패널 확인 값에 현재 발급 인증을 한 줄로 보여 준다.
2. **수단별로 앱이 맡는 정도를 정한다.**
   - 보안카드: 완전 위임. 홈택스 아이디·비밀번호와 카드 30개 번호를 금고 창에서 한 번 등록하고, 발급 때 금고가 요청 번호를 홈택스 칸에 바로 넣는다(ADR-005 타이피스트).
   - 사업자 간편인증: 로그인과 전자서명 때마다 사용자가 폰에서 승인한다.
   - 공동·금융인증서: 비밀번호만 사용자가 브라우저 창에 직접 넣고 나머지는 앱이 한다. 비밀번호를 저장하거나 자동 입력하지 않는다.
3. **보안카드 저장**: 번호를 JSON으로 묶어 AES-256-GCM으로 암호화하고, 열쇠는 Windows가 로그인 계정에 묶어 보관한다(DPAPI·자격 증명 관리자, 한 항목 2,560바이트 이내). 발급마다 Windows Hello 확인을 설정에서 켤 수 있다(기본 꺼짐). 값은 금고 프로세스만 다루며 모델·우리 서버·대화·활동 기록으로 가지 않는다. 같은 Windows 사용자 권한의 악성코드는 막지 못한다고 고지한다. 카드 사진으로 채우는 경우 Windows 기본 OCR(`Windows.Media.Ocr`, GPU 불필요·추가 배포 없음)로 금고 프로세스 안에서 숫자만 읽어 칸에 채우고, 사진은 바로 지운다. 읽은 값은 사용자가 확인·수정한다. Electron에서 부를 네이티브 연결(WinRT 바인딩 또는 작은 헬퍼)은 구현 때 정한다.
4. **별도 승인 창을 없앤다(ADR-014 §2 대체).** 홈택스에서 되읽은 값을 "홈택스 확정"으로 보여 주는 승인 대기 카드·작업 패널의 [승인하고 발급]을 누르면 바로 발급한다. 이 버튼은 승인 대기 카드·패널과 모바일 승인 시트에만 두고, 입력창 Enter로는 눌리지 않는다.
5. **응답이 끊기면 앱이 스스로 확인한다.** 발급 후 결과를 모르면 발급목록을 다시 조회한다("확인 중", 조회 횟수 표시). 확인 전에는 재발급하지 않고, 발급되지 않았다고 확인되면 승인 대기로 돌아간다. 사람이 필요한 경우는 홈택스 재로그인뿐이다. 조회가 계속 실패하면 그때 "확인 필요"로 넘긴다.
6. **세금계산서 금액은 부가세 토글로 정한다.** 금액 해석을 고르는 카드를 없앤다. 입력창에 "계산서"가 보이면 보내기 전에 부가세 [별도] [포함] 토글을 띄운다. 고르지 않으면 별도로 계산하고(추정 값으로 표시) 초안 카드에 [부가세 포함하기] [금액 수정] [취소]를 둔다. 과세·영세·면세는 여전히 앱이 추측하지 않는다.
7. **새 PC는 폰 승인으로 연결한다(ADR-016의 복구 문구 경로 대체).** 12단어 복구 문구를 온보딩에서 없앤다. 두 번째 PC에 로그인하면 연결된 폰에서 생체 인증으로 승인해 백업과 기기 연결을 넘겨받는다. 폰을 쓸 수 없으면 PASS 본인인증으로 계정을 되찾고 72시간 보류·전 기기와 이메일 알림을 둔다. 폰만 바뀌면 PC에서 다시 연결한다. 공동인증서는 백업하지 않는다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 발급할 때마다 인증 수단을 묻기 | 매번 같은 답을 하게 된다. 사용자는 한 가지 수단을 계속 쓴다 |
| 공동인증서 비밀번호를 저장해 가상키패드를 앱이 누르기 | 보안 모듈을 우회하는 동작이라 05 문서·R3 원칙과 충돌하고, 탐지·제재 위험이 있다 |
| 별도 승인 창 유지(ADR-014) | 사용자가 흐름이 끊긴다고 판단했다. 보호 일부는 Windows Hello 옵션으로 남긴다 |
| 결과 미확인을 사용자에게 넘기기 | 에이전트가 할 수 있는 조회를 사람에게 미룬다 |
| 금액 두 해석 카드 | 한 번 더 고르게 해 흐름이 끊긴다. 토글은 보내기 전에 정할 수 있다 |
| 12단어 복구 문구 | 사용자 부담이 크고, 백업이 없는 PoC·Phase 1에서는 쓸 일이 없다 |

## 결과

- 08 §3·§4·§5·§6·§9·§10·§11·§12·§13, 02 §2·§3·§4·§7, D01 §4를 고친다. 디자인 캔버스와 디자인 시스템(승인 버튼 규칙, 상태 칩 "확인 중")을 맞춘다.
- **보안 영향**: 별도 창이 없어지면 렌더러(대화창)가 오염됐을 때 승인 클릭을 위조할 수 있다. 커밋 가드의 승인 근거(`LocalApproval`, D03 §5·D05 §3.3)를 다시 정해야 한다. 후보는 (a) Windows Hello 확인을 켠 경우 main이 `UserConsentVerifier` 결과로 근거를 발급, (b) main이 렌더러 버튼 클릭을 입력 이벤트로 직접 관찰. D01·D03·D05·D08·D11·D13·D14·D19의 승인 창 서술은 이 재설계 때 함께 고친다. → ADR-021에서 main 소유 승인 바를 근거로 정하고 Hello는 그 위의 선택 단계로 두었다(2026-10-31).
- 보안카드 자동 입력이 홈택스 이용 규정상 허용되는지 법률 질의에 추가한다.
- 모바일 원격 발급은 발급 인증이 간편인증이나 보안카드일 때 가능하다. 공동·금융인증서는 PC에서만 발급한다.

## 조건

- 보안카드 입력칸이 가상키패드인지, 홈택스 아이디 로그인 2차 인증(2025-07, 2차 자료)이 어떤 방식인지 PoC에서 확인한다. 가상키패드라면 결정 2의 보안카드 완전 위임은 보류하고 사용자 직접 입력으로 바꾼다.
- PASS 본인인증만으로 백업 서류까지 열지(서버 HSM에 열쇠 사본 필요), 계정만 되찾을지는 미결이다. 정해지면 ADR-016을 함께 고친다.
