# ADR-046. 폰에서 세금계산서 발급: 폰 승인(M7-7)을 Phase 1로, 폰 발급 명령, PC가 넘기는 폰 사본

> 상태: 결정 1 채택(2026-11-16 yulmu, 폰 앱 기획 v2 결정 카드 "이번에 넣기") · 결정 7 "대화는 기기마다 따로, 일·기록 공유"와 "PC 꺼짐 때 폰이 모델을 직접 부름" 채택(2026-11-16 yulmu) · 폰 사진은 카메라와 앨범 둘 다(2026-11-16 yulmu) · 결정 4 iPhone 승인 기기 채택(2026-11-17 yulmu) · 그 밖의 결정 2~7 세부는 제안(사용자 확인 전)
> 근거: 폰 앱 기획 v2(Claude Docs "택스오프 폰 앱 기획 v2", 2026-11-16) §0·§4·§10
> 관련: [ADR-034](ADR-034-phase1-scope-single-plan-accountant-link.md) 결정 9(개정), [ADR-016](ADR-016-account-trust-anchor-hardware-approval.md)(하드웨어 승인), [ADR-021](ADR-021-pc-approval-evidence-main-approval-bar.md)(main 승인 카드), [ADR-029](ADR-029-remote-recovery-data-minimization.md)(원격 실행 시작 게이트), D08 §6·§6.1·§7·§8.1, D14 §2.7 M7-7, 08 §3 P-02~P-05·§10, 09 §13, 11-cash-flow §3.7(PR #391)

## 맥락

- ADR-034 결정 9는 Phase 1 폰을 "종이 증빙 촬영 + 현금매출 입력"으로 두고, 폰 승인(M7-7)을 Phase 2 리모트 묶음으로 미뤘다.
- 대표 지시(2026-11-16): 폰 앱은 단순 채팅이 아니라 밖에서 빠르게 발급하고, 종이 증빙을 찍어 올리고, PC가 꺼져 있을 때 시킨 일을 모아 두는 앱이어야 한다. 계좌 연결로 받을 돈·낼 돈과 현금흐름도 폰에서 본다.
- 폰 승인이 없으면 폰 발급은 "폰에서 적고 PC 앞에서 승인"이 된다. 밖에서 거래처 앞에서 끊는 상황(기획 v2 S1)을 못 푼다.
- 프로토콜은 이미 있다. 원격 비가역 승인 규칙(D08 §6.1), 의도 봉투 큐와 시작 → 커밋 2단계 게이트(D08 §7), 라이브 WSS(PR #386로 운영 룸 호스트에서 켜짐).

## 결정

1. **폰 승인(D14 M7-7)을 Phase 1에 넣는다**(채택). ADR-034 결정 9의 "폰 승인 Phase 1 제외"를 이 결정으로 바꾼다. Phase 1 공수에 M7-7 7일을 더한다(D14 §2.7 소계 26일 → 33일).
   - 안전 규칙은 D08 §6.1 그대로다. 비가역 원격 승인은 P-256 하드웨어 키(`Px`)로만, `remote.irreversiblePerDay` 기본 5, `remote.newCounterpartyRequiresLocal` 기본 true, `remote.notifyOnIrreversible` 기본 `["desktop","email"]`. 정책은 더 엄격하게만 바꾼다.
   - 승인 화면은 08 P-03(원격 확인 카드)이다. 값은 PC readback, 라벨은 앱 사전, 폰이 `cardHash`를 다시 계산해 맞을 때만 승인 단추를 켠다. 한 시트에 비가역 행위 하나, 묶음 승인 없음.
2. **(제안) 폰 발급 명령.** 폰은 발급 플레이북을 `cmd.run`(라이브) 또는 의도 봉투(큐)로 시작한다. 입력은 `counterpartyRef`(로컬 거래처 ID) · 공급가액 · 부가세 별도/포함 · 품목 · 작성일자이고, 사업자번호·이메일 원문은 넣지 않는다(D08 §7, C-34). 받는 이메일은 PC가 그 거래처에 저장된 값을 쓴다. 큐로 온 명령은 PC가 켜진 뒤 시작 게이트(폰 생체 + `Vm` 서명)를 지나고, 비가역 단계에서 커밋 게이트(결정 1)를 지난다. 메시지 모양은 remote-envelope v1.8(`cmd.ack`, `run.event`의 `phase`·`result`, D08 §6)이다.
3. **(제안) 밀린 일.** PC가 꺼져 있을 때 폰이 시킨 일은 폰 로컬 목록에 남는다. 우편함 의도 봉투 한도(`queue.maxIntentsPerPair` 5, 72시간)를 넘는 것은 폰에 두었다가 앞의 일이 시작되면 이어서 맡긴다. PC가 켜지면 깨우기 푸시(D08 §8.1)로 폰이 "시작할까요?"를 띄우고, 시작 게이트는 한 번의 생체 확인으로 묶어 통과할 수 있다(커밋 게이트는 건마다).
4. **iPhone도 승인 기기로 받는다**(채택, 2026-11-17 yulmu: "받자"). iOS는 Secure Enclave 키 생성을 증명할 수 없어 `hw_attest_state = ios_app_attest`(앱 무결성만)다. 이 상태의 `p256` 응답을 받되, 하루 한도·처음 거래처 PC·이메일 알림을 그대로 걸고 잔여 위험을 ADR-016과 D08 §6.1에 적는다. 기각하면 iPhone 사장님은 늘 PC 앞 승인이다.
5. **(제안) PC가 넘기는 폰 사본.** PC는 라이브 세션이 열릴 때마다 폰 화면에 필요한 요약(거래처 목록과 최근 발급 값, 이번 달 판의 발급할 것, 받을 돈·낼 돈·흐름 요약 = 엔진 `db.query.bank.summary`·`db.query.bank.cashflow` 결과)을 종단간 암호화로 보낸다. 폰은 봉인 저장(백업 제외)하고, PC가 꺼져 있으면 기준 시각과 함께 보여 준다. 서버에는 남지 않는다. 09 §13 "PC 꺼짐 조회·폰에서 보기 제외"를 이 범위에서 바꾼다(11-cash-flow §9 결정 6과 같은 안). 메시지 모양은 remote-envelope v1.8 `phone.copy`(D08 §6)다.
6. **(제안) 폰 디자인 기준 예외.** 폰 `docs/design.md`의 "파랑 채움 단추는 폰에 없다"를 "승인 시트의 [승인하고 발급] 하나에만"으로 고친다.
7. **대화는 기기마다 따로, 일과 기록은 공유한다**(채택, 2026-11-16 yulmu 결정 카드 "대화 따로, 일·기록 공유"). 처음 방향("PC와 채팅을 공유")을 이것으로 바꾼다. 계정에 PC·폰이 여러 대(ADR-048)여도 대화를 합치지 않는다.
   - 기기마다 자기 대화를 가진다. 공유하는 것은 발급기록(원장), 밀린 일(결정 3), 거래처 목록(폰 사본), 받을 돈·낼 돈이다.
   - 새 대화를 열면 맨 위에 다른 기기에서 한 일을 한 줄로 보인다(예: "폰에서 2건 맡김 · 1건 발급됨"). 근거는 공유한 원장·밀린 일이지 다른 기기의 대화 원문이 아니다.
   - PC 켜짐: 폰 대화는 폰의 것이다. 폰이 발급·조회를 하려면 명령(결정 2)으로 PC에 맡긴다.
   - PC 꺼짐(채택, 2026-11-16 yulmu: "PC가 꺼져 있을 때 폰이 AI를 직접 부르게 해. 컨텍스트 관리도 잘 하고"): 폰에서 대화를 이어 간다. 폰이 게이트웨이를 거쳐 PC 에이전트와 같은 모델을 부른다. 실행은 밀린 일(결정 3)로만 한다.
   - 컨텍스트(제안, 기획 v2 §3.2): 한 번 부를 때 역할(앱 내장) + PC가 만든 긴 요약(≤ 1,500토큰) + 최근 20턴 + 이번 말에 나온 거래처·건만 고른 사실(폰 사본, 거래처 5곳까지) + 읽기·카드 채우기 도구. 상한 8,000토큰, 넘으면 고른 사실 → 오래된 턴 순으로 줄이고 역할·긴 요약은 줄이지 않는다. 거래처 목록·원장 전체는 보내지 않는다.
   - 가림: 폰도 `@sax/redaction`과 같은 규칙을 쓰고, 같은 시험 자료로 PC·폰 결과가 같아야 한다(CI). 사업자번호·이메일·계좌·전화·주민번호는 모델에 보내지 않고, 거래처는 자리표로 보내 화면에 그릴 때만 폰에서 되돌린다. 비밀이 입력되면 보내기 전에 막는다.
   - 폰 호출은 같은 계정의 하루 사용 한도(PR #384)에 센다.
   - 다시 켜짐: 폰에서 맡긴 밀린 일이 PC로 넘어가 실행된다. 폰 대화 원문은 PC로 보내지 않는다(대화 합치기 없음).
   - 폰 기능은 PC의 일부다. 금고·인증수단 등록, 계좌 연결, 급여대장, 세무사 꾸러미 보내기, 발급 취소·수정은 PC에만 둔다(기획 v2 §3.1 표).

## 결과

- 폰 앱 작업(taxoff-mobile): 앱 틀·홈·밀린 일·발급 작성·승인 시트·진행·결과·서류 보기·등록증 찍기·돈 탭(기획 v2 §9 PR 1~9).
- tex 작업: `@sax/remote`에 발급 `cmd.run`·`gate.request`/응답·진행 이벤트·폰 사본 메시지와 CAP, PC `phone-link`에 명령 수신·게이트·사본 송신, 폰 `Px` 등록과 증명 검증.
- D14 §2.7 M7-7을 Phase 1로 옮기고, 08 §3의 P-02~P-05 범위를 Phase 1로 고친다(이 PR).
- 폰 발급 품질은 PC 발급 경로(발급 사다리 #387 등)에 그대로 기댄다.

## 기각

- **폰 승인 Phase 2 유지**(폰은 작성·준비만): 출시는 빠르지만 밖에서 바로 발급이 안 된다. 대표가 기각했다(2026-11-16).
- **소프트웨어 키(`Vm`, Ed25519)로 비가역 승인**: D08 §6.1·ADR-016의 하드웨어 키 규칙을 깬다.
- **PC 꺼짐 때 모델 없이 정해진 문장만 해석**: 대화가 끊겨 "대화를 공유한다"는 경험이 깨진다. 대표가 기각했다(2026-11-16).
- **서버에 받을 돈 요약을 두고 폰이 읽기**: 거래처·금액이 서버에 남는다(ADR-006 원칙 위반).
