# ADR-047. PC가 꺼져 있을 때 폰이 모델을 직접 부르는 길: 게이트웨이 chat 범위, 폰 대화 툴셋, 컨텍스트 관리, 합치기

> 상태: 방향 채택(2026-11-16 yulmu: "PC가 꺼져 있을 때 폰이 AI를 직접 부르게 해. 컨텍스트 관리도 잘 하고", ADR-046 결정 7) · 결정 1~5 구현, 결정 6은 폰 쪽 기록·묶음·합치기 규칙까지 구현(`@sax/chat-core`) · 봉투(chat.sync·chat.context)와 PC 쪽 배선(결정 6 나머지·결정 7), 폰 앱 연결은 이어지는 PR
> 근거: [ADR-046](ADR-046-phone-issuance-approval-phase1.md) 결정 7, 폰 앱 기획 v2 §3.1·§3.2(Claude Docs "택스오프 폰 앱 기획 v2")
> 관련: [ADR-029](ADR-029-remote-recovery-data-minimization.md)(서버는 내용을 모른다), [ADR-040](ADR-040-engine-gateway-auth-scoped-device-token.md)(범위 축소 기기 토큰), [ADR-015](ADR-015-model-provider-neutral.md), D04 §4·§6·§7, D06 §4·§8, D08 §6·§7, D09 §2.1·§3, `poc/services/gateway/API.md`

## 맥락

- ADR-046 결정 7: 폰과 PC는 대화 하나를 같이 쓰고, PC가 꺼져 있으면 폰이 게이트웨이를 거쳐 PC 에이전트와 같은 모델을 부른다. 실행은 밀린 일로만 한다.
- 지금 게이트웨이는 데스크톱 기기 토큰(`gateway` 범위)만 받는다. 폰 토큰은 `relay·push`뿐이라 모델을 부를 길이 없다.
- 모델 공급사 키는 게이트웨이 서버에만 있다. 폰에 키를 넣는 안은 처음부터 없다(앱에서 꺼낼 수 있다).
- 하루 AI 사용 금액 한도가 작다: 체험 50원, 구독 300원(한국 시간 새벽 4시 초기화, 계정 단위). 한도 단가(`LIMIT_PRICES`, DeepSeek 공식 피크)로 입력 6,000토큰·출력 150토큰 한 번이 약 2.9원이고, 그중 5,000토큰이 캐시에 맞으면 약 0.7원이다. 컨텍스트를 어떻게 짜느냐가 하루에 할 수 있는 대화 횟수를 네 배쯤 바꾼다.
- PC 대화 에이전트는 값이 아니라 토큰·슬롯만 모델에 보낸다(D06, `chat_agent`). 폰도 같은 원칙이어야 하고, 같은 문장은 PC와 폰에서 같게 가려져야 한다.

## 결정

1. **폰 기기 토큰에 `chat` 범위를 준다(구현).** 계정 서비스는 폰에 `relay, push, chat`을 준다. `chat`은 `gateway`와 같은 유료 범위다: 체험 중이거나 구독 중일 때만 주고 등급(`tier`)을 싣는다. 폰은 `gateway` 범위를 받을 수 없다(역할 범위 밖).
2. **게이트웨이는 폰에 대화만 연다(구현).** 역할과 범위를 짝으로 본다(데스크톱+`gateway`, 폰+`chat`). 폰이 부를 수 있는 것은 셋뿐이고 나머지는 `403 account.scope_denied`다.
   - `POST /v1/run-tokens`: `{chatSessionId}`만. 실행 범위(`runId`) 토큰은 받지 못한다. 그래서 판정(`/v1/decide`)과 에이전트 예산도 열리지 않는다.
   - `POST /v1/respond`: 툴셋 `chat_phone`, `chat_digest`만.
   - `GET /v1/usage`.
   - 그대로인 것: DPoP(폰 서명 키 `Vm`), 기기 상태 조회(분실 폰을 정지하면 받아 둔 토큰이 살아 있어도 즉시 거부), 2차 트립와이어와 기기 자동 정지, 계정 단위 분당 한도, 무저장. 하루 한도는 계정으로 PC와 폰이 같이 센다.
   - 폰에 새로 저장하는 비밀은 없다. 이미 있는 기기 키로 15분짜리 토큰을 받아 요청마다 서명한다.
3. **폰 대화 툴셋 둘(구현, 정의는 `packages/model/src/chat-phone.ts`).** 머리말·도구·출력 스키마는 게이트웨이가 넣는다(폰은 역할을 바꿀 수 없다).
   - `chat_phone`: 도구 5개(`invoice_history`·`receivables`·`invoice_draft`·`draft_edit`·`draft_discard`), 4턴. `chat_agent` 표에서 장부 전체가 필요한 `sales_summary`만 뺀 것이라 이름·인자·슬롯 문법이 PC와 같다. 발급·전송·맡기기 도구는 없다. 답 종류에 `defer`(PC를 켜면 이어서 할 일)가 더 있다. 폰 전용이다.
   - `chat_digest`: 도구 없음, 1턴, 가린 대화를 900자 안으로 줄인다. 폰(폰 구간 접기)과 PC(폰에 넘길 긴 요약) 모두 부른다.
   - 둘 다 대화 범위 예산(`l2PerChat` 20)을 쓴다. 사용자 턴마다 새 L2, 도구 왕복은 replay다.
4. **폰 대화 코어는 tex에 두고 폰에는 고정 사본으로 넣는다(구현, `poc/packages/chat-core` = `@sax/chat-core`).** `@sax/remote`와 같은 방식이다. 순수 TypeScript이고 `tsconfig`의 `types: []`로 Node 전용 API를 컴파일에서 막는다. tex CI가 시험한다.
   - 가림은 `@sax/redaction`을 그대로 쓴다. 이 패키지도 순수 TS로 만들었다(발급 영수증 해시는 `@noble/hashes`, 바이트 수는 `utf8Length`).
   - PC 엔진의 대화 경로 규칙을 `@sax/chat-core`로 옮겼다: 추가 가림(단위 없는 금액, 이름 변형, 오타 별칭, 이메일 조각), 금액 읽기, 답 검사(세무 판단 말, 식별자·링크·비밀 유도 말, 슬롯·토큰 밖 숫자). 엔진은 같은 이름으로 다시 내보내고 장부만 레코드 목록으로 넘긴다. PC와 폰이 같은 함수를 쓴다.
   - 도구 표·슬롯 문법·답 종류도 `@sax/chat-core`(tables.ts)가 원본이고 `@sax/model`이 이것으로 툴셋 정의를 만든다.
   - 값 공간의 작은 함수(조사, 부가세 나누기, 품목 정리, 금액·날짜 표기)는 데스크톱 것을 옮겨 두고 시험(`chat-core-parity`)이 결과를 대조한다.
   - 폰은 게이트웨이 응답의 `toolsetDigest`를 고정하지 않는다. 폰 앱 배포는 서버보다 늦으므로 머리말을 고칠 때마다 옛 앱이 멈추면 안 된다. 대신 도구 이름·인자 모양과 답 모양을 표로 다시 검사한다.
5. **컨텍스트: 한 번 부를 때 넣는 것과 순서(구현, `PhoneChat`).** user 메시지 하나에 `[요약]` → `[앞 대화]` → `[사실]` → `[지금]` 순서로 넣는다. 덜 바뀌는 것이 앞이라 공급사 접두 캐시에 맞는다.
   - 기록의 모양: 메시지마다 화면 문장(가리지 않은 글)과 컨텍스트용 가린 글(`MaskedText` = 토큰이 든 문장 + 그 토큰의 종류·값·레코드)을 같이 둔다. 대화 세션이 바뀌면 값으로 새 세션의 토큰을 받아 다시 쓴다(`rebind`). 규칙으로 다시 가리지 않으므로 처음에 가려진 것은 나중에도 똑같이 가려지고, 토큰 번호는 세션을 넘어 남지 않는다. 요약도 같은 모양으로 둔다.
   - `[요약]`: PC가 넘긴 긴 요약 + 폰 구간 요약("(그 뒤 폰에서)").
   - `[앞 대화]`: 사용자 턴 20개까지(PC 쪽은 "(PC에서)" 표시). 넘으면 한 턴씩 밀지 않고 오래된 절반을 한꺼번에 `chat_digest`로 접는다(접두가 접을 때만 바뀐다). 요약 호출이 실패하거나 요약에 식별자가 섞이면 요약 없이 접기만 한다. 접기는 답을 돌려준 뒤에 돈다.
   - 앞 답에 채워 보였던 값은 모델에 다시 가지 않는다: 금액은 금액 토큰, 거래처는 이름 토큰, 날짜·건수·승인번호는 "(날짜)"·"(건수)"·"(승인번호)" 자리표시로 남긴다.
   - `[사실]`: "사본:" 줄(fresh·stale·none)과, 이번 말에 나온 거래처(없으면 직전 턴의 거래처, 5곳까지)의 최근 발급·받을 돈을 폰이 사본에서 미리 조회한 결과를 도구 결과와 같은 꼴(ref·status·fields·needs)로 넣는다. 같은 세션의 같은 조회는 같은 ref를 다시 쓴다. 모델이 도구를 다시 부르지 않아 왕복이 줄어든다.
   - 상한 8,000토큰(머리말·도구 정의 포함, 추정). 넘으면 사실 → 오래된 턴 순으로 줄이고 요약과 이번 문장은 줄이지 않는다. 거래처 목록·원장 전체는 보내지 않는다. 폰에는 토크나이저가 없어 넉넉한 추정식을 쓰고 시험이 BPE 토크나이저보다 작지 않은지 본다.
   - 대화 세션(실행 토큰·토큰 맵)은 15분 쉬거나 16턴을 쓰면 새로 연다(게이트웨이 대화 예산 20에 닿기 전). 기록은 값으로 들고 있어 이어진다.
   - 답 검사는 PC와 같은 코드다. 같은 턴에 같은 도구를 같은 인자로 다시 부르면 실행하지 않고 첫 결과로 답하고, 답 없이 턴 상한에 닿으면 이미 낸 표·카드를 고정 문장과 같이 보인다(PC 대화 품질 스레드의 안전망과 같다).
   - 나가는 글은 마스킹 계층이 만든 것만 보낸다(`wasMinted`, PC egress와 같은 규칙).
6. **폰 대화 기록과 PC로 되돌리기(기록·묶음·합치기 규칙 구현, 봉투와 PC 배선은 다음 PR).** 폰은 메시지마다 ULID와 쓴 시각을 붙여 포트(`store`)로 저장한다. 폰 앱이 기기 키로 봉인한다(백업 제외). PC가 켜지면 라이브 세션으로만 한 묶음 보낸다(`chat.sync`, remote-envelope v1.8, hello 기능 `chat.v1`). 우편함에는 대화 원문을 두지 않는다.
   - 폰은 PC의 `chat.sync.ack`를 받은 메시지만 "보냄"으로 표시한다(`acked`). 못 받으면 같은 묶음을 다시 보내고(`pendingSync`), PC는 메시지 id로 중복을 버린다(`mergeSegment`, 여러 번 받아도 결과가 같다).
   - 순서: 폰 구간 안에서는 폰이 쓴 순서 그대로. 구간의 자리는 폰이 그 메시지를 쓸 때 알고 있던 PC의 마지막 메시지(`base`) 바로 뒤이고, 그 뒤 PC에서 생긴 메시지와는 쓴 시각으로 맞춘다(두 줄을 순서를 지키며 섞는다). 폰 시계가 틀려도 구간 안 순서와 "이미 본 PC 메시지 뒤"는 지켜진다.
   - 상태는 PC가 이긴다. 지난 답은 고치지 않는다. `defer`로 미룬 요청과 사장님이 카드에서 맡긴 일(대화 기록에 한 줄 남는다)은 PC 에이전트의 다음 턴 컨텍스트에 들어간다.
   - 카드는 모델 출력으로 맡길 수 없다. 폰 대화가 하는 일은 만들기·고치기·취소까지이고, 맡기기는 화면의 버튼(`entrust`)뿐이다.
7. **(다음 PR) PC → 폰 `chat.context`.** 라이브 세션이 열릴 때와 합친 뒤에 PC가 긴 요약과 최근 20턴(메시지 모양은 결정 5와 같다, 종단간 암호화)을 보낸다. 폰은 PC 쪽 최근 턴을 이것으로 바꾸고(`applyContext`, 구현) 받았다는 답이 온 폰 메시지를 지운다. 긴 요약은 PC가 `chat_digest`로 만든다.

## 결과

- 침해 범위(D09 §1): 게이트웨이가 보는 것은 지금과 같다(가린 프롬프트는 메모리에서만, 계정·기기·툴셋·토큰 수 기록). 호출 기록의 기기가 폰일 수 있고 표면에 `chat_phone`·`chat_digest`가 더해진다. 대화 원문은 서버에 오지 않는다.
- 폰을 잃으면: 기기 정지 한 번으로 릴레이·푸시·대화가 같이 막힌다. 그 전까지 쓸 수 있는 것은 하루 한도 안의 대화뿐이고, 폰 토큰으로는 실행·판정·계좌 토큰을 열 수 없다.
- 요청 스키마 `gateway-request.schema.json` v1.4: toolset 열거에 `chat_phone`, `chat_digest`.
- 분당 한도(계정 단위 L2 10회)도 PC와 폰이 같이 센다. 닿으면 폰은 `chat.rate_limited`로 알리고 그 턴은 기록하지 않는다.
- 실제 모델(DeepSeek V4.1 Flash 1017) 확인은 chat-eval 방식으로 한두 건씩 돌려서 한다. 지금까지의 시험은 모의 공급사 기준이다.

## 기각

- **폰에 공급사 키를 넣거나 폰이 공급사를 직접 부르기**: 키가 앱에서 새고, 한도·가림 2차 검사·계량이 다 빠진다.
- **폰 토큰에 `gateway` 범위를 그대로 주기**: 판정·진위확인·CODEF 토큰·실행 범위까지 폰에 열린다. 폰은 PC보다 잃기 쉽다.
- **폰이 역할(머리말)과 도구 정의를 보내기**: 폰 앱을 고치면 모델에 무엇이든 시킬 수 있다. 지금처럼 게이트웨이가 넣는다.
- **대화 원문이나 요약을 서버(우편함 포함)에 두고 PC가 읽기**: 거래처·금액이 서버에 남는다(ADR-029).
- **최근 턴을 한 턴씩 밀기**: 매 턴 접두가 바뀌어 캐시를 못 쓴다. 한도 안에서 할 수 있는 대화가 줄어든다.
