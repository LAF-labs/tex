# ADR-007 Noise 페어링 + 내용을 볼 수 없는 릴레이

상태: 채택 · 2026-10-28 · 개정 메모 v1.3(아래)

> 파일 이름의 "zero-knowledge"는 이전 판의 표현이며 링크 유지를 위해 남겨 둔다. 이 ADR은 릴레이를 '영지식'이라고 부르지 않는다(개정 메모).

## 맥락
폰과 PC가 인터넷 너머로 통신하되 릴레이(우리 서버)가 내용을 볼 수 없어야 하고, 사용자가 암호학을 몰라도 가짜 기기를 걸러낼 수 있어야 한다.

## 결정
- 페어링은 데스크톱이 만든 바이너리 QR(정적 공개키 + 1회용 PSK + 임시 룸 + 만료)로 시작하고 `Noise_XXpsk0`로 상호 인증한다. 폰은 QR의 키와 **AIK 서명 계정 기기 목록**으로 PC를 검증하고, 사용자는 폰의 **6자리 코드를 PC에 입력**해야 완료된다. 상시 세션은 `Noise_IK`.
- 전송은 Noise 세션 키, 파일은 블롭 경유, 비밀은 금고 전용 키 `Kv`로 **인증 봉인**(챌린지·origin·종류 결속) + 라이브 세션 전용.
- 릴레이는 내용과 키를 볼 수 없다. 오프라인 큐는 의도 봉투만 72시간이며, 큐의 명령은 실행이 아니라 시작 게이트 → 커밋 게이트의 새 승인 요청이 된다.

## 대안
- 우리 서버가 TLS 종단에서 평문 중계: 구현이 쉽지만 "우리 서버도 못 본다"는 약속이 깨진다.
- WebRTC P2P: NAT 환경에서 불안정, 릴레이가 결국 필요.

## 결과
- 모바일에 libsodium 바인딩이 필요하다(Expo 커스텀 네이티브 모듈).
- 기기 해제·키 폐기 UX가 필수다.

## 개정 메모 (v1.3, 공격표면 감사 반영)

- **신뢰 앵커** (감사 C C-01, ADR-016): v1.2의 "계정 기기 목록 대조"는 서버가 정직하고 계정이 안전하다는 전제에 섰다. 계정 탈취자나 내부자가 자기 PC를 목록에 넣으면 원격 페어링 피싱이 성립했다. v1.3은 기기 목록의 모든 항목을 AIK 서명 `DeviceListEntry`로 바꾸고, 계정 `AIK_pub`를 1회 고정(교체는 옛 AIK 서명 + 7일 지연 + 전 기기 알림)하며, ~~폰은 서버가 준 `AIK_pub`와 `PAIR_OK`의 값이 같을 때만 진행한다.~~ 24시간 이내 등록 데스크톱은 전면 경고, `KEK_N` 전달은 Hello 확인이 있는 별도 단계다. 새 폰의 첫 페어링마다 내부자(서버)와 공격자 PC가 공모해 `AIK_pub`까지 속이는 경우(TOFU)는 잔여 위험으로 남긴다(D08 §1·§4, E-12).
  - 2026-11-06 개정(팀장 결정, PR #102·#118): Phase 1 폰은 서버 기기 목록을 받지 않는다. `AIK_pub`는 `PAIR_OK`로 처음 받아 고정하고, 다시 연결할 때 그 값과 대조한다(D08 §4.2 7단계). 서버 대조가 없으므로 첫 페어링 TOFU는 공모 없이도 피싱 QR·6자리로 성립한다(D08 §1).
- **우편함 토큰 난수화** (C-16): `mbx_id`·`tok_read`·`tok_write`를 핸드셰이크 해시 `h`에서 파생하지 않는다. PC가 CSPRNG로 만든 32B 난수를 `PAIR_OK` 안으로 보내고, 재발급도 라이브 세션 안에서 같은 방식으로 한다. `h`는 SAS와 채널 바인딩에만 쓴다.
- **정직한 릴레이 서술** (C-14): "릴레이는 내용과 키를 볼 수 없다. 계정과 우편함의 연결은 분리 저장·접근 통제·짧은 보존으로 줄이지만, 운영자는 연결 시점·IP 상관으로 언제든 연결할 수 있다." '무지식'·'영지식' 표현은 쓰지 않는다. 접속 IP는 일 회전 솔트 HMAC으로만 레이트리밋에 쓴다. 비연결 토큰(Privacy Pass 계열)은 Phase 3 후보(SP-10).
- **푸시 경로** (C-15): 깨우기는 릴레이가 아니라 PC가 기기 범위 토큰으로 호출하는 `POST /v1/wake{device_id}`다. 서버는 `device_id → 암호화된 푸시 토큰`만 갖고 우편함 ID는 이 경로에 없지만, 운영자는 깨우기 시각과 우편함 접속을 상관시킬 수 있다. APNs(Apple Inc., 미국)·FCM(Google LLC, 미국)을 수탁·국외이전으로 고지하고, 기기 폐기 시 푸시 토큰을 즉시 지운다.
- **의도 봉투** (C-17): 와이어 형식을 `schemas/intent-envelope.schema.json`으로 고정했다. 바깥은 `{v, kind, enc, ct}`만 평문이고 `pair_id`·`seq`·`exp`는 HPKE 안에 있다. 큐 상한은 pair당 5건이다.
