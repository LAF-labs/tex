# ADR-009 게이트웨이 무저장 계량 + BYOK

상태: 채택 · 2026-10-28 · 개정 메모 v1.3(아래)

## 맥락
구독에 모델 사용량을 포함하려면 계량이 필요하다. 동시에 프롬프트 본문을 우리 서버가 저장·열람하지 않아야 한다. 일부 사용자는 우리 서버조차 거치길 원하지 않는다.

## 결정
- 게이트웨이는 본문을 저장하지 않고 `usage`만 계량한다. 번들·툴셋 정의는 서버가 주입하고 클라이언트 파라미터는 화이트리스트로 제한한다.
- BYOK 모드: 사용자가 자기 OpenAI 키를 금고에 넣으면 공급사 직결. 계량은 로컬만.
- 공급사 계정은 `store:false`, 계정 ID HMAC을 `safety_identifier`로, 캐시 키는 **계정별 격리**(`acct:<HMAC>:…`). ~~D04·D09와 일치~~ → **[정정 v1.3]** 정본은 D04 §2.1의 `acct:<HMAC(server_secret, accountId)>:b:<bundleId>`(Terra는 `:t:<toolsetId>`)이고, 이전 판의 "D04·D09와 일치"는 D09가 계정 접두 없는 키를 적고 있었으므로 사실이 아니었다(B-20, 감사 C C-11). 게이트웨이가 명시 캐시 모드와 브레이크포인트 위치를 강제하고 클라이언트는 캐시 필드를 보낼 수 없다.
- 계량은 결제 레코드(월 단위)·호출 단위 계정 연결 레코드(35일)·운영 통계(계정 비연결, 13개월)로 나눈다(D09 §3, C-23). '토큰 수만'이라고 말하지 않고 항목·보존을 처리방침에 적는다.

## 대안
- 클라이언트에 공급사 키 내장: 유출·남용 위험, 계량 불가. 기각.
- 게이트웨이가 프롬프트 로깅: 디버깅은 쉽지만 약속 위반. 기각(디버깅은 사용자 옵트인 진단 내보내기로).

## 결과
- 게이트웨이 장애 시 L1/L2 불가 → 플레이북은 L0 범위에서 진행하거나 핸드오프.
- 문제 재현이 어려울 수 있어 리플레이 하네스와 마스킹 미리보기에 투자한다.

## 개정 메모 (v1.3, 공격표면 감사 반영)
- **캐시 키 정정** (B-20, 감사 C C-11): 위 결정 셋째 항목의 정정 표시 참조. 게이트웨이는 응답의 `cached_tokens`를 클라이언트에 넘기지 않고 계량에만 쓴다. 클라이언트 요청 본문의 규범 원천은 `schemas/gateway-request.schema.json` 하나이며 D04 §7·D09 §3은 인용만 한다.
- **안전 식별자 월 회전** (감사 C C-23): `safety_identifier = hex(HMAC-SHA256(K_sid, accountId ‖ yyyymm))[:32]`, `K_sid`는 KMS에 두고 게이트웨이만 접근한다. 공급사가 한 사용자의 모든 마스킹 프롬프트를 무기한 묶는 것을 월 단위로 끊는다. 대가로 공급사의 남용 추적도 월 단위로 끊긴다.
- **게이트웨이는 모델 출력 무결성의 신뢰 지점** (감사 C C-24): 엔진은 응답을 비신뢰 입력으로 다루고 결과 매핑·임계값을 로컬 번들 정의로 계산한다. `bundleDigest` 409는 배포 불일치 감지용이다(D04 §5·§7).
- **BYOK 로컬 검사** (B-21): BYOK 모드는 게이트웨이 백스톱을 잃으므로 어댑터가 (1) 앱 내장 번들 다이제스트 허용 목록, (2) 게이트웨이 요청 스키마 검증, (3) 실행당 예산 로컬 카운터, (4) 2차 PII 트립와이어를 로컬에서 수행하고, 하나라도 실패하면 호출하지 않는다(D04 §8). BYOK 키를 금고가 보관하고 호출 단위 서명 요청을 만드는 방식은 Phase 2에 검토한다.
- **공급사 보존** (감사 C C-29): ZDR 승인 전에는 Responses·Decisions 모두 공급사 남용 모니터링 보존(최대 30일)과 법적 보존 예외가 적용되며, 처리 국가는 미국·EU·UAE다(D04 §7). "게이트웨이 무저장"은 우리 쪽 보존만 센 것임을 처리방침에 함께 적는다.
