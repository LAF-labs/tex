# ADR-005 비밀 타이피스트: 금고가 Chrome을 소유하고, 엔진에는 기본 거부 중계만 준다

상태: 채택 v3(스파이크 S1b·S6·S6b·S6c·S6d·S6e·S6f 결과에 조건부) · 2026-10-28
개정: v3 — 공격표면 감사(research/AUDIT-A·B·C, design/19-attack-surface.md) 반영(A-01, A-02, A-03, A-04, A-06, A-07, A-12, A-13, A/C-05), 재감사 E-01·E-02·E-18 반영(비밀 창 2상태, R-C1 금고 대조, 오염 범위 확대). v2 — Review B A-1(금고 파이프 단독 소유).

## 맥락
인증서 비밀번호·보안카드 값은 결국 브라우저 입력란에 타이핑되어야 한다. 엔진이 평문을 받아 Playwright로 입력하면, 엔진(업무 데이터·네트워크 송신 모듈을 가진 프로세스)이 비밀을 보게 된다. v2는 금고가 Chrome 파이프를 소유하고 타이핑 구간에만 엔진 명령을 보류했다. 감사 A는 이것이 (1) 타이핑 구간 밖에서는 엔진에 모든 CDP(브라우저 타깃·쿠키·다운로드 경로 포함)를 열어 두고, (2) 정상 경로에서도 요청 바디·접근성 트리 값으로 평문이 엔진 힙에 들어오며, (3) 사용자가 직접 입력하는 `human:secret` 구간은 보호하지 않는다는 점을 지적했다.

## 결정
1. **금고 소유 파이프**: 금고 프로세스가 Chrome을 `--remote-debugging-pipe`로 띄우는 단독 소유자다. `--remote-debugging-port`는 금지한다(포트는 OS 사용자 인증이 없어 같은 PC의 다른 계정·인포스틸러가 로그인된 포털 세션을 조종할 수 있고, `--remote-allow-origins`는 네이티브 클라이언트를 막지 못한다). `browser.launch()`는 인자가 없고 프로필 경로·기동 플래그는 금고 상수다(D05 §3.1).
2. **기본 거부 허용 목록 중계(Phase 1)**: 엔진은 금고가 이번 실행을 위해 만든 page 타깃과 그 허용 origin 팝업의 세션에만 붙는다. 브라우저 타깃·사용자 탭은 노출하지 않는다. `relay.allowedDomains`·`relay.deniedMethods`는 금고 바이너리 상수이며 플레이북·정책으로 바꿀 수 없다. `Target.setAutoAttach`는 금고만 호출한다. origin은 매 문서 커밋마다 금고가 재집행하고, 다운로드·인쇄 경로는 금고 상수다(D05 §3.3).
3. **응답 정리(Phase 1)**: 비밀 오염 범위(창이 열린 프레임·하위 프레임·부모 프레임·같은 탭 워커)의 요청 바디(`postData` 등)를 지우고 바디 조회를 거부한다. 금고가 입력한 노드, `human:secret`·`fillFromRemote` 대상 노드, `type=password` 노드의 접근성·DOMSnapshot·`DOM.describeNode` 값 필드를 지운 뒤 전달하고, 값이 있는 동안 스크린샷을 거부한다(D05 §3.4). 정상 경로에서 평문이 엔진 힙에 들어오지 않는다는 약속은 이 정리로만 지켜진다.
4. **비밀 창(Phase 1)**: 타이피스트 입력, `human(kind=secret)`, `fillFromRemote` 세 경우 모두 금고가 비밀 창을 연다. **활성 창**(타이핑·직접 입력 중) 동안 대상 타깃의 입력·포커스·캡처·접근성·DOMSnapshot·**대상 프레임 `Runtime`** 명령을 거부하고 바인딩·콘솔 이벤트를 전달하지 않는다. 활성 창은 타이핑 완료, 사용자 "입력 완료"(또는 blur + 값 확인), 문서 커밋·노드 분리, 엔진의 종료 요청을 금고가 포커스 해제 확인 후 승인할 때 끝나고, 그 뒤 다음 문서 커밋까지는 **오염 상태**로 엔진 입력은 허용(로그인 버튼 클릭)하되 응답 정리를 유지한다(E-01). 개시 조건에 전용 프로필 `Preferences` 확인, 확장 허용 목록, Google 로그인 없음, 데몬 실행 아님(타이피스트)을 둔다(D05 §3.5·§3.6).
5. **원자적 타이핑(Phase 2, 채택)**: `secret_fill.submitWith`(`secretSubmit:true` 항목)로 입력 → 제출 → 노드 분리·문서 커밋까지 보류하고, 비밀 origin에 엔진이 등록한 문서 스크립트·바인딩이 있으면 개시를 거부한다(`relay.denyOnSecretOrigins`). Playwright 호환성은 S6b(D05 §4.1).
6. 타이피스트는 `type=password` 또는 셀렉터 사전에 `secretSlot: true`로 표시된 요소에만 입력한다. 엔진은 Actuator에서 비밀 창 개시 허가 1회만 받고, 글자 간격은 금고가 집행한다(길이 비노출).
7. 폰에서 온 비밀은 금고 공개키로 인증 봉인되어 엔진이 복호화할 수 없다.
8. **허용 목록 없이 엔진 샌드박스는 의미 없다**: 엔진을 AppContainer·Low IL 등으로 격리해도 중계가 브라우저 수준 프로토콜을 열어 두면 엔진은 사용자 권한 Chrome(쿠키 읽기, 다운로드 경로 변경, 새 브라우저 컨텍스트)을 통해 밖으로 나간다. 따라서 결정 2가 이후 모든 엔진 격리의 전제다.
9. **이 장치의 범위**: 평문이 엔진의 힙·로그·덤프·모델 페이로드에 남지 않게 하는 위생 장치다. 같은 OS 사용자 악성코드·엔진 RCE에 대한 경계가 아니다. Phase 1에서 침해된 엔진은 오염 상태에서 `Runtime.evaluate`로 비밀 칸 값을 읽을 수 있고(거부 목록 패턴 차단은 시도일 뿐), 사전 심은 페이지 스크립트도 막지 못한다. Phase 2 원자적 타이핑(입력 → 제출 → 분리까지 활성 창 유지)이 이 창을 닫는다. 사용자 고지 문구는 결정 5 채택 후에도 바꾸지 않는다.
10. **커밋 가드와 금고**(A-03, E-02): 커밋 요청 **본문 대조(R-C1)는 Phase 1부터 금고 중계가 수행**한다. 엔진은 `commit.arm{bodyFieldMap, expectedHash}`만 넘기고 금고가 본문을 비교해 `{match: true|false|opaque}`만 돌려주므로 엔진은 바디를 보지 않고, 결정 3의 바디 제거와 충돌하지 않는다. 커밋 엔드포인트 인터셉트와 **무장 근거 검증**(금고가 폰 `Sign_Vm` 또는 main 승인 창(2026-10-31부터 main 승인 바, ADR-021)의 `LocalApproval`을 직접 검증해 근거 하나당 요청 1회 집행)은 **Phase 2**다. 본문이 암호화(`opaque`)되면 대조할 수 없으므로 그 경우 이 장치는 승인 없는 발급의 횟수만 제한한다(D03 §5.4, D05 §3.3).

## 조건(스파이크)
- S1b: 홈택스 브라우저 인증서 가져오기, 키보드 보안 모듈 칸에 합성 입력이 닿는지.
- S6: 다른 OS 사용자 CDP 접속 불가, 엔진 지정 엔드포인트 접속 없음, 브라우저 타깃·`Storage` 호출 거부와 `vault.cdp_denied`.
- S6b: Playwright가 금고 중계(MessagePort 또는 토큰 WS) 위에서 동작하는가, 브라우저 타깃 없이 쓸 수 있는 최소 메서드 집합, 비밀 origin에서 `addScriptToEvaluateOnNewDocument`·`addBinding`을 막아도 동작하는가. 불가하면 WS 폴백 규칙(D05 §3.2)을 쓰고, 그래도 불가하면 이 ADR을 재검토한다.
- S6c: 홈택스 로그인·보안카드·포털 비밀번호 제출 시 엔진이 받는 Network·Fetch 이벤트의 평문, 중계 제거 후 0건(정부24 제외, 보안 모듈 동작 분석 없음).
- S6d: Chrome 156에서 비밀 칸 값이 실리는 접근성·DOMSnapshot·`describeNode` 응답 필드.
- S6e: 프로필 `Preferences` 기록만으로 비밀번호 저장 제안·자동완성·동기화가 꺼지는가, `Local State` 보고 설정 기본값.
- S6f: 비밀 창 활성 상태의 엔진 수신 CDP 메시지(`Runtime` 응답 포함) = 허용 목록, SPA 로그인에서 활성 창 종료 후 엔진 클릭 가능(가상키패드·보안 모듈은 관찰·조작하지 않음).

## 대안
- (기각) 엔진에 짧게 평문 전달 후 즉시 폐기: 구현이 단순하지만 TB-1→TB-2 평문 금지 원칙(D01 §3, D05 §1)을 깬다. v2까지 "포털 모듈이 CDP 입력을 거부하는 경우의 폴백"으로 남아 있었으나 **폴백으로도 쓰지 않는다**. 모듈이 합성 입력을 거부하는 칸은 `human:secret`(사용자 직접 입력, 비밀 창 적용)으로 처리한다. (A/C-05)
- (기각) 엔진 중계(엔진이 파이프를 소유하고 금고가 엔진을 통해 입력): 평문이 엔진 파이프를 지난다.
- (기각) 거부 목록 방식 유지(v2): 타이핑 구간 밖 전 도메인 개방, `human:secret` 무보호, 정상 경로 누출(A-01, A-02, A-06).
- 사용자가 항상 직접 입력: 가장 안전하지만 리모트·데몬 가치가 크게 줄어든다. 기본값(미저장)으로는 유지.
- **고수준 동작 브로커(Phase 3 재검토 예약)**: 엔진은 원시 CDP를 받지 않고 `click(stableId)`·`fill(stableId, value)`·`readback(fieldKey)`·`snapshot(scopeId)`만 요청하며, Playwright는 무권한 드라이버 프로세스로 옮긴다. 엔진이 비밀 칸을 읽을 수단이 없는 유일한 완전 경계다. ADR-001 재검토와 엔진 AppContainer 분리를 함께 다루는 별도 ADR로 Phase 3에 결정한다.

## 결과
- 다중 CDP 클라이언트·포커스 경쟁 처리가 필요하다(엔진은 비밀 창 동안 해당 타깃 명령이 거부된다).
- 중계가 프로토콜을 이해해야 하므로 금고 코드가 커진다. 금고 공격면을 줄이기 위해 Phase 2에 금고를 Rust 별도 실행 파일로 분리하는 것을 검토한다(D05 §8).
- Chrome 업데이트로 CDP 응답 필드가 바뀌면 응답 정리 규칙이 깨질 수 있다. S6d 측정을 회귀 테스트로 고정한다.
- 커널 드라이버 기반 키보드 보안(nxKey 계열)은 합성 키 입력이 닿지 않을 가능성이 높다(R3). S1b에서 확인되면 공동인증서 비밀번호 칸은 사용자 직접 입력(비밀 창 (b))으로 고정하고, 홈택스 브라우저 인증서 모드 또는 간편인증을 기본 권장한다. 타이피스트는 그 외 칸(포털 비밀번호·보안카드 등 모듈이 없는 칸)에서 가치를 가진다.
