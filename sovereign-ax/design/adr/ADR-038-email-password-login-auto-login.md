# ADR-038. 이메일·비밀번호 로그인과 자동 로그인

> 상태: 채택(사용자 결정 2026-11-06, 팀장 지시로 문서화). 결정 (a)~(g)가 채택이다. 같은 날 개정: 각 결정의 "세부"도 채택(팀장 결정 2026-11-06)이고, (d)에 잠금 알림 메일 1회와 화면 안내를 더했다. 클라우드·데스크톱 세션은 이 ADR을 기준으로 구현한다.
> 관련: D09 §1.1·§2.1·§10, [ADR-016](ADR-016-account-trust-anchor-hardware-approval.md), D05(금고), D08 §1(폰은 Phase 1에 계정 없음), `poc/services/shared/CONTRACT.md` §4(계정 세션 `sxs1`)

## 맥락

- 지금 로그인 수단은 이메일 6자리 일회용 코드(수명 10분, 5회 실패 잠금)와 패스키다(D09 §2.1). 비밀번호가 없다.
- 로그인하면 계정 세션(`sxs1`, 30일, 서버는 sha256 해시만 저장)을 받는다. 계정 세션은 구독·결제, 기기 관리(목록 열람·긴급 정지·해제 요청), 동의 관리, 데스크톱 첫 로그인에만 쓴다(CONTRACT.md §4, D09 §2.1).
- 갱신 토큰이 없다. 그래서 세션이 끝나면 매번 메일 코드를 다시 받아야 한다.
- 금고 비밀·기기 키(AIK·`Vx`)·RK는 계정 로그인과 무관하다. PC 금고는 Windows Hello·TPM으로 열린다(D05). 블롭·메타데이터·게이트웨이는 기기 범위 토큰(AIK 인증서 + DPoP)만 받는다(D09 §2.1).
- 사용자는 메일을 열지 않고 로그인하는 길과, 앱을 켜면 로그인된 상태를 원한다(사용자 결정 2026-11-06).

## 결정

### (a) 로그인 수단

- 수단은 셋이다: **비밀번호**, **이메일 6자리 코드**, **패스키**.
- 셋 다 같은 계정 세션을 준다. 비밀번호로 로그인해도 권한은 계정 세션 범위 그대로다(D09 §2.1). 기기 범위 토큰은 지금처럼 AIK 인증서가 있는 기기에만 준다.
- 가입은 이메일 코드로 주소를 확인한 뒤에 끝난다. 비밀번호는 그다음에 **선택으로** 설정한다. 비밀번호 없이 코드·패스키만 쓰는 계정도 그대로 된다.
- Phase 1 폰에는 계정 로그인이 없다(D08 §1). 비밀번호 로그인은 데스크톱 로그인 화면과 계정 웹에만 있다.

### (b) 저장

- `argon2id`(m = 64 MiB, t = 3, p = 1, 솔트 16바이트, 계정마다 무작위)로 해시한다.
- 서버 페퍼를 더한다. 페퍼는 HMAC 키이고 환경 변수에 둔다. DB에는 없다. 그래서 DB만 빠져나가면 오프라인 대입을 시작할 수 없다.
- 해시 레코드에는 **매개변수 버전 필드**가 있다. 로그인에 성공했는데 버전이 현재보다 낮으면, 그 자리에서 새 매개변수로 다시 해시한다.
- 서버는 비밀번호 평문을 저장하지 않는다. 데스크톱도 비밀번호를 저장하지 않는다(금고에도 두지 않는다). 금고에는 갱신 토큰만 둔다(결정 (f)).
- 세부(결정, 팀장 2026-11-06):
  - 해시 입력은 `argon2id(HMAC-SHA256(pepper, utf8(NFKC(password))), salt)`.
  - 버전 필드에 페퍼 키 ID를 함께 넣는다. 그러면 페퍼를 회전한 뒤에도 로그인 때 재해시로 옮길 수 있다.

### (c) 비밀번호 정책

- 길이는 10자 이상 128자 이하다.
- 구성 규칙(대문자·숫자·특수문자 강제)은 두지 않는다(NIST SP 800-63B).
- 다음은 거부한다:
  - 유출·흔한 비밀번호 목록에 있는 것. 목록은 상위 N개만 로컬에 번들한다. 외부 호출(유출 조회 API 등)은 하지 않는다.
  - 이메일(전체 또는 로컬 부분)이나 서비스명을 포함한 것.
- 거부 판정은 서버가 한다. 앱은 같은 목록으로 미리 안내만 할 수 있다.
- 세부(결정, 팀장 2026-11-06):
  - 길이는 NFKC 정규화 뒤 코드 포인트 수로 센다.
  - N은 10만으로 둔다.
  - 서비스명 비교는 대소문자를 무시하고, 대상은 `SovereignAX`·`sovereign`·`소버린`이다.

### (d) 무차별 대입·계정 열거 방지

- **계정 잠금**: 계정당 비밀번호 연속 실패 5회면 15분 잠근다. 잠금이 반복되면 시간을 늘린다(점증). 성공하면 횟수를 0으로 되돌린다.
- **IP 한도**: 기존 limits(일 회전 솔트 HMAC 카운터, D09 §4)를 쓴다. 새 카운터 방식을 만들지 않는다.
- **열거 방지**: 이메일이 없을 때와 비밀번호가 틀릴 때 **같은 응답을 같은 시간에** 낸다. 이메일이 없으면 더미 해시로 `argon2id`를 똑같이 돌린다.
- 세부(결정, 팀장 2026-11-06):
  - 점증: 잠금마다 두 배, 상한 24시간.
  - 잠금 중의 응답도 틀린 비밀번호와 같게 한다. 응답 차이가 계정이 있다는 사실을 드러내기 때문이다.
  - **잠금 알림**: 잠금이 처음 걸릴 때 계정 이메일로 알림을 보낸다. 내용은 "비밀번호가 여러 번 틀려 잠시 잠겼어요. 이메일 코드로 로그인할 수 있어요."다. 알림은 잠금 주기마다 1회로 제한한다. 그래서 본인은 잠긴 것을 알고, 알림이 남의 열거나 메일 폭탄에 쓰이지 않는다.
  - **화면 안내**: API 응답이 같으므로 로그인 화면은 잠금 여부를 알 수 없다. 그래서 따로 잠금 화면을 두지 않는다. 비밀번호가 맞지 않았다는 안내에 이메일 코드 로그인으로 넘어가는 길을 함께 둔다(08 A-01).
  - 비밀번호 잠금은 비밀번호 수단만 막는다. 이메일 코드·패스키 로그인은 막지 않는다. 남이 일부러 실패를 쌓아 사용자를 잠그는 것(가용성 공격)을 피하기 위해서다.

### (e) 비밀번호 찾기

- 이메일 6자리 코드로 재설정한다. 코드의 수명·실패 잠금은 로그인 코드와 같다(10분, 5회).
- 재설정 코드 메일은 응답 경로에서 기다리지 않는다(팀장 결정 2026-11-07). 응답은 계정 유무와 상관없이 같은 본문·같은 시각 하한이다. 코드 평문은 DB 큐에 두지 않으므로 메모리에서만 따로 보내고, 서버가 멈춰 유실되면 사용자가 다시 요청한다. 계정 없는 주소로 같은 호출을 하는 방식은 기각했다(서버가 임의 주소로 메일을 보내는 수단이 된다). 하한을 공급사 p99보다 크게 두는 방식도 기각했다(공급사 지연에 묶여 깨지기 쉽다).
- 재설정하면 그 계정의 **다른 세션과 갱신 토큰을 모두 폐기**한다. 그리고 알림 메일을 보낸다.
- 재설정은 금고·기기 키·기기 목록을 건드리지 않는다. 기기 범위 토큰도 그대로다. 기기를 끊으려면 긴급 정지(D09 §2.2)를 쓴다.

### (f) 자동 로그인

- 기본은 **켬**이다.
- 데스크톱은 계정 **갱신 토큰**을 금고에 두고, 앱을 켤 때 이것으로 계정 세션을 새로 받는다.
- 갱신 토큰은 쓸 때마다 **회전**한다. 새 토큰을 주고 이전 토큰은 무효가 된다. 서버는 해시만 저장한다.
- 이미 회전된 이전 토큰이 다시 오면(**재사용 감지**) 그 계정의 **전체 세션과 갱신 토큰을 폐기**한다. 토큰이 복제됐다는 신호이기 때문이다.
- 설정에 두 가지를 둔다:
  - **[로그인 상태 유지 끄기]**: 갱신 토큰을 금고에서 지우고, 서버에서도 폐기한다. 다음 실행부터는 다시 로그인한다.
  - **[모든 기기에서 로그아웃]**: 그 계정의 모든 계정 세션과 갱신 토큰을 폐기한다. 기기 범위 토큰과 기기 등록은 그대로다(결정 (e)와 같다).
- 세부(결정, 팀장 2026-11-06):
  - 계정 세션(`sxs1`) 수명을 30일에서 1시간으로 줄인다.
  - 갱신 토큰은 30일 동안 쓰지 않으면 만료한다.

### (g) 금고·기기 키와 무관

- 비밀번호(또는 코드·패스키)로 얻는 것은 계정 세션뿐이다.
- 비밀번호를 알아도 PC 금고를 열 수 없고 Windows Hello를 넘지 못한다. 금고 비밀·RK·AIK·`Vx`는 계정 로그인과 결속되어 있지 않다(D05, ADR-016).
- 이 사실을 D09 §1.1 투명성표에 적는다.

## 대안과 기각 이유

- **이메일 코드만 유지**: 메일을 열 때마다 마찰이 생긴다. 메일함이 침해되면 어차피 코드로 들어온다. 비밀번호를 선택으로 더해도 기본 권한은 늘지 않는다.
- **패스키만 추가 권장**: 이미 권한다. 패스키를 등록하지 않은 사용자에게 메일 없이 들어오는 길이 없다.
- **비밀번호를 금고에 저장해 자동 입력**: 평문 비밀번호가 PC에 남는다. 갱신 토큰은 회전·폐기할 수 있지만 비밀번호는 다른 서비스에서도 재사용될 수 있다.
- **외부 유출 조회 API(k-익명성 범위 조회)**: 외부 호출이 생긴다(egress 허용 목록 밖). 로컬 상위 목록으로 대신한다.

## 영향과 잔여 위험

- 새 공격 표면이 생긴다. 다른 서비스에서 재사용한 비밀번호, 피싱, 대입이다. 피해는 계정 세션 권한 안에 머문다: 결제, 기기 목록 열람, 긴급 정지(정지만 가능하고 해제는 AIK 서명이 필요, CONTRACT.md §5), 동의. 금고·서류·기기 키는 노출되지 않는다.
- 서버는 로그인을 처리하는 동안 메모리에서 평문 비밀번호를 거친다. 운영자나 침해자가 처리 코드를 바꾸면 평문을 모을 수 있다. 다른 서비스에 같은 비밀번호를 쓰는 사용자에게 위험이다. D09 §1.1 "능동 공격" 열에 적는다.
- 재설정 코드를 받는 메일함이 침해되면 비밀번호를 바꿀 수 있다. 이는 지금 로그인 코드와 같은 위험이다.
- D09 §1.1 투명성표, §2.1 인증, §10 보존표를 이 ADR에 맞춘다(같은 PR).
- 클라우드: 해시 레코드, 잠금 상태, 갱신 토큰 회전 계보, 재설정 코드를 구현한다.
- 데스크톱: 로그인 화면의 비밀번호 칸, 금고의 갱신 토큰 보관, 설정 두 항목을 구현한다.
- D19 위협 행 추가는 후속이다.
