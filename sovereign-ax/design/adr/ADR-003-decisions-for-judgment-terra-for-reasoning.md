# ADR-003 판단은 Decisions API, 추론은 GPT-6.1 Terra

상태: 채택 · 2026-10-28 · 개정 v1.3 2026-10-28(공격표면 감사 반영, 아래 개정 메모)

## 맥락
모델이 필요한 지점은 두 종류다. (a) "이 화면이 무엇인가, 성공했는가, 어느 작업인가"처럼 선택지가 정해진 판단, (b) 셀렉터 복구·자연어 인자 채우기처럼 열린 문제. (a)에 생성형 호출을 쓰면 출력이 통제되지 않고 느리며 비싸다.

## 결정
- (a)는 OpenAI Decisions API(`gpt-6-luna`, `POST /v1/decisions`). 정식 출시, 입력 $0.10/1M, 출력 무료, 요청당 질문 ≤ 400. 질문·임계값은 **앱 바이너리에 포함된** 번들 카탈로그로 고정하고 플레이북은 참조만(개정 메모 BV-06).
- (b)는 GPT-6.1 Terra(Responses API), 엄격 스키마 도구 3종 이하, 비가역 도구 없음, 출력은 구조화 JSON. effort low/medium(툴셋 정의가 고정, 클라이언트가 고를 수 없음).
- 공급사 간 다단 캐스케이드는 만들지 않는다. 어댑터 한 곳에 공급사 종속을 가둔다.

## 대안
- 단일 LLM(Terra)으로 모든 판단: 단순하지만 출력 통제·지연·비용에서 불리.
- 로컬 소형 모델로 판단: 비용은 0에 가깝지만 한국어 화면 판정 품질·유지 부담 미검증. Phase 3 실험.

## 결과
- 임계값 조정과 라벨 코퍼스 운영이 상시 업무가 된다(S7, 회귀). 번들 변경은 앱 릴리스 주기를 따른다.
- Decisions의 `refusal` 응답과 `unknown`은 항상 "자동 진행 금지"로 해석한다. 거절이 진행 쪽 결과를 만들 수 없음을 BV-02로 기계 검사한다.

## 개정 메모 (v1.3, research/AUDIT-B 반영)
- **BV-06 — 번들 정의는 앱 바이너리 전용**(B-14, B-21, B/C-20): 번들 정의는 앱(그리고 게이트웨이 빌드)에만 포함하고 레지스트리로 배포하지 않는다. 앱은 번들 다이제스트 허용 목록을 내장하고, `manifest.bundlesUsed`의 다이제스트가 그 목록에 없으면 패키지를 로드하지 않는다. 엔진은 게이트웨이 응답을 비신뢰 입력으로 보고 결과 매핑·임계값을 로컬 번들 정의로 다시 계산한다. 따라서 BYOK 경로도 같은 번들을 쓰고, 서명 파이프라인 하나로 임계값을 낮춘 번들을 내려보낼 수 없다. 번들 스키마에는 `riskClass`·`outcomes[{name, kind}]`·`needsAmounts`가 생기고 `sideEffectFree`는 삭제한다. 검증 규칙 BV-01~06은 D03 §3.2.
- **결정적 사전 필터**(B-15): 인젝션 탐지를 같은 요청 안의 모델 predicate(`page_text_addresses_agent`)에만 맡기지 않는다. 모델 호출 전에 키워드·구조 필터를 돌려, 걸리면 Terra에는 보내지 않고 Decisions 판정의 `progress` 결과는 `unknown`으로 강등한다(`safety` 결과는 유지). 모델 predicate는 보조이며, 그 refusal은 "지시문 있음"으로 간주한다. 필터 규칙은 D04 §3, 레드팀 측정은 S17.
- **Terra 출력의 구조화 슬롯 원칙**(B-15, B-28): 사용자에게 보이는 Terra 출력은 구조화 슬롯(열거값·날짜·숫자·우리 문자열 키)뿐이다. 화면·PDF·이메일에서 온 텍스트를 요약한 자유 문장은 표시하지 않는다. 불가피한 예외 경로는 "포털 원문 요약(신뢰할 수 없음)" 고정 라벨을 붙이고, 전화번호·URL·비밀 입력 유도 패턴이나 세무 상담으로 판정되는 문장은 표시하지 않는다. 우리 앱의 말투로 제3자 텍스트가 사용자를 사회공학하는 경로를 막기 위해서다.
- 요청 본문 규범은 `schemas/gateway-request.schema.json` 하나이며 `effort`·`max_output_tokens`는 클라이언트 필드에서 빠졌다(B-20). Phase 1에서는 이미지 입력을 모델로 보내지 않는다(B-18).
