# ADR-024. 승인 정밀도: 바의 줄 수를 늘리지 않고 더 정확하게, 사용자 동작은 main이 본 입력에 묶는다

> 상태: 채택(2026-11-03) · 개정: ADR-021 결정 1(표시 조건·클릭 활성화 예외·중복 경고 표시) · 관련: ADR-020 결정 5, D02 §4.4·§7·§8, D03 §2·§3·§5·§5.3·§5.6, D11 §4, D13 §8, D17 §1, 08 §6·§8·§11, design-system ApprovalBar
> 근거: [AUDIT-D](../../research/AUDIT-D-v13-poc-security.md) N-21·N-22·N-26·N-27·N-48·N-50(6건) = [D19 §3.5](../19-attack-surface.md) D-40·D-18·D-20·D-21·D-31·D-32

## 맥락

- 바는 공급받는자·합계·이메일 세 줄만 보이고 작성일자를 보지도 대조하지도 않는다. 작성일자는 KST가 아니라 OS 시간대로 정해진다. 비KST PC나 자정을 넘긴 승인에서 다른 과세기간 날짜로 비가역 발급이 승인될 수 있다(N-26). 검증자 정정: 지금은 해시에만 쓰이고 포털 값과 대조가 없다.
- 중복 경고 바는 "이미 발급 확정(승인번호 있음)"과 "발급 여부 모름"을 같은 문구·같은 파랑으로 보인다. verify는 최소 대기 직후 끝나 `in_doubt`가 남발되고 PoC에는 해소 경로가 없다(N-22). 습관 클릭이 곧 중복 발급이다.
- ADR-021 클릭 활성화 예외(100ms)는 다른 창 뒤에 있던 앱을 앞으로 가져오는 클릭을 그대로 승인으로 받는다(N-48).
- [다시 발급]·[지난번과 같게]는 세금계산서에서 "새 법적 발급"인데 PDF 재취득처럼 읽힌다. 작성일자만 바뀐 같은 건은 중복 경고에 걸리지 않는다(N-50).
- 커밋 구간의 클릭은 Playwright 자동 대기(30초) 동안 바뀐 값을 제출할 수 있다. 클릭 전 실패도 `dispatched`로 처리된다(N-21).
- 렌더러 IPC(`run.prepare`·파일 대화상자·외부 뷰어·비밀 창)는 사용자 동작 결속이 없다(N-27).
- 제약(제품 UX 약속): 손대는 순간은 두 번(P3), 앞으로 가져오는 첫 클릭(P6), 바와 카드의 시각 연속성(P8), 같은 내용으로 다시(P18), 앱이 스스로 확인(P10).

## 결정

1. **작성일자는 KST 하나로 정하고 포털 값과 대조한다(N-26, D-20).** 엔진은 `issueDate = kstDay(유효 시각)`로 정한다. H-01에 `s19e: assert readbackEquals {fieldKey:'issueDate', ref:'$inputs.issueDate'}`(코드 `assert.issue_date_mismatch`)를 넣는다. D02 §8 골든 플레이북과 V-03j 계열 정적 규칙에 "readback에 날짜형 fieldKey가 있으면 입력값 대조 assert 필수"를 더한다.
2. **바의 작성일자는 오늘과 다를 때만 보인다(N-26, D-20).** main이 KST 오늘과 `fields.issueDate`를 비교한다. 다르면 합계 줄에 줄이지 않는 조각 ` · 작성일 YYYY-MM-DD`를 붙인다(넘치면 기존 "창을 넓혀 주세요" 규칙). 같으면 화면은 지금과 같다. `fields`에 이미 있는 값이라 해시·스키마 변경이 없다.
3. **중복 경고는 원장 상태별로 다르게, 주의 색으로(N-22, D-18).**
   - `$dup.businessKey` 상태 목록에 `committed`가 있으면: 표시 "이미 발급됨(승인번호 있음)" + `attention` 배경 + 동작 글자 "발급된 기록을 확인했고 한 번 더 발급".
   - `in_doubt`·`armed`·`dispatched`·`observed_manual`이 있으면: "발급 여부 확인 안 됨" + `attention` + 기존 동작 글자 "같은 건 기록을 확인했고 발급".
   - 직전 시도만 `not_committed`면: "직전 시도 미발급 판정"(기본 색).
   - 첫 클릭이 명시 확인이라는 ADR-021 규칙은 그대로다.
4. **verify는 상한까지 스스로 확인한다(N-22, D-18).** `minElapsedMs`·`lookups` 하한을 넘긴 뒤에도 `verify.maxMs`(앱 하한 300초)까지 지수 간격(10·20·40초, 분당 네비게이션 상한 안)으로 조회한다. 상한에서만 `in_doubt`다. Phase 1에 `run.reverify{intentId}`(조회만, 새 탭)를 둔다. 앱 기동 시 1회 자동, 카드의 [발급목록 다시 확인], 같은 업무 키 새 실행 직전에 돌린다. 1건이면 `committed`로 바꾼다.
5. **클릭 활성화 예외는 앱이 연 핸드오프에서 돌아올 때만(N-48, D-31).** main이 전용 Chrome 창·비밀 입력 창·Hello 대화상자를 앞에 올린 뒤 120초 안에 포커스가 돌아온 경우만 100ms 예외를 적용한다. 그 밖의 비활성→활성 전환은 첫 클릭을 "앞으로 가져오기"로만 받고 600ms 뒤 무장한다. 창이 blur되면 바를 무장 전(흐림) 페이지로 바꿔 상태를 보인다. 연속 게이트 규칙은 두지 않는다(검증자 정정).
6. **세금계산서의 "다시"는 법적 발급이 아니게(N-50, D-32).** 문서함 상세에서 세금계산서는 [다시 발급] 대신 [PDF 다시 받기](H-02 조회·저장, 비가역 아님)와 [메일 다시 보내는 방법]을 둔다. 새 발급은 거래처 화면의 [세금계산서 발급]으로만 한다. [지난번과 같게] 초안에는 고정 문구와 작성일자 추정 표시(점선)를 둔다. 보조 중복 키 `$dup.recentSameAmount`는 작성일자를 뺀 `(공급자, 공급받는자, 공급가, 세액, 품목명[])`이다. 이 키가 최근 10일 안에 `committed`면 합계 줄 꼬리 "N일 전 같은 금액 발급 있음"과 중복 동작 글자를 쓴다(차단 아님).
7. **커밋 클릭은 짧고 정직하게(N-21, D-40).** 재계산·할트 검사 뒤 `click({ trial: true, timeout: 1_500 })`로 동작 가능성만 먼저 본다. 실패하면 입력이 나가지 않았으므로 `not_committed(identity_mismatch)`다. 이어지는 실제 클릭의 예외만 `dispatched`다. R-G6 입력 잠금(Phase 1)은 "게이트 열림~토큰 소비·재계산 완료"와 "verify 구간" 두 구간이며 엔진의 발급 버튼 클릭 직전에만 푼다(`setIgnoreInputEvents`가 CDP 입력도 막는다는 실측 반영). 잠금 실패 시 게이트를 열지 않는다.
8. **사용자 동작 명령은 main이 본 실제 입력에 묶는다(N-27, D-21).**
   - main이 메인 창 `webContents`의 `before-mouse-event`(mouseUp)·`before-input-event`(비수식 Enter/Space)로 본 마지막 입력 시각을 기준으로 한다.
   - `run.prepare`는 2초, `docs.import{pick}`·`vault.importPdf`(pickId 없음)·`ocr.bizcert`·`docs.open`은 3초 안에만 받는다(없으면 `gesture_required`).
   - `run.prepare`는 분당 3회다. 게이트 없이 끝난 실행이 연속 3회면 `main.prepare_throttled`다. `docs.open`은 분당 5회다. 대화상자는 메인 창을 부모로 띄운다.
   - `subject_mismatch` 해제는 빈 patch가 아니라 `patch.subjectConfirmed: true`(체크 "내 사업장 서류가 맞아요")로만 받고 `document.confirmed{by:'user', fields}`를 남긴다.
   - 사업자등록증명·기타 서류의 `expiresOn` 상한은 발급일 + 2년이다.
   - `runs_day`는 D03 §7대로 시작 시점에 센다(검증자 정정).
9. **원격·예약 실행의 바 표시 조건(N-27, D-21).** `trigger≠local` 게이트의 바는 "게이트 요청 이후 main이 메인 창에서 직접 본 실제 입력이 있고, 그 뒤 렌더러가 카드 ID를 알려 옴"일 때만 뜬다. 표시 뒤 60초 동안 입력이 없으면 내린다(카드를 다시 열면 다시 뜬다). 합성 입력(M·E의 SendInput) 한계는 ADR-021과 같다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 작성일자를 바에 항상 표시(4줄) | 3줄 규칙과 바·카드 시각 연속성(P8)을 깬다. 다를 때만 보여도 위험한 경우를 모두 덮는다 |
| 중복 경고 시 별도 확인 대화상자 | 별도 승인 창 없음(P4)·손대는 순간 두 번(P3) 위반 |
| 같은 금액 반복을 차단 | 정당한 월 반복 발급을 막는다. 경고 꼬리만 단다 |
| 보조 중복 키 35일 | 월 반복 발급마다 경고 피로. 10일로 좁힌다(검증자 정정 7~10일) |
| 연속 게이트 무장 지연 1.5초·"n/N번째 건" | 검증자가 삭제. 단건 사용자 이득 없음 |
| `runs_day`를 게이트 시점으로 이동 | 포털 활동 상한이라 게이트 전 반복도 세야 한다(검증자 정정) |
| 키보드 승인 복귀 | ADR-021 결정 1 유지 |

## 결과

### 보안 영향

| 주체 | 닫는 것 |
|---|---|
| 사용자 습관·피로(공격자 없음) | "모름"인 건에 대한 습관 클릭 중복 발급, 앞으로 가져오기 클릭이 승인, 재취득인 줄 알고 누른 재발급, 날짜만 바뀐 중복 |
| 시간대·자정(공격자 없음) | 다른 과세기간 작성일자의 비가역 발급 |
| R 렌더러 침해 | `run.prepare` 무한 반복으로 상한 소진·포털 반복 접근, 파일 대화상자·외부 뷰어 남발, 빈 patch로 사용자 확인 대체, 원격 게이트 바 표시 시점 통제(R-3) |
| P5 페이지·DOM 조작자 | 승인 뒤 값 변경을 자동 대기 30초 동안 제출(창을 1.5초로 줄이고 Phase 1 입력 잠금으로 닫음) |

남는 것: 승인 바를 덮는 브라우저 팝업과 사람의 습관 클릭은 Windows 실기기 사람 요인 시험(RETRO B-07) 전까지 남는다(D19 §8).

### UX 영향(사용자 화면 문장 그대로)

- 작성일자가 오늘과 같으면 변화 없음. 다르면 바 합계 줄 "합계 3,630,000원 · 세액 330,000원 · 작성일 2026-11-02". 포털 값이 의도와 다르면 바가 뜨기 전에 "홈택스 작성일자가 오늘(한국 시간)과 달라 멈췄어요. 아무것도 발급하지 않았어요."
- 중복 바 꼬리: "이미 발급됨(승인번호 있음)" / "발급 여부 확인 안 됨" / "직전 시도 미발급 판정" / "N일 전 같은 금액 발급 있음". 동작 글자: "발급된 기록을 확인했고 한 번 더 발급" 또는 "같은 건 기록을 확인했고 발급".
- 중복 카드 문장: "이 거래와 같은 건이 이미 발급돼 있어요(승인번호 있음). 한 번 더 발급하면 같은 계산서가 2건이 돼요." / "같은 건이 발급됐는지 아직 확인하지 못했어요. 홈택스 발급목록을 먼저 확인해 주세요." / "직전 시도는 발급 안 됨으로 판정했어요. 다시 발급하기 전에 홈택스 발급목록을 한 번 확인해 주세요."
- verify 진행 표시: "홈택스 발급목록에서 확인 중이에요(최대 5분)". Phase 1 in_doubt 카드 버튼: [발급목록 다시 확인]. 클릭 수 변화 없음. "확인 필요"가 스스로 "발급 완료"로 바뀌는 일이 늘어난다.
- 다른 창에서 돌아온 첫 클릭: 바는 기존 문구 "잠시 뒤 다시 눌러 주세요"를 보이고 0.6초 뒤 눌린다. 비밀번호 창·전용 Chrome에서 돌아온 클릭은 지금처럼 바로 눌린다.
- 문서함 세금계산서: [PDF 다시 받기] [메일 다시 보내는 방법]. 증명서의 [다시 발급]은 그대로다.
- [지난번과 같게] 초안 첫 줄: "지난번(10-27, 승인번호 끝 0012)과 같은 금액·품목으로 새 계산서를 끊어요. 작성일자는 오늘이에요."
- 대상 사업자 불일치 서류: 체크 "내 사업장 서류가 맞아요" 한 칸. 지금은 '저장'만 눌러 조용히 사라지던 것이 명시 확인이 된다.
- 사람 속도를 넘는 반복(분당 3회 초과) 때만: "잠시 뒤 다시 눌러 주세요."
- 커밋 클릭 전 실패: 지금의 "발급됐는지 모름" 대신 기존 문구 "홈택스 화면이 예상과 달라 멈췄어요. 아무것도 발급하지 않았어요."로 정확해진다.

### 후속

- PoC-3에서 `form.issueDate` 셀렉터 확정과 s19e를 같은 PR로 한다.
- RETRO B-07 Windows 사람 요인 프로토콜에 "외부 창 복귀 첫 클릭 20회"를 넣는다.
- ADR-021 머리말에 개정 메모를 단다. design-system ApprovalBar에 `attention` 무장 상태·작성일 조각 명세를 더한다(디자인 시스템 담당).
- Phase 1: `run.reverify`·`$dup.recentSameAmount`·입력 잠금·`subjectConfirmed`.
- 문서 반영: D02 §4.4·§7·§8, D03 §2·§5·§5.3·§5.6, D11 §4, D13 §8, D17 §1, 08 §6·§8·§11.
