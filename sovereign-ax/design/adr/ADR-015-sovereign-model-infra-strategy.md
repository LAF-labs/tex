# ADR-015. 소버린 모델·인프라 전환 전략 — 공급사 중립 설계와 전환 트리거

> 상태: 채택(2026-10-28, 재감사 E-15 반영) · 근거: [R6 Upstage Solar](../../research/R6-upstage-solar.md), [R7 네이버클라우드](../../research/R7-naver-cloud-sovereign.md), [R8 로컬 판정 모델](../../research/R8-local-decision-model.md), [AUDIT-C §4 데이터 주권 표](../../research/AUDIT-C-remote-cloud-sovereignty.md) · 관련: ADR-003, ADR-009, ADR-013, D04 §1, D09 §9, D19 §6
> 2026-11-05 개정(팀장 결정): Phase 1 인프라는 AWS 서울이 아니라 D09 §1 "Phase 1 통합 환경"(Supabase PostgreSQL·Vercel·AWS SES 서울·APNs/FCM)이다. 결정 5의 공급사 중립 원칙과 결정 3의 "국내 처리" 조건은 그대로다. 결정 6의 남는 외국 의존 목록에 Supabase·Vercel·AWS SES를 더했다.

## 맥락

- 현재 설계는 모델을 OpenAI(Decisions `gpt-6-luna`, Responses `gpt-6.1-terra`), 인프라를 AWS 서울 리전으로 가정한다. OpenAI 한국 리전은 저장 전용이고 처리는 미국·EU·UAE다. 공공 AX·소버린 데이터 맥락에서 "완전 소버린"(국산 모델 + 국내 CSP)으로 옮길 수 있는지 평가했다.
- E2EE 구조에서는 블롭이 암호문이므로 **저장소 국적의 기술적 이득은 작고, 마스킹된 평문이 흐르는 모델 경로가 주권의 병목**이다(R7 §5). 서버 평문(계정·메타데이터·계량·로그)은 국내 CSP로 옮기면 외국 법인 통제에서 빠진다(AUDIT-C §4 지점 1~5).
- 사실(2026-10-28 조사, 각 노트에 출처):
  - Upstage `solar-decide`(`POST /v1/systemone`, 베타 2026-09-22)는 OpenAI Decisions와 같은 단가(입력 $0.10/1M, 출력 무료)로 choice/score/noul 확률을 돌려준다. 한국 리전(`kr.api.upstage.ai`)은 요청·처리를 국내에서 끝내지만 비공개 베타·별도 승인이고, 지원 모델은 Mini 4·Decide·Document AI뿐이다. **Solar Pro 4는 한국 리전에 없다.** 선택지 ≤26, 질문별 refusal 없음, 스키마는 GA 전 변경 가능, 한국어 정확도 미공개, SLA 95.0%, 모델 수명 약 9개월(R6).
  - HyperCLOVA X(HCX-007)는 확률·캐시가 없고 L1 비용이 약 9.6배라 판정 계층 대체에 부적합하다. 네이버는 독자 AI 파운데이션 모델 1차 평가에서 탈락했다(R7 §3).
  - 네이버클라우드 이전은 비용 중립(사용자 1천 명 기준 월 약 47만 원 대 46만~56만 원)이지만 KMS가 Ed25519를 지원하지 않고, S3 호환 API에 버전 관리·Object Lock이 없으며, ALB의 WebSocket 지원이 문서에 없다. CSAP 인증은 "공공기관용" 존에 한정된다(R7 §1·§2·§6).
  - 사용자 PC에서 돌리는 로컬 판정 모델(Strands Decider 2B 등)은 문맥 4,096토큰·영어 중심·Windows CPU 런타임 미검증이라 지금은 L1을 대체할 수 없다. L1 질문의 약 55%는 결정적 규칙으로 대체 가능하다는 추정이 있다(R8).
  - 완전 소버린이 되어도 APNs/FCM, 앱 스토어, 코드서명 CA, npm/GitHub, 전용 Chrome의 Google 서비스 의존은 남는다(R7 §4, AUDIT-C §4 지점 11~16·22).

## 결정

1. **모델 계층(Phase 0~1)은 OpenAI Decisions + Terra를 유지한다.** 이유: 정식 출시, 질문별 refusal(인젝션·보수 처리 설계의 일부), 명시 캐시, 1M 컨텍스트, 측정된 비용. 단 `decide()` 계약을 **System One 계약까지 포괄하도록 일반화**한다(D04 §1): `refusals`는 빈 배열 허용, 임계값은 (번들, 공급사·모델 스냅샷) 단위 프로필, `choice` 선택지 ≤ 26을 번들 정적 검증(BV)에 추가, `answers`는 이름 기반 조인, 입력 절단은 **금지**(한도 초과 시 `unknown`, 조용한 절단 금지). 공급사 종속 코드는 `model/adapters/*`에만 둔다(기존 원칙).
2. **Upstage `solar-decide` 어댑터를 Phase 0 S7에서 병행 평가한다.** 같은 홈택스 라벨 코퍼스로 정확도·보정·지연을 Luna와 비교한다. 한국 리전 비공개 베타 신청은 대외 작업(EX)으로 등록한다. Solar Pro 4는 한국 리전에 없으므로 L2 비용 대안으로만 A/B 후보에 둔다.
3. **"국내 처리" 요금제 옵션은 조건부로 연다.** 조건: (a) Upstage Decide 한국 리전 GA 또는 서면 승인, (b) S7에서 핵심 번들 정확도가 Luna 기준선의 −2%p 이내, (c) 무보존·학습 미사용 서면 계약, (d) **L2 호출 100%가 국내 리전 처리 모델(Mini 4 한국 리전 또는 동급)로 라우팅되고, 공급사가 처리 위치와 호스팅 법인을 서면으로 확인**, (e) **모델 처리와 게이트웨이를 운영하는 인프라가 국내 법인이 운영하는 인프라**(국내 리전이라도 외국 법인 인프라면 불충족, 서면 확인). 다섯 중 하나라도 없으면 "국내 처리"라고 표기하지 않는다(E-15). HyperCLOVA X는 L1 후보에서 제외한다.
4. **로컬 판정(egress 0)은 지금 채택하지 않는다.** 먼저 결정적 규칙 L0를 넓힌다(S-L0: 번들 질문별 규칙 대체 가능성 측정). 로컬 모델은 S-L1~S-L4(한국어 정확도·Windows CPU 지연·변환본 무결성·하이브리드 폴백) 결과가 나온 뒤 Phase 3 "엄격 프라이버시 모드"(옵트인) 후보로 재검토한다. 하이브리드를 쓰더라도 비가역 직전·직후 판정(`form_ready_v2`, `issue_result_v2`)과 보안 판정(`security_warning`, `blocked`)은 로컬 단독으로 **통과**시키지 않는다(중단 쪽 단독 결정만 허용). 모델 파일은 플레이북 레지스트리와 같은 서명·투명성 경로로 배포한다(ADR-013).
5. **인프라는 AWS 서울로 MVP를 시작하되 공급사 중립으로 설계한다**(D09 §9). 원칙: S3 호환 API의 공통 하위 집합만 사용(버전 관리·Object Lock에 의존하지 않고 삭제 유예·백업은 앱 레벨 소프트 삭제·별도 버킷 복제로 구현), PostgreSQL 표준 기능만, WSS는 LB 기능에 의존하지 않고 서버가 직접 TLS 종단 가능, **서명 키는 클라우드 KMS가 아니라 우리가 국내에서 운영하는 HSM/스마트카드**(Ed25519 유지, ADR-013), 로그인 메일은 국내 발송 사업자, IaC는 공급사별 모듈로 분리. (2026-11-05 개정: Phase 1은 D09 §1 "Phase 1 통합 환경"에 올린다. 로그인 메일은 국내 발송 사업자 대신 AWS SES 서울 리전이다. 위 원칙은 그대로 지킨다.) 전환 트리거는 기술이 아니라 조달·계약이다: (a) 공공 조달에서 CSAP 또는 국내 사업자 요구, (b) 고객 계약에서 국내 CSP 명시 요구, (c) 유료 사용자 1,000명 시점의 정기 재평가. 전환 전 PoC 항목: WSS 유지(Network Proxy LB 또는 직접 TLS), S3 호환 범위, 메일 발송, 장애 이력 점검(R7 §7).
6. **대외 문구**: "완전 소버린"이라고 쓰지 않는다. "국내 저장, 마스킹본만 모델 전송(처리 국가 고지), 국내 처리 옵션(조건 충족 시), 남는 외국 의존 목록 공개"로 쓴다. 남는 의존은 처리방침과 투명성 페이지에 표로 공개한다(D11 §8 점검표에 추가). **이 목록이 정본이며** D11 §8·D19 §6·§8·README는 인용한다(E-15): APNs/FCM(Apple·Google), App Attest·Play Integrity(Apple·Google), Microsoft(SmartScreen·Artifact Signing·Windows Update, Windows Hello는 클라우드 요소가 없음을 확인해 기재), 앱 스토어, 코드서명 CA, npm/GitHub, 레지스트리 CDN·DNS, 전용 Chrome의 업데이트·세이프 브라우징 등 Google 서비스, 모델 공급사의 하위 처리자. Phase 1 통합 환경(2026-11-05 추가, D09 §1): Supabase(PostgreSQL, 프로젝트 리전 미정), Vercel(HTTP 서비스 전부, 함수 실행 리전 미정), AWS SES(메일, 서울 리전). 셋 다 외국 법인 인프라라 리전과 관계없이 이 목록에 둔다(결정 3 (e)). 리전이 정해지면 여기와 D09 §1을 함께 고친다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 즉시 전면 이전(네이버클라우드 + HyperCLOVA X) | L1 비용 약 9.6배, 확률 부재로 임계값 설계 불성립, 레이트 리밋 300K TPM, 보존 정책 미확인. 인프라 쪽은 Ed25519·S3 호환·WSS 공백으로 PoC 전 전환 불가 |
| Solar Pro 4 전면 채택 | 한국 리전 미제공이라 주권 이득이 없고, L1 대체 상품이 아니다. SLA 95%·9개월 수명·세대 교체 시 가격 2배 이력 |
| 로컬 2B 판정 모델 즉시 도입 | 한국어 평가 없음, 문맥 4,096 조용한 절단, Windows CPU 런타임 전부 미검증, GPU 없는 노트북에서 분 단위 지연 추정 |
| 모델만 국산·인프라는 AWS 유지 | 게이트웨이가 외국 법인 인프라(AWS) 위에 있어 결정 3의 조건 (e)를 채우지 못하므로 "국내 처리"라고 표기할 수 없다 |

## 결과

- D04 §1 계약 일반화(System One 호환), D04 §8 공급사 비교 각주, D09 §9 공급사 중립 원칙, ADR-013 서명 키 자체 HSM, D14 스파이크 S7 확장(`solar-decide` 비교)·S-L0~S-L4, D19 §6 주권 지점 표, 기획 03 §스택·06 가능성 검토의 공급사 문구 갱신(기획 문서는 별도 커밋).
- 대외 작업: Upstage 한국 리전 베타 신청, 무보존 계약 확인(EX-7과 묶음), 네이버클라우드 PoC 계정(전환 트리거 발생 시).

## 조건(이 결정이 뒤집히는 경우)

- S7에서 `solar-decide`가 Luna와 동등 이상이고 한국 리전이 GA되면 "국내 처리"를 기본값으로 올리는 것을 재검토한다.
- S-L1에서 한국어 파인튜닝 모델이 핵심 번들 98%를 넘고 S-L2에서 일반 노트북 p95 ≤ 3초면 Phase 3 엄격 프라이버시 모드를 로드맵에 올린다.
- 공공 조달이 사업 축이 되면 트리거 (a)로 네이버클라우드 전환 PoC를 시작한다.
