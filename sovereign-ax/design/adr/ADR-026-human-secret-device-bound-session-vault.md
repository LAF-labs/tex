# ADR-026. 사람 비밀 등급 정합: 기기 결박 열쇠와 Windows 세션을 따르는 금고, 엄격 모드는 발급마다 Hello

> 상태: 채택(2026-11-03, TPM·세션 이벤트는 스파이크 S10c 조건부) · 대체: ADR-020 결정 3의 "열쇠는 DPAPI·자격 증명 관리자, Hello 기본 꺼짐" 문장, D05 §2의 "대화형 전용: 꺼낼 때마다 Hello" 규칙 · 관련: ADR-005, ADR-020(결정 2·조건), ADR-021(Hello 옵션), D03 §3·§7, D05 §2·§3.8·§4·§7, D10 §6, D11 §0, D17 §1·§3, D19 A-22·A-23·§8, 02 §2·§6, 08 §6·§9·§11
> 근거: [AUDIT-D](../../research/AUDIT-D-v13-poc-security.md) N-07·N-11·N-25·N-31·N-46(5건) = [D19 §3.5](../19-attack-surface.md) D-01·D-03·D-19·D-42·D-30

## 맥락

- 같은 비밀(홈택스 아이디·비밀번호, 보안카드 30칸)에 정본이 둘이다(N-07).
  - ADR-020은 "통째 JSON, DPAPI, Hello 기본 꺼짐"이다.
  - D05 §2는 "Hello 결박 대화형 전용, 칸 단위, 미저장 기본"이다.
  - D19 A-22·A-23은 후자를 근거로 "닫힘"이다.
  - 검증자 정정: 새 지적은 "정본 둘·등록부 미갱신"에 한정한다. 자리 비운 PC는 D19 §8의 기존 수용 범위다.
- 사용자 약속 "한 번 등록하면 앱이 알아서 입력"(P1)과 "손대는 순간은 두 번"(P3)은 발급마다 Hello를 기본으로 두는 것을 막는다.
- 지금 설계는 다음을 막지 못한다.
  - (a) 디스크·백업 사본을 다른 곳에서 여는 것.
  - (b) 잠기지 않은 채 자리를 비운 PC의 제3자.
  - (c) 앱 모달로 위장한 가짜 등록 창(N-11).
  - (d) 서명된 플레이북이 다른 password 칸에 비밀을 넣는 것(N-46).
  - (e) 저장 자격의 자동 재입력이 포털 비밀번호 오류 횟수를 소모하는 것(N-25).
- 암호 걸린 PDF의 열기 암호에는 등급이 없다(N-31).
- Windows 로그인 자체가 이미 사람 확인이다. 금고가 Windows 세션의 잠금·해제를 따르면 추가 프롬프트 없이 (b)의 대부분을 닫는다.
- 같은 Windows 계정에서 도는 악성코드(M)는 금고가 열린 동안 어떤 무프롬프트 설계로도 막지 못한다. 그것을 막는 유일한 수단(발급마다 Hello)은 선택으로 둔다.

## 결정

1. **정본은 D05 §2 개정판 하나다(N-07, D-01).** ADR-020 결정 2(보안카드 완전 위임)는 유지하고 결정 3의 저장 방식만 이 ADR로 대체한다. D19 A-22는 "변형(ADR-026)", A-23은 "채택 유지(데몬은 사람 비밀 미사용, 금고가 `trigger=daemon` 거부)"로 고친다. ADR-020 조건(보안카드 칸이 가상키패드면 위임 보류)은 그대로다. 보류되면 보안카드는 미저장·사용자 직접 입력이다.
2. **칸 단위 저장과 기기 결박 열쇠.** 보안카드는 칸별 항목 `securitycard/<profile>/<row>`, 포털 자격은 `portal/<profile>/id`·`portal/<profile>/pw`다. 각 항목은 슬롯 KEK(32B 무작위)로 AES-256-GCM 암호화한다(AAD = 항목 이름). 슬롯 KEK는 (a) 이 PC TPM의 **내보낼 수 없는 키**(Microsoft Platform Crypto Provider, UI 정책 없음)로 래핑한다. TPM이 없으면 (b) DPAPI(CurrentUser)로 조용히 대체한다. Hello가 Available인 PC는 Hello 결박 래핑 사본(KeyCredentialManager 서명 → KEK)을 하나 더 둔다. 발급 1회에 요청된 칸만 복호한다.
3. **금고는 Windows 세션을 따른다.**
   - 금고 열림 = Windows 세션 열림 ∧ 시스템 유휴 < `vault.idleLockSec = 900` ∧ 열린 지 < `vault.unlockMaxSec = 28800`.
   - 화면 잠금(`lock-screen`)·절전(`suspend`)·사용자 전환·원격 세션 전환(WTS, S10c)이면 즉시 잠그고 메모리의 슬롯 KEK를 지운다.
   - Windows 잠금 해제(`unlock-screen`)는 Windows가 사람을 확인한 것이므로 **프롬프트 없이** 다시 연다.
   - 유휴 잠금 뒤에는 Hello 사본(가능한 PC) 또는 Windows 잠금·해제로만 다시 연다.
   - 잠긴 금고에서는 보안카드 실행이 시작되지 않고 열린 승인 바는 내려간다(카드를 다시 열면 다시 뜬다). `gate.waitMs` 기본 10분은 유지한다.
4. **엄격 모드 = 발급마다 Windows Hello.** 설정 "발급마다 Windows Hello 확인(가장 안전)"을 켜면 TPM 무프롬프트 래핑을 지우고 발급마다 Hello 사본을 연다(`vault.unlockTtlSec = 300`). ADR-021의 "발급 전 Windows Hello 확인"과 같은 설정이다. 승인 바 Hello와 금고 Hello는 **한 번의 프롬프트**로 합친다(ADR-021 조건의 합치기 미결을 닫는다). Hello를 쓸 수 없게 된 순간의 "이번만 Hello 없이 승인" 규칙은 ADR-021 그대로다.
5. **등록 창은 위장할 수 없는 모양이다(N-11, D-03).** T-06은 Windows 표준 프레임·제목줄(`금고 · 보안카드 등록`)·앱 아이콘이 있는 별도 최상위 창이다. 앱 본체에는 main이 그리는 반투명 덮개 뷰로 모달 느낌만 준다(렌더러는 OS 제목줄도, 자식 뷰 위도 그릴 수 없다). 렌더러 번들은 `type=password` 입력과 `sx-secret-*` 클래스를 쓸 수 없다(lint). Hello 프롬프트는 구별 단서로 쓰지 않는다(Hello 없는 PC가 있다).
6. **비밀 종류와 칸을 묶는다(N-46, D-30).** 셀렉터 사전의 `secretSlot`을 `secretKind: cert_password|portal_password|security_card` + `secretPurpose: login|sign`으로 바꾼다. V-02에 "`secret_fill.secret == entry.secretKind`, `secretPurpose`는 그 흐름 안에서만"을 넣는다. 금고 `typist.fill`은 요청 kind와 사전 kind가 같을 때만 입력한다(「또는」→「그리고」). 앱 상수로 실행당 종류별 1회(보안카드는 칸별 1회)를 `runId`로 집행한다.
7. **로그인 실패는 한 번에 멈춘다(N-25, D-19).** `login_failures/day/profile/portal` 카운터를 두고 `POLICY_FLOOR.loginFailuresPerDay ≤ 2`다. 포털의 명시적 인증 실패(`auth_failed` 신호: 비밀번호 오류·보안카드 오류 문구) 1회 뒤 그 kind·scope를 `vault.credential_suspect`로 표시한다. 사용자가 금고 창에서 확인·수정하기 전에는 타이피스트가 다시 넣지 않는다. 타이피스트 `blocked_by_module`·네트워크·셀렉터 실패는 인증 실패로 세지 않는다. PoC-3 로그인 구현과 같은 PR이다.
8. **PDF 열기 암호는 "낮음" 등급으로 닫는다(N-31, D-42).** 메인 렌더러 입력을 허용하고 저장·로그는 금지한다. 작업마다 샌드박스 창을 파기해 지움을 대신한다. 파일 하나당 틀린 암호 5회면 그 선택을 닫는다(TTL은 첫 선택 시각 기준 5분, 재시도로 늘지 않음). main 소유 입력 줄은 보류한다.
9. **위협 표를 맞춘다.** D11 §0·D19 §2에 `W`(PC 앞 제3자: 동료·방문자·가족·퇴사자) 행을 더하고 완화를 "금고 유휴 잠금·Windows 잠금 연동·바 10분 만료, 엄격 모드면 막음"으로 적는다. M 행의 완화는 "기기 결박 KEK(오프라인 복호 차단)·엄격 모드 Hello·데몬의 사람 비밀 미사용·덤프 제외. 열린 금고 세션 동안의 무음 사용은 막지 못함"으로 고친다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 발급마다 Hello를 기본 켬(N-07 원안 (1)·(2)) | 보안카드 사용자(14%)에게 발급당 PIN·지문 1회가 새로 생긴다(P1·P3 위반). 같은 보호를 원하는 사용자는 엄격 모드로 켠다 |
| Windows 세션당 첫 발급에 Hello 1회 | 하루 1회 마찰이 생긴다. Windows 잠금 해제 신호가 같은 사람 확인을 프롬프트 없이 준다 |
| DPAPI 통째 JSON 유지(현 ADR-020) | 오프라인 복호, 30칸 동시 노출, 자리 비운 PC 무방비, 정본 충돌이 남는다 |
| 보안카드 미저장 복귀(D05 원안) | P1 약속 위반. PoC-3에서 가상키패드로 확인될 때만 그쪽으로 간다(ADR-020 조건) |
| 등록 창을 앱 모달처럼 유지 | 프로세스 경계를 화면에서 지워 렌더러의 위장이 쉬워진다 |
| Hello 프롬프트를 진짜 창의 표식으로 | Hello 없는 PC가 있고 ADR-020이 Hello를 선택으로 둔다 |

## 결과

### 보안 영향

| 주체 | 닫는 것 / 줄이는 것 |
|---|---|
| W PC 앞 제3자 | 잠긴 PC·15분 이상 비운 PC에서 1클릭 발급(닫음). 엄격 모드면 잠기지 않은 PC에서도 닫음 |
| 디스크·백업 사본 탈취(분실 노트북, 동기화·수리·포렌식 사본) | TPM 결박 사본은 다른 기기에서 열 수 없음(닫음). TPM 없는 PC는 DPAPI 수준으로 남음 |
| R 렌더러 침해 | 가짜 T-06 모달로 ID/PW·카드 30칸 수집(OS 프레임 창으로 구별, lint로 렌더러가 비밀 칸을 그리지 못함) |
| P 서명된 오류·악성 플레이북 | 다른 password 칸에 사용자 비밀 입력·비밀번호 변경 유도(kind↔칸 결박, 실행당 1회) |
| 포털 사건 | 저장 자격 자동 재입력으로 홈택스 비밀번호 오류 잠금(1회 뒤 정지) |
| M 같은 계정 악성코드 | 잠긴 동안의 무음 사용(닫음). 열린 동안은 엄격 모드에서만 줄임(잔여, D19 §8) |

D-01의 M 부분(열린 금고 세션 동안의 무음 사용)은 잔여 위험으로 **수용**한다.

### UX 영향(사용자 화면 문장 그대로)

- 평소: 변화 없음. 보안카드 사용자의 발급당 프롬프트는 0회 그대로다. Windows를 잠갔다 풀면 금고도 따라 열린다.
- 등록 창 아래(TPM PC): "번호는 이 PC의 보안 칩(TPM)에 묶인 열쇠로 잠가 이 PC 안에만 둬요. 다른 PC로 옮기면 열리지 않아요."
- 등록 창 아래(TPM 없는 PC): "이 PC에는 보안 칩(TPM)이 없어 Windows 로그인 계정으로만 잠가요. Windows가 열려 있는 동안 같은 계정의 프로그램이 열 수 있어요."
- 두 경우 공통(기존 고지 유지): "같은 Windows 계정에서 도는 악성 프로그램까지 막지는 못해요." · "앱은 대화창 안에서 비밀번호·카드 번호를 묻지 않아요. 이 창의 제목줄이 보일 때만 입력하세요."
- 유휴 잠금 뒤 승인 바 안내 줄(Hello PC): "자리를 비운 사이 금고를 잠갔어요 · 누르면 Windows Hello로 열고 발급해요". 바 클릭 1회 + Hello 1회이며 15분 이상 비운 뒤에만 생긴다.
- 유휴 잠금 뒤 승인 바 안내 줄(Hello 없는 PC, 바는 무장하지 않음): "자리를 비운 사이 금고를 잠갔어요 · Windows를 잠갔다 풀면(Win+L) 이어서 발급돼요"
- 설정 S-02: "발급마다 Windows Hello 확인(가장 안전)" / 설명 "켜면 발급할 때마다 얼굴·지문·PIN을 한 번 확인해요. 이 PC 앞의 다른 사람이나 프로그램이 몰래 발급하기 어려워져요." 기존 승인 바 Hello 설정을 대신한다. 켠 사용자의 프롬프트는 바 Hello와 금고 Hello가 합쳐져 줄어든다.
- 로그인 실패: "홈택스가 비밀번호 오류라고 알렸어요. 저장된 비밀번호를 금고에서 확인해 주세요. 확인 전에는 앱이 다시 입력하지 않아요." [금고에서 확인]
- PDF 암호 5회: "암호가 5번 틀려 이 파일은 닫았어요. 파일을 다시 골라 주세요."

### 후속

- 스파이크 S10c(신설, D14 §1): Electron에서 Rust 헬퍼로 NCrypt Platform Crypto Provider 무UI 키 생성·래핑, 대상 PC TPM 보유율, `lock-screen`/`unlock-screen`/WTS 세션 이벤트 신뢰성, 유휴 시간 측정. 불가하면 DPAPI 폴백과 위 고지로 간다.
- 법률 회신("보안카드 자동 입력 허용 여부") 뒤 재검토한다. 회신 전에는 등록 화면에 "홈택스 이용 규정 확인 중" 배지를 둔다는 ADR-020 결과를 따른다.
- ADR-020·ADR-021 머리말에 개정 메모(결정 3 대체, Hello 합치기 확정)를 단다. 디자인 시스템 SecretField·T-06 미리보기를 OS 프레임 창으로 갱신한다(디자인 시스템 담당).
- 문서 반영: D02 §2.1·§6, D03 §3·§7·§7.1, D05 §2·§3.8·§4·§7, D10 §6, D11 §0, D14 §1, D17 §1·§3, D19 §2·§3.1·§8, 02 §2·§6, 08 §6·§9·§11.
