# ADR-029. 원격·복구·데이터 최소화: 서버는 열쇠를 갖지 않고, 폰은 범위만큼만, 문구는 사실대로

> 상태: 채택(2026-11-03, 하드웨어 키 증명은 SP-2 조건부, 결정 1의 PASS 범위는 2026-11-03 (가)로 확정) · 개정: ADR-016 → v2(복구 문구 경로 삭제), ADR-006(정직 문장 유지), D07 §1.3·§2·§5·§6·§7, D08 §3·§4·§6·§7·§9, D09 §1·§2·§4.1·§5·§6·§10, D12 §1, D11 §0·§3·§8 · 관련: ADR-007, ADR-009, ADR-020 결정 7
> 2026-11-06 정합(팀장 지시, 큐 16~22): 결정 8과 UX 영향의 화면 문구 "진위확인"은 "상태조회"로 읽는다(08 §4 O-02·§9, 팀장 결정 2026-11-06. 결정 내용은 그대로).
> 근거: [AUDIT-D](../../research/AUDIT-D-v13-poc-security.md) N-09·N-13·N-30·N-37·N-41·N-53·N-55·N-81·N-83(9건) = [D19 §3.5](../19-attack-surface.md) D-16·D-34·D-22·D-24·D-26·D-35·D-36·D-51·D-52

## 맥락

- ADR-020 결정 7이 복구 문구를 없앴지만 D08·D07·ADR-006·README는 여전히 "복구 문구 → RK → AIK"다(N-09). 폰은 RK·AIK를 갖지 않아 새 PC에 넘길 것이 없다. PASS 경로는 서버 판정이 계정 신원 앵커가 되며 HSM 에스크로까지 미결이다.
- 원격 라이브 `cmd.run`은 시작 게이트가 없다. 페어링 폰 침해(P6)만으로 저장 자격 로그인이 시작된다(N-13).
- 폰의 서류 권한은 계정 전체다(N-53). E-10 하드웨어 키 증명 결과를 담을 필드가 없다(N-55). 게이트웨이는 이메일 6자리 코드 세션만으로 쓸 수 있다(N-41).
- 공개 표와 실제가 어긋난다: 텔레메트리(N-37), 진위확인 프록시의 사업자번호 평문 통과(N-81), 서버 레코드 시각(N-83).
- DB 키 유실 시 조용히 새 키를 만들어 원장·중복 이력이 사라진다(N-30). RETRO A-05는 길이 불일치만 다룬다.
- 제약(제품 UX 약속): 12단어 없음(P11), PC가 꺼져 있어도 답함(P22), 데몬 반자동(P24), 그 밖 P13·P16.

## 결정

1. **ADR-016 v2: 열쇠는 기기에만(N-09, D-16).**
   - RK·AIK는 첫 PC에서 무작위로 만든다. 래핑 사본은 페어링된 폰(하드웨어 키 결박)과 사용자가 고른 두 번째 PC에만 E2EE로 둔다. 서버·HSM 사본은 없다. `K_chk`·복구 문구 절을 지운다.
   - 새 PC: 기존 폰이 `Px`(생체)로 `"SAX-aik-rotate-v2"‖account_id‖old_aik_pub‖new_aik_pub‖ts`에 서명한다. 서버는 "옛 AIK 서명 또는 등록 폰 `Px` 서명" + 72시간 보류 + 전 기기 알림으로만 `aik_change_pending`을 받는다. 백업 열람은 그 폰이 이미 받은 `KEK_N`을 라이브 세션으로 새 PC에 되돌려 준다.
   - **PASS는 계정만 되찾는다(2026-11-03 사용자 결정 (가), ADR-020 결정 7의 미결을 닫음).** 백업 서류는 연결된 기기(폰 또는 두 번째 PC)가 남아 있을 때만 되찾고, 기기를 모두 잃으면 되찾을 수 없다. 서버·HSM 에스크로는 두지 않는다.
   - **복구용 기기는 아무 때나 더한다(ADR-020 결정 8).** 온보딩에서 권하되 건너뛸 수 있고, 설정 > 기기 연결에서 폰이나 다른 PC를 언제든 더한다. 새 기기는 이미 연결된 기기가 승인해야 붙는다(위 `Px`·AIK 서명 경로, 래핑 사본을 그 기기에 E2EE로 넘긴다).
   - PASS 경로: 계정 세션 회복과 기존 AIK 폐기 선언까지만 한다. AIK′ 등록은 7일 지연 + 전 기기·이메일 알림이다. 블롭·메타데이터 열람은 불가하고 에스크로는 없다. D08 §9.5의 보류·거부·재생성 AIK 서명 거부 규칙을 PASS 경로에도 적용한다. PASS 결과는 일 단위 확인 시각과 CI의 HMAC만 계정에 둔다.
2. **저장 자격을 쓰는 원격 시작은 시작 게이트(N-13, D-34).** 저장된 사람 비밀(포털 ID·PW·보안카드)이 필요한 플레이북의 라이브 `cmd.run`도 큐 명령과 같은 시작 게이트(D08 §7 `gateKind=start`)를 지난다: 폰 앱 생체 잠금 해제 뒤 일반 기기 키 서명 `Sign_Vm("SAX-start-v1"‖pair_id‖cmdId‖intent_hash)`. 하드웨어 키 `Px`는 비가역 승인(D08 §6.1)에만 요구한다. 하드웨어 키 없는 폰을 조회 전용으로 묶지 않는다(보안카드 사용자의 조회도 저장 자격 로그인이 필요해 자기모순, 검증자 정정). 금고는 `trigger=remote` 실행의 `typist.fill`을 엔진이 넘긴 "start 게이트 통과" 플래그가 있을 때만 허용한다. D10 `semi_auto` 로그인 경로도 같은 규칙이다.
3. **게이트웨이는 기기 토큰만(N-41, D-26).** 데스크톱 AIK 기기 인증서에 결속한 기기 범위 토큰(DPoP `SAX-dpop-v1`)만 받고 `X-Device-Id`는 토큰에서 유도한다. `runToken` 발급 엔드포인트 `POST /v1/run-tokens`를 명시하고 `tag = HMAC(gw_key, accountId‖deviceId‖runToken‖item)`이다. 계정 세션으로는 호출할 수 없다. 자동 정지는 기기 단위로 먼저 하고, 계정 정지 전 다른 기기에 알린다.
4. **폰은 허용 범위만 본다(N-53, D-35).** D07 `remote_devices.doc_scope_json{slots[], docTypes[]}`를 두고 기기 범위 토큰 클레임에 슬롯 범위를 넣는다. 서버 `GET /v1/docs`·블롭 조회는 토큰 범위만 돌려준다. PC는 `query.result`·`file.offer`를 범위로 거른다. 페어링 마지막 단계는 "[사업자 서류] [개인 서류]" 두 토글이다(기본 사업자만, 개인 프로필이 없으면 숨김). 슬롯별 KEK(`KEK_{N,slot}`)는 악성 폰 앱까지 막는 Phase 3 강화로 분리한다.
5. **하드웨어 키 증명 결과를 기록·집행한다(N-55, D-36).** `remote_devices`에 `hw_attest_state`(`verified_strongbox|verified_tee|ios_app_attest|unverified`), `hw_attest_chain_sha256`, `hw_attest_verified_at`을 둔다. 페어링 msg3 직후·7단계 `Cert_M` 서명 전에 `px.attest{chain[]}`를 처리하고, 체인의 `attestationChallenge`를 핸드셰이크 해시로 결속한다(`HKDF(h, 'SAX-attest-v1')`). 실패·미제출이면 `Px_pub`을 `Cert_M`에 넣지 않고 `unverified` → "PC에서 승인 필요"(E-06)다. PC는 `requiredSigAlg=p256` 응답을 `verified_*` 기기에서만 받는다. `rotate.static`·재페어링 때 재검증한다.
6. **서버 시각을 남기지 않는다(N-83, D-52).** 서버 메타데이터·`biz_key_marks` 테이블에 생성·갱신 시각 컬럼을 두지 않는다(감사는 `day`만). `track_commit_timestamp=off`이고 스키마 린트로 막는다. `doc_index`·`biz_key_marks` 포함 DB 백업·WAL 아카이브 보존 30일(wDEK 백업 7일 유지)을 D09 §10에 게시한다. 블롭 객체 저장소의 객체 생성 시각은 남는다고 정직하게 적는다(SP-9 일괄 업로드와 함께 재검토).
7. **텔레메트리 표를 하나로(N-37, D-24).** D09에 "텔레메트리 수신" 행·엔드포인트·식별자·보존을 둔다. 식별자는 계정·`X-Device-Id`를 쓰지 않고, 날마다 바뀌는 무작위 설치 토큰 또는 없음이며, 게이트웨이와 다른 호스트·토큰이다. 보존은 집계 90일이다. D12 §1: `decide.stats`·`block.signal`·`policy.applied`·`selector.repair`는 `*.daily{5건 버킷}`, `allowlistedSelector`는 `proposalDigest`만, `step.fail`은 개편 감지용 시간 버킷(5건 단위, 기기 식별자 없음), 안전 지표는 `security.daily`다. D19 §5·D11 §8·F-06에 같은 행을 둔다.
8. **진위확인 문구는 사실대로(N-81, D-51).** O-02 카드와 02 §9에 "사업자번호만 국세청 진위확인에 보내요(기본: 우리 서버 경유, 설정에서 내 키)"와 배지 출처 "국세청 조회"를 둔다. README의 정부24 문장은 "정부24의 자동화와 캡차 중계는…"으로 중의성만 없앤다(상한 상수 그대로). 승인 바 설명 문서에 "R-1만 막으며 값은 사용자가 바에서 확인" 한 구절을 더한다(UI 문구 그대로).
9. **DB 키는 조용히 바뀌지 않는다(N-30, D-22).** 금고 키 저장소를 `get`/`create`로 나눈다. 길이가 다르면 덮어쓰지 않고 `vault.keystore_mismatch`(기동 거부, RETRO A-05)다. 항목이 없는데 `db\db.sqlite`가 있으면 만들지 않고 `db.key_missing`이다. main은 이 fatal에서 복구 화면을 띄운다(Phase 1): 자격 증명 관리자 복원 안내 / "기록을 포기하고 새로 시작"(기존 파일을 `db\db.sqlite.unreadable-<ts>`로 보존 → 새 키·새 DB → `ledger.reset` → 첫 발급 카드 경고 1회). Phase 1 후반에 DB 키 회전(`PRAGMA rekey` 트랜잭션 + WAL 체크포인트)과 원장 HMAC 키 분리(키체인 루트 키에서 다른 info로 HKDF)를 한다. Phase 2 폰 복구 묶음에 DB 키 래핑을 넣는다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| PASS로 백업까지 열기(서버 HSM 에스크로) | 운영자가 열쇠를 갖게 되어 ADR-006 무지식 원칙이 무너진다. 2026-11-03 사용자가 (가)(PASS는 계정만)를 골랐다 |
| 12단어 복구 문구 복귀 | 12단어 없음(P11) 위반(ADR-020 결정 7) |
| 원격 시작에 하드웨어 키 필수 | 하드웨어 키 없는 폰의 보안카드 사용자는 조회조차 못 한다(자기모순) |
| 슬롯별 KEK 지금 도입 | 악성 폰 앱 방어는 Phase 3. 지금은 범위 필터로 충분하다 |
| 텔레메트리 시간 단위 유지 | B-31이 폐지한 실행당 활동 기록이 되살아난다(개편 감지는 일 20건 기준으로 유지) |

## 결과

### 보안 영향

| 주체 | 닫는 것 |
|---|---|
| T 계정 탈취자(이메일 장악) | 게이트웨이 예산 소진·PII 트립와이어 유발로 계정 정지·캐시 오염(기기 토큰), PASS만으로 백업 열람(불가) |
| I 운영자·서버 침해 | 에스크로 열쇠로 백업 열람(사본 없음), 레코드 시각·WAL로 발급 리듬 복원(시각 컬럼 금지·보존 상한) |
| J 외국 법역 강제 제출 | 위와 같음(제출할 것이 줄어든다) |
| P6 페어링 폰 버그·악성 앱 | 사람 확인 없이 저장 자격 로그인 시작(시작 게이트), 소프트웨어 키로 비가역 승인(증명 상태 집행) |
| L 분실 폰·가족·직원 단말 | 개인 프로필 서류 열람(doc_scope) |
| 키체인 사건(사용자 정리·프로필 이동) | 원장·쿨다운·중복 이력 무음 소실(fail-closed + 복구 선택지) |
| 신뢰(정직 고지) | 공개 표와 다른 텔레메트리·진위확인 전송 |

남는 것: 연결된 기기가 0대인 계정은 백업을 되찾을 수 없다(의도). iOS는 하드웨어 키 생성을 증명할 수 없다. 블롭 객체의 저장소 생성 시각은 남는다. 진위확인 기본 프록시는 사업자번호 평문을 지난다(D19 §8).

### UX 영향(사용자 화면 문장 그대로)

- 새 PC: 지금처럼 "연결된 폰에서 승인해 주세요" → 폰 생체 1회. 12단어 없음.
- 백업 켜기·PASS 복구 화면 한 줄: "백업한 서류는 연결된 폰이나 다른 PC가 있을 때만 되찾을 수 있어요. 폰 없이 PASS로는 계정만 되찾아요." 설정 > 기기 연결(옛 폰 연결)에 [복구용 기기 더하기].
- 폰 원격 실행: 폰에서 [실행]을 누르는 그 탭에 생체 확인이 붙는다(발급 승인 탭과 별도 화면 없음). 문구 "내 PC가 홈택스에 로그인해요 · 얼굴·지문으로 확인".
- 페어링 마지막 화면: "서류 열람 허용: [사업자 서류] [개인 서류]"(개인 프로필이 없으면 한 줄도 바뀌지 않는다). 기기 목록 배지 "하드웨어 키 확인됨".
- O-02 카드: "등록증 파일은 이 PC 안에서만 읽어요 · 사업자번호만 국세청 진위확인에 보내요(기본: 우리 서버 경유, 설정에서 내 키)", 배지 옆 "국세청 조회".
- 설정 진위확인 줄 설명: "기본은 우리 서버를 거쳐 국세청에 조회해요. 서버는 번호를 계정과 묶거나 기록하지 않아요."
- DB 키 유실 시(Phase 1, 지금은 '앱이 안 켜짐'): "이 PC의 자격 증명 관리자에서 앱 열쇠를 찾지 못했어요. 기록을 지키려고 앱을 열지 않았어요. [복원 방법 보기] [기록을 포기하고 새로 시작]" · 새로 시작 뒤 첫 발급 카드: "이전 발급 이력이 없어 중복 확인을 할 수 없어요."
- 게이트웨이·텔레메트리·서버 시각: 화면 변화 없음. 옵트인 고지 문구가 실제 전송과 같아진다.
