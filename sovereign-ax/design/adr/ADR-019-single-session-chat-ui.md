# ADR-019. 단일 메인 세션과 대화 중심 화면, PC·폰 공용 타임라인

> 상태: 채택(2026-10-30) · 결정 7(복구 문구 표시)은 ADR-020 결정 7과 ADR-029(복구 문구 없음)으로 폐기 · 결정 2(홈은 메인 대화)는 ADR-033(홈은 "이번 달 판")으로 대체(2026-11-05) · 관련: ADR-007, ADR-014, ADR-016, ADR-018, D01 §4, D08, D09, 02 §2·§3·§7·§8, 08

## 맥락

- Claude Design에 넘기기 전에 화면과 기능을 기획했다(08 문서). 범용 에이전트(Claude·Codex)처럼 대화 스레드를 여러 개 두는 구조와, 한 분야 전용 에이전트(레퍼런스 instinct.xyz)처럼 대화 하나에 작업 카드를 쌓는 구조를 비교했다.
- 기존 홈(02 §3, D01 §4)은 작업 버튼 격자에 대화창이 붙은 형태였다. 사용자는 PC에서도 채팅 중심, 온보딩도 채팅, 모바일은 채팅 메인을 요구했다.
- D01 §4는 "대화 내역은 로컬 DB에만"이고, 조회 에이전트(D09)는 세션이 없고 대화 본문을 저장하지 않는다. 폰에서 같은 대화를 보려면 원본 위치와 전달 경로를 정해야 한다.

## 결정

1. **대화 세션은 PC당 하나다.** 새 대화·스레드 목록을 만들지 않는다. 지난 작업은 명령 팔레트 검색, 문서함, 활동 기록으로 찾는다. 프로필 전환은 대화를 나누지 않고, 새 요청의 기본 프로필을 바꾸고 카드에 프로필 표시를 붙인다.
2. **(ADR-033으로 대체) 홈은 메인 대화다.** 왼쪽 레일(문서함·거래처·내 사업장·활동 기록·설정), 가운데 대화, 오른쪽 작업 패널의 3단이다. 자주 쓰는 작업은 입력창 위 빠른 실행 칩으로 둔다. 레일 화면의 실행 버튼은 요청을 메인 대화로 넘겨 모든 작업이 대화 한 곳에 기록되게 한다.
3. **온보딩은 메인 대화의 첫 부분이다.** 가입·첫 로그인·복구 문구를 뺀 단계(사업자 등록, 인증수단, 맡길 업무, 거래처, 보관 위치, 첫 작업)를 채팅으로 묻는다. 인증서 비밀번호·보안카드·복구 문구 같은 비밀은 대화에 들어오지 않는다. 금고 비밀 창이나 전용 전체 화면(08 A-03)에서만 다룬다.
4. **타임라인의 원본은 PC 로컬 DB다.** 폰은 PC가 켜져 있을 때 페어링된 E2E 채널(ADR-007)로 타임라인을 받아 보여 준다. 서버와 릴레이는 대화 본문을 저장하지 않는다. 폰의 타임라인 캐시는 ADR-016 모바일 저장 규칙(기기 전용, 인증 필요, 백업 제외)을 따른다.
5. **PC가 꺼져 있을 때의 조회는 폰이 보관했다가 합친다.** 폰과 조회 에이전트가 나눈 질문·답은 폰에 남기고 "서버 답변"으로 표시한다. PC와 다시 연결되면 E2E로 PC 타임라인의 같은 시각 자리에 합친다. 서버는 여전히 대화 본문을 저장하지 않는다(D09).
6. **대화 안의 보안 규칙은 그대로다.** 모델 출력은 구조화 슬롯과 sanitizer를 거치고(ADR-014 §3), 비가역 승인은 PC의 main 승인 창 또는 폰의 하드웨어 키로만 한다(ADR-014·016). PC 쪽은 2026-10-31부터 대화 열 하단 main 승인 바다(ADR-020·021).
7. **복구 문구는 첫 로그인 직후 보여 준다.** 화면 위치(08 A-03)만 정하며, AIK를 첫 설치 때 고정하는 ADR-016 결정은 바꾸지 않는다.

## 대안과 기각 이유

| 대안 | 기각 이유 |
|---|---|
| 대화 스레드 여러 개(범용 에이전트 방식) | 작업이 스레드마다 흩어져 진행·만료 상태를 한곳에서 볼 수 없다. 이 앱이 하는 일은 카탈로그(02 §10) 안의 플레이북이라 주제별 스레드가 필요 없다 |
| 작업 버튼 격자 홈 + 보조 대화창(기존 02 §3) | 온보딩·입력 보완·예외 안내가 화면마다 따로 생긴다. 사용자가 채팅 중심을 요구했다 |
| 폰은 별도의 짧은 대화 | 동기화는 단순하지만 어디서 시켰는지에 따라 기록이 갈려 "세션 하나" 원칙이 깨진다 |
| 대화를 서버에 E2EE로 저장해 동기화 | PC가 꺼져 있어도 전체 대화를 볼 수 있지만 서버 보관 데이터와 메타데이터(시각·크기)가 늘어난다. 필요가 확인되면 Phase 2 이후 다시 본다 |

## 결과

- 02 §2·§3·§7·§8, D01 §4를 고치고 08 문서를 새로 둔다.
- D08에 타임라인 전달·병합 메시지(범위, 커서, 중복 제거)를 정의해야 한다. 리모트 기능을 설계할 때(Phase 2) 추가하며, PC만 쓰는 PoC·Phase 1에는 영향이 없다. (2026-11-05, ADR-034: 폰 앱이 Phase 1에 들어왔지만 Phase 1 폰은 촬영·현금매출·승인만 맡는다는 제안이라 타임라인 전달은 여전히 Phase 2다.)
- 타임라인이 계속 길어지므로 로컬 DB에 대화 검색 색인이 필요하다(명령 팔레트).

## 조건

- 폰 타임라인 캐시의 보존 범위·용량은 D08 설계 때 정한다.
