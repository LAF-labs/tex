### 2.1 모델 호출별 Rule of Two 판정 (B-16)

A = 신뢰 불가 입력, B = 민감 데이터, C = 외부 행위·상태 변경. 한 호출에 둘 이상이 결합되면 "사람 확인 또는 결정적 검증 + 상태 보존 동작"만 허용한다.

| 호출 | A | B | C | 허용 조건 |
|---|---|---|---|---|
| L1 판정 번들(`screen_state_v2` 등) | 화면 텍스트 | 없음(금액 기본 치환) | 열거 분기만 | 임계값·`unknown`·게이트, 커밋 구간 밖 |
| `selector_repair` | 화면 텍스트 | 없음 | 셀렉터 제안 → 클릭 | `fill`·`select`·`wait`·`extract` 타깃만 자동 적용, `click`·`press`는 사용자 확인, `risk_flags` 비어 있을 때만 |
| `intent_fill` | 사용자 문장(A′) | 거래처 목록(토큰) | 확인 카드까지 | 카드가 C를 막음. 역치환은 레코드 ID로만 |
| 조회 에이전트(`query_parse` + 서버 결정적 조회) | 사용자 질문(폰 로컬 마스킹, E-09) | 없음(행은 모델에 가지 않음) | 없음 | `query_kind` 열거·열거형 파라미터만, 템플릿 응답만 |
| `doc_meta_check_v1` | PDF 텍스트 | 서류 본문 파생 | 만료일 확정 → 데몬 일정 | 규칙 추출 후보 중 선택만, 규칙표와 30일 넘게 차이 나면 사용자 확인 |
| `summarize` | 화면·PDF 텍스트 | 서류 본문 | 표시(C′) | 구조화 슬롯만 표시, 자유 문장은 "신뢰할 수 없음" 라벨 + 비밀·URL·전화 패턴 시 비표시 |
