## 2. STRIDE 표 (상위 위협)

| # | 위협 | 범주 | 통제 | 잔여 위험 |
|---|---|---|---|---|
| T1 | 악성 플레이북 패키지가 사용자 기기에서 임의 행위 | Tampering/Elevation | 선언적 IR(코드 아님), Ed25519 서명·핀 고정, 정적 검증 V-01~13, 도메인 허용 목록, 게이트 강제, 타이피스트의 `secretSlot` 검사 | 서명 키 유출 → 2인 승인·HSM·로테이션 |
| T2 | 엔진 프로세스 침해로 비밀 탈취 | Information Disclosure | 비밀은 금고만, 타이피스트, 폰 비밀은 금고 키 이중 봉인 | 같은 OS 사용자의 악성코드가 금고 프로세스 메모리 읽기 → OS 보안에 의존, 생체 게이트 옵션 |
| T3 | 모델 공급사로 식별자 유출 | Information Disclosure | 마스킹 브랜드 타입 강제, egress 단일 모듈, 스크린샷 기본 비전송, 코퍼스 회귀 | 신종 식별자 패턴 미탐 → 사전 확장, 보수적 치환 |
| T4 | 프롬프트 인젝션(포털 화면 텍스트, H-02 조회 화면의 거래처 입력 텍스트 등 제3자 텍스트)으로 모델이 유해 행위 | Tampering | **Rule of Two**(신뢰 불가 입력·민감 데이터·외부 행위 중 한 호출에 두 개 이상 결합 금지) + Action-Selector 패턴(모델은 열거형 선택·제안만). 비가역 도구 없음, `page_text_addresses_agent` 사전 필터, 화면 텍스트=데이터 지시 | 판정 오염으로 잘못된 분기 → 임계값·`unknown`·게이트 |
| T5 | 릴레이 운영자·네트워크 도청 | Information Disclosure | Noise E2E, 푸시 내용 없음 | 메타데이터(시각·크기) 노출 → 패딩 고려(Phase 3) |
| T6 | 가짜 폰(페어링 피싱) | Spoofing | QR은 데스크톱만 생성, 지문 확인, 데스크톱 측 승인, 기기 해제 | 사용자가 지문 확인을 건너뜀 → UI 강제 단계 |
| T7 | 재전송(승인·명령) | Tampering | 메시지 id 캐시, nonce, 게이트 토큰 바인딩·만료 | — |
| T8 | 서버 침해 | Information Disclosure | 서버에 비밀·본문 없음, 메타데이터 최소, dedup HMAC | 이메일·메타데이터 유출 → 통지 절차 |
| T9 | 사용자 PC의 다른 사용자/악성코드가 보관함 PDF 열람 | Information Disclosure | 사용자 권한 폴더, OS 디스크 암호화 안내, 옵션 폴더 암호화(Phase 3) | 사용자 선택 |
| T10 | 감사 로그 변조로 책임 회피·분쟁 | Repudiation | 해시 체인, 내보내기 서명(기기 키) | 로컬 전체 삭제 → 서버 측 실행 카운트(메타)와 대조 |
| T11 | 비용 폭주(모델 남용) | DoS | 실행당·월 예산, 게이트웨이 화이트리스트·서버 정의 번들, 분당 한도 | — |
| T12 | 포털 차단·계정 제한 유발 | DoS(사용자 피해) | 사람 속도 정책, 상한, 차단 신호 즉시 중단, 쿨다운, 공문 | 포털 정책 변경 → 공문 채널 |
| T13 | 업데이트 공급망 공격 | Tampering | 코드서명, 공증, 레지스트리 서명+freshness, SBOM, 의존성 고정·검증 | — |
| T14 | 세무대리로 오인될 기능 추가(규제) | Compliance | 기능 게이트: 세액 계산·신고서 작성 코드 경로 없음, 대화 `mentions_tax_advice` 거절, 프로필 2개 상한 | 사용자가 도구를 대행에 악용 → 약관·탐지 |

## 4. Electron 하드닝 체크리스트

- `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, 프리로드는 최소 API.
- CSP: `default-src 'self'; connect-src 'none'; img-src 'self' data:`(렌더러는 네트워크 없음).
- 원격 콘텐츠 로드 금지, `webview` 비활성, `shell.openExternal` 허용 목록.
- 엔진·금고는 `utilityProcess`, 금고는 추가로 네트워크 차단(코드 레벨 + 샌드박스 프로파일 검토).
- 자동 업데이트: `electron-updater` ≥ 6.3.0-alpha.6(CVE-2024-39698), 서명 검증 필수, 다운그레이드 금지, 단계적 롤아웃. Windows 서명은 Artifact Signing 검토(EV가 SmartScreen을 우회하지 않음), 서명 주체 DN은 출시 전 고정(변경 시 브리지 릴리스 필요). macOS Developer ID + 공증. Electron fuses로 `runAsNode`·`nodeOptions` 등 비활성.
- 크래시 리포트: 금고 제외, 나머지는 비밀 없음 확인 후 옵트인.
- 의존성: lockfile 고정, 서명/프로비넌스 검증, 월 1회 감사.
- 로그: 비밀 타입 포맷터, 레벨별 보존, 사용자 내보내기 시 마스킹.

## 5. 보안 테스트 (D13와 연결)

- 비밀 누출 스캐너: 테스트 비밀 패턴을 심고 로그·텔레메트리·크래시 덤프·IPC 캡처에서 검색(0건 기준).
- 마스킹 코퍼스 회귀.
- IR 검증기 퍼징(무작위 IR로 V-03 우회 시도).
- 게이트 우회 테스트: 토큰 위조·만료·다른 실행 토큰.
- 리모트 프로토콜 테스트: 재전송, 잘못된 키, 저수준 명령 주입.
- 외부 점검: 출시 전 1회 모의해킹(데스크톱 + 클라우드 + 모바일).

## 7. 사고 대응

- 서버 침해: 정보통신망법 제48조의3·시행령 제40조에 따른 신고(인지 후 24시간 내 1차, 72시간 내 상세), 메타데이터·이메일 범위 이용자 통지, 토큰 전면 무효화, 기기 재인증.
- 서명 키 유출 의심: 레지스트리 인덱스 즉시 동결, 앱 업데이트로 새 공개키 배포, 기존 패키지 해시 재검증 목록 게시.
- 포털 차단 다발: 운영 정책 긴급 보수화(서명 배포), 사용자 공지, 운영기관 연락.
