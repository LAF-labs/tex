# D10. 서류 데몬

## 1. 책임

만료 추적, 알림, 사용자가 등록한 서류의 주기적 재발급을 **사용자 동의 수준에 맞게** 수행한다. 새 종류의 작업을 만들지 않는다.

## 2. 동의 수준

| 모드 | 조건 | 동작 | 플랜 |
|---|---|---|---|
| `notify` | 기본 | D-7, D-1 알림(데스크톱·폰). 사용자가 "지금 갱신" 탭 → 일반 실행 | 스타터 |
| `semi_auto` | 사용자가 서류별 동의 | 예정 시각에 폰·데스크톱으로 "갱신 시작할까요" 게이트 → 승인 시 실행. 간편인증 PUSH는 사용자가 홈택스/정부24 앱에서 승인 | 비즈니스 |
| `auto` | 서류별 동의 + 프로필에 공동인증서·저장된 비밀번호 + 법률 의견 플래그(`policy.autoDaemonAllowed=true`) | 예정 시각에 무인 실행. 게이트는 사전 승인 규칙(`consent_json.preapproved=true`)으로 통과하되, 비가역 스텝은 여전히 **발급(조회성) 스텝에 한정** | 비즈니스 |

`auto` 모드에서도 `send_email`·결제·수정 발급 같은 외부 효과가 있는 스텝은 금지(V-14: 데몬 프로파일 플레이북은 `send_email` 불가). 데몬이 하는 비가역은 "서류 한 장 더 발급"뿐이다.

## 3. 스케줄러

- `main` 프로세스, SQLite `schedules` 기반. 1분 틱, 조건 확인 후 엔진에 `trigger: 'daemon'`으로 실행 요청.
- 실행 조건: 실행 창 안(요일·시간대), PC 유휴(사용자 입력 없음 5분 이상) 또는 사용자 허용, 네트워크 OK, 쿨다운 아님, 포털별 동시 실행 없음, 일일 상한 여유.
- 시각 지터 ±30분. 같은 날 여러 서류는 순차 + 간격 5~15분 무작위.
- 실패: 1회 재시도(다음 틱, 30분 후), 그래도 실패 → `notify`로 강등 + 사용자 알림 + 원인 코드.
- PC 꺼짐으로 놓침: 다음 기동 시 "놓친 갱신 N건" 카드 → 사용자가 실행 선택. 자동 모드라도 기동 직후 자동 실행은 하지 않는다(사용자가 막 켠 PC에서 브라우저가 튀어나오는 경험 방지, 10분 유예).

## 4. 만료 계산

- `documents.expires_at` 우선(문서 추출값). 없으면 `validity_rules`.
- `next_due_at = expires_at - lead_days`(기본 7, 사용자 조정). 제출 예정일 입력 시 그 날짜 기준.
- 중소기업확인서처럼 회계연도 규칙은 `fiscal_year_rule` 평가기: 직전 사업연도 말일 + 3개월 + 1년 − lead.

## 5. UX 원칙

- 데몬 실행 중에는 트레이 아이콘 상태 + "지금 자동 갱신 중: 지방세 납세증명(중단 가능)" 토스트.
- 브라우저 창은 최소화 상태로 시작하되 사용자가 언제든 볼 수 있다. 숨김 창·가상 데스크톱 트릭은 쓰지 않는다.
- 실행 결과는 알림 1회 + 감사 로그.

## 6. 안전장치

- 데몬 실행은 `policy.pace.daemon`(더 느림) 적용.
- 캡차·추가 인증이 뜨면 `semi_auto`와 동일하게 사람에게 넘긴다(폰). 90초 무응답 → 보류.
- 같은 서류를 30일 내 3회 이상 자동 재발급 시도하면 자동 모드 해제 + 알림(루프 방지).
