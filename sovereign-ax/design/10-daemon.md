# D10. 서류 데몬

## 1. 책임

만료 추적, 알림, 사용자가 등록한 서류의 주기적 재발급을 **사용자 동의 수준에 맞게** 수행한다. 새 종류의 작업을 만들지 않는다.

## 2. 동의 수준

| 모드 | 조건 | 동작 | 플랜 | 출시 |
|---|---|---|---|---|
| `notify` | 기본 | D-7, D-1 알림(데스크톱·폰). 사용자가 "지금 갱신" 탭 → 일반 실행 | 스타터 | Phase 1 |
| `semi_auto` | 사용자가 서류별 동의 | 예정 시각에 폰·데스크톱으로 "갱신 시작할까요" **시작 동의**(토큰 아님) → 실행 → 로그인(간편인증 PUSH는 사용자가 승인) → 비가역 직전 **커밋 게이트**(건별 토큰, 폰 승인 한 번) | 비즈니스 | Phase 2 |
| `auto` | 서류별 동의 + `StandingAuthorization` + 법률 의견 플래그(`policy.autoDaemonAllowed`) + 사람 없이 끝나는 로그인 경로 존재 | 예정 시각에 무인 실행. 엔진이 `StandingAuthorization{scheduleId, playbookId@major, docType, profileId, maxPerPeriod, expiresAt, userSignature}`에서 **건별 단일 사용 토큰**을 만든다 | 비즈니스 | **보류** |

`auto`를 보류하는 이유: 홈택스 공동인증서 경로는 가상키패드(사용자 직접 입력), 간편인증은 폰 승인이 필요해 **사람 없이 로그인이 끝나지 않는다**(D05 §4). 정부24는 허락 전 후처리 모드다. 사람 없이 끝나는 로그인 경로가 생기고 법률 의견이 나오면 운영 정책으로 켠다. 그때도 허용 효과는 `issue_document`뿐이며(V-14), `send`·`pay`·`sign`이 있는 플레이북은 데몬이 실행하지 않는다.

## 3. 스케줄러

- `main` 프로세스, SQLite `schedules` 기반. 1분 틱, 조건 확인 후 엔진에 `trigger: 'daemon'`으로 실행 요청.
- 실행 조건: 실행 창 안(요일·시간대), PC 유휴(사용자 입력 없음 5분 이상) 또는 사용자 허용, 네트워크 OK, 쿨다운 아님, 포털별 동시 실행 없음, 일일 상한 여유.
- 시각 지터·간격·유예·재시도 상수는 서명된 `policy.daemon`에서 온다(±30분, 5~15분, 10분, 30분).
- 실패: 직전 실행에 `in_doubt` 원장이 있으면 재시도하지 않고 `notify`로 강등. 그 외 1회 재시도(`policy.daemon.retryAfterMin`), 그래도 실패 → `notify` 강등 + 알림 + 원인 코드.
- PC 꺼짐으로 놓침: 다음 기동 시 "놓친 갱신 N건" 카드 → 사용자가 실행 선택. 자동 모드라도 기동 직후 자동 실행은 하지 않는다(사용자가 막 켠 PC에서 브라우저가 튀어나오는 경험 방지, 10분 유예).

## 4. 만료 계산

- `documents.expires_at` 우선(문서 추출값). 없으면 `validity_rules`.
- `next_due_at = expires_at - lead_days`(기본 7, 사용자 조정). 제출 예정일 입력 시 그 날짜 기준.
- 중소기업확인서처럼 회계연도 규칙은 `fiscal_year_rule` 평가기: 직전 사업연도 말일 + 3개월 + 1년 − lead.

## 5. UX 원칙

- 데몬 실행 중에는 트레이 아이콘 상태 + "지금 자동 갱신 중: 지방세 납세증명(중단 가능)" 토스트.
- 브라우저 창은 최소화 상태로 시작하되 사용자가 언제든 볼 수 있다. 숨김 창·가상 데스크톱 트릭은 쓰지 않는다.
- 실행 결과는 알림 1회 + 감사 로그.

## 6. 안전장치

- 데몬 실행은 `policy.pace.daemon`(더 느림) 적용.
- 캡차·추가 인증이 뜨면 `semi_auto`와 동일하게 사람에게 넘긴다(폰). 90초 무응답 → 보류.
- 같은 서류를 30일 내 3회 이상 자동 재발급 시도하면 자동 모드 해제 + 알림(루프 방지).
