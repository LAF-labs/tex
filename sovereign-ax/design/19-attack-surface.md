## 0. 왜 했는가

공공 AX와 소버린 데이터를 내세우는 제품은 "비밀은 기기 밖으로 안 나간다", "승인 없는 비가역 실행은 없다", "서버는 내용을 모른다"는 세 약속이 **정상 경로에서도, 공격 경로에서도** 지켜져야 한다. 설계 v1.2는 세 약속을 선언했지만, 세 영역을 나눠 전수 감사한 결과 정상 경로에서 약속이 깨지는 지점(예: 로그인 요청 바디로 비밀이 엔진 힙에 들어옴, 핫픽스 한 장으로 게이트 없는 발급 가능, 조회 에이전트가 메타데이터 행을 국외 모델에 전송)이 있었다. 코드 착수 전에 문서·스키마 수준에서 메운다.

### 1.1 가장 중요한 결정 12개

1. **핫픽스 범위 축소 + 액추에이션 시 동일성 검사**(B-01, Critical → ADR-012). 핫픽스는 비커밋·비비밀·비readback 항목의 `candidates`만 바꾸고, 랜드마크·조건식·W 안에서 참조되는 항목은 바꾸지 못한다(E-03). 클릭·입력마다 실제 접근성 이름을 사전과 대조하고(R-A1), 비커밋 항목이 커밋 항목과 같은 요소면 거부한다(R-A2). 핫픽스 적용 후 검증기 재실행.
2. **금고 중계를 기본 거부 허용 목록으로**(A-01) + **응답 정리**(A-02·A-04: 요청 바디·접근성 값·스크린샷) + **비밀 창**(A-06: 타이피스트·사용자 직접 입력·폰 봉인 비밀 공통) → ADR-005 v3. 정상 경로에서 비밀이 엔진에 닿는 길을 닫는다.
3. **운영 정책 앱 내장 상한**(B-23 → ADR-012). 정부24 `auto`·캡차 중계는 서명된 정책으로도 켤 수 없다. 포털 키가 없으면 `postprocess`.
4. **readback 범위를 폼 전체로, 공급자 사업자번호 assert**(B-05). 홈택스 자동 발송 이메일·공급자·비고·청구/영수가 카드에 들어간다. `supplierBizNo == $profile.bizNo`는 잘못된 명의 발급과 대리 사용을 함께 막는다.
5. **verify 의미 재정의**(B-07·B-08): 게이트 직전 기준선 대비 "새로 생긴 1건"만 `committed`, `not_committed`는 부재 증거 요건, 조회 하위 플레이북은 다이제스트 결속·모델 금지·새 탭.
6. **레지스트리 2-of-3 임계 서명 + 투명성 로그 + 키 세대·폐기 채널 + 48시간 status 채널 + 정책 신선도 72시간(타임스탬프 키 자동 재서명, 만료 후 7일 유예, E-05)**(B-22·C-26·C-27 → ADR-013). 서명 키는 클라우드 KMS가 아니라 국내 자체 HSM/스마트카드.
7. **계정 신뢰 앵커 = AIK**(C-01·C-02·C-03 → ADR-016): 기기 목록은 AIK 서명, 계정 AIK 1회 고정, 즉시 삭제·블롭·메타데이터·조회 에이전트는 AIK 인증 기기 토큰만. 디바이스 플로우 삭제, 매직링크 대신 코드.
8. **원격 비가역 승인은 하드웨어 키만**(C-06 → ADR-016): SE/StrongBox P-256, 일일 상한 5건, 처음 쓰는 거래처는 PC 로컬 승인, 계정 웹 긴급 정지.
9. **서버 메타데이터 최소화**(C-09·C-10·C-12·C-13 → ADR-006 개정): `bytes`·초 단위 시각·dedup 토큰 삭제, 월 단위 발급일, 종류별 서버 색인(기본 켬 4종), 레코드는 `Vd` 서명. 조회 에이전트는 **질문만** 모델로 보내고 행은 절대 보내지 않는다.
10. **docparse를 Chromium 렌더러 샌드박스로, 로컬 비가역 승인은 main이 그린 화면의 실제 클릭으로**(A-14·A-15 → ADR-014). 승인 창은 ADR-020으로 폐지했고, 지금 근거는 대화 열 하단(입력창 위)의 main 소유 승인 바다(ADR-021).
11. **프롬프트 인젝션 방어를 결정적으로**(B-15·B-16): 화면 밖 텍스트 제거·구분자, 결정적 사전 필터, Terra 출력은 구조화 슬롯만, 대화창 비밀 DLP, `doc_meta_check`는 후보 선택형, click 수리는 사용자 확인.
12. **소버린 전환은 공급사 중립 설계 + 조달 트리거**(ADR-015): 모델은 OpenAI 유지하되 `decide()`를 System One 호환으로 일반화하고 Upstage Decide를 S7에서 병행 평가, 로컬 판정은 규칙 L0 확대 뒤 Phase 3 재검토.

## 8. 정직하게 남는 것 (잔여 위험)

- 같은 OS 사용자 악성코드(M)와 관리자(A)에 대해서는 경계가 없다. 기기 결박 열쇠는 다른 기기에서의 복호를 막고 금고 잠금은 자리를 비운 PC를 막을 뿐이며, 금고가 열린 동안 같은 계정의 악성코드는 막지 못한다. 엄격 모드(발급마다 Hello)도 프롬프트 뒤의 메모리 읽기까지는 막지 못한다. 비밀은 결국 사용자 권한 Chrome에 입력된다. 관리자 권한 고지: "PC 관리자 권한을 가진 프로그램은 앱이 막을 수 없어요." 사용자 고지: "같은 Windows 계정에서 도는 악성 프로그램까지 막지는 못해요. 더 안전하게 쓰려면 '발급마다 Windows Hello 확인'을 켜세요."(D-01(N-07), ADR-026)
- TPM 없는 PC의 저장 자격은 DPAPI 수준이다. Windows 자격으로 다른 곳에서 복호될 수 있다. 고지: "이 PC에는 보안 칩(TPM)이 없어 Windows 로그인 계정으로만 잠가요. Windows가 열려 있는 동안 같은 계정의 프로그램이 열 수 있어요." S10c에서 원격 세션 전환 감지(WTS)·TPM 무UI 키가 불가로 나오면 "원격 데스크톱으로 접속한 동안에도 금고가 열려 있을 수 있어요"를 더한다(ADR-026).
- 잠기지 않은 PC에서 유휴 잠금(15분) 전의 제3자(W)는 승인할 수 있다. 엄격 모드면 닫힌다. 고지: "자리를 비울 때는 Windows를 잠가 주세요(Win+L). 15분이 지나면 앱 금고도 스스로 잠겨요."(ADR-026)
- 엔진 침해 시 비밀 칸 값의 되읽기는 비밀 창이 닫힌 뒤에만 가능한 것이 아니다. 활성 창 동안에는 대상 프레임의 `Runtime`을 거부하지만, **오염 상태(활성 창 종료 후 다음 문서 커밋까지)에서 침해된 엔진은 `Runtime.evaluate`로 비밀 칸 값을 읽을 수 있다**(거부 목록 패턴 차단은 우회 가능). 이것이 D05 §1 범위 문구의 실체이며 Phase 2 원자적 타이핑(입력 → 제출 → 분리까지 활성 창 유지)이 이 창을 닫는다. 완전한 경계는 고수준 브로커(Phase 3 ADR)뿐이다. Phase 1 비밀 창이 줄이는 것은 입력·접근성·스냅샷·스크린샷·요청 바디 경로다(E-01).
- 커밋 요청 본문이 보안 모듈로 암호화되어 있으면(`opaque`) 금고도 본문을 대조할 수 없어 "화면 ≠ 제출 값"(P5)을 탐지할 수 없다(S1 결과에 따라 D11 T1·T4 갱신). 공동인증서 서명(`signFlow`의 `human:secret`) 구간에서 서명 대화상자가 같은 탭 안 요소라 입력 잠금을 대화상자 단위로 걸 수 없으면 그 구간에 폼 편집이 가능하고, 남는 방어는 금고의 본문 대조뿐이다(E-02, S15).
- 셀렉터 핫픽스는 서명·CI를 통과한 것만 로드되지만, 클라이언트는 녹화가 필요한 SV-01~03을 다시 돌리지 못한다. 서명된 핫픽스의 실수에 대해서는 이름·랜드마크 대조(R-A1)·커밋 충돌 검사(R-A2)와 네트워크 커밋 가드가 마지막 방어이며, 사전에 `commits:true`로 등록되지 않은 트리거는 이름 검사로 잡지 못한다(E-03).
- 로컬 승인 바(ADR-021)는 렌더러 침해 중 승인 위조를 막고 클릭 유도를 줄인다. 렌더러가 평소 같은 자리에 자기 버튼을 두어 클릭 습관을 들이는 것과, 브라우저 팝업(`<select>` 목록 등)이 바를 덮는 것(미확인, PoC-6)은 남는다. 카드 본문은 렌더러가 그리므로 표시 위조는 바의 요약 줄(3줄 이하)까지만 막는다. 렌더러가 입력 단계에서 바꾼 값은 요약 줄과 "처음 거래"·"처음 보내는 주소" 표시에 드러날 뿐 막지는 못하므로, 사용자가 바의 값을 봐야 한다. 렌더러가 게이트를 끝내고 다시 열면 무장 지연만 방어다. 원격·데몬 실행의 "자동으로 띄우지 않음"은 렌더러 요청에 기대므로 렌더러가 침해되면 사라진다. 같은 사용자 권한의 악성코드나 침해된 엔진이 보내는 합성 입력(`SendInput`)은 실제 입력과 구분되지 않는다. PC 앞에 있는 제3자도 승인할 수 있다(엄격 모드를 켜지 않은 경우 금고 유휴 잠금 전까지, 또는 Hello를 쓸 수 없는 순간의 1회 면제, E-06·ADR-026). 바를 덮는 브라우저 팝업과 습관 클릭은 Windows 실기기 사람 요인 시험(RETRO B-07) 전이다. 고지: "승인하기 전에 바에 적힌 상호·사업자번호·금액·이메일을 확인해 주세요."
- 원격 비가역 승인의 "하드웨어 키"는 Android에서는 키 증명 체인으로 검증하지만, iOS에서는 App Attest로 앱 무결성만 확인할 수 있어 변조 앱이 소프트웨어 키를 신고하면 구별하지 못한다(E-10).
- 새 폰은 **첫 페어링마다** 서버가 준 `AIK_pub` 외에 독립 앵커가 없다. 우리 내부자(서버)와 공격자 PC가 공모하고 사용자가 피싱에 응하면 그 폰은 공격자 PC와 페어링되며, `PAIR_OK` 대조로도 막지 못한다. 계정 키 투명성은 Phase 3 후보다(E-12).
- (잠정안, PASS 범위는 보류: ADR-029 결정 1) PASS로는 계정만 되찾는다. 연결된 기기가 0대이고 72시간·7일 안에 거부하지 못하면 공격자가 새 AIK를 등록할 수 있으나 백업 서류는 열지 못한다. 복구 문구는 없다(ADR-016 v2, ADR-029, D-16(N-09), E-11). 연결된 기기가 0대인 계정의 백업은 되찾을 수 없다(의도, 서버에 열쇠 사본이 없다). 고지: "백업한 서류는 연결된 폰이 있을 때만 되찾을 수 있어요. 폰 없이 PASS로는 계정만 되찾아요."
- 백업(메타데이터 동기화)을 켠 계정에서 서버는 **발급 활동 표시**(업무 키 HMAC·상태·일, 90일)와 게이트 직전 조회 시각을 안다. 이것은 계정별 발급 건수와 영업 리듬에 대한 계정 연결 기록이며 법적 제출 대상이다. 백업을 끈 계정은 기기 간 중복 경고가 없다(E-07).
- 블롭의 패딩 크기와 업로드 시각, 일 단위 만료일은 색인을 끈 서류의 발급 일자와 쪽수(등본의 세대원 수 등)를 근사할 수 있게 한다. Padmé 패딩은 크기 등급만 숨기며 쪽수 차이를 숨기지 못한다. 업로드 시각 로그는 7일만 보존한다(E-08).
- 아이덴포턴시 원장의 "중복 0건"은 한 PC 안의 엔진 버그에 대한 보장이다. 발급목록 반영 지연 중의 사용자 증언, 두 PC가 수 초 안에 동시에 통과하는 게이트, 전용 Chrome 밖의 수동 발급은 중복을 막지 못하고 경고만 한다(D03 §4.1, E-13). 고지(세 약속 3의 단서): "홈택스 반영이 늦거나 다른 PC·홈택스 화면에서 같은 건을 발급하면 앱은 경고만 할 수 있어요."
- 운영 정책 신선도는 72시간이며 타임스탬프 키가 자동 재서명한다. 레지스트리에 닿지 못하면 마지막 정책 유지·데몬 중지 상태가 되고 7일 뒤 전 포털 `postprocess`로 내려간다. 1인 긴급 키(또는 그 탈취자)는 완화는 못 하지만 status 하향으로 서비스 가용성을 떨어뜨릴 수 있다. 하향 status는 72시간 뒤 자동 만료되어 2-of-3 재확인이 없으면 이전 값으로 돌아간다(E-04·E-05).
- Phase 1의 split-view 탐지는 별도 호스트 미러 1곳과의 트리 헤드 비교뿐이다(포함 증명은 기록만). 레지스트리와 미러를 함께 장악하면 탐지하지 못하며, 투명성 로그·외부 증인 강제(Phase 2)가 사후 탐지 수단이다(E-14).
- 릴레이 운영자는 연결 시점·IP 상관으로 계정↔우편함을 이을 수 있다. Privacy Pass 계열은 Phase 3.
- 평문 메타데이터·계정·계량은 국내 저장이어도 법적 제출 대상이다. 주권은 "누구의 법이 미치는가"이지 "아무도 못 봄"이 아니다. "국내 처리" 표기는 모델 공급사의 하부 호스팅 법인까지 국내일 때만 의미가 있다. 국내 리전이라도 외국 법인 인프라 위라면 외국 법역의 제출 요구가 미친다(ADR-015 조건 (e), E-15).
- APNs/FCM·App Attest·Play Integrity·Microsoft(SmartScreen·Artifact Signing)·앱 스토어·코드서명·npm/GitHub·레지스트리 CDN·전용 Chrome의 Google 서비스 의존은 국내 이전 후에도 남는다(정본 목록 ADR-015 결정 6).
- 코드서명(Artifact Signing)은 Microsoft가 보관하는 외부 단일 키이고, 앱 릴리스 매니페스트(`latest.yml`) 키는 비운영자 1인이 하드웨어에 보관한다. 뿌리(핀 키·내장 허용 목록·상한)를 바꾸는 릴리스만 2-of-3이다. 고지: "앱 설치 파일 서명은 Microsoft 서비스를 쓰고, 업데이트 목록 서명 열쇠는 운영자가 아닌 1인이 하드웨어에 보관해요. 모든 업데이트는 공개 기록과 대조한 뒤 설치돼요."(D-02(N-10), ADR-028)
- 블롭 객체의 저장소 생성 시각은 객체가 있는 동안 남는다(객체 저장소 기본 메타데이터). 서버 DB 레코드에는 시각 컬럼을 두지 않고 백업·WAL은 30일만 보존한다. 고지: "서버에는 서류 내용 대신 암호문과 그 업로드 시각이 남아요(서류 종류는 알 수 없어요)."(D-52(N-83), ADR-029)
- 진위확인 기본 프록시는 조회 사업자번호 평문을 지난다(국세청 API 키를 사용자마다 받게 할 수 없다). 프록시는 계정과 묶지 않고 기록하지 않으며, 설정에서 자기 키로 바꿀 수 있다(D-51(N-81), ADR-029).
- 홈택스 차단·추가 인증·캡차 문구는 PoC-3 실측 전까지 비어 있다. 모르는 화면은 보수 모드·쿨다운으로 막지만 "차단을 봤다"는 보고는 할 수 없다. PoC-3 보고서에 "차단 0건 = 탐지 사전 미완성 기간 포함"을 적는다(D-06(N-03), ADR-025).
- iOS 폰은 하드웨어 키 생성을 증명할 수 없다(App Attest는 앱 무결성만). 기기 목록 배지는 "앱 무결성만 확인됨(iPhone)"이다(D-36(N-55), E-10).
- 로컬 판정 모델은 한국어·Windows CPU 검증이 없다. "egress 0"은 L2까지 로컬화해야 성립한다.
