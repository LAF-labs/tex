# D09. 클라우드 서비스

## 1. 서비스 목록과 원칙

| 서비스 | 무상태 | 저장 | 외부 의존 |
|---|---|---|---|
| Accounts & Billing API | 아니오 | PostgreSQL | PG(결제), 이메일 발송 |
| Model Gateway | 예 | 계량 레코드만 | OpenAI |
| Relay | 예(큐는 디스크) | 암호문 큐 | APNs/FCM |
| Blob Store API | 예 | S3 호환 | — |
| Metadata Index API | 아니오 | PostgreSQL | — |
| Playbook Registry | 예 | 정적 저장소 + 서명 키(HSM/KMS) | — |
| Query Agent | 예 | 없음 | Gateway |

원칙: 비밀 0, 본문 0, 메타데이터 최소. 모든 서비스는 "침해되면 무엇이 새는가"를 README에 한 줄로 적는다(투명성 페이지에 그대로 노출).

## 2. 계정 모델

```text
account(id, email, status, plan, created_at)
  ├─ subscription(plan: starter|business, period, renew_at, pg_customer_ref)
  ├─ profile_slots: 1..2  (slot 1: personal, slot 2: business — 서버는 번호만, 종류는 클라이언트 설정)
  ├─ devices(desktop: 1~2, mobile: 1~3) — 공개키 등록, 해제 가능
  ├─ usage(month, l1_tokens, l2_in, l2_out, cost)
  └─ consents(version, at)
```
- 프로필 슬롯 상한 2는 서버가 강제한다(슬롯 등록 API가 3번째를 거부). 기기당 로컬 DB에도 `ux_profiles_kind`로 이중 강제.
- 인증: 이메일 매직링크 또는 패스키. 데스크톱은 OAuth 디바이스 플로우로 토큰 수령 → 금고 보관. 토큰은 기기 바인딩(디바이스 공개키 서명 챌린지).
- 계정 삭제·대량 삭제: 즉시 삭제가 아니라 **7일 유예**(기간 중 복구 가능, 기기 서명이 있는 삭제 요청만 유예 없이 즉시). 계정 탈취 시 백업이 한 번에 사라지는 것을 막는다. 유예 후 메타데이터·블롭 삭제, 계량 레코드는 익명화 후 회계 보존 기간만 보관.
- 디바이스 플로우는 피싱에 취약하므로 승인 화면에 기기명·위치·코드를 보여주고, 새 기기 등록은 기존 기기 또는 이메일 2차 확인을 요구한다.

## 3. 모델 게이트웨이 통제 명세

| 통제 | 구현 |
|---|---|
| 본문 무저장 | 요청·응답 바디를 디스크·로그·APM에 쓰지 않는다. 접근 로그는 경로·상태코드·바이트 수·지연·계정 ID 해시만. 스트리밍 프록시로 메모리 체류 최소화. **검증 수단**: 오류 경로 포함 로그 스키마 고정(본문 필드 없음), 로그 싱크에 식별자 패턴 탐지기, 분기 1회 외부 점검, 배포 산출물 해시 공개 |
| 파라미터 화이트리스트 | `/v1/decide`: `bundleId, bundleDigest, input, cacheKey, runId`(다이제스트 불일치 409). `/v1/respond`: `toolset, messages, effort, max_output_tokens, replay[]`(replay는 이전 `response.output`·`function_call_output` 항목만, 도구 정의·developer 메시지 불가). 그 외 필드·중첩 필드 거부(400) |
| 번들·툴셋 서버 정의 | 질문·도구 정의는 게이트웨이가 번들/툴셋 ID로 주입. 클라이언트가 임의 질문·도구를 보낼 수 없음 → 프롬프트 변조·비용 폭주 방지 |
| 계량 | `usage` 필드만 저장: 토큰 수, 캐시 적중 수, 모델, 번들/툴셋 ID, 플레이북 ID, 지연, 비용. 이것은 **호출 단위 활동 기록**이므로 처리방침에 항목·보존(13개월)·목적을 명시하고, 90일 뒤에는 플레이북 ID·시각을 일 단위로 집계해 원본을 지운다 |
| 한도 | 계정 월 토큰 한도, 분당 요청 한도(L1 60/min, L2 10/min), 실행당 예산은 게이트웨이가 서명한 `runToken`으로 서버가 집행. L1 하드 상한(플랜 2배) 이후 안전 판정 번들만. 거절·위반 급증 계정 자동 정지 |
| 공급사 설정 | `safety_identifier` = HMAC(서버 비밀, 계정 ID) 앞 32자, `prompt_cache_key` = `pb:<playbookId>:v<major>:shard<n>`(계정 접두 없음, D04 §2.1), `store:false`, ZDR 승인 시 전 계정 공통 |
| 장애 | 공급사 5xx·429 → 지수 백오프 2회 → 클라이언트에 `unavailable` → 엔진은 L0만으로 진행 가능하면 진행, 아니면 핸드오프 |
| 키 관리 | 공급사 API 키는 KMS, 로테이션 90일, 게이트웨이 외 서비스는 접근 불가 |

## 4. 릴레이

- WSS 우편함(D08 §8): 릴레이는 **내용을 볼 수 없다**(키 없음). 우편함 = 32B 무작위 ID + **기기 범위** 능력 토큰(서버는 토큰 해시만 저장, 기기 폐기 시 재발급). 기기 인증 토큰은 남용 방지용 별도 레이어이며 우편함 ID와 조인되지 않게 분리 저장하되, 운영자가 두 저장소를 합치면 연관을 알 수 있으므로 '영지식'이라고 부르지 않는다. 페어링 룸(1회용, 120초)과 영구 우편함의 연관은 기록하지 않는다.
- 큐: 우편함당 50건·10MB·72시간. 디스크 암호문(이미 E2E 암호문이지만 저장소 레벨 암호화 추가). 길이 패딩 버킷.
- 푸시: 내용 없는 깨우기 + fetch. iOS 알림 푸시(+Notification Service Extension), Android FCM data. 토큰 → 기기 매핑만, 우편함 ID 미포함.
- 남용 방지: 룸당 초당 메시지 20, 기기당 룸 3. 크기 상한 1MB(파일은 청크).
- 메타데이터 최소화: 접속 IP는 30일 후 삭제, 메시지 크기·시각은 7일.

### 4.1 사업자등록 진위확인 프록시

공공데이터포털 국세청 사업자등록정보 API(`api.odcloud.kr/api/nts-businessman/v1/status`, `/validate`)는 서비스 키가 필요하다(키 없이 401). 포털 표기 한도는 1회 100건·일 100만 건이나 서드파티 안내는 일 1만 건으로 불일치한다. 선택지: (a) 우리 게이트웨이가 우리 키로 프록시 — 거래처 사업자번호(공개 정보)가 서버를 **통과**하되 저장·로그하지 않는다, (b) 사용자가 자기 키를 발급받아 금고에 저장(BYO 키). 기본 (a), 설정에서 (b). 프록시는 요청당 사업자번호 ≤ 10, 계정당 분당 30회.

## 5. 블롭 저장소 API

| API | 설명 |
|---|---|
| `POST /v1/blobs` | 멀티파트 암호문 업로드, 응답 `blob_id`. 서버는 크기·계정만 기록 |
| `GET /v1/blobs/{id}` | 계정 소유 확인 후 반환 |
| `DELETE /v1/blobs/{id}` | 즉시 삭제 + 메타데이터 참조 제거 |
| 용량 | 플랜별(2GB/10GB). 초과 시 업로드 거부, 로컬 보관은 계속 |

## 6. 메타데이터 인덱스 API

- `PUT /v1/docs/{doc_id}`: D07 §5 스키마 필드만 허용. 추가 필드 400.
- `GET /v1/docs?profile_slot&doc_type&expires_before`.
- 서버는 `doc_type` 사전(열거형)만 받는다. 자유 텍스트 필드 없음.
- 동기화: 클라이언트가 소스 오브 트루스. 충돌은 `client_updated_at` 최신 우선.

## 7. 조회 에이전트 (PC 꺼짐)

- 입력: 사용자 질문(모바일에서 마스킹 후 전송) + 해당 계정의 메타데이터 행들(서버가 조회해 Terra 프롬프트에 포함).
- 모델은 자유 서술하지 않는다. Decisions `intent_route_v1`(+`query_kind` choice: {has_doc, expiry, count_by_type, latest_issued, needs_body, unknown})로 **허용 질의 열거형**으로 변환 → 서버가 메타데이터를 결정적으로 조회 → 템플릿 응답. Terra `query_agent` 툴셋은 열거형으로 표현되지 않는 질문의 재구성에만 쓰고, 최종 응답도 템플릿 슬롯 채우기다. 본문이 필요하면 "폰에서 열어 보기" 안내 + 선택적으로 폰이 복호화·마스킹한 요약 요청.
- 저장: 대화 로그 본문 비저장. 질문 유형·토큰만 계량.
- 할 수 없는 것: 발급 실행, 본문 열람, 메타데이터 밖 필드 추론.

## 8. 플레이북 레지스트리

- 정적 호스팅(`/registry/{channel}/index.json`, `/packages/{id}@{ver}.sxp`, `/policy/{ver}.json`).
- 서명: Ed25519. **플레이북 서명키와 운영 정책 서명키를 분리**해 각각 핀 고정. 키는 KMS/HSM, 서명은 CI에서 사람 승인(2인) 후. 키 로테이션은 앱 업데이트로. 서명은 **로드할 때마다** 다시 검증한다(`signature_ok` 플래그를 믿지 않음).
- 인덱스는 **단조 증가 `version`** + 만료(`expires` ≤ 14일)를 가진다. 클라이언트는 본 최고 버전을 저장해 더 낮은 인덱스·패키지·정책을 거부한다(롤백 방어). 패키지·정책·핫픽스마다 최저 버전을 둔다. 인덱스가 만료되면 **가장 보수적인 정책**(모든 포털 `postprocess`)으로 돌아간다(동결 공격 시 약관 위반 상태로 동작하지 않게).
- 서명키 유출 피해 반경: 엔진의 포털 eTLD+1 내장 허용 목록과 금고의 비밀 종류별 origin 허용 목록은 패키지가 바꿀 수 없다(앱 업데이트로만).
- 채널: `stable`, `beta`, `hotfix`. 단계적 롤아웃(1% → 10% → 100%) 비율은 인덱스에 명시, 클라이언트가 기기 ID 해시로 자기 비율을 결정.
- 변경 로그는 사용자에게 보임(`strings.ko.json.changelog`).

## 9. 가용성·운영

- 게이트웨이 장애 시 영향: L1/L2 불가 → 플레이북은 L0만으로 가능한 범위까지 진행, 판정이 필요한 지점에서 핸드오프. 발급 자체는 가능(사람이 화면 보며).
- 릴레이 장애 시: 리모트 불가, 로컬 사용 무영향.
- 블롭·메타데이터 장애 시: 백업 보류, 로컬 무영향. 조회 에이전트 불가.
- 모든 서비스 SLO: 가용성 99.5%, 게이트웨이 p95 지연(공급사 제외) 50ms.
