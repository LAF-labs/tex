# D00. 개발 설계 개요

> 상태: 설계 v1.3 (검수 A·B·C + 공격표면 감사 AUDIT-A·B·C 반영, [D19](19-attack-surface.md)) · 기준 기획: v1.2 (`../README.md`) · 작성일 2026-10-28

## 1. 이 설계서의 목적과 범위

기획서 v1.0이 "무엇을, 왜"를 정했다면, 이 설계서는 "어떻게"를 코드 작성 직전 수준까지 정한다. 코드는 아직 쓰지 않는다. 여기 있는 것은 명세(인터페이스·스키마·상태 머신·프로토콜·정책 상수)와 결정 기록(ADR)이다. 구현자는 이 문서만 보고 모듈을 나눠 착수할 수 있어야 하고, 검수자는 이 문서만 보고 보안·운영·규제 위반을 잡아낼 수 있어야 한다.

범위 안: 로컬 하네스(데스크톱), 모바일 앱, 클라우드(계정·게이트웨이·릴레이·블롭·메타데이터·플레이북 배포), 플레이북 IR, 모델 계층, 보안 설계, 테스트 전략.
범위 밖: UI 비주얼 디자인, 마케팅 사이트, 결제 PG 연동 상세, 법률 의견서 본문.

## 3. 설계 원칙 (기획 6원칙의 구현 번역)

| 기획 원칙 | 설계에서 강제하는 방법 |
|---|---|
| 플레이북 우선, 모델은 예외용 | 플레이북은 **선언적 IR**로만 배포되고 엔진이 해석한다. 플레이북 실행 중 모델 호출은 `decide`·`recover` 두 스텝 타입에서만 가능하고(커밋 구간 안에서는 금지), 실행 밖 호출(대화 의도·인자 채우기·조회·서류 메타 확인)은 D04 §3·§4의 목록으로 닫혀 있다. 모두 엔진이 입력을 만들고 출력 범위를 열거형·구조화 슬롯으로 제한한다 |
| 비밀값은 기기 밖으로 안 나감 | 비밀은 **금고 프로세스**만 평문으로 다룬다. 금고가 Chrome 파이프를 소유하고 엔진은 **기본 거부 허용 목록** 중계 CDP만 쓰며, 중계가 요청 바디·접근성 값·스크린샷에서 비밀을 정리한다. 비밀이 화면에 입력되는 모든 구간(타이피스트·사용자 직접 입력·폰 봉인 비밀)은 **비밀 창**으로 보호된다(ADR-005 v3). 이는 정상 경로에서 평문이 엔진에 닿지 않게 하는 장치이며, 엔진 RCE·같은 OS 사용자 악성코드에 대한 경계는 아니다(D11 T2) |
| 업무 데이터 최소 노출 | 네트워크 송신은 **단일 모듈**(`net/egress`)만 할 수 있고, 모델 송신 경로는 반드시 `redaction` 모듈을 거친다. 빌드 타임 린트로 우회 import를 금지한다 |
| 최종 실행 버튼은 사용자 | 비가역성은 셀렉터 사전의 `commits` 속성에서 오고(핫픽스로 바꿀 수 없음, ADR-012), 정적 검증기의 커밋 구간 규칙(V-03a~l·V-03c′) + 액추에이션 시 이름 동일성 검사 + 단일 사용 게이트 토큰 + 원장(`(intent_id, step_id)`) + 네트워크 커밋 가드(본문이 평문일 때 금고가 대조, 암호화 시 불가)를 겹으로 둬 "승인 없는 비가역 실행 없음"을 지킨다(엔진 버그 범위, 엔진 침해에는 경계가 아님). 로컬 승인은 main 승인 창, 원격 승인은 하드웨어 키다(ADR-014·016) |
| 꺼져 있어도 답한다 | 메타데이터 인덱스(평문 최소: doc_type 옵트인·발급 월·만료일)와 E2EE 블롭을 분리한다(ADR-006 개정). 조회 에이전트는 사용자 질문만 모델에 보내고 메타데이터 행은 서버가 결정적으로 조회한다 |
| 허용은 받고, 탐지 신호는 만들지 않고, 위조·은폐는 없다 | 요청률 상한 정책이 엔진에 상수로 내장되고 플레이북이 완화할 수 없다. 실제 설치 Chrome, 헤드풀, `--enable-automation` 배너 플래그 미사용이되 `navigator.webdriver=true` 표식은 그대로(ADR-010). 정부24는 허락 전 후처리 모드로 기본 브라우저 사용(ADR-011). 캡차는 `human` 스텝으로만 처리(ADR-004) |

추가 설계 원칙:
- **결정성 우선**: 같은 입력·같은 화면이면 같은 경로. 모델 판정은 confidence 임계값 아래에서 "자동 진행 금지"로만 작동한다.
- **실패는 체크포인트로**: 모든 스텝은 가장 가까운 안전 지점으로 되돌아갈 수 있어야 한다. 비가역 스텝은 아이덴포턴시 키로 1회만 실행된다.
- **관측 가능하되 내용은 없다**: 텔레메트리는 스텝 ID·셀렉터 ID·버전·지연·결과 코드만. 화면 텍스트·입력값은 절대 포함하지 않는다.
- **공급사 격리**: 모델 공급사 종속 코드는 `model/adapters/*` 한 곳에만 두고, `decide()` 계약은 System One 계약(Upstage Decide 등)까지 포괄한다. 클라우드도 공급사 중립으로 설계하고 전환은 조달·계약 트리거로 결정한다(ADR-015).
- **정직한 경계**: 설계가 막지 못하는 것(같은 OS 사용자 악성코드, 관리자, 운영자의 상관 분석, 남는 외국 의존)은 D11 §0·§8과 D09 §1 가시성 표에 그대로 적고 대외 문구도 그 범위를 넘지 않는다.

## 5. 용어

| 용어 | 뜻 |
|---|---|
| 플레이북(Playbook) | 포털 작업 하나를 수행하는 선언적 IR 문서. 서명된 패키지로 배포 |
| 스텝(Step) | 플레이북의 실행 단위. 타입별로 엔진 핸들러가 있다 |
| 게이트(Gate) | 비가역 스텝 앞의 사용자 승인 지점. 로컬 또는 폰에서 승인 |
| 체크포인트 | 실패 시 안전하게 복귀할 수 있는 스텝. 세션·화면 상태가 정의됨 |
| 번들(Bundle) | Decisions API에 한 번에 보내는 질문 묶음과 임계값·결과 매핑의 정의 |
| 금고(Vault) | 비밀을 평문으로 다루는 유일한 프로세스 |
| 비밀 타이피스트 | 금고가 CDP로 브라우저에 직접 입력하는 기능 |
| 비밀 창 | 비밀이 화면에 입력되는 동안 금고가 엔진의 입력·관찰 명령을 보류하는 구간(타이피스트·사용자 직접 입력·폰 봉인 비밀 공통) |
| 중계 허용 목록 | 금고가 엔진에 넘겨 주는 CDP 도메인·메서드의 기본 거부 목록. 브라우저 타깃·Storage·다운로드 경로 변경은 엔진에 열리지 않는다 |
| AIK | 복구 문구에서 파생되는 계정 신원 키. 기기 목록·폐기 목록·즉시 삭제의 유일한 서명 주체 |
| 프로필 | 계정 아래의 신원 단위(개인 1, 법인/개인사업자 1) |
| 운영 정책 | 요청률 상한·고정 간격·쿨다운 등 엔진 상수. 서명되어 배포, 플레이북이 완화 불가 |
| 핸드오프 | 작업을 사람에게 넘기는 것. 데스크톱 전면 또는 폰 |
