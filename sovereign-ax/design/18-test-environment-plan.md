# D18. 테스트 환경·데이터 계획서 (초안, Phase 0 이전 확정)

> v1.3.2 — AUDIT-D 반영 2026-11-03: PoC 상한의 앱 집행·사람 규칙 구분(§1 항목 4), 공문 보고 기준의 차단 신호 정의·쿨다운 해제 절차(§3), 영상·스파이크 폴더(§4)(ADR-025, D19 §3.5). v1.3.1 — ADR-017 반영: PoC 기간 테스트 계정은 관계사 법인(§1.3 예외), 실발급은 법률 회신을 기다리지 않음(§1.2). v1.3 — 변경 없음(2026-10-28 확인)

## 1. 규칙

1. `postprocess` 포털(정부24·SMINFO·4대보험)은 스파이크·녹화·코퍼스 수집에서도 **자동화하지 않는다.** 사람이 조작하고 하네스는 파일 감지만 한다.
2. 전자세금계산서 실발급은 **관계사 간 실거래 소액 용역**(실제 공급) 2~3건으로 제한한다. '0원·취소 가능 발급'은 존재하지 않는다(수정세금계산서로만 상쇄, 공급 없는 발급은 조세범처벌법 제10조 위험). 법률 질의 5번째 항목은 발송하되 회신을 기다리지 않는다(ADR-017 결정 5). 회신 전 실발급의 위험은 대표가 수용했다(`poc/reports/PoC-1-risk-acceptance.md`).
3. 테스트 사업자는 창업자의 실제 영업 법인이 **아닌** 테스트 전용 법인·개인사업자다. 차단·정지가 실제 업무 계정에 미치지 않게 한다. **PoC 기간(2026-10-29~11-26) 예외**: 관계사 법인 1곳을 PoC 전용 계정으로 쓰고 정지 위험은 대표가 수용한다(ADR-017 결정 5).
4. 요청률 상한 정책을 스파이크에도 그대로 적용한다. S8을 제외한 하루 홈택스 실행 20회 이하·하루 실발급 1건·누적 3건·하루 로그인 3회는 앱이 PoC 프로필 상수(`POC_BUILD`)로 집행한다. 시간대 제한은 앱이 집행하지 않는 사람 규칙이다(ADR-025, D-04(N-01)).

## 3. 계정 정지·차단 시 대응

- 홈택스 차단 신호 발생 즉시 모든 스파이크 중단, 24시간 쿨다운, 원인 분석 후 재개 여부를 PM이 결정. 2회 발생 시 공문 채널로 운영기관에 상황 설명.
- 공문 보고 기준의 '차단 신호'는 `portal.blocked` 계열이다. `extra_auth.repeat`(반복 추가 인증)와 `portal.unknown_screen`은 내부 점검 대상이며 보고하지 않는다. 오탐 쿨다운은 PM이 `poc/tests/dev-reset-cooldown.ts`로만 해제하고 사유를 decisions.tsv에 남긴다(ADR-025, D-09(N-14), D-04(N-01), D-06(N-03)).
- 정부24는 자동화하지 않으므로 매크로 제재 대상이 아니어야 한다. 그럼에도 제재 통지가 오면 즉시 모든 정부24 작업을 중단하고 법률 자문과 함께 대응한다.

## 4. 데이터

- 합성 식별자 생성기(체크섬 유효), 실제 화면 스냅샷은 테스트 법인 데이터만, 저장 전 마스킹.
- 리플레이 녹화는 실거래 2~3건과 조회성 플레이북에서만.
- 스파이크 산출물(스냅샷·HAR)은 보관함과 분리된 폴더, 2026년 말 삭제.
- 화면 영상은 로그인·비밀 창 활성 구간·인증서 선택·비밀번호 화면을 찍지 않는다(로그인은 녹화 밖에서 하고 세션을 이어 쓴다). 영상·스크린숏·HAR은 `%LOCALAPPDATA%\SovereignAX\spikes\`(사용자 전용 DACL, OneDrive 밖)에만 두고 누출 스캐너 대상에 넣으며 12-31에 지운다. HAR은 `recordHar({content:'omit', urlFilter: 조회 경로})`로 바디·쿼리를 처음부터 뺀다(D13 §3과 같은 문장, ADR-025, D-08(N-05)).
