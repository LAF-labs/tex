# 04. 로드맵·팀·리스크·KPI

## 1. 단계별 로드맵 (총 약 7개월, 2026-11 ~ 2027-05)

### 개발 착수 게이트 (G0 / G1)

> **2026-10-28 결정(ADR-017)**: G0를 당일 판정하고 Phase 0 스파이크를 **4주 PoC(10-29 ~ 11-26)**로 재편한다. PoC 범위는 사업자 계정·거래처 저장, 전자세금계산서 발행 + 이메일, 홈택스 민원증명이며 정부24는 제외한다. 공문 회신은 착수 조건이 아니다(홈택스는 금지 명문이 없고, 정부24는 회신 전 어떤 자동화도 하지 않으므로 회신과 무관). 무응답을 정부24 허락으로 간주하지 않는다. G1은 PoC-12에서 11-27에 판정한다. 작업분해는 design/14 §0.

> **2026-10-30 결정(ADR-018)**: 공고문 36건 수요 집계(07 문서)로 플레이북 우선순위를 다시 정했다. Phase 1 코어는 홈택스 자동 6종(H-01·H-03·H-04·H-05·H-08·H-09), 정부24 후처리는 출시 조건에서 빠지고, 법인등기 S-03과 위택스 W-01은 베타 중 추가, 공고문 → 서류 꾸러미 K-01은 Phase 2. PoC 범위는 그대로다.

- **G0 — Phase 0(스파이크) 착수, 11-03**: ① 법률 자문 계약과 질의서 **6건**(세무사법·발급시스템 사업자·약관·공동·금융인증서 비밀번호 직접 입력 구조·테스트 발급 적법성·보안카드 저장과 자동 입력. 원래 5건이었고 EX-1 10-31·ADR-020에 따라 Q6을 더하고 Q4를 바꿨다, outreach/04) 발송 ② 공문 2종 최종안과 수신 부서 확인(발송은 1주차) ③ 테스트 전용 법인·인증수단 확보 일정 확정(외부 리드타임 즉시 착수) ④ "`postprocess` 포털 무자동화" 스파이크 규칙 확정 ⑤ 공격표면 감사 반영본(설계 v1.3, D19) 확정과 Upstage 한국 리전 베타 신청 접수(ADR-015).
- **G1 — Phase 1(제품 코드) 착수, 11-27(PoC-12)**: 06 문서 §5의 Go 조건(S1 자동 구간·S1a·S1b·S6·S7·S8·S16·지불의사 20건). S3 수동 실측은 PoC 범위 밖이라 G1 조건에서 빼고 Phase 1 중 정부24 후처리 착수 전 조건으로 옮긴다.

스파이크 코드는 폐기 전제다. 미결 항목은 06 §6과 `research/REVIEW-*`의 Top 항목으로 관리한다.

### Phase 1 — MVP (12주, 2026-11-24 ~ 2027-02-13) · Windows 전용

범위:
- 온보딩(프로필 1개: 사업자) + 로컬 금고 + 내 사업자 정보
- 플레이북 코어(출시 조건, ADR-018): H-01, H-03, H-04, H-05, H-08, H-09(홈택스 자동. H-03·H-08·H-09는 즉시발급 민원증명 템플릿 공유). 베타 중 추가: H-02, H-10, H-11, S-03(결제는 사용자, 약관 확인과 상한 상향 앱 업데이트 뒤), W-01(위택스 사전 허락 회신과 앱 업데이트 뒤, 그 전에는 G-02 후처리, ADR-022). G-01~03은 **후처리 모드**로 포함하되 출시 조건이 아니다
- 대화창(의도 → 플레이북), 확인 카드, 감사 로그
- 서류 보관함 + 메타데이터 + 만료 알림(데몬 알림 모드)
- 계정·구독(결제 연동), 모델 게이트웨이(계량), 플레이북 서명 배포
- 베타 50명 초대(스타트업 2~3곳 집중)

제외: 모바일, 클라우드 백업(서류 암호문 블롭·메타데이터 색인), 자동 갱신, macOS, 법인 프로필 2개 동시. 단 계정의 '백업(메타데이터 동기화)' 스위치는 Phase 1에도 있고, 켜면 기기 간 중복 발급 경고용 업무 키 표시(HMAC·상태·일)만 올라간다(D03 §4, D09 §6).

출구 기준: 베타 활성화율 60%+, **자동 구간 성공률**(홈택스 `auto` 실행 중 게이트·인증 승인 외 사람 개입 없이 완료) 90%+, **보관 완료율**(후처리 실행 중 PDF 감지·분류) 90%+, 주 1회 이상 사용 40%+.

### Phase 2 — 리모트·클라우드·데몬 (8주, 2027-02-16 ~ 04-10)

- 모바일 앱(페어링, 승인 카드, 조회 에이전트, E2EE 뷰어)
- 릴레이 + 블롭 저장소 + 메타데이터 인덱스
- 데몬 승인형 갱신 `semi_auto`(비즈니스 플랜). 무인 `auto`는 보류(사람 없이 끝나는 로그인 경로·법률 의견 확보 후)
- 두 번째 프로필(개인 + 법인) 동시 운영
- 플레이북 H-06, G-04, W-02(G-05 대체), S-01, S-02, S-04
- 공고문 → 서류 꾸러미(K-01, 02 §15)
- 정식 출시 + 가격 적용

출구 기준: 유료 200명(기준 시나리오), 월 이탈 5% 이하, Terra 개입률 15% 이하.

### Phase 3 — 확장 (2027-04 ~)

- macOS 지원
- 단체 라이선스(워크스페이스 관리자, 좌석 배정, 그러나 프로필 상한은 유지)
- 거래처·반복 발급 템플릿, 세금계산서 발급 일괄 처리(사용자 승인은 건별 또는 묶음 1회)
- BYOK 모드, 온디바이스 소형 모델로 라우팅 비용 추가 절감 실험
- 입찰 확장: S-05(직접생산확인증명), 입찰용 꾸러미 프리셋

## 5. 베타 검증 질문 (Phase 1에서 반드시 답할 것)

1. 보안카드를 고른 사용자는 홈택스 아이디·비밀번호와 보안카드 번호를 PC에 한 번 등록하는 완전 위임에 동의하는가? (공동·금융인증서 비밀번호는 저장하지 않고 매번 직접 입력한다는 고지와 함께, ADR-020)
2. 확인 카드 1회 승인이 번거롭다고 느끼는가, 안심된다고 느끼는가?
3. "우리 서버에 없다"는 메시지가 실제 결제 전환에 영향을 주는가? (A/B 랜딩)
4. 세금계산서와 민원서류 중 어느 쪽이 주 사용 동기인가? (가격·플랜 재설계 근거)
5. 리모트 컨트롤 수요가 실제로 있는가, 아니면 '안심 기능'인가?
