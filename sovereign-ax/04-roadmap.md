# 04. 로드맵·팀·리스크·KPI

## 1. 단계별 로드맵 (총 약 7개월, 2026-11 ~ 2027-05)

### 개발 착수 게이트 (Phase 0 이전)

코드 작성은 아래 세 가지가 끝난 뒤에만 시작한다.

1. 기획서 v1.0 확정: 05 문서까지 포함해 미결 항목 0건(미결 목록은 README 하단).
2. 법률 1차 의견 수령: 세무사법·발급시스템 사업자·약관·인증서 비밀번호 저장.
3. 자동화 접근 허용 공문 발송 완료(국세청·행정안전부 최소 2곳) 및 접수 확인.

Phase 0의 스파이크도 "기획 검증"이지 제품 코드가 아니다. 스파이크 코드는 폐기 전제로 작성한다.

### Phase 1 — MVP (10주, 2026-11-24 ~ 2027-01-30) · Windows 전용

범위:
- 온보딩(프로필 1개: 사업자) + 로컬 금고 + 내 사업자 정보
- 플레이북 H-01, H-02, H-04, H-05, G-01, G-02, G-03
- 대화창(의도 → 플레이북), 확인 카드, 감사 로그
- 서류 보관함 + 메타데이터 + 만료 알림(데몬 알림 모드)
- 계정·구독(결제 연동), 모델 게이트웨이(계량), 플레이북 서명 배포
- 베타 50명 초대(스타트업 2~3곳 집중)

제외: 모바일, 클라우드 백업, 자동 갱신, macOS, 법인 프로필 2개 동시.

출구 기준: 베타 사용자 활성화율 60%+, 플레이북 무인 성공률 90%+, 주 1회 이상 사용 40%+.

### Phase 2 — 리모트·클라우드·데몬 (8주, 2027-02-02 ~ 03-27)

- 모바일 앱(페어링, 승인 카드, 조회 에이전트, E2EE 뷰어)
- 릴레이 + 블롭 저장소 + 메타데이터 인덱스
- 데몬 자동 갱신 모드(비즈니스 플랜)
- 두 번째 프로필(개인 + 법인) 동시 운영
- 플레이북 H-06, G-04, G-05, S-01, S-02
- 정식 출시 + 가격 적용

출구 기준: 유료 300명, 월 이탈 5% 이하, LLM 개입률 15% 이하.

### Phase 3 — 확장 (2027-04 ~)

- macOS 지원
- 단체 라이선스(워크스페이스 관리자, 좌석 배정, 그러나 프로필 상한은 유지)
- 거래처·반복 발급 템플릿, 세금계산서 발급 일괄 처리(사용자 승인은 건별 또는 묶음 1회)
- BYOK 모드, 온디바이스 소형 모델로 라우팅 비용 추가 절감 실험
- 추가 포털(인터넷등기소 S-03 등)

## 4. KPI 체계

| 영역 | 지표 | 목표(Phase 2 말) |
|---|---|---|
| 활성화 | 설치 → 첫 발급 성공 | 60% |
| 신뢰성 | 플레이북 무인 성공률 | 97% |
| 비용 | LLM 개입률 / 사용자당 월 모델비 | ≤15% / ≤3,000원 |
| 속도 | 세금계산서 발급 소요(승인 후) | ≤30초 |
| 유지 | 월 이탈률 / 주간 활성 비율 | ≤5% / 50% |
| 주권 체감 | "서버 보유 데이터" 페이지 열람률, NPS | 30% / 50+ |
| 운영 | 포털 개편 → 핫픽스 배포 시간 | ≤24시간 |

## 5. 베타 검증 질문 (Phase 1에서 반드시 답할 것)

1. 사용자는 인증서 비밀번호 저장에 동의하는가? (동의율이 낮으면 데몬 자동 모드 가치가 떨어진다)
2. 확인 카드 1회 승인이 번거롭다고 느끼는가, 안심된다고 느끼는가?
3. "우리 서버에 없다"는 메시지가 실제 결제 전환에 영향을 주는가? (A/B 랜딩)
4. 세금계산서와 민원서류 중 어느 쪽이 주 사용 동기인가? (가격·플랜 재설계 근거)
5. 리모트 컨트롤 수요가 실제로 있는가, 아니면 '안심 기능'인가?
