## 2. 첫 실행 (온보딩)

1번을 뺀 나머지는 메인 대화 안에서 채팅으로 한 번에 하나씩 묻는다. 질문 순서·카드·화면 ID는 08 §4, 근거는 ADR-019.

1. 계정 가입(이메일) → 구독 선택 → 앱 설치. 두 번째 PC부터는 연결된 폰(또는 연결해 둔 다른 PC) 승인으로 백업과 기기 연결을 넘겨받는다. 폰을 쓸 수 없으면 PASS 본인인증으로 계정만 되찾고, 백업은 연결된 기기가 있을 때만 되찾는다. 복구용 기기는 설정에서 언제든 더한다(08 A-03, ADR-020).
2. **프로필 등록** (계정당 최대 2개: 개인 1 + 법인/개인사업자 1)
   - 개인(맡길 업무에서 개인 서류를 고른 경우에만 묻는다): 간편인증(카카오·네이버·PASS 등, 정부24 간편인증은 주민번호 기반) 연결 또는 공동인증서(NPKI 폴더 자동 탐지) 선택.
   - 법인/개인사업자: 전자세금계산서용·사업자범용 공동인증서 선택, 또는 홈택스 사업자용 간편인증(카카오뱅크·IBK·KB, PUSH/QR/클라우드, 건별·수정·반복·복사 발급 가능) 등록 안내. **정부24는 사업자번호로 간편인증 로그인이 안 되므로 법인 서류는 공동·금융인증서 또는 법인 아이디가 필요**함을 안내. 선택적으로 보안카드 등록(홈택스 온라인 신청 후 지정 세무서 수령).
   - **발급 인증 수단을 하나 고른다**(보안카드·사업자 간편인증·공동인증서·금융인증서). 한 번 고르면 모든 발급에 고정이고 설정에서만 바꾼다(ADR-020). 보안카드는 홈택스 아이디·비밀번호와 카드 30개 번호를 금고에 한 번 등록하면 이후 앱이 입력한다. 번호는 이 PC의 보안 칩(TPM)에 묶인 열쇠로 칸마다 잠가 두고, Windows를 잠그거나 15분 넘게 자리를 비우면 금고도 잠긴다. 원하면 발급마다 Windows Hello로 확인하게 할 수 있다(ADR-026, D-01(N-07)). 간편인증은 발급마다 폰에서 승인한다. 공동·금융인증서 비밀번호는 가상키패드·키보드보안 때문에 저장·자동 입력하지 않고 매번 사용자가 직접 넣는다. 같은 PC의 악성코드로부터는 보호하지 못한다는 범위를 함께 고지한다.
3. **내 사업자 정보 입력**: 상호·사업자번호·대표자·업태·종목·주소·이메일. 로컬에만 저장. 홈택스 로그인 후 자동 채움 제공.
4. **맡길 업무 선택**: 플레이북 카탈로그(§10)에서 맡길 일을 고르면 빠른 실행으로 만들고, 고른 업무에 필요한 것(거래처·유효기간 알림·개인 프로필)만 이어서 묻는다.
5. **서류 보관함 위치** 지정(기본: `%LOCALAPPDATA%\SovereignAX\vault`, 동기화·색인 대상 아님. 문서 폴더를 고르면 OneDrive 등 동기화 루트인지 감지해 경고) + 클라우드 백업 ON/OFF(Phase 2부터). 이 스위치('백업(메타데이터 동기화)')는 서류 암호문 백업·메타데이터 색인과, PC를 두 대 이상 연결한 계정의 기기 간 업무 키 표시를 켠다(D03 §4, ADR-024). Phase 1에는 스위치가 없고, 기기 간 중복 발급은 PC가 홈택스 발급목록을 조회해 경고한다(서버로 가는 것 없음).
6. 첫 작업 추천: 사업자등록증명 1건 발급(돈이 오가지 않아 연습에 안전하고, 공고문 97%가 요구하는 서류다. 07 §0). 세금계산서 1건 발급도 함께 제안한다.

## 3. 메인 화면

홈은 **"이번 달 판"**이다(결정, ADR-033이 ADR-019 결정 2를 대체). 해야 할 일을 기한 순으로 보여 주는 카드 목록이다. 카드는 발급할 세금계산서, 받아야 할 증빙, 세무사에게 줄 것, 만료가 다가오는 서류다. 화면 구성·카드·예외 상태의 상세는 08 §5~§11.

- (제안) 판 카드를 누르면 기존 확인 카드와 승인 바로 이어진다. 판 카드에는 승인 버튼이 없다(ADR-021).
- (제안) 대화는 입력 수단으로 남는다. 아래의 "오늘 요약"을 키워 판으로 만들고, 단일 세션 타임라인과 입력창은 그대로 둔다. 판과 대화의 배치는 디자인 단계에서 정한다.

- 왼쪽 레일: 대화, 문서함, 거래처, 내 사업장, 활동 기록, 설정. 상단 바: 프로필 전환(개인/사업자), 금고 잠김/열림, 폰 연결, 검색(Ctrl+K).
- 가운데: 이번 달 판과 단일 세션 대화 타임라인. 판에 확인 필요·진행 중·만료 임박이 들어간다(ADR-033). 입력창 위에 빠른 실행 칩(온보딩에서 맡긴 업무)을 둔다. 새 대화·스레드 목록은 없고, 지난 작업은 검색·문서함·활동 기록으로 찾는다.
- 오른쪽: 작업 패널(확인 값 전체와 발급 인증, 실행 단계, 결과). 실행은 한 번에 하나이고 나머지 요청은 대기열에 쌓인다.
- 대화창은 **의도 → 플레이북 매핑**용이다. 자유 문장을 받아 플레이북과 인자를 채운 뒤 **확인 카드**를 띄운다. 모델은 여기서만 개입하고 실행은 플레이북이 한다. 비가역 승인은 홈택스에서 되읽은 값을 확인한 뒤 대화 열 하단 승인 바(입력창 바로 위, 앱이 대화창과 따로 그리는 화면)의 [승인하고 발급]으로만 한다. 별도 승인 창은 없다(ADR-020·021).
- 프로필 전환은 대화를 나누지 않는다. 새 요청의 기본 프로필이 바뀌고 카드에 프로필 표시가 붙는다.

## 4. 핵심 흐름 A — 전자세금계산서 발급 + 이메일

입력: 거래처(사업자번호 또는 저장된 거래처), 공급가액(또는 합계), 품목, 작성일자, 이메일(저장값 자동).

1. 사용자가 거래처 사업자등록증 이미지를 끌어다 놓거나 사업자번호 입력 → **로컬 OCR/텍스트 추출**로 번호·상호·대표자·주소 후보 생성 → 국세청 사업자등록정보 진위확인 API(공공데이터포털, 서비스 키 필요: 기본은 우리 게이트웨이 프록시, 설정에서 자기 키 사용)로 상태 확인. (제안, R15 P1-1) 이 서비스의 진위확인(번호·개업일자·대표자명 일치)과 상태조회(계속·휴·폐업·과세유형)는 다른 기능이고, 화면 배지는 상태조회 결과다. 상태는 세 가지다: 계속, 휴업·폐업, 확인 불가(인증 오류·호출 제한·네트워크 실패. 폐업으로 처리하지 않는다). 결과와 확인 시각을 함께 저장한다. 휴·폐업과 확인 불가는 등록·발급을 막지 않고 경고와 사용자 확인으로 둔다(08 §4·§11).
2. 금액 입력: 입력창에 "계산서"가 보이면 보내기 전에 부가세 [별도] [포함] 토글을 띄운다. 고르면 그 기준으로 계산하고, 고르지 않으면 별도로 계산한 뒤(330만원 → 공급가 3,300,000 + 세액 330,000) 초안 카드에 [부가세 포함하기] [금액 수정] [취소]를 둔다(ADR-020). 과세·영세·면세는 사용자가 고르며 모델은 추론하지 않는다(홈택스 '계산' 버튼과 같은 산술만).
2-1. 품목: 거래처별 저장 품목·최근 품목 중 선택 또는 직접 입력(필수). 이메일: 거래처 저장값을 **초안 카드에 표시**하고 홈택스 발급 화면의 공급받는자 이메일 칸에 입력한다(홈택스는 발급 시 그 주소로 자동 발송).
3. **초안 카드**: 공급자·공급받는자·금액·품목·이메일·발급 인증을 한 화면에. 사용자가 [홈택스에서 준비]를 누르기 전까지 어떤 외부 전송도 없다.
4. 플레이북 실행: 홈택스 로그인(고정된 발급 인증: 간편인증 PUSH → 폰 승인 / 공동·금융인증서 → 사용자가 비밀번호 직접 입력 / 보안카드 → 아이디 로그인을 앱이 수행) → 건별발급 화면 → 항목 입력 → 되읽기(readback) → 승인 대기 카드 + 대화 열 하단 승인 바의 [승인하고 발급] → 전자서명(간편인증 폰 승인 / 인증서 비밀번호 직접 입력 / 보안카드 번호는 금고가 입력) → 발급 → **발급목록 조회로 확정**(verify. 응답이 끊기면 앱이 다시 조회하고 재발급하지 않는다) → 승인번호 획득.
5. 후처리: 발급분 PDF 저장 → 보관함에 `tax_invoice_20261027_7K3P.pdf`(파일명에 거래처·승인번호 같은 식별 정보를 넣지 않고 표시 이름은 앱 안에) → 이메일 전송(홈택스 자체 전송 기능, 전송 상태 조회로 확정) → 거래처 장부(로컬)에 기록.
6. 결과 카드 + 감사 로그 한 줄: "어떤 값이 어디로 갔는지".

예외 처리: 셀렉터 실패·팝업·세션 만료 시 플레이북이 체크포인트로 복귀 → 스텝 재시도(최대 3회, D03 §6)를 다 쓰면 모델에게 **마스킹된 접근성 트리**를 주고 복구 시도 → 그래도 실패하면 사용자에게 화면 핸드오프.

인증수단별 로그인·전자서명 경로와 사람 개입 지점, 그리고 위 예외 처리를 싼 단계부터 비싼 단계로 정리한 폴백 파이프라인은 [ADR-036](design/adr/ADR-036-issuance-auth-fallback-pipeline.md) 결정 1·2가 정본이다. 단계 0 플레이북·셀렉터 사전(모델 0) → 단계 1 규칙 판정(모델 0) → 단계 2 Decisions 판정 → 단계 3 Terra 셀렉터 복구 → 단계 4 사람. 발급 버튼부터 verify까지(커밋 구간)는 단계 0만 쓰고, 차단·캡차는 복구하지 않고 멈춘다. 인증수단은 실행 중에 바꾸지 않는다(ADR-020 결정 1).

### 4.1 발급 취소 (H-01c, ADR-036 결정 3)

전자세금계산서는 지울 수 없다. "취소"는 수정세금계산서(음(-) 1장)를 새로 발급하는 것이고, 그것도 되돌릴 수 없는 발급이다. H-01c는 전액 상쇄 두 사유만 다룬다.

| 사유 | 작성일자 | 발급기한 안내(국세청 자료, 법정 기한 아님) |
|---|---|---|
| 계약의 해제(공급 전 계약 취소) | 계약해제일(사용자가 입력, 시행령 §70①2호) | 계약해제일 다음 달 10일(국세청 안내 자료 기준) |
| 착오에 의한 이중발급 | 당초 작성일자(시행령 §70①7호) | 날짜 없음. "착오를 알면 바로 발급하세요" |

시행령 §70①2호·7호에는 날짜로 된 발급기한이 없다. 화면은 이 열을 "법정 기한"이라 부르지 않고 "안내(국세청 자료)"로 보인다. 지났으면 막지 않고 세무사 확인을 권하며, 가산세율·금액은 보이지 않는다(R14 I-1·D-L7, ADR-036 결정 3).

1. 문서함 세금계산서 상세의 [발급 취소] 또는 대화로 시작한다. 대상은 원장·보관함에 승인번호가 있는 당초분(합계 양(+), 수정분 아님)뿐이다. 취소로 낸 음(-) 수정분이나 정정 발급분에는 [발급 취소]가 없다.
2. 사유는 사용자가 고른다. 앱은 사유를 권하지 않고 정의와 기한 안내(국세청 자료)만 보여 주며, 모르면 세무사 확인을 안내한다(§12).
3. 흐름은 H-01과 같다: 로그인(고정한 발급 인증) → 수정발급 → 승인번호로 당초분 조회 → 되읽기(당초분 = 원장 기록) → 사유·작성일자 → 되읽기(음(-) 금액 = −원본 합계) → 승인 바 [승인하고 취소 발급] → 전자서명 → 발급목록 조회로 확정(verify) → 원본 기록에 "취소 발급됨"을 붙인다.
4. 한 원본에 전액 취소는 한 번이다. 원장에 같은 원본의 취소가 발급됨·확인 중(`armed`·`in_doubt` 등)이면 시작하지 않고, 승인 직전에도 다시 확인한다. 일반 발급의 중복 경고와 달리 막는다(ADR-036 결정 3.6).
5. 정정 사유(기재사항 착오·공급가액 변동·환입·내국신용장)는 H-06(Phase 2)이다.

## 5. 핵심 흐름 B — 민원서류 발급

민원서류의 MVP 코어는 **홈택스 민원증명**이다(H-03·H-04·H-08·H-09, ADR-018). 정부24 서류(G-01~03)는 Phase 1에 후처리로 남지만 출시 조건이 아니다. 위택스·인터넷등기소는 베타 중 추가 후보이며 켜는 조건은 ADR-022다.

### 5.1 홈택스 민원증명 (자동)

1. 대화 한 줄("사업자등록증명 떼 줘") → 서류 종류·용도·제출처를 확인 카드로 보여 준다.
2. 로그인. 민원증명의 로그인 수단은 공동·금융인증서가 기본이고, 사업자용 간편인증으로 발급되는지는 S16에서 확인한다(ADR-018 결정 10). 보안카드는 전자(세금)계산서 발급 전용이라(R2 §1-1) 보안카드를 발급 인증으로 고른 사용자는 민원증명용 인증(간편인증 또는 인증서)이 따로 필요할 수 있다.
3. `[민원증명] > [즉시발급 증명]`에서 서류 종류를 고르고 용도·제출처를 넣는다. H-03·H-08·H-09는 하나의 즉시발급 템플릿을 서류 종류 파라미터로 공유하고, H-04(납세증명)는 목적·제출처 규칙이 달라 따로 둔다(ADR-018 결정 2). 공식 PDF 경로는 S16에서 확인한다.
4. 발급은 되돌릴 수 없는 단계라 다른 발급과 같이 승인한 뒤에만 실행한다. 홈택스에서 되읽은 값(서류 종류·용도·제출처)을 승인 바에 보여 주고, 사용자가 [승인하고 발급]을 누르면 발급한다(05 §5-6, ADR-020 결정 4, ADR-021).
5. PDF 저장 → 로컬 텍스트 추출로 발급일·유효기간 → 보관함·만료 추적(아래 5.2의 4·5와 같음).

### 5.2 정부24 (허락 전 후처리, 허락 뒤 자동)

사전 허락 회신 전에는 **후처리 모드**다. 하네스는 Chrome을 띄우지 않고 기본 브라우저로 정부24를 열어 안내하며, 사용자가 로그인·발급·출력을 하고, 하네스는 사용자가 저장해 고른 PDF만 보관함으로 옮긴다(05 §7, D17 §1-3). 아래 1~3은 허락 회신과 앱 업데이트 뒤 `assisted`/`auto`로 올렸을 때의 흐름이고, 4·5는 두 모드에 공통이다.

1. 서류 선택 + 옵션(등본의 경우 세대원 포함 여부, 주민번호 뒷자리 표시 여부 등은 **기본 최소 노출**).
2. 로그인(간편인증 PUSH 또는 공동인증서).
3. 신청 → 발급 → **출력 단계**: 정부24 공식 안내는 상충한다(2021-09 공지·등본 FAQ는 가상 프린터·파일 저장 불가, 2023-12 공지는 Microsoft Print to PDF를 정상 방법으로 안내). 서류별로 S3에서 실측하고, 우선순위는 원본 PDF(다운로드·전자문서지갑) → `--kiosk-printing`+Save as PDF → 헤드풀 `page.pdf()` → Microsoft Print to PDF → 사용자 핸드오프. 전자문서지갑은 모바일 앱 중심이라 폰 연동과 묶어 Phase 2에서 설계.
4. 저장 파일에서 로컬 텍스트 추출 → 발급일·유효기간 메타데이터 생성 → 보관함 + (옵션) E2EE 백업.
5. 사용처 전달: "메일로 보내기", "폴더 열기", "폰으로 보내기(E2EE)".

## 6. 서류 데몬 (주기적 최신화)

- 서류별 **유효기간 규칙표**(예: 납세증명 30일, 중소기업확인서 발급 기준 1년, 건강보험 자격득실 통상 제출처 기준 1~3개월)를 내장하고 사용자가 조정.
- 두 가지 모드:
  - **알림 모드(Phase 1)**: 만료 D-7, D-1에 데스크톱·모바일 알림. 사용자가 "지금 갱신" 탭.
  - **반자동 모드(Phase 2)**: 사전 동의한 서류는 예정 시각에 폰으로 '시작할까요' 한 번, 비가역 직전 승인 한 번으로 갱신된다. 간편인증 PUSH는 사용자가 승인한다.
  - **무인 자동 모드는 보류**: 홈택스 공동인증서 경로는 가상키패드로 사용자 직접 입력이 필요하고 간편인증은 폰 승인이 필요해 사람 없이 로그인이 끝나지 않으며, 정부24는 허락 전 후처리 모드다. 사람 없이 끝나는 로그인 경로와 법률 의견이 확보되면 서명된 운영 정책으로 켠다. 보안카드 사용자는 저장 자격으로 로그인할 수 있지만, 데몬은 사람 비밀을 쓰지 않으므로(금고가 거부) 사람 없이 로그인이 끝나지 않는다. 반자동은 폰 '시작할까요'의 생체 확인(시작 게이트) 뒤에만 저장 자격을 쓴다(ADR-026·029, D-01(N-07), D-34(N-13)).
- 실행 창: 사용자가 정한 시간대(예: 평일 09:00~18:00), PC가 켜져 있고 유휴일 때. 꺼져 있어 놓친 작업은 모바일로 알린다.
- 데몬은 절대 '새 종류의 작업'을 만들지 않는다. 사용자가 명시 등록한 서류만 갱신.

## 7. 모바일 리모트 컨트롤 (PC 켜짐)

**Phase 1 폰 앱 (ADR-034 결정 1·9)**: 사장님은 PC 앱과 폰 앱을 둘 다 쓴다(결정). Phase 1 폰 앱은 종이 증빙을 촬영해 올린다(결정). 현금매출 입력도 맡기는 안은 제안이다. 폰 승인은 Phase 1에서 뺐다(Phase 2, ADR-034 결정 9 채택, 2026-11-05). 촬영과 현금매출을 아래 페어링과 E2EE 전송으로 PC에 넘기는 방식도 제안이다. 폰은 앱 안 카메라로만 찍고, PC가 docparse 샌드박스에서 다시 읽은 값이 정본이다. 폰에서 글자를 읽을 때는 폰 OS의 기기 안 OCR을 쓰고 모델을 부르지 않는다(제안). 아래의 리모트 지시·폰 타임라인은 Phase 2다. 하드웨어 키 승인과 원격 실행 생체 확인은 폰 승인과 함께 Phase 2다.

- 페어링: 데스크톱에 QR 표시 → 모바일 앱 내 스캐너로 스캔 → 폰에 뜬 6자리 코드를 PC에 입력 → 기기 간 키 교환 완료(E2E). 릴레이 서버는 내용을 볼 수 없다.
- 모바일 화면: 채팅 메인 + 채팅바 위 빠른 실행 칩. PC와 같은 메인 대화 타임라인을 보고, 폰에서 보낸 말에는 "폰에서" 표시가 붙는다(ADR-019, 08 §10). "거래처 B에 55만원 세금계산서" → 로컬 하네스가 플레이북 준비 → **확인 카드가 폰에 뜸** → 승인 → 실행 → 간편인증 PUSH(홈택스 앱) 승인 → 완료 알림 + PDF 미리보기(E2EE 전송).
- 보안카드·포털 비밀번호가 필요한 단계: 폰에서 입력 → 금고 전용 키로 인증 봉인 → 금고가 직접 입력 → 즉시 폐기. 릴레이·서버·엔진은 평문을 볼 수 없다. **홈택스 공동인증서 비밀번호(가상키패드)는 폰에서 대신 입력할 수 없으므로** 리모트 발급은 발급 인증이 간편인증이나 보안카드일 때 가능하다(ADR-020). 폰에서 실행을 누르는 탭에 생체 확인이 붙는다(저장된 홈택스 자격을 쓰는 작업). 하드웨어 키는 발급 승인에만 필요하다(ADR-029, D-34(N-13)).
- 로컬 하네스는 리모트 명령을 **같은 플레이북 화이트리스트**로만 받는다. 임의 브라우저 조작 명령은 받지 않는다.

## 8. 클라우드 조회 에이전트 (PC 꺼짐)

- 서버에는 **메타데이터 인덱스**만 평문: 서류 종류(종류별로 서버 노출을 켜고 끌 수 있음. 만료 추적 대상 4종만 기본 켬), 발급 월, 만료일, 무작위 슬롯 토큰. 상호·사업자번호·주민번호·금액·파일명·정확한 크기·초 단위 시각은 없음(설계 D19 C-09).
- 답할 수 있는 질문: "지난달 납세증명 받았어?", "중소기업확인서 언제 만료돼?". "10월 세금계산서 몇 건 발급했지?"는 세금계산서 종류의 서버 노출을 켠 사용자만(건수·월만). 질문 문장만 모델로 가고 메타데이터 행은 서버가 조회한다.
- 본문이 필요한 질문("그 등본 보여줘"): 모바일 앱이 E2EE 블롭을 내려받아 **폰에서 복호화**해 보여준다. 본문 요약은 PC가 켜져 있을 때 PC의 마스킹 계층(사용자 사전 포함)을 거쳐서만, 사용자가 그 자리에서 허용할 때 한다. PC가 꺼져 있으면 요약하지 않는다(설계 D09 §7).
- PC가 꺼져 있을 때 폰에서 나눈 질문·답은 폰에 남겼다가, PC와 다시 연결되면 E2E로 PC 타임라인에 "서버 답변" 표시로 합친다. 서버는 대화 본문을 저장하지 않는다(ADR-019, D09).
- 발급 자체는 불가(PC가 꺼져 있으므로). "PC 켜지면 실행" 예약은 가능하되, PC가 켜지면 **자동 실행이 아니라 승인 요청**이 다시 온다(비가역 단계는 항상 그 시점의 승인이 필요).

## 9. 신원·프로필 모델

```
계정(이메일, 구독)
 ├─ 프로필 A: 개인      — 인증수단: 간편인증 | 공동인증서(개인)   — 작업: 정부24, 홈택스(개인)
 └─ 프로필 B: 법인/개인사업자 — 인증수단: 사업자용 공동인증서 | 사업자 간편인증 | 보안카드 — 작업: 홈택스(사업자), SMINFO, 정부24(법인)
```

- 서버는 "슬롯 2개 중 몇 개가 쓰이는가"와 사업자 프로필의 사업자번호 HMAC(재바인딩 90일 1회 제한용, 평문 아님)만 안다. 종류·인증수단은 서버에 보내지 않는다. 새 폰은 PC와 페어링(계정 신원 키 AIK의 기기 인증서 발급) 전에는 조회 에이전트·백업을 쓸 수 없다. 로그인은 6자리 일회용 코드 기본·패스키 권장이다. 새 PC는 연결된 폰 승인으로 연결한다. 폰이 없으면 PASS 본인인증으로 계정만 되찾는다(ADR-020, ADR-029).
- 서버는 사업자번호의 HMAC만 안다. 다만 진위확인을 기본 프록시로 쓰면 조회 대상 사업자번호는 평문으로 프록시를 지나가며, 프록시는 계정과 묶지 않고 기록하지 않는다(설정에서 자기 키로 바꿀 수 있다). 백업한 서류는 연결된 폰이나 다른 PC가 있을 때만 되찾을 수 있다(ADR-029, D-51(N-81), D-16(N-09)).
- 계정당 2개 초과 등록 불가(기획 요구). 세무사·경리대행이 다수 고객을 한 계정에 묶는 **대리 사용을 어렵게** 하는 장치다(사업자 재바인딩 90일 제한, 발급 시 공급자 = 프로필 사업자 확인). 다계정 생성은 신원 확인 없이는 막지 못하며 약관·기기 등록 이력 상한으로만 비용을 올린다(D19 C-32).

## 11. 감사 로그와 투명성 화면

- 모든 작업: 시각, 프로필, 플레이북 버전, 접속 포털, 입력값 요약, 결과, **모델 호출 여부와 전송된 바이트 수(마스킹 후)**.
- "우리 서버에 있는 내 데이터" 페이지: 서버가 보유한 레코드를 그대로 보여주고 내보내기·삭제.
- 모델 전송 미리보기: 예외 복구 때 모델로 나가는 마스킹된 내용을 사용자가 열어볼 수 있다(기본 접힘).

## 12. 하지 않는 것 (제품 규칙)

- 신고세액 계산, 절세·공제 판단, 신고서 작성·신고 대리, 세무 상담 답변. (부가세 10% 분리는 홈택스 '계산' 버튼과 같은 산술로만 제공하고 과세유형은 사용자가 고른다. 급여의 원천징수액과 4대보험 근로자 부담분은 공식 표를 적용하는 계산 보조로 제공한다, §16·ADR-031.)
- 간편장부, 장부 작성 대행.
- (제안, ADR-032) 계정과목 분류와 경비 인정 여부 판단. 빠진 것을 표시하고 차이를 보여 주는 데까지만 한다.
- 4대보험 취득·상실 신고(결정, ADR-034 결정 8). 사장님이 EDI로 하거나 세무사가 한다. 원천세 신고는 위 '신고 대리'에 들어간다.
- 세무사(세무사 PC)에서의 세금계산서 발급(결정, ADR-034 결정 5). 발급은 사장님 PC에서 사장님 인증수단으로만 한다.
- 사업용 신용카드 사용내역의 매일 자동 수집(결정, ADR-032 결정 3). [최신화]를 누를 때만 조회한다.
- 세무사 화면의 AI 기능(결정, 다음 단계, ADR-034 결정 12).
- (제안, ADR-034 결정 11) 세무사 매칭(세무사 찾아 주기·소개).
- 사용자 승인 없는 발급·전송·결제.
- 서버 측 브라우저 자동화.
- 다수 고객 대행용 멀티 테넌트 계정.
- 캡차 자동 해독, 지문 위조, 흔적 삭제, 비정상 속도의 반복 요청. 캡차는 사용자가 데스크톱 또는 폰에서 직접 푼다.

## 13. 포털별 운영 수준과 후처리 모드

운영기관의 허락 상태에 따라 포털별로 `postprocess`(후처리) / `assisted`(보조) / `auto`(자동) 수준이 서명된 운영 정책으로 배포된다(접근 허용·봇탐지 문서 §7). 포털별 최대 수준은 앱에 내장된 상한이 정하고, 상한을 올리는 일은 앱 업데이트로만 한다(ADR-012·022). 정부24·위택스는 사전 허락 회신 전 후처리 모드가 상한이다.

후처리 모드의 사용자 경험:
1. 작업 카드를 누르면 하네스가 **사용자의 기본 브라우저**(자동화 프로필이 아닌)에 정부24 페이지를 열고 옆에 단계 안내 패널을 띄운다(로그인 → 메뉴 → 입력값 → 발급 → 출력). 이 모드에서 하네스는 브라우저에 연결하지 않는다.
2. 사용자가 직접 로그인·입력·발급·출력(PDF 저장)한다. 패널의 '복사' 버튼으로 사업자번호·주소 등을 붙여넣을 수 있다.
3. 저장된 PDF가 감지되면 하네스가 보관함으로 옮기고 메타데이터(발급일·유효기간)를 추출해 만료 추적·백업·알림에 올린다.
4. 감사 로그에는 '후처리 모드 실행'으로 기록된다.

홈택스 이중로그인: 실행 전 "다른 기기에서 홈택스에 로그인하면 작업이 중단됩니다" 안내, 세션이 끊기면 재개 여부를 묻는다.

## 14. 전자세금계산서 기한 알림 (Phase 2 후보, 법률 의견 대상)

발급기한은 공급시기(월합계는 다음 달 10일), 전송기한은 발급 다음 날이다. 세무 상담이 아니라 **기한 캘린더**로서 "이번 달 발급 미완료 거래처"와 D-day 알림을 제공한다. 가산세율 등 세법 수치의 표시 여부는 법률 의견(세무사법 광고·상담 경계)에 따라 정한다. 세액·공제 판단은 하지 않는다.

## 15. 공고문 → 서류 꾸러미 (K-01, Phase 2)

공고 1건은 평균 6.4종의 서류를 3.6곳에서 요구한다. 25/36건이 발급일 조건을 거는데 그 기준이 제각각이다(07 §0). 그래서 공고 단위로 서류를 준비하게 한다.

1. 사용자가 공고문 PDF·HWP 또는 본문을 넣는다. 공고문은 공개 문서이므로 마스킹 없이 Terra로 보낸다.
2. Terra가 요구 서류를 표준 서류명으로 정리하고, 서류별 발급일 조건(N개월 이내, 공고일 이후, 마감일까지, 유효기간 내, 말소사항 포함)과 제출 단계(신청·선정 후·협약)를 뽑는다. 결과는 사용자가 확인·수정한다.
3. 로컬 규칙이 보관함과 대조해 서류마다 상태를 매긴다: 재사용 가능 / 새로 발급 필요 / 직접 준비(법인인감 등 범위 밖) / 공동이용·마이데이터로 생략 가능(공고문에 명시된 경우).
4. 새로 발급할 서류는 해당 플레이북을 묶어 실행한다. 비가역 승인 규칙(승인 대기 카드)은 같고, 결제(S-03)는 사용자에게 넘긴다.
5. 결과는 공고별 폴더(파일명 규칙 포함)와 체크리스트로 나온다. 선정 후 단계의 서류는 마감일 알림으로 남긴다.

하지 않는 것: 신청서·사업계획서 작성, 기관 시스템 업로드 대행, 공고 적격 여부 판단.

## 16. 급여대장 (ADR-031, Phase 1 베타)

급여대장을 정말 편하게 작성할 수 있게 하고, 4대보험 계산을 포함한다(결정). **사장님이 원할 때만 쓰는 기능이다.** 쓰지 않는 사장님에게는 숨긴다. 최소한의 입력으로 되게 하고, 필요하면 근무표(shift) 기능까지 둔다. 앱은 4대보험 취득·상실 신고를 하지 않고 계산과 정리까지만 한다(결정, ADR-034 결정 8). 원천징수액 계산 보조는 세무대리가 아니다(ADR-031 결정 2). Phase 1 베타에 내고, 계산은 결정적 산술이라 모델을 부르지 않는다(결정 7). 아래 흐름·계산·범위는 제안이다.

- **처음 한 번 입력**: 직원별 입사일, 월급, 비과세 항목(식대 등), 공제대상가족 수, 8세 이상 20세 이하 자녀 수, 원천징수 비율(80·100·120%).
- **매달**: "이번 달도 지난달과 같나요?"를 한 번 묻는다. 사장님은 수당·결근처럼 바뀐 것만 고친다.
- **산출물**: 급여대장(근로기준법상 임금대장)과 직원별 임금명세서(2021-11-19부터 교부 의무). 임금명세서는 PDF로 만들고 교부는 사장님이 인쇄하거나 직접 전한다. 앱은 직원에게 보내지 않는다.
- **4대보험**: 정본은 공단 고지액이다(S-06). 요율 계산값은 예상치로 옆에 두고, 차이는 표시만 하고 판정하지 않는다. 급여일이 고지보다 앞서면 예상치를 "예상"으로 표시해 쓴다.
- **소득세**: 근로소득 간이세액표로 구하고, 지방소득세는 소득세의 10%다.
- **표**: 4대보험 요율, 국민연금 상·하한(매년 7월 변경), 간이세액표는 시행일이 붙은 데이터로 둔다. 금액은 원 단위 정수이고 반올림·절사 규칙은 표마다 명시한다.
- **근무표**(채택, ADR-034 결정 8, 2026-11-05): 간단한 계산기 수준이다. 사장님은 직원별 **세전 금액만 입력**하고, 앱은 원천징수(간이세액표·지방소득세)와 4대보험 근로자 부담분을 뺀 **세후 금액**을 보여 준다. 연장·야간·휴일 가산과 주휴는 앱이 계산하지 않는다. 사장님이 세전 금액에 반영한다. 근무 시간 합계는 임금대장에 적을 보조 입력으로만 받는다.
- **범위**: 1차는 월급제 상용직이 기본이다. 시급제는 사장님이 세전 금액을 정해 근무표 계산기에 넣는다(시급 × 시간 계산은 하지 않는다). 일용직, 퇴사 정산, 연말정산은 다음 단계다.
- 급여대장에는 주민번호가 들어가므로 서류 본문과 같은 등급(로컬 전용, 서버 평문 없음)으로 다룬다.

## 17. 세무사 꾸러미 (ADR-032, Phase 1 베타)

공고문 → 서류 꾸러미(§15, K-01)와는 다른 기능이다. 9,900원 한 플랜에 들어가고(ADR-034) Phase 1 베타에 낸다. 세무사 꾸러미의 수집·정리·내보내기·알림은 모델을 부르지 않는다(ADR-032 결정 11). tex는 사장님 편 도구다. 세무사는 판단하고 신고하고, tex는 사장님 PC에서 발급하고, 모으고, 정리해서 넘긴다(결정). 원칙은 둘이다. 매달 필수 제출자료 중 **공통적인 것은 UI로 강하게 지원하고**, **일부 업체에만 필요한 것은 세무사 꾸러미에 추가할 수 있게 한다**(결정).

| 층 | 항목 | 들어오는 길 |
|---|---|---|
| 1층: 모든 업체 공통 | 매출·매입 세금계산서 | 홈택스 조회(H-02) |
| | 급여대장 | §16(Phase 1 베타). 급여대장 기능을 안 쓰는 업체는 파일 첨부 |
| | 사업용 신용카드 사용내역 | 내역 화면의 [최신화] 버튼(H-12). 아래 참고 |
| | 종이 세무자료(종이 세금계산서·종이 계산서·간이영수증 등) | 폰 앱에서 촬영(Phase 1, ADR-034), PC에서는 파일 첨부(선택) |
| | 이번 달 빠진 것(제안) | 앱이 모은다(증빙 없는 지출, 확인 안 한 급여) |
| 2층: 업종 묶음(설정에서 업종을 고르면 생김) | 배달앱 월별 정산내역(음식점) | J-01 |
| | 오픈마켓 월별 정산내역(온라인 판매) | J-02 |
| | 영수증을 발행하지 않은 순수 현금매출 내역(현금매출이 있는 업종) | 하루 한 번 "오늘 현금 매출" 숫자 하나(제안). 폰 앱이나 PC에서 넣는다 |
| 3층: 업체별 추가 항목 | 예: 임대차계약서, 차량 운행일지, 해외 결제 인보이스, 대출 이자 내역 | "세무사 꾸러미에 항목 추가"로 이름·주기를 정하면 업로드 칸이 생긴다(제안) |

**사업용 카드 [최신화] (결정)**

- 매일 자동으로 가져오지 않는다. 내역 화면에 [최신화] 버튼을 두고 옆에 "마지막 최신화: n일 전"을 표시한다. 버튼을 누르는 것이 곧 실행 승인이다.
- 사람이 시작한 실행이라 데몬 규칙(§6, ADR-026)에 걸리지 않는다. 조회라 승인 바는 띄우지 않는다.
- 로그인은 고정한 발급 인증(ADR-020)을 따르고, 그 수단으로 이 메뉴가 열리는지는 PoC로 확인한다. 보안카드는 버튼 한 번, 간편인증은 폰 승인 한 번 더, 공동·금융인증서는 비밀번호 직접 입력이다.
- 폰에서 누르는 것은 폰 승인이 들어오는 Phase 2이고(ADR-034 결정 9 채택) 생체 확인이 붙는다. 공동·금융인증서 사용자는 PC에서 누른다(§7).
- 연달아 눌러도 요청률 정책(D03 §7) 안에서만 실행한다.
- 건별로 메모를 달 수 있다. 용도 분류나 경비 인정 판단은 하지 않는다.

**종이 증빙**: 모바일 앱에서 촬영해 올리고, PC에서는 파일 첨부(선택)다(결정). 금액·날짜·상호·사업자번호를 읽어 내고, 원본 사진을 함께 보관하며, 읽어 낸 값은 사장님이 확인하고, 폰에서 PC로는 E2EE 전송으로 넘긴다(제안). 글자 읽기는 기기 안에서 하는 것을 기본으로 한다(ADR-032 조건).

**내보내기**

- 엑셀은 우리 표준 서식으로 먼저 낸다(결정, ADR-034 결정 7). 세무사랑·위하고T 업로드 서식 맞춤은 다음 단계다. 표준 서식은 다음 단계의 서식 맞춤을 생각해 사업자번호, 거래일, 공급가액·세액을 별도 열로 둔다(제안).

아래는 제안이다.


- 세무사 꾸러미는 매달 엑셀 한 파일이다. 시트는 매출, 매입, 사업용 카드, 종이 증빙(사진 파일 연결), 정산·현금매출(켜진 업종만), 급여대장, 원천세 요약(인원, 총지급액, 소득세, 지방소득세), 추가 항목, 빠진 것.
- 파트너 세무법인이 쓰는 프로그램 이름과 업로드 양식은 다음 단계의 서식 맞춤에 쓴다.
- 원천세 신고 기한(다음 달 10일, 반기납부 사업장은 반기)에 맞춰 매달 초 "세무사 꾸러미 준비됨"을 알린다. 사장님이 미리 보고 [보내기]를 누른다.
- [보내기](채택, ADR-034 결정 10, 2026-11-05): §18에 등록한 "내 세무사" 이메일 주소로, 사장님 PC의 기본 메일 프로그램에 꾸러미 파일을 첨부한 메일 창을 연다. 사장님이 그 창에서 보내기를 누른다. 우리 서버를 거치지 않는다. 받는 주소와 첨부는 앱이 설정에서 정하고 화면이 바꿀 수 없다. 메일 프로그램이 없거나 웹메일만 쓰면 [폴더 열기]로 대신한다. 우리 메일 서버로 보내는 안은 폐기했다.
- 급여대장에는 주민번호가 있다. 엑셀에 암호를 걸고, 암호는 다른 경로(문자 등)로 전한다.
- (채택, 2026-11-05, ADR-032 결정 8) 첨부는 암호 엑셀과, 사진·PDF가 있으면 같은 암호의 ZIP 두 파일이다. 급여 시트의 주민번호는 처리 근거 확인 전 가림이 기본이고 사장님이 설정에서 켤 수 있다(R13 D-L3). 증빙과 대조되지 않은 카드 지출은 표시만 한다.

## 18. 세무사 연결 (ADR-034)

- 연결은 양쪽에서 할 수 있다. 사장님이 내 세무사를 초대하거나, 세무사가 거래처를 초대한다. 연결 대상은 사장님이 이미 계약한 세무사다(결정).
- 세무사는 발급하지 않는다. 판단하고 신고한다(결정, §12).
- **Phase 1 (채택, ADR-034 결정 10, 2026-11-05)**: 세무사 화면이 없으므로 사장님이 "내 세무사" 이메일 주소를 등록하고, 세무사 꾸러미를 그 주소로 보내는 것까지만 한다(§17). 세무사가 거래처를 초대하는 흐름은 세무사 화면과 함께 다음 단계에 넣는다.
- **다음 단계: 세무사 화면**: 내 고객 리스트와 대시보드가 있고, 양식에 맞춘 파일을 받는 데까지다. 목표는 고객의 실수로 세무사가 피곤해지지 않게 하는 것이다. AI 기능은 없다. 요금은 거래처당 월 최대 5천 원이다(결정, 01 §5).
  - (제안) 받기 전용이다. 발급, 수정, 사장님 홈택스 조작은 할 수 없다. §12의 "다수 고객 대행용 멀티 테넌트"와 무엇이 다른지는 별도 ADR로 정의한다.
  - (제안) 서버는 암호문만 보관한다(ADR-006 방식). tex는 세무사무소의 개인정보 수탁자가 되므로 위탁계약서, 재위탁 목록, 안전조치 증빙을 갖춘다(개인정보 보호법 제26조).
  - 자료가 언제 보이는지(사장님이 보낼 때만인지, 항상 동기화인지)는 열린 질문이다.
- §9의 대리 사용 억제(계정당 프로필 2개, 공급자 = 프로필 사업자 확인)는 그대로다. 세무사 화면은 사장님 계정에 들어가지 않는다.
