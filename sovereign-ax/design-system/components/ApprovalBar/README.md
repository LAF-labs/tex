# ApprovalBar

PC에서 되돌릴 수 없는 발급·전송을 승인받는 유일한 자리다(ADR-021). 대화창과 따로, 앱이 스크립트 없는 정적 화면으로 그린다. 그래서 대화창이 악성 내용에 장악돼도 이 바를 누른 것처럼 꾸밀 수 없다.

- 자리: 대화 열 하단, 입력창 바로 위(사용자 결정 2026-11-01). 폭은 대화 열 폭 `min(chat-max, 창 폭 − rail-width − panel-width)`이고, 그보다 좁으면 레일 오른쪽부터 창 끝까지 넓힌다. 승인 대기 카드가 맨 끝이면 카드의 버튼 줄처럼 붙어 보인다. 대화 화면은 이 자리를 비워 두고, 입력창은 승인 대기 중 3줄 높이까지만 늘어난다. 바와 입력창 사이에 간격을 둔다.
- 구성: 요약 줄 3줄(라벨 칸 고정 + 값 한 줄) → 동작 글자. **바 전체가 버튼 하나**이고, 바 안에 작은 버튼을 따로 두지 않는다.
  - H-01: 공급받는자(상호 · 사업자번호), 합계금액 · 세액, 받는 이메일.
  - 민원증명(H-03·H-04 등): 서류명 · 부수, 발급 대상(상호 · 사업자번호), 용도·제출처 · 주민등록번호 공개 범위.
- 값 줄이기: 사업자번호·금액·이메일 `@` 뒤는 줄이지 않는다. 상호와 이메일 `@` 앞만 말줄임(…)으로 줄인다. 줄이지 않는 값이 안 들어가면 "창을 넓혀 주세요" 상태가 된다.
- 모양: 직각 모서리, 그림자 없음(앱 화면 밖에 그릴 수 없고 둥근 모서리도 클릭을 받기 때문이다). 서체는 시스템 서체(tokens `승인 바`). 파랑(`accent`) 채움은 승인 상태에만 쓴다.
  - v1.2(2026-11-02) 시각 다듬기: 무장 전은 `accent-soft` 바탕에 `accent` 글자, 무장됨은 `accent` 바탕에 `on-accent` 글자, 무장 거부는 `surface` 바탕에 `ink` 글자와 `line-strong` 안쪽 테두리다. 라벨 칸은 12px 500이고 무장 상태에서는 `on-accent` 78%로 값보다 한 단 뒤에 선다. 처음 거래·중복 경고 같은 표시 칩은 12px 500, 현재 글자색 1px 테두리, 모서리 6px(`radius-sm`). 동작 글자는 18px 700, 자간 -0.01em. 바 안의 치수(높이 90, 좌우 16, 라벨 칸 76, 동작 칸 132, 간격 12 DIP)와 세 상태 페이지 교체, 무장 지연 0.6초, 머무름 0.15초, 키보드 승인 없음은 그대로다(ADR-021).
  - v1.2.1(2026-11-03, ADR-024): 원장에 같은 건이 `committed`이거나 발급 여부를 모르면(`in_doubt`·`armed`·`dispatched`) 무장 상태 바탕을 `attention`으로 바꾸고 표시 칩에 "이미 발급됨(승인번호 있음)" 또는 "발급 여부 확인 안 됨"을 쓴다. 동작 글자는 각각 "그래도 한 번 더 발급"과 "같은 건 기록을 확인했고 발급"이다. 동작 칸에서 두 줄을 넘지 않게 짧게 쓴다. 작성일자가 오늘(한국 시간)과 다를 때만 합계 줄 끝에 줄이지 않는 조각 " · 작성일 YYYY-MM-DD"를 붙이고, 오늘이면 줄을 늘리지 않는다. 작성일 형식이 맞지 않으면 무장하지 않는다.
  - 클릭 활성화 예외(앱이 뒤에 있을 때 첫 클릭 승인)는 앱이 연 인계(전용 Chrome·비밀 입력 창)에서 120초 안에 돌아올 때만 쓴다. 그 밖의 활성화와 창이 포커스를 잃는 순간은 무장 전 페이지로 되돌린다(ADR-024).

|---|---|---|---|---|
| 무장 전(0.6초) | 있음 | 승인하고 발급 | 흐린 파랑 | 아니요. 누르면 "잠시 뒤 다시 눌러 주세요" |
| 승인 | 있음 | 승인하고 발급 | 파랑 | 예. 마우스를 움직인 직후 0.15초 안이면 "마우스를 조금 움직인 뒤 눌러 주세요" |
| 처음 거래·처음 보내는 주소 | 해당 줄 끝에 표시 | 승인하고 발급 | 파랑 | 예 |
| 중복 경고 | 해당 줄 끝에 "같은 건 기록 있음"(또는 "직전 시도 발급 안 됨", "다른 PC 기록 확인 불가") | 같은 건 기록을 확인했고 발급 | 파랑 | 예. 이 클릭이 명시 확인이다 |

| 무장 거부 | 넘친 칸·고칠 칸 표시 | 창을 넓혀 주세요(또는 고칠 칸 이름, 필요한 값 없음, 값 대조 불일치) | 무채색 | 아니요 |
| InDoubt 증언 | 그 건의 공급받는자·합계 2줄 + E-13 고정 문구 | 홈택스 발급목록에 없음을 확인했어요 | 황토(`attention`) | 예 |
| Hello 설정 | 없음 | 발급 전 Windows Hello 확인 켜기(끄기) | 무채색 테두리 | 예 |

- 승인 대기 중에는 작업 패널을 접어도 패널 폭을 비워 둔다. 바 자리는 패널 폭을 늘 빼고 계산하므로, 접힌 패널 자리를 대화 열이 쓰면 바와 대화 열이 어긋난다(PoC-9 측정 170 DIP).
- 자리 우선순위는 승인(게이트) > 증언 > Hello 설정이다. 높은 것이 오면 낮은 것은 내려간다.
- 무장 전·무장됨·무장됨 + 문구의 세 화면을 앱이 바꿔 불러온다(애니메이션 없음). 무장된 바에 문구만 보일 때는 흐려지지 않는다.
- 대화 카드의 안내 문구는 "아래 [승인하고 발급]에서 값을 한 번 더 확인하고 눌러 주세요"로 통일한다. "승인 바"라는 말은 사용자 화면에 쓰지 않는다.
- 하지 말 것: 바 안의 작은 버튼, 값의 끝 자르기, 그림자·둥근 모서리, 키보드 포커스 링으로 승인하는 동작(키보드 승인 없음).
