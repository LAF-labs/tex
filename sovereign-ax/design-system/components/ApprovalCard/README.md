# ApprovalCard

PC에서 되돌릴 수 없는 발급·전송을 승인받는 유일한 자리다. **main이 그리는 신뢰 영역**이다(ADR-021 결정 7, 2026-11-06 개정). 대화창과 따로, 앱이 스크립트 없는 정적 화면으로 그린다. 대화창이 악성 내용에 장악돼도 이 카드를 덮거나, 같은 모양을 그려 승인으로 만들 수 없다. 이전의 승인 바(ApprovalBar, 90px 띠)와 렌더러의 승인 대기 카드 두 겹을 이 카드 하나로 합쳤다.

## 지킬 것(ADR-021 결정 7 유지 원칙)

1. **값은 main이 엔진 readback에서 직접 받는다.** 게이트 요청 `fields`(V-03h)만 쓰고, 렌더러 문자열과 패키지 문자열은 쓰지 않는다. 라벨은 앱 내장 `fieldKey` 사전이다.
2. **렌더러가 겹치거나 흉내 낼 수 없다.** 카드는 메인 창 `contentView`의 맨 위 자식 뷰다. 렌더러가 다른 자리에 비슷한 카드를 그려도 그 클릭은 근거가 되지 않는다.
3. **기본 포커스는 [중지]다.** Enter·Space·조합키로는 승인되지 않는다. 승인은 main이 관찰한 [승인하고 발급] 영역의 마우스 down → up뿐이다.
4. **두 버튼을 떨어뜨린다.** 사이에 앱 상수 간격을 둔다. 판정 영역은 main의 고정 레이아웃(DIP)으로 정하고 렌더러 보고는 쓰지 않는다. ~~무장 지연(0.6초)·머무름(0.15초)은 [승인하고 발급]에만 걸고, [중지]는 기다리지 않는다.~~ (2026-11-09 철회, 사용자 결정: 두 버튼 모두 카드가 뜨자마자 눌린다. ADR-021 개정)
5. **발급 취소와 황토 증언도 같은 틀이다.** 동작 글자와 색만 바뀐다.

## 자리

- 대화 열 아래, 입력창 예약 영역 위다. 위치는 main이 창 크기만으로 정한다(ADR-021 결정 1 위치 규칙).
- 폭은 대화 열 폭 `min(chat-max, 창 폭 − rail-width − panel-width)`이다. 줄이지 않는 조각이 안 들어가면 레일 오른쪽부터 창 끝까지 넓히고, 그래도 넘치면 무장하지 않는다.
- 높이는 main이 서류 종류별 앱 내장 표의 줄 수로 정한다. 렌더러가 보고하는 높이는 쓰지 않는다. 대화 화면은 그 높이만큼 자리를 비운다.
- 승인 대기 중 렌더러의 작성 카드는 **"작성 완료" 한 줄**로 접힌다(체크 + "작성 완료" + 서류·거래처·합계 한 줄). 렌더러는 이때 되읽은 값을 그리지 않는다.
- 승인 대기 중에는 작업 패널을 접어도 패널 폭을 비워 둔다(PoC-9).

## 구성(위에서 아래로)

1. 머리 줄: 서류 종류 · 상호(앱 라벨) + 상태 칩 "승인 대기".
2. 금액(D1): 합계, 그 아래 한 줄로 공급가액 + 세액. 발급 취소는 음(−) 합계.
3. 되읽은 값 전체(라벨 칸 고정 + 값 한 줄). 줄마다 끝에 표시 칩을 붙일 수 있다.
   - H-01 세금계산서: 공급받는자(상호 · 사업자번호), 품목, 작성일자, 받는 이메일. 처음 거래(`$first.bizNo`), 처음 보내는 주소(`$first.email`), 중복 경고(`$dup.*`).
   - 민원증명(H-03·H-04 등): 서류명 · 부수, 발급 대상(상호 · 사업자번호, 개인이면 이름), 용도·제출처, 주민등록번호 공개 범위.
   - 발급 취소(H-01c, ADR-036): 공급받는자, 원본(작성월 · 승인번호 끝 8자리), 사유, 발급기한(안내, 출처 한 줄).
4. 비가역 한 줄: 서류 종류별 앱 고정 문구(예: "홈택스에서 다시 읽은 값이에요. 승인하면 바로 발급되고 {상호} 메일로 가요. 되돌릴 수 없어요." `{상호}`는 `fields`의 값). 패키지 문자열이 아니다.
5. 버튼 줄: 왼쪽 [중지], 앱 상수 간격, 오른쪽 [승인하고 발급](남은 폭 전부).

값 줄이기는 승인 바 규칙 그대로다. 사업자번호·금액·이메일 `@` 뒤는 줄이지 않고, 상호와 이메일 `@` 앞만 말줄임(…)으로 줄인다. 국제화 도메인은 punycode로 보인다. 값에 제어문자·양방향 문자·폭 없는 문자가 있으면 무장하지 않고 고칠 칸을 보인다.

## 모양

- 서체는 시스템 서체(`font-system`)만 쓴다(CSP, 외부 서체 없음). 합계 24/30 600, 값 14/22(`approve-body`), 동작 글자 16 700. 라벨은 12 500 `ink-3`.
- 뷰는 불투명한 사각형이다. 뷰 바탕은 `canvas`로 칠해 대화 열과 이어 보이게 하고, 그 안의 카드 면은 `surface`에 `radius-lg`(12)다. 둥근 모서리는 그림일 뿐이고 판정 영역은 두 버튼의 사각형뿐이다. 그림자는 없다.
- 뷰가 불투명한 사각형이어야 렌더러가 비쳐 보이거나 겹쳐 그릴 수 없다. 카드 밖, 뷰 안의 여백은 클릭을 삼킨다(아래 렌더러로 통과시키지 않는다).
- 카드 테두리는 1.5px로 상태 색을 따른다: 승인 대기 `accent`, 증언·같은 건 확정 `attention`, 무장 거부 `line-strong`. 렌더러 카드(1px `line`)와 테두리 굵기로도 구분된다.
- [중지]: 보조 버튼(`surface` 바탕, `line-strong` 테두리), 폭 112 DIP, 높이 44. 기본 포커스라 `focus-ring` 2px 링이 처음부터 보인다.
- [승인하고 발급]: 높이 44, 무장됨은 `accent` 채움에 `on-accent`, 무장 안 됨(커서 위장 중일 때만)은 `accent-soft` 바탕에 `accent` 글자. 두 버튼 사이 간격은 앱 상수 48 DIP(캔버스 T-03 기준, PoC MainConfirm 측정으로 확정).
- 표시 칩: 12px 500, 현재 글자색 1px 테두리, 모서리 6(`radius-sm`).
- 애니메이션 없음. 카드는 첫 페이지부터 무장됨이다. 커서 위장 중에만 무장 안 됨 + 문구 페이지로 바꿔 불러온다.

## 문구

- 사용자 화면에 "승인 카드"·"승인 바"·"신뢰 영역"이라는 말을 쓰지 않는다.
- 렌더러 대화에는 "작성 완료" 한 줄만 남고, "아래 [승인하고 발급]에서…" 안내 문장은 쓰지 않는다(값이 바로 아래 카드에 있다).

## PoC MainConfirm으로 확인할 것(ADR-021 결정 7 조건)

- 작은 창에서 카드 높이가 대화 열을 얼마나 가리는지.
- 카드가 뜰 때 입력창의 키보드 포커스를 가져가는지, 타이핑 중 Enter가 [중지]로 가는지.
- 정적 페이지(`javascript:false`)에서 [중지] 기본 포커스와 두 버튼 판정이 되는지.

## 하지 말 것

- 렌더러 카드 안의 승인 버튼(PC), 카드에 렌더러·패키지 문자열 쓰기, 값의 끝 자르기.
- [승인하고 발급]을 기본 포커스로 두기, 키보드 승인, 두 버튼 붙이기.
- 그림자, 애니메이션, 커스텀 커서, 외부 서체.
