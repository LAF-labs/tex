# 소버린 AX 디자인 시스템

> 작성일: 2026-10-30 · 갱신: 2026-11-07(승인 카드, ADR-021 결정 7) · 상태: v1.2(디자인 갱신 "더 조용하고, 더 적게, 더 분명하게") · 관련: 08 화면 기획, ADR-014·019·020·021, research/R12

미리보기(`preview.html`)는 아티팩트가 `tokens.json`에서 만드는 CSS 변수 위에서 렌더된다. 저장소의 `preview.html`만 열면 색과 서체가 빠진다. 전체 모습은 `direction-review.html`로 본다. 토큰이나 컴포넌트를 바꾸면 아티팩트와 이 폴더를 함께 고친다.

소버린 AX는 자영업자·소규모 법인이 세금계산서와 홈택스 증명서 발급을 맡기는 Windows 데스크톱 에이전트다. 화면은 서류처럼 정확하고 조용해야 한다. 바탕과 글자는 무채색이고, 색은 두 가지 뜻에만 쓴다. 어떤 값이 얼마나 중요한지는 색이 아니라 **데이터 위계**([data-hierarchy.md](data-hierarchy.md)) 단계가 정한다.

## 원칙

- 색은 두 가지 뜻만 가진다. `accent`(파랑)는 사용자의 차례와 승인, `attention`(황토)은 확인이 필요함이다. 그 밖의 모든 것은 `ink`·`surface` 계열 무채색으로 만든다.
- 값을 강조하려고 색이나 굵기를 바꾸지 않는다. 데이터 위계 D1~D6 중 맞는 단계의 스타일을 고른다.
- 구분은 선(`line`)으로 한다. 그림자(`shadow-overlay`)는 떠 있는 것에만 쓴다. 입력창만 `shadow-raised`로 살짝 뜬다.
- 되돌릴 수 없는 승인은 대화 열 아래 승인 카드(PC)와 모바일 승인 시트의 승인 버튼으로만 받는다. 승인 카드(components/ApprovalCard)는 main이 대화창과 따로 그리는 스크립트 없는 신뢰 영역이고, 렌더러의 대화 카드에는 승인 버튼을 두지 않는다. 별도 승인 창은 없다(ADR-020, ADR-021 결정 7).
- 홈은 대화 하나다. 숫자 타일 대시보드, 마스코트, 그라데이션, 이모지를 쓰지 않는다.
- 더 조용하고, 더 적게, 더 분명하게(v1.2). 면은 네 단(`canvas`·`surface`·`surface-tint`·`surface-overlay`)으로 끝내고, 테두리는 필요한 곳에만, 굵기는 400·500·600 셋으로, 움직임은 상태가 바뀔 때만 쓴다.

## 색

- 바탕은 `canvas`, 카드·작업 패널·레일·제목줄·입력창은 `surface`, 선택된 레일 항목·행 hover·무채 상태 칩·검색 칸은 `surface-tint`, 누름 상태와 서식 표의 라벨 칸은 `surface-sunken`, 명령 팔레트·메뉴·모달·토스트와 사용자 말풍선은 `surface-overlay`(말풍선은 그림자 없음). 모달 뒤는 `scrim`.
- 글자는 네 단계다. 값과 본문은 `ink`, 보조 문장·식별 번호·추정 값·무채 칩은 `ink-2`, 라벨·출처는 `ink-3`, 비활성과 빈 값 "—"만 `ink-4`.
- 카드 테두리와 서식 표의 선, 작은 보조 버튼(복사·빠른 실행 칩·필터)의 테두리는 `line`, 카드 안의 보조 구분선은 `line-soft`, 입력 칸·주요/보조 버튼·선택지의 테두리는 `line-strong`(3:1 이상). 빈 입력 칸은 테두리가 유일한 식별 수단이라 반드시 `line-strong`이다(WCAG 2.2 1.4.11).
- `accent`는 내 차례 칩, 승인 대기 칩, 실행 단계의 현재 점, 승인 버튼(승인 카드의 무장된 [승인하고 발급]), 승인 카드 테두리, 승인 도장, 포커스 링(`focus-ring`)에만 쓴다. 링크, 선택된 항목, 일반 주요 버튼(`sx-btn-primary`, `ink`로 채움)에는 쓰지 않는다. 한 화면에 파랑으로 채운 면은 하나까지다. `accent-strong`은 파랑 버튼의 hover·누름에만 쓴다(승인 카드에는 hover가 없다).
- `accent-soft`는 내 차례 칩, 차례 안내 줄, 무장 전 [승인하고 발급]의 바탕이다. 그 위 글자는 `ink` 또는 `accent`.
- `attention`은 확인 필요, 만료 임박(D-7 이하), 휴·폐업 경고, 입력 형식 오류, 되읽기 불일치, InDoubt 증언 카드에 쓴다. 바탕이 필요하면 `attention-soft`.
- 완료는 색으로 표시하지 않는다. `ink` 글자와 체크 표시다. 실패와 차단에도 빨강이 없다. `ink` 테두리 칩과 원인 문구로 보여 준다.
- 모든 글자 토큰은 `surface`·`canvas`·`surface-tint` 위에서 두 테마 모두 4.5:1 이상이다(`ink-4` 제외). 토큰 설명에 실제 대비 값이 있다.

## 서체

- 본문과 UI는 `font-sans`(IBM Plex Sans KR), 식별 번호는 `font-mono`(IBM Plex Mono), 서류 이름은 `font-serif`(Noto Serif KR)로 `doc-name`에만 쓴다. 세 서체 모두 Google Fonts에서 불러오고, 앱에는 OFL 파일로 넣는다.
- 굵기는 400(본문·값)·500(라벨·버튼·칩)·600(제목·D1·주요 버튼) 셋이 기본이다. 700은 서류 이름과 승인 카드의 동작 글자에만 쓴다. 한글 라벨에는 자간을 넣지 않는다.
- 보안카드 등록은 앱과 같은 서체를 쓰고 번호 칸만 `font-mono`다(SecretField). 창은 대화창 안 모달이 아니라 main이 띄우는 OS 테두리 창("금고 · …" 제목)이다(ADR-025·026).
- 승인 카드는 시스템 서체(`font-system`)만 쓴다(ADR-021의 CSP). 값은 `approve-body` 14/22, 합계 24/30 600, 동작 글자 16 700이다(토큰 묶음 이름 "승인 바"는 코드가 읽어서 그대로 둔다).
- 수치에는 고정폭 숫자(`font-variant-numeric: tabular-nums`)를 쓴다. `figure-lg`·`figure`·`value`에 이미 들어 있다.
- 가장 작은 글자는 12px(`label`, `meta`)이다. 한글 본문 행간은 1.6이다(`body` 15/24). 화면 제목(`title-screen`)은 18/26이다.

## 간격과 배치

- 간격은 4px 단위(`space-1`~`space-7`)다. 카드 안쪽 `space-4`, 카드 안 요소 사이 `space-3`, 메시지 사이 `space-4`, 대화 좌우 `space-5`. 한 줄 안의 미세 간격만 `space-0`(2px)이다. 14·18px 같은 반 칸 값은 쓰지 않는다.
- PC 메인은 `titlebar-height` 제목줄 아래에 `rail-width` 레일, 가운데 대화, `panel-width` 작업 패널을 둔다. 대화 콘텐츠는 `chat-max`에서 멈추고, 남는 폭은 작업 패널이 쓴다. 승인 카드의 자리는 이 치수와 앱 상수로만 정하고, 높이는 서류 종류별 줄 수로 main이 정한다(ADR-021 결정 7). v1.2에서 치수는 바꾸지 않았다.
- 모서리는 버튼·입력 칸·선택지 `radius-md`(8), 카드·목록 표 `radius-lg`(12), 입력창·떠 있는 창·사용자 말풍선 `radius-xl`(16), 칩·보내기 버튼 `radius-full`. 서식 칸과 작은 복사 버튼은 `radius-sm`(6). 승인 카드는 불투명한 사각형 뷰 안에 `radius-lg` 카드 면을 그리고, 판정 영역은 두 버튼의 사각형뿐이다. 모든 것을 크게 둥글리지 않는다.
- 조작 높이는 `control-height-sm`(28, 빠른 실행 칩·필터·프로필 전환), `control-height`(32, 버튼·입력 칸), `control-height-lg`(40, 모바일 시트)다.
- 라벨·값 목록의 라벨 칸은 `field-label-width`로 맞춘다.
- 스크롤바는 평소 보이지 않는다. PC에서는 마우스가 스크롤 영역 위에 있거나 스크롤하는 동안만 `line-strong` 얇은 막대로 보이고, 멈추면 다시 투명해진다(앱이 스크롤 뒤 0.8초 동안 `is-scrolling`을 붙인다). 모바일은 OS가 스크롤할 때만 띄우는 표시를 그대로 쓴다.
- 좌우 스크롤은 만들지 않는다. 넘치는 칩·버튼 줄은 줄바꿈하고, 표는 열을 줄이거나 값을 줄바꿈한다. 예외는 문서를 확대해 볼 때뿐이다(특히 모바일).

## 상태

작업 상태는 StatusChip 하나로 보여 준다. 열한 가지이며 강조색이 붙는 것은 셋뿐이다. 무채 칩은 테두리 없이 `surface-tint` 바탕이다.

- 내 차례(`is-turn`)·승인 대기(`is-waiting`): `accent`.
- 확인 필요(`is-attention`): `attention`.
- 작성 중·준비 중·발급 중·확인 중·처리 대기: 기본(무채색). 확인 중은 응답이 끊겨 앱이 발급목록을 다시 조회하는 상태다.
- 완료(`is-done`): `ink` + 체크. 중지됨(`is-stopped`): `ink-3`. 실패(`is-fail`): `ink` 테두리.
- 조작의 hover는 `surface-tint`, 누름은 `surface-sunken`이다. 주요 버튼의 hover는 `ink-2`, 승인 버튼의 hover는 `accent-strong`이다.

## 움직임

움직임은 상태가 바뀌었음을 알리는 데만 쓴다. hover·누름의 색 변화 `motion-fast`(120ms), 상태 칩 변화 `motion-base`(160ms), 작업 패널 열림 `motion-slow`(220ms), 곡선은 `ease-out`. 진행 중은 StepList 현재 점이 `motion-pulse`(2.4초) 주기로 숨 쉬듯 흐려졌다 돌아오는 것으로만 보여 준다. 튀는 효과, 회전 아이콘, 등장 애니메이션을 쓰지 않는다. 승인 카드에는 애니메이션이 없다(정적 페이지 교체, ADR-021). 동작 줄이기 설정이면 모두 끈다.

## 포커스

키보드 포커스는 `focus-ring` 2px 실선, 간격 2px이다. 테두리가 있는 입력 칸은 링 대신 테두리 색을 `ink-2`로 바꾼다. 승인 카드의 기본 포커스는 [중지]이고 링이 처음부터 보인다. 키보드로는 승인되지 않는다(Enter·Space·조합키 모두, ADR-021 결정 7).

## 아이콘

1.5px 선 아이콘을 레일 20px, 본문 16px로 쓴다. 색은 주변 글자 색을 따른다. 채운 아이콘과 이모지는 쓰지 않는다. 로고는 아직 없다. 로고 자리에는 이름을 `title-card`로 쓴다.

## 테마

라이트와 다크는 같은 토큰 이름을 쓴다. 기본값은 시스템 설정을 따른다. 다크에서는 위로 뜰수록 밝다(`canvas` → `surface` → `surface-tint` → `surface-overlay`). 라이트에서는 `canvas`와 `surface`의 차이를 작게 두어 카드가 떠 보이지 않게 한다. 다크의 `accent`는 밝은 파랑이므로 그 위 글자는 `on-accent`(어두운 남색)다. 두 테마를 함께 설계하고 한쪽에서 다른 쪽을 만들어 내지 않는다.

## 문구

짧은 해요체로, 일어난 일과 사용자가 할 일만 쓴다. 사과·감탄·"AI가" 같은 표현을 쓰지 않는다. 버튼은 동사로 끝낸다.

- 내 차례: "카카오뱅크 앱에서 간편인증을 승인해 주세요." ("인증 대기 중입니다..." 아님)
- 결과 미확인: "발급됐는지 아직 모르겠어요. 중복 발급을 막으려고 다시 발급하지 않아요."
- 완료: "발급했어요. A상사 메일로 보낸 것도 확인했어요." ("성공적으로 완료되었습니다!" 아님)
- 범위 밖: "신고와 세금 판단은 하지 않아요. 신고에 필요한 증명서는 뗄 수 있어요."
- 버튼: "승인하고 발급", "다시 조회", "브라우저로 가기" ("확인", "다음" 아님)

## 변경 기록

### v1.2.2 (2026-11-07) · 승인 카드(ADR-021 결정 7)

- `components/ApprovalCard` 신설: main이 그리는 승인 카드 하나(금액, 되읽은 값 전체, 비가역 한 줄, [중지]·[승인하고 발급]). 기본 포커스 [중지], 두 버튼 사이 앱 상수 간격, 키보드 승인 없음. 발급 취소와 InDoubt 증언도 같은 틀이다. 기준 화면은 디자인 캔버스 T-03·D-01 발급 취소·예외(확인 필요)다.
- `components/ApprovalBar`는 폐지 기록으로 남긴다. 무장 지연 0.6초·머무름 0.15초·값 줄이기·상태 목록은 카드로 옮겼고, "바 전체가 버튼 하나"·"거절·중지는 바에 두지 않는다"는 철회됐다.
- 원칙·색·서체·간격·움직임·포커스 절과 Button·MainScreen·TaskCard·data-hierarchy의 승인 바 문장을 카드 기준으로 고쳤다.
- 바꾸지 않은 것: `tokens.json`(토큰 묶음 이름 "승인 바" 포함, 코드가 이름으로 읽는다)과 `components/bundle.css`(PoC 셸이 그대로 받는다). PoC 코드(approval-gate의 정적 HTML·두 버튼 판정·포커스)는 데스크톱 쪽 후속이다.

### v1.2 후속 (2026-11-03) · 스크롤바와 좌우 스크롤

- 스크롤바는 평소 투명하고, 마우스가 스크롤 영역 위에 있거나 스크롤하는 동안(`is-scrolling`)만 얇게 보인다(`bundle.css` "Scroll"). 터치 기기는 OS 표시를 그대로 쓴다.
- 좌우 스크롤을 만들지 않는다. 목록 표는 상자 안에서 가로로 밀지 않고 값을 줄바꿈한다.
- 서체 절의 보안카드 등록 문장을 SecretField 지침(OS 테두리 창, ADR-025·026)에 맞췄다.

### v1.2 (2026-11-02) · 디자인 갱신 "더 조용하고, 더 적게, 더 분명하게"

2026년 실리콘밸리 AI 제품 UI가 수렴하는 방향(research/R12: 대화 중심 캔버스와 옆 패널, 조용한 무채 면과 강조색 하나, 시스템·가변 서체, 4/8pt 간격, 최소한의 테두리와 은은한 높이, 인라인 상태 표시, 점진 공개, 명령 팔레트, 다크 동등, 절제된 움직임, 접근성 대비)에 맞춰 v1.1의 시각 규칙을 다듬었다. 구조와 보안 규칙은 그대로다.

원칙

- 면은 네 단으로 끝낸다: `canvas` → `surface` → `surface-tint` → `surface-overlay`. 라이트는 바탕과 카드의 차이를 줄이고, 다크는 위로 뜰수록 밝다.
- 테두리는 필요한 곳에만: 카드·표·작은 보조 버튼은 `line`, 입력 칸·주요/보조 버튼은 `line-strong`(3:1), 무채 칩과 오늘 요약·검색 칸은 테두리 없음.
- 굵기는 400·500·600 셋: 700은 서류 이름과 승인 바 동작 글자에만. 한글 라벨에 자간을 넣지 않고, 화면 제목은 18px로 낮춰 값(D1)이 먼저 보이게 한다.
- 간격은 4px 격자에 맞춘다: 카드 안쪽 16, 요소 사이 12, 메시지 사이 16. 반 칸 값(14·18)을 없앴다.
- 모서리는 담는 것은 조금 더(카드 12, 입력창·말풍선 16), 누르는 것은 그대로(버튼 8, 칸 6). 승인 바는 직각.
- 움직임은 상태가 바뀔 때만: 120/160/220ms와 현재 단계 점의 2.4초 숨 쉬기. 동작 줄이기면 모두 끈다.
- 두 테마를 함께 설계하고, 모든 글자 색은 네 면 위에서 4.5:1 이상을 지킨다.

바뀐 것

- `tokens.json`: 더함 `surface-tint`, `line-soft`, `accent-strong`, `scrim`, `shadow-raised`, `space-0`, `control-height-sm`, `motion` 묶음(120/160/220/2400ms, 두 곡선). 값 조정 `canvas`(라이트 #F5F6F7), `surface-sunken`(라이트 #EEF0F2), `line`(라이트 #E4E7EB), `shadow-overlay`(더 가깝고 옅게), `radius-lg` 10→12, `radius-xl` 12→16, `figure-lg` 행간 32→30·자간 -0.015em, `label` 자간 0, `title-screen` 20/28→18/26. 기존 토큰 이름은 모두 남겼다(코드·컴포넌트가 이름으로 읽는다).
- `components/bundle.css`: 버튼 4단 위계와 hover·누름, 무채 칩 테두리 제거, 말풍선 `surface-overlay`·테두리 없음, 입력창 `radius-xl`+`shadow-raised`·원형 보내기 버튼, 오늘 요약 상자 → 한 줄, 레일 선택 `surface-tint`, 패널 간격 16/12, 현재 단계 점 숨 쉬기, 색 변화 전환.
- 컴포넌트 지침: ApprovalBar(시각만), Button, StatusChip, Message, Composer, TaskCard, KeyValue, StepList, MainScreen, ChoiceCard, Identifier, DocumentCard, Amount에 "모양(v1.2)" 줄을 더했다.
- `direction-review.html`: v1.2 토큰과 컴포넌트를 브라우저에서 바로 보는 미리보기(라이트·다크 전환, 승인 바 세 상태 포함)로 고쳤다. 2026-10-30의 방향 3안 비교는 결정 기록으로 접어 두었다.
- PoC 셸(`poc/apps/desktop/static/shell/shell.css`, 승인 바 내장 CSS `approval-gate.ts` `barCss`): 같은 토큰을 적용했다. 승인 바는 라벨 굵기·불투명도, 표시 칩 모서리, 동작 글자 자간만 바뀌었고 치수는 같다.

바뀌지 않은 것

- 보안 규칙 전부(ADR-021): 승인 바는 main이 소유하는 대화 열 하단·입력창 위의 띠이고, 카드 안에 승인 버튼이 없으며, 무장 지연 0.6초·머무름 0.15초, 세 정적 페이지 교체(애니메이션 없음), 직각·그림자 없음, 시스템 서체, 커스텀 커서 금지, 키보드 승인 없음, 요약 줄은 사용자가 확인해야 할 값(공급받는자 상호·사업자번호, 합계·세액, 받는 이메일) 그대로. 바 안의 치수(높이 90, 라벨 76, 동작 132, 간격 12 DIP)와 레이아웃 치수(`titlebar-height`·`rail-width`·`panel-width`·`chat-max`, 입력창 예약 110, 간격 12)도 같다.
- 한국어 문구 전부(문구 원칙, 상태 이름, 버튼 글자, 안내 문장).
- 데이터 위계 D1~D6과 값의 확실성 5단계, 표기 형식, 배치 순서(`data-hierarchy.md`).
- 색의 두 가지 뜻(파랑 한 색 = 차례·승인, 황토 = 확인 필요), 완료·실패에 색 없음, 서체 세 벌.
