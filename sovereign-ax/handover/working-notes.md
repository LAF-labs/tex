# 작업 방식 노트 (살아 있는 문서)

Claude Projects 스레드와 로컬 세션이 같은 실수를 되풀이하지 않게, 겪은 마찰과 그 처방을 모은다. 매일 점검(`retro/`)에서 새로 배운 것을 여기에 옮긴다. 인계 문서 `2026-11-16-projects.md`(PR #378)가 "무엇을 하나"라면, 이 문서는 "어떻게 하나"다.

근거는 측정, 추정, 짐작으로 나눠 적는다.

## 1. 어디서 할까: 클라우드 / 맥북

- **클라우드:** 미리보기가 필요 없는 일. 조사·분석·문서, 크론·DB·백엔드·크롤러 PR, CI·스크립트 수정.
- **맥북(원격 세션):** 미리보기가 필요한 일(화면·문구·레이아웃), 실화면 예행, 서명·공증 빌드, 게시 ceremony, 로컬 CLI 로그인이 필요한 일.
- 대표가 "맥북으로/클라우드로"라고 쓰면 그대로 따른다. 애매하면 시작 전에 추천과 함께 한 번 묻는다.

## 2. 맥북 원격 작업 전에 한 번에 확인할 것

대표에게 여러 번 나눠 묻지 않도록, 맥북 일을 시작할 때 아래를 **한 메시지로** 확인한다. (측정: 2026-11-16 민원증명 5차 예행에서 컴퓨터 사용 권한 → 손쉬운 사용 → 인증서 비밀번호를 세 번 따로 물었다.)

1. Claude 앱 설정 › 컴퓨터 사용이 켜져 있고, SovereignAX가 차단 목록에 없다.
2. macOS 시스템 설정 › 개인정보 보호 및 보안 › 「손쉬운 사용」과 「화면 및 시스템 오디오 녹음」에 Claude가 켜져 있다.
3. 권한 허용 창은 Mac 화면에만 뜬다. 대표가 Mac 앞에 있을 때 요청한다("지금 요청해"를 받고 요청).
4. 예행용으로 앱을 새로 빌드해 바꿔 넣으면 **인증서 비밀번호를 다시 물을 수 있다**(3절). 대표가 Mac 앞에 있는 시간에 맞춘다.

## 3. 예행용 앱과 키체인

- **측정:** 예행용으로 새로 빌드한 0.1.85·0.1.86(서명, 공증 생략)을 띄울 때마다 앱 금고가 인증서 비밀번호를 다시 물었다. 대표는 "Mac에 저장돼 있을 텐데"라고 했다.
- **짐작:** macOS 키체인 항목의 접근 허용이 앱 서명(지정 요구사항)에 묶여 있어서, 판이 바뀌면 다시 허락을 받아야 한다. 확인하지 않았다.
- **처방:**
  - 같은 예행 묶음 안에서는 판을 덜 바꾼다. 고칠 것을 모아 한 판으로 만든다.
  - 판을 바꾸기 전에 "새 판을 넣으면 비밀번호를 한 번 더 물을 수 있다"고 미리 알린다.
  - 키체인 창이 뜨면 [항상 허용]을 고르게 안내한다.
  - 예행이 끝나면 원래 공증판(예: 0.1.33)을 되돌려 넣는다.
- **할 일 후보:** 원인을 확인해(같은 Developer ID·번들 id인데도 묻는지) 예행판도 다시 묻지 않게 할 수 있는지 본다.

## 4. 브랜치·PR

- 브랜치가 360개까지 쌓여 대표가 정리 스크립트를 두 번 돌렸다(측정, 2026-11-16). 스레드 세션은 원격 브랜치를 지울 권한이 없다.
- **처방:** 저장소 설정 › General › Pull Requests › "Automatically delete head branches"를 켠다(대표 결정 2026-11-16: 켠다). 머지된 PR 브랜치가 저절로 지워진다.
- PR은 작게 나눈다. 스레드 하나가 PR 하나를 끝까지 맡는다.
- 푸시 전 `git merge origin/main`. force-push와 rebase는 하지 않는다.

## 5. 머지 순서와 CI

- **측정(2026-11-16):** 머지 스레드가 PR 11개를 하나씩 "최신 main 받기 → 세 OS 여섯 잡 녹색 → 머지"로 합쳤다. 한 건에 15~20분, 전체 두세 시간 걸렸다. 최근 CI 40회 중 15회가 새 푸시로 취소, 4회 실패였다.
- **머지 기준(2026-11-16 대표 위임으로 정함, 출시 주간 표준):** 최신 main을 받은 head에서 build·lint 녹색, 그리고 바꾼 영역의 시험이 녹색이면 합친다. 알려진 불안정 시험만 실패하면 한 번 다시 돌린다. 다시 돌려도 빨가면 원인을 고친다. 문서만 바꾼 PR은 build·lint와 리뷰 봇만 본다. 인계 문서 4절의 "build·lint와 리뷰 봇" 기준은 이것으로 바꾼다.
- **알려진 불안정 시험:** `발급 사다리(가짜 홈택스 + 가짜 API)` › "홈택스 발급 실패(verify not_committed)면 다음 길로 가고…"가 Windows에서 65초 걸리며 실패한 적이 있다(main 런 43811842223, 다시 돌리면 녹색). macOS 2/2에서도 PR 런 하나가 실패했다. 재실행 전에 이 시험인지 먼저 본다. 시험을 끄거나 건너뛰지 않는다.

## 6. 대표에게 묻는 법

- 대표 몫(본인 인증, [승인], 사업자 정보, 결정)은 모아서 한 번에 묻는다.
- 받을 파일은 다운로드 경로를 가정하지 않는다. 가능하면 저장소 안 스크립트나 한 줄 명령으로 준다.
- 이미 답한 것(예: 상호 "택스오프", 나머지 사업자 정보는 나중에)은 다시 묻지 않는다.
