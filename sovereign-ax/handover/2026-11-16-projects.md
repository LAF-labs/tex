# 인계: 부장 세션 → Claude Projects (2026-11-16)

대표가 2026-11-16 작업을 Claude Projects로 옮겼다. 이 문서 하나로 이어받을 수 있게 썼다. 근거는 측정, 추정, 짐작으로 나눠 적는다.

## 1. 제품과 지금 위치

tex(소버린 AX)는 Electron 데스크톱 앱이다. 사장님이 채팅 한 문장으로 홈택스 전자세금계산서와 민원증명을 발급한다. 대상은 세금계산서를 직접 끊는 개인사업자와 소상공인이다.

대표 지시(2026-11-13)는 "팔아도 되겠다 싶을 때까지 자율로 완성"이다. 판매 기준은 B1~B6이다.

| 기준 | 내용 | 상태(2026-11-16) |
|---|---|---|
| B1 핵심 흐름 | 한 문장 → 실제 홈택스 발급. 사람 몫은 인증서 비밀번호 첫 1번과 [승인]뿐 | 실화면 예행 3회 연속 통과(H-01 2.3.8). 실제 발급은 1/3이고 대표가 했다. 나머지 2건은 **대표 지시가 있을 때만** 한다 |
| B2 실패 안전 | 폴백 순서: 재시도 → role·label 재탐색 → AI 위치 찾기 → 화면 다시 열기 → 사람. 두 번 발급되는 길은 없다 | 들어가 있다 |
| B3 보이는 진행 | Chrome이 앱을 가리지 않고, 앱 안에 진행 화면이 보인다 | 들어가 있다 |
| B4 첫 실행 | 설치부터 첫 발급까지 10분, 막히는 화면 없음 | 깨끗한 Mac에서 실측한 적은 아직 없다 |
| B5 발급 뒤 | 문서함(승인번호·금액·거래처·PDF·메일 상태), "지난달 발급 보여줘" | 들어가 있다 |

## 3. 이어서 할 일

### 3.1 민원증명 4종 (PR #272, draft, head f0c6486f)
- **목표:** 사업자등록증명(H-03), 납세증명서(H-04), 부가세 과세표준증명(H-08), 표준재무제표증명(H-09)을 대화나 맡긴 업무에서 시작한다. 흐름은 `run.startCert` → 승인 카드 1번 → 문서함 증명서다.
- **실화면 예행 4차(0.1.84-cert, 2026-11-16) 결과:**
  - H-03, H-08은 입력을 모두 통과하고 승인 직전 s20(gate)까지 갔다. 그곳에서 `verify.baseline_missing`으로 멈췄다. 원인은 처리결과 조회 기준선 `hometax.cert.issued_list` s1 wait `hometax.certlookup.root`의 step.timeout이다. 처리결과 조회 화면은 아직 실화면에 맞춘 적이 없다.
  - H-09는 s16b `hometax.cert.form.openDate`(개업일자 select)에서 identity_mismatch로 멈췄다.
  - H-04는 납세증명서 메뉴로 가면 홈택스 메인으로 돌아온다. 개인사업자 로그인이라 막힌 것으로 짐작한다(대표자 개인 인증서가 필요할 수 있다). 확정하려면 **대표가 그 메뉴를 직접 열었을 때 나오는 안내 글**이 필요하다. 아직 받지 못했다.
- **진행 중:** 로컬 cert-docs 세션이 5차 수정 중이다(처리결과 조회 화면 맞춤과 H-09 개업일자). 남은 일과 예행 명령은 그 세션이 PR #272에 남긴다.
- **예행은 대표 Mac 설치본에서만 된다(로컬).** 순서는 다음과 같다.
  1. 앱을 바꿔 넣는다.
  2. `git archive <패키지 커밋> poc/packages/engine/playbooks poc/scripts/rehearsal-package.mjs`로 패키지를 꺼낸다. `rehearsal-package.mjs --id <id>`로 issued_list와 4종을 넣는다.
  3. 메뉴 도구 › 민원증명 예행(발급 안 함) › 서류를 돈다.
  4. engine.log의 `run.rehearsal_report`와 `run.stopped_at`을 본다.
- **같은 판 실패는 반복하지 않는다.** 고친 판만 돌린다. 4건을 연속으로 돌리면 `throttled.streak`가 걸리니 1분쯤 띄운다.
- **끝난 모습:** 3종이 gate(승인 카드)까지 사람 손 없이 간다. 그 뒤 PR #272를 머지하고, cert-1.0.0 패키지 게시 키트(minApp ≥ 0.1.34)를 만든다.

## 4. 지키는 규칙 (대표 지시, 요약)

- **빠르고 편하게:** 법적 걱정, 새 동의 카드, 권한 승인 창, 확인 대화상자를 만들지 않는다. 사람 몫은 본인 인증 1번과 [승인] 1번뿐이다.
- **실제 발급:** 대표가 직접 지시할 때만 한다. 허락을 묻지도 않는다. 예행은 승인 카드 직전에서 멈춘다.
- **인증서 비밀번호:** 앱 금고에만 둔다. 에이전트는 읽거나, 옮기거나, 입력하거나, 클립보드에서 꺼내지 않는다. 비밀값은 메시지, 레포, 로그, 보드 어디에도 남기지 않는다.
- **금지:** 정부24 자동화와 CAPTCHA 우회는 하지 않는다. 같은 세금계산서가 두 번 발급될 수 있는 길을 만들지 않는다. 원장 규칙 "POST 0번이어도 in_doubt"는 바꾸지 않는다.
- **증명은 pstack 방식이다:** 바꾼 기능을 실제로 한 번 쓰고 산출물을 남긴다. 로컬에서 시험 묶음 전체, e2e 묶음, 반복 실행은 돌리지 않는다. 확인은 tsc, 바꾼 파일 lint, 관련 시험 파일만 한다. CI 결과는 참고만 한다.
- **git:** 자기 브랜치에서만 일한다. 푸시와 PR 직전에 `git merge origin/main`을 한다. force-push와 rebase는 하지 않는다. 머지는 스쿼시로 한다. CI는 시험 단계가 자주 늦으니 build·lint 통과와 리뷰 봇(Bugbot 메인, CodeSolar) 통과를 머지 기준으로 쓴다. decisions.tsv 충돌은 양쪽 행을 모두 남긴다.
- **코드 찾기:** artiboard `board_start {project:"tex"}`를 먼저 하고, 그 다음 `board_map {project:"tex"}`(query·file·impact·inside)를 쓴다. 그 뒤 필요한 줄만 읽는다. 지도는 main 기준이다.
- **문체:** 한국어로, 짧은 평서문으로 쓴다. 긴 줄표는 쓰지 않는다.
- **운영:** 조율하는 세션은 일을 그 일 맥락만 가진 스레드에 나눠 맡긴다. 겹치지 않는 일은 병렬로 돌린다. 끝난 스레드는 바로 정리한다.

## 5. 로컬에서만 되는 일 (클라우드 스레드는 못 한다)

- 대표 Mac의 /Applications/SovereignAX.app 교체와 실화면 조작(예행, 화면 확인). 앱은 늘 `open -a /Applications/SovereignAX.app`(경로)로 띄운다. 이름으로 띄우면 옛 빌드 폴더의 다른 앱이 뜬다.
- Developer ID 서명과 공증 빌드. 키체인 프로필 `sax-notary`를 쓴다.
- 게시 ceremony(Touch ID), Supabase 비밀번호, 인증서 비밀번호 첫 입력.
- 산출물 위치:
  - 서명 빌드: `~/sax-builds/`
  - 게시 작업: `~/sax-publish/`
  - 예전 부장 노트: 대표 Mac의 Claude 앱 데이터 `side-session-notes/local_0708a716…/`. 판매 기준, 상시 지시, cert-docs 기록이 있다.
- 클라우드 스레드가 이런 일이 필요하면 대표에게 넘기거나, 로컬 세션을 열어 달라고 요청한다.
