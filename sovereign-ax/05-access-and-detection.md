# 05. 자동화 접근 허용과 봇탐지 비대상 설계

## 1. 입장

세 문장으로 요약한다. **허용은 공문으로 받는다. 탐지 신호는 애초에 만들지 않는다. 위조와 은폐는 하지 않는다.**

2026-10 리서치(R5)로 확인된 사실이 입장의 무게중심을 바꿨다. **정부24 이용약관(2026.3.9 시행) 제14조 ④ 9호는 사전 허락 없는 자동화 수단(매크로·스크래핑) 로그인 자체를 금지**하고, 10호는 IP 변경 접속과 캡차 외부 우회를 금지한다. 매크로 사용 제재는 1회 1개월·2회 3개월·3회 영구 정지(2024.10.15 공지)다. 즉 정부24에서는 요청률 상한 설계가 약관 준수의 근거가 되지 못하며, **사전 허락(공문 회신)이 선행 조건**이다. 홈택스 이용약관(2015.2.23 시행본)에는 매크로·스크래핑 명시 조항이 없으나 제15조 ②·③·④(영리행위, 얻은 정보의 타인 제공, 안정 운영 저해)가 포괄 조항으로 있어 법률 검토가 필요하고, 국세청은 전자정부법을 근거로 IP별 대량 접속을 차단해 왔으며 2025.5부터 안티 스크래핑을 운영한다. 홈택스 개인정보처리방침 제5조 ⑩은 **대리인 자동화 도구의 사전협의 창구**를 명시하므로 국세청 공문은 이 창구와 연결한다. 정부24 약관은 제16조 ④ 8·9호에도 같은 금지가 있다. 또 개인정보보호법 시행령(공공 2026.8.20 시행)은 '대리인'의 스크래핑에 공공기관 사전협의를 요구한다. 우리가 대리인인지는 공개 해석이 없어 개인정보위 질의가 필요하다. 그래서 §7의 **포털별 운영 수준**을 도입한다: 정부24는 허락 전 후처리 모드(사용자 기본 브라우저), 홈택스는 요청률 상한 자동화 + 공문.

- **허용**: 운영기관에 접근 방식·빈도·연락처를 알리고 허용 범위를 합의한다. 차단되기 전에 연락이 오는 관계를 만든다.
- **비대상화**: 사용자 본인 PC, 본인 IP, 본인이 설치한 실제 Chrome, 본인 인증수단, 요청률 상한. IP·브라우저·계정·요청률은 사람이 쓰는 값 그대로다. 피할 수 있는 신호는 피한다. 헤드리스를 켜지 않고, `--enable-automation` 배너 플래그를 켜지 않고, 초당 수십 요청을 보내지 않는다. 제어 채널 플래그(`--remote-debugging-pipe`)는 쓰며 이를 '자동화 플래그 미사용'이라고 부르지 않는다. 다만 **Playwright가 CDP 파이프로 구동한 Chrome은 `navigator.webdriver=true`를 그대로 노출한다.** 이 값을 false로 만드는 연결 방식(포트 연결 후 attach)은 기술적으로 가능하지만 은폐로 읽힐 수 있어 쓰지 않는다. 표식은 그대로 두고, 포털 동작 차이는 S1a로 확인해 차이가 있으면 운영기관과 협의한다.
- **위조·은폐 없음**: 가짜 지문, IP 로테이션, 가짜 기기 정보, 자동화 흔적을 지우는 코드는 만들지 않는다. 실제 값을 그대로 쓰는 것과 가짜 값을 만드는 것은 다르다. 전자는 하고 후자는 하지 않는다.

캡차와 추가 인증은 **사람이 푼다**. 다만 "사람이 푼다"가 "작업이 멈춘다"는 뜻은 아니다. 캡차가 뜨면 10초 안에 데스크톱 또는 폰으로 넘겨 사용자가 풀고, 플레이북은 그 자리에서 이어진다(4절). 모델로 캡차를 자동 해독하는 기능은 넣지 않는다. 공문에서 한 약속과 정면으로 충돌하고, 운영기관이 '우회 사업자'로 분류할 근거를 스스로 주는 일이기 때문이다.

## 2. 탐지 시스템이 보는 것과 우리의 설계

| 탐지 신호 | 일반 봇 | 소버린 AX 하네스 |
|---|---|---|
| 접속 IP | 데이터센터·프록시, 다수 계정이 같은 IP | **사용자 본인 PC의 가정·사무실 IP**. 우리 서버는 포털에 접속하지 않는다 |
| 브라우저 | 헤드리스, 자동화 전용 플래그, 번들 Chromium, 지문 위조 | **사용자가 설치한 실제 Chrome**을 전용 프로필로 최소 플래그 모드(`ignoreDefaultArgs: true` + 파이프 + 전용 프로필, `--no-sandbox`·`--disable-extensions` 없음)로 띄운다. 헤드풀, 사용자가 창을 볼 수 있음. `--enable-automation`은 쓰지 않지만(Playwright ≥ 1.60 기본) `navigator.webdriver=true`는 그대로 노출된다. 가짜 값을 주입하지 않는다 |
| 인증 | 탈취·공유 세션, 인증 우회 | 사용자가 고른 **본인 발급 인증 하나**(ADR-020 결정 1·2): 본인 공동·금융인증서(비밀번호는 사용자가 직접 입력하고 앱은 저장·자동 입력하지 않음), 본인 폰의 사업자 간편인증 승인, 또는 사용자가 한 번 등록한 본인 보안카드(아이디 로그인과 요청 번호 입력을 금고가 함, PC 안에서만 암호화 보관). 가상키패드·키보드 보안 칸은 우회하지 않고 사용자가 입력 |
| 속도·리듬 | 로드 직후 즉시 클릭, 일정 간격, 24시간 가동 | 페이지 안정화 대기 + 스텝 간 지연 범위(요청률 상한), 입력은 `fill()` 즉시(모사 없음), 사용자가 정한 활동 시간대에만 |
| 요청량 | 계정당 수백 건/일 | 사용자 1인 = 사람 1인 수준. 세션당 작업 수 상한, 동시 세션 1개, 데몬은 실행 시각 분산 |
| 재시도 | 실패 시 무한 반복 | 한 스텝 재시도 최대 3회(첫 시도 제외, 정책 `retries.stepMax`), 되돌릴 수 없는 스텝은 0회. 그 뒤 원인 분류(L1)와 셀렉터 복구 1회(L2), 그래도 안 되면 사용자 핸드오프(D03 §6). 작업 전체 자동 재시도는 데몬의 30분 뒤 1회뿐(§8). 차단 신호는 즉시 중단·알림, 양성 탐지가 **2회 연속이면 24시간 쿨다운**(D03 §7) |
| 캡차·추가 인증 | 자동 풀이·우회 | **10초 핸드오프**. 캡차 영역을 데스크톱 전면 또는 폰(E2E)으로 보내 사용자가 풀고 플레이북이 이어진다. 자동 해독 없음 |
| 보안 모듈 | 미설치·우회 | 설치 안내 후 공존. 키보드 보안 등이 자동 입력을 막으면 해당 칸은 사용자 직접 입력 |
| 다계정 | 한 기기에서 다수 사업자 | 계정당 프로필 2개 상한, 기기 바인딩 |
| 행위 범위 | 크롤링·대량 조회 | 발급·조회 플레이북 화이트리스트만. 목록 페이지 반복 순회 금지 |

운영 기준 수치(초안, 스파이크 S8에서 조정):

| 항목 | 기준 |
|---|---|
| 스텝 간 지연 | 0.8~2.5초 균등 분포 + 페이지 안정화 대기 |
| 입력 | 일반 칸은 `fill()`(즉시 입력, 모사 없음). 키 이벤트가 필요한 칸(보안 모듈·비밀 타이피스트)만 고정 간격 150ms(요청률 상수, '사람 수준' 아님) |
| 세션당 작업 | 홈택스 15건(로그인 세션 기준), 정부24는 후처리 모드라 해당 없음 |
| 일일 상한 | 프로필당 홈택스 실행 40건, 비가역(발급) 30건, 로그인 6회 |
| 동시 세션 | 포털당 1개 |
| 데몬 실행 창 | 사용자 지정 시간대, 시작 시각 ±30분 지터 |
| 차단 신호 | 차단 안내 페이지, 비정상 접근 경고, 연속 추가 인증 요구 → 즉시 중단·알림. 2회 연속이면 24시간 쿨다운 |

## 3. 식별: 드러내되 과시하지 않는다

- 기본값은 **실제 Chrome의 실제 User-Agent**다. 바꾸지 않는다. 이것은 은폐가 아니라 진짜 값이다.
- 공문에는 접근 방식·빈도·연락처를 적어 보내고, 운영기관이 식별자 부착(예: User-Agent 접미사, 등록 헤더)이나 화이트리스트 등록을 **요구하거나 제공하면 그 절차를 따른다**. 요구가 없으면 식별자를 임의로 붙여 불필요한 탐지 신호를 만들지 않는다.
- 운영기관이 물으면 언제든 "어느 접속이 우리 도구였는지"를 사용자 동의 하에 감사 로그로 소명할 수 있도록, 로컬 감사 로그에 세션별 시각·작업·플레이북 버전을 남긴다.

## 3-1. 캡차·추가 인증 핸드오프 흐름

1. 플레이북이 Decisions API `predicate`로 "캡차 또는 추가 인증 화면인가"를 판정(confidence 임계값 이상).
2. 데스크톱 앞에 사용자가 있으면(최근 입력 60초 이내) 창을 전면으로 올리고 해당 영역을 강조한다.
3. 없으면(그리고 포털별 정책 `captchaRelay`가 허용이면) 폰으로 E2E 알림: 캡차 이미지 영역(비밀값 아님)과 입력창을 폰 화면에 보여 준다. 사용자가 폰에서 입력하면 암호문으로 데스크톱에 전달해 입력한다. 정부24는 허락 전 비활성.
4. 90초 내 응답이 없으면 작업을 체크포인트에 안전하게 멈추고 "다시 시작" 버튼으로 재개한다. 자동 재시도하지 않는다. 폰 중계는 포털별 정책(`captchaRelay`)이 허용할 때만 쓰며 공문에 중계 방식을 적는다. 지연 목표는 판정 2초·알림 3초·사용자 반응(측정)으로 나눈다.
5. 횟수 기록: 캡차 발생 빈도가 특정 플레이북·시간대에서 치솟으면 운영 기준(속도·상한)을 자동으로 보수적으로 조정하고 운영팀에 알린다. 캡차가 자주 뜬다는 것은 탐지 경계에 가까이 갔다는 신호다.

## 4. 공문 계획

### 4.1 수신처 (확인 필요 항목은 Q2)

| 포털 | 운영 주체(1차 확인) | 요청 내용 |
|---|---|---|
| 홈택스·손택스 | 국세청 (홈택스 운영 부서 + 개인정보처리방침 제5조 ⑩의 대리인 자동화 도구 사전협의 창구) | **통지·질의**(허가 신청이 아님, ADR-017 결정 1): 전자세금계산서 발급·조회, 증명 발급 플레이북의 접근 방식·빈도·연락처를 알리고, 허용 여부·금지 행위·기술 기준·식별 방식을 묻는다. 운영기관이 식별자 등록이나 사전협의 절차를 요구하면 따른다 |
| 정부24 | 행정안전부 (정부24 운영 부서; 위탁 운영기관 여부 확인) | **이용약관 제14조 ④ 9호에 따른 자동화 수단 로그인의 사전 허락 요청**. 허락 범위(플레이북 목록·빈도·식별 방식)와 절차 질의. 허락 전에는 후처리 모드로만 운영함을 명시 |
| 위택스 | 행정안전부 (지방세 부서, 정부24 공문에 포함, ADR-018 결정 9) | **이용약관 제17조 ②에 따른 자동화 로그인의 사전 허락 요청**(W-01·W-02). 허락 전에는 위택스 자동화 없음, 지방세 납세증명은 정부24 후처리(ADR-022) |
| 인터넷등기소 | 법원행정처 (운영 부서 확인) | 법인등기사항증명서(S-03) 신청 자동화 접근. 약관 자동화 조항을 확인한 뒤 내용을 정한다(사전 허락이 필요하면 허락 요청, ADR-022 결정 4). S-03을 켜기 전에 발송 |
| 중소기업현황정보시스템 | 중소벤처기업부 (운영 부서 확인) | 중소기업확인서 신청·발급 자동화 접근 (Phase 2 전 발송) |
| 4대사회보험 정보연계센터 | 국민연금공단 (운영 주체 확인) | 완납증명 발급 자동화 접근 (Phase 2 전 발송) |

발송 순서: 국세청·행정안전부를 Phase 0 1주차에 동시 발송. 나머지는 해당 플레이북 개발 4주 전.

### 4.2 공문에 담을 내용

1. **서비스 개요**: 사용자 본인 PC에서 본인 인증수단으로 본인 명의 업무를 수행하는 도구. 사업자 서버의 포털 접속 없음. 세무대리·대행 아님.
2. **요청 범위**: 플레이북 목록(작업명, 접근 화면, 행위, 사용자당 예상 빈도, 일일 상한). 범위 밖 행위 없음을 명시.
3. **기술 방식**: 사용자가 설치한 실제 Chrome(전용 프로필, CDP 파이프 제어, 포털이 읽을 수 있는 자동화 표식 `navigator.webdriver=true` 노출, `--enable-automation` 배너 플래그는 화면 표시줄 때문에 미사용), 사용자 IP, 요청률 상한 수치, 동시 세션 1, 재시도 상한, 캡차·추가 인증은 사용자 직접 수행(폰 중계 방식 명시), 보안 모듈 공존.
4. **식별·연락**: 운영 연락처(24시간 내 응답), 운영기관이 원하는 식별 방식이 있으면 따르겠다는 의사, 차단·문의 시 처리 절차.
5. **준수 약속**: 이용약관 준수, 차단 신호 시 즉시 중단, 운영기관 요청 시 기준 조정·기능 중단(요청 당일 정책 배포, 켜져 있는 앱은 배포 뒤 20분 안 반영이 목표, 진행 중인 발급은 결과 확인 뒤 멈춤, ADR-023). 인증정보·서류 원문은 우리가 볼 수 있는 형태로 서버에 보내지 않는다. 다만 서버나 외부로 가는 항목이 있으므로 '수집하지 않는다'고 쓰지 않고 항목을 적는다: 계정·결제 참조·계량, 진위확인 때 프록시를 거쳐 가는 거래처 사업자번호, 모델 공급사(국외)로 가는 마스킹된 화면 텍스트·대화 지시·서류 날짜 후보 주변 텍스트(정부24 후처리 서류 포함), 2단계의 서류 메타데이터·암호문 백업·사용자가 허용한 서류 요약 마스킹본, 2단계에서 PC를 두 대 이상 연결하고 백업을 켠 계정의 발급 활동 표시(HMAC, ADR-024). 개인정보 흐름표(D09 §1.1·D11 §6 기준)와 비밀 경계 요약을 첨부한다.
6. **질의 사항**: (a) 위 방식의 접근이 허용되는지 (b) 금지되는 행위가 있는지 (c) 식별자 등록·화이트리스트 절차가 있는지 (d) 준수해야 할 기술 기준(요청 빈도 등)이 있는지 (e) 향후 소통 창구.
7. **첨부**: 아키텍처 요약 1장, 비밀 경계표, 개인정보 흐름표, 감사 로그 샘플, 변호사 의견서(수령 시).

### 4.3 회신 시나리오와 대응

| 회신 | 대응 |
|---|---|
| 허용 (조건 없음) | 운영 기준을 공문 내용으로 고정, 요구된 식별 방식이 있으면 적용, 분기별 사용 현황 자율 보고 |
| 조건부 허용 (빈도·시간대·범위 제한) | 조건을 엔진 레벨 상수로 반영, 플레이북 카탈로그에서 제외 항목 표시 |
| 명시적 불허 | 해당 포털은 **후처리 모드**(`postprocess`) 고정: 사용자가 기본 브라우저에서 로그인·입력·발급·출력을 직접 하고, 하네스는 안내·저장 파일 정리·보관·메타데이터·만료 추적만 담당. 발급 시간은 줄지 않고 정리·추적 가치만 남는다 |
| 무응답 | 접수 후 30일 경과 시 국민신문고 질의로 전환, 분기마다 재발송. **정부24·위택스는 허락이 없는 한 약관상 금지 상태이므로 후처리 모드 유지.** 홈택스는 법률 의견서 기반으로 보수적 운영 기준(세션당 작업 절반)으로 베타 진행 |

### 4.4 개인정보위 사전협의·질의 (공문과 병행)

- 질의: "사용자 기기에서 사용자가 직접 실행하고, 인증정보와 결과를 사업자 서버로 보내지 않는 로컬 자동화 도구의 배포자가 개인정보보호법 시행령상 본인전송요구권의 '대리인'에 해당하는가."
- 창구: 온마이데이터, 국민신문고. 개별 공공기관 사전협의 창구는 상시 운영.
- 해당 시: 사전협의 신청(전송 항목 범위, 위임 확인 방식, 자동화 도구 접근 방식·인증 수준, 보호조치). 대리인에게 요구되는 '자체 서버 저장·분석 금지'는 우리 구조(서버 비저장)와 방향이 같지만 충족 여부는 회신으로 확정한다.
- 비해당 시: 서면 회신을 확보해 공문과 처리방침에 인용한다.

## 5. 플레이북 최대화 원칙

"가능한 건 플레이북으로"를 측정 가능한 규칙으로 바꾼다.

1. **결정적 스텝 비율 ≥ 95%**: 플레이북의 전체 스텝 중 모델 호출 없이 끝나는 스텝의 비율. 미달 시 플레이북을 더 쪼개거나 셀렉터를 보강한다.
2. **판단은 Decisions, 추론은 Terra**: 모델이 필요해도 먼저 "선택지가 정해진 질문으로 바꿀 수 있는가"를 묻는다. 바꿀 수 있으면 Decisions API(출력 통제). 바꿀 수 없을 때만 Terra. 커밋 구간 안에서는 어느 쪽도 개입하지 않는다.
3. **Terra 호출 ≤ 15건 / 실행 100건**: 초과하는 플레이북은 '불안정' 표시 후 우선 보강.
4. **신규 플레이북 승인 기준**: 스파이크 환경에서 연속 20회 자동 구간 완주(인증·게이트 승인 외 사람 개입 0회), Decisions 판정 confidence 평균 0.9 이상, 운영 기준 수치 준수.
5. **개편 대응**: 실패 텔레메트리(스텝 ID·셀렉터·버전만)로 영업일 1일 임시 조치·3영업일 핫픽스(전담 인력 후 24시간). Terra 자가 복구는 임시 조치이며, 복구 성공 사례는 다음 플레이북 버전에 **결정적 스텝으로 환원**한다. 모델이 매번 고치게 두지 않는다.
6. **비가역 단계는 모델 무관**: 발급·전송·서명은 모델 판정이 아무리 확신해도 user_gate 없이는 실행되지 않는다.

## 6. 사용자에게 보여줄 것

- 설정 화면에 "운영 기준" 페이지: 현재 적용 중인 속도·상한·시간대, 운영기관 공문 회신 상태.
- 작업 중 "지금 천천히 가는 이유" 안내: 요청률 상한이 차단을 막고 계정을 보호한다는 설명.
- 차단·쿨다운 발생 시 숨기지 않고 알린다. 원인 후보와 사용자가 할 수 있는 일(직접 로그인 확인 등)을 함께.

## 7. 포털별 운영 수준

운영 수준은 서명된 운영 정책(`policy.json.portalMode`)으로 배포된다. **내리는 것과 상한 안의 조정은 앱 업데이트 없이** 정책으로 하고(켜져 있는 앱은 20분 안이 목표, ADR-023), **포털별 최대 수준은 앱에 내장된 상한**(`PORTAL_MODE_CEILING`, D03 §7.1)이 정하므로 상한을 올리는 일은 허락 회신이나 약관 확인 뒤 **앱 업데이트로만** 한다(ADR-011·012·022). 어떤 회신·확인이 있어야 올릴 수 있는지는 ADR-022 결정 4의 판정 기준을 따른다.

| 수준 | 하네스가 하는 것 | 하네스가 하지 않는 것 | 적용 |
|---|---|---|---|
| `postprocess` 후처리 | 포털 URL을 **사용자의 기본 브라우저**(자동화 프로필 아님)로 열기, 단계별 안내 패널, 입력값 복사 버튼(30초 후 클립보드 비움), 저장된 PDF 감지·파일 정리·메타데이터 추출·만료 추적·알림·백업 | Chrome·CDP 기동, 로그인·클릭·입력·제출 자동화, 화면 읽기, 캡차 중계 | **정부24·위택스: 사전 허락 회신 전 상한. SMINFO·4대보험·인터넷등기소: 약관 확인 전 상한. 명시 불허 회신도 이 수준**(D03 §7.1 상한 표) |
| `assisted` 보조 | 위 + 로그인 **후** 비식별 입력값 자동 채움, 화면 상태 판정, 결과 수집. 로그인과 제출 클릭은 사용자(`human_commit`) | 로그인 자동화, 제출 자동 클릭 | **조건부 허락**(로그인 후 화면 읽기·입력 보조를 허용하는 회신)이 있을 때만 |
| `auto` 자동 | 플레이북 전체(게이트·캡차 핸드오프 포함) | — | 홈택스 기본값(공문·S8 전제). 정부24·위택스는 허락 회신과 앱 업데이트 뒤 |

- 후처리 모드에서도 제품 가치의 핵심인 **보관·만료 추적·알림·조회 에이전트**는 전부 동작한다. 발급에 걸리는 사용자 시간만 줄지 않는다.
- 운영 수준은 설정 화면 '운영 기준' 페이지에 포털별로 표시하고, 바뀌면 사용자에게 알린다.

## 8. 홈택스 이중로그인 방지

홈택스는 한 번에 한 세션만 허용하므로 사용자가 폰(손택스)·다른 PC·세무사 계정으로 로그인하면 자동화 세션이 끊긴다.
- 실행 전 안내: "실행 중 다른 기기에서 홈택스에 로그인하면 작업이 중단됩니다."
- `screen_state_v2`에 `logged_out_by_other_session` predicate(예약 결과)를 두어 세션 종료를 판정하고, 체크포인트 `session`으로 복귀해 사용자에게 재개 여부를 묻는다. 자동 재로그인으로 상대 세션을 끊지 않는다(사용자가 지금 폰에서 뭔가 하고 있을 수 있다).
- 데몬은 사용자 활동 시간대를 피하고, 재시도는 30분 이후 1회만.
