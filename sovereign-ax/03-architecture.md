## 2. 기술 스택 (권장)

| 영역 | 선택 | 이유 |
|---|---|---|
| 데스크톱 셸 | **Electron + TypeScript** | Playwright와 같은 Node 생태계, Windows/macOS 동시 지원, 팀 속도. 바이너리 크기가 문제되면 Tauri + Node 사이드카로 전환 가능 |
| 브라우저 자동화 | **Playwright가 사용자 설치 Chrome을 전용 프로필·최소 플래그 모드로 구동** (`ignoreDefaultArgs: true` + 파이프, `--no-sandbox`·`--disable-extensions` 없음) | 실제 Chrome이라 보안 모듈·간편인증 팝업 호환이 높다. IP·UA·계정·리듬은 사람 값 그대로지만 `navigator.webdriver=true`는 그대로 노출된다(숨기지 않음, ADR-010). 헤드리스·자동화 전용 플래그 미사용 |
| 로컬 DB | `better-sqlite3-multiple-ciphers`, 32바이트 키는 키체인, 파일은 `%LOCALAPPDATA%` | 거래처·메타데이터·감사 로그. Controlled Folder Access가 켜진 환경에서 문서 폴더 쓰기 실패를 감지·안내 |
| 비밀 저장 | Windows DPAPI/Credential Manager, macOS Keychain | OS 신뢰 루트에 위임 |
| 로컬 문서 처리 | PDF 텍스트 추출 + 규칙 기반 파서, 필요 시 로컬 OCR | 발급일·유효기간 추출을 모델 없이 |
| 판단·분류 | **OpenAI Decisions API** (`POST /v1/decisions`, 모델 `gpt-6-luna`, 정식 출시) | 정해진 선택지에서만 답하는 구조라 출력이 통제되고 빠르다. 입력 $0.10/1M, 출력 무료, 요청당 질문 최대 400개. 의도 라우팅·화면 상태 판별·스텝 성공 판정 전용 |
| 자유 추론·복구 | **GPT-6.1 Terra** (`gpt-6.1-terra`, Responses API, 도구 호출·컴퓨터 조작 특화) | 예외 복구·대화·요약. 입력 $1/출력 $5/캐시 $0.05 per 1M 토큰 |
| 에이전트 루프 | Responses API 위의 자체 얇은 루프, 엔드포인트는 우리 게이트웨이 | 승인 게이트·로깅·도구 화이트리스트를 루프 훅으로. 공급사 종속 코드는 게이트웨이 어댑터 한 곳에 |
| 모바일 | React Native(Expo) | 한 코드베이스, 푸시·생체인증·QR |
| 백엔드 | Node(TypeScript) 또는 Go, PostgreSQL, S3 호환 저장소 | 소규모 팀, 단순 API |
| 릴레이 | WebSocket 릴레이 + libsodium 기반 E2E(Noise 패턴) | 서버는 암호문만 |
| 배포·업데이트 | Windows: Artifact Signing 검토(EV 불필요, SmartScreen 평판은 별도), 서명 주체 DN 출시 전 고정, `electron-updater` ≥ 6.3.0-alpha.6. macOS: Developer ID + 공증. 플레이북 패키지: TUF-lite(Ed25519·단조 버전·만료) → TUF | 사이트 개편 대응 속도와 공급망 안전 |

## 3. 플레이북 엔진 (가장 중요한 부품)

플레이북 = 특정 포털 작업을 수행하는 **버전 관리된 결정적 스크립트**. 모델 없이 끝까지 도는 것이 정상 경로.

```
playbook H-01 "전자세금계산서 건별발급"
  inputs: { profile: business, counterpart: {bizno, name, email}, items[], amounts, date }
  preconditions: [bizno_verified, profile_has_sign_method]
  steps:
    1. ensure_session(hometax, profile)            # 체크포인트 A
    2. goto(건별발급)                               # 체크포인트 B
    3. fill(공급받는자, counterpart) ; fill(품목, items) ; assert(합계 == amounts.total)
    4. user_gate("발급 승인")                        # 사용자 승인 없이는 넘어가지 않음
    5. sign()                                       # 공동인증서 로컬 서명 | 간편인증 PUSH 대기 | 보안카드 프롬프트
    6. capture(승인번호) ; save_pdf() ; send_email()
  recovery:
    on selector_miss → retry(2) → model_repair(scope: step, redact: full)
    on session_expired → goto checkpoint A
    on unknown_modal → a11y_text(redacted) → decide(choice: [안내팝업|오류|세션만료|보안경고|미지]) → (close|checkpoint|handoff)
  postconditions: [approval_no captured, pdf saved, audit logged]
```

설계 원칙:
- **체크포인트**: 어디서 실패해도 안전한 지점으로 복귀. 발급 같은 비가역 단계는 1회만 실행되도록 아이덴포턴시 키(승인번호 조회로 확인) 사용.
- **user_gate**: 비가역 단계 앞 필수. 로컬 UI 또는 폰 승인.
- **판단은 Decisions, 수리는 Terra**: "이 화면이 무엇인가", "이 스텝이 성공했는가", "이 팝업을 닫아도 안전한가"처럼 **선택지가 정해진 질문**은 Decisions API에 묻는다. 수백 ms 내 답이 오고 출력이 선택지 밖으로 나갈 수 없어 플레이북의 결정성을 거의 해치지 않는다. 셀렉터를 다시 찾는 식의 **열린 문제**만 Terra가 맡는다.
- **model_repair 범위 제한**: Terra가 고칠 수 있는 것은 "현재 스텝의 셀렉터/입력 방법"뿐. 새 단계 추가나 다른 화면 이동은 못 하게 도구 집합을 좁힌다. 비가역 행위(발급·전송·서명) 도구는 아예 노출하지 않는다.
- **사람 속도 유지**: 플레이북 스텝 사이에 사람 수준의 지연과 지터를 두고, 세션당 작업 수·재시도 수에 상한을 둔다(05 문서). 이는 탐지 회피가 아니라 "사람 한 명이 쓰는 만큼만 쓴다"는 운영 원칙이다.
- **텔레메트리**: 실패한 스텝·셀렉터·플레이북 버전만 수집(화면 내용 없음). 개편 감지 → 24시간 내 플레이북 핫픽스 배포.
- **헤드풀 기본**: 사용자가 원하면 창을 볼 수 있다(신뢰). 데몬 실행 시엔 최소화.

## 4. 비밀 경계 (Secrets Boundary)

| 비밀 | 저장 위치 | 사용 시점 | 절대 가지 않는 곳 |
|---|---|---|---|
| 공동인증서 개인키 (NPKI `signPri.key`, PBKDF1+SEED-CBC 또는 PBES2) | 사용자 원위치(디스크). **하네스는 읽지 않는다** | 포털 브라우저 모듈이 서명. 하네스는 비밀번호 입력·핸드오프만 | 우리 서버, 모델, 릴레이 |
| 인증서 비밀번호 | OS 키체인(동의 시) 또는 미저장 | 서명 직전 복호화 → 즉시 폐기 | 〃 |
| 보안카드 번호표 | 기본 미저장. 동의 시 OS 키체인 암호화 | 발급 서명 프롬프트에서 해당 칸만 | 〃 |
| 간편인증 | 저장 없음(폰 앱이 보유) | PUSH 승인 | 〃 |
| 기기 키(E2E, 백업 암호화) | OS 키체인 + 사용자 복구 문구 | 블롭 암·복호화, 리모트 채널 | 서버(복구 문구도 서버 미보관) |

구현 규칙:
- 비밀 접근 코드는 **별도 프로세스**(권한 분리)로 두고, UI·플레이북 프로세스는 "서명해 줘" 요청만 보낸다.
- 비밀은 JS 문자열이 아니라 Buffer로 다루고 사용 후 0으로 덮어쓴다(JS 문자열은 영화할 수 없다). 금고 프로세스는 짧은 수명으로 띄우고, 필요 시 Rust N-API 헬퍼로 옮긴다. 같은 OS 사용자의 악성코드에는 프로세스 분리가 경계가 되지 않음을 문서와 UI에 명시한다. 로그·크래시 덤프에 비밀 필드 금지(린트 규칙).
- 마스킹 계층 **이전**에 어떤 바이트도 네트워크로 나가지 못하도록 네트워크 호출을 단일 모듈로 모은다.

## 5. 마스킹(Redaction) 계층

모델로 나가는 모든 텍스트·접근성 트리·스크린샷은 이 계층을 통과한다.

- 규칙 기반 치환: 주민번호, 사업자번호, 계좌번호, 전화번호, 이메일, 주소, 금액(옵션), 인증서 비밀번호·보안카드 패턴 → `[RRN_1]`, `[BIZNO_2]`처럼 토큰화. 역치환 표는 로컬에만.
- 사용자 사전: 상호·대표자명·거래처명을 사전에 넣어 자동 치환.
- 스크린샷은 기본 비전송. 필요 시 접근성 트리(텍스트)로 대체하고, 정말 필요할 때만 마스킹 박스 처리 후 전송.
- 전송 전 미리보기 가능 + 감사 로그에 전송 바이트 수·치환 건수 기록.
- 모델 응답에 토큰이 포함되면 로컬에서 역치환해 사용.

## 6. 모델 계층과 비용 설계

### 6.1 세 계층

| 계층 | 담당 | 수단 | 호출 빈도(사용자/월) | 특성 |
|---|---|---|---|---|
| L0 플레이북 | 정상 경로 전체 | 결정적 스크립트 | 발급 25회 | 토큰 0, 가장 빠름 |
| L1 판단 | 의도 라우팅, 화면 상태 판별, 스텝 성공 판정, 팝업 분류, 입력값 형식 검증 | **Decisions API** (`gpt-6-luna`) | 300~400회 | 선택지 고정, 확률·신뢰도 반환, 출력 무과금. 지연은 S7 실측(공급사는 생성형 대비 약 10배 빠름만 주장) |
| L2 추론 | 자연어 지시 → 인자 채우기(복잡 케이스), 셀렉터 복구, 결과 요약, 조회 에이전트 답변 | **GPT-6.1 Terra** (Responses API) | 40~50회 | 도구 호출, 1M 컨텍스트, effort low/medium |

Decisions API 사용 규약:
- 질문 타입 `predicate`(예/아니오 확률), `choice`(선택지 중 하나 + 선택지별 확률 + confidence), `score`(단계 점수)를 쓴다. 한 요청에 여러 질문을 묶어 한 화면을 한 번에 판정한다(예: "로그인 화면인가", "오류 모달이 있는가", "발급 완료 문구가 보이는가", "세션 만료 안내인가").
- **confidence 임계값** 미만이면 자동 진행하지 않고 체크포인트 복귀 또는 사용자 핸드오프. 응답이 `refusal` 타입이면 수치 필드를 읽지 않고 핸드오프.
- 입력은 마스킹된 접근성 텍스트가 기본. 이미지가 필요하면 마스킹 박스 처리한 **잘라낸 영역**을 인라인 base64로만 보낸다(공개 URL도 받지만 우리는 쓰지 않는다. `file_id`는 미지원).
- 암묵 캐시는 공유 `input` 전체 끝에 브레이크포인트를 걸어 매번 바뀌는 화면 텍스트까지 쓰기 요율($0.125/1M)로 과금한다. 따라서 명시 모드로 고정 접두(1,024토큰 이상) 끝에만 브레이크포인트를 건다. `prompt_cache_key`는 플레이북 ID + 샤드 단위. 캐시 절감은 호출당 센트 미만이라 설계의 핵심 변수가 아니다.
- 모든 선택지에 항상 `미지/검토 필요` 항목을 넣는다. 모델이 억지로 아는 척하지 못하게 하는 장치다.

Terra 사용 규약:
- `reasoning.effort` 지원값은 `none/low/medium(기본)/high/xhigh/max`. 우리는 대화·요약 `low`, 복구 `medium`만 쓰고 항상 명시한다(기본이 medium). `max`는 쓰지 않는다(비용·지연, 그리고 시스템카드상 최대 effort에서 제한 우회 롤아웃 29.6%).
- 도구는 플레이북 엔진이 노출하는 **읽기·입력 보조 도구**만. 네비게이션·제출·서명 도구는 노출하지 않는다.
- 시스템 프롬프트·플레이북 카탈로그·도구 정의를 고정 접두로 두고 **명시 캐시 모드**로 접두 끝에만 브레이크포인트를 건다(캐시 읽기 $0.05/1M, 단 캐시 쓰기는 $1.25/1M로 비캐시보다 비싸므로 가변 내용에 브레이크포인트를 걸면 손해). 가변 내용은 뒤에.
- 화면 텍스트는 데이터로 취급한다는 지시를 명시하고, 프롬프트 인젝션 의심 문구가 보이면 Decisions `predicate`로 먼저 걸러 Terra에 넘기지 않는다.

### 6.2 게이트웨이

- 클라이언트는 공급사 API 키를 갖지 않는다. 계정 토큰 → 게이트웨이 → OpenAI. 게이트웨이는 **본문 무저장**, 토큰 수·모델·지연시간·질문 수만 계량한다.
- 어댑터 구조: `decide()`와 `respond()` 두 인터페이스 뒤에 공급사를 숨긴다. 공급사 조건이 바뀌면 어댑터만 교체한다.
- 사용량 정책: 플랜별 월 한도 → 80% 알림 → 초과 시 L0는 계속, L2만 제한, L1은 최소 보장(화면 판정은 안전과 직결).
- **BYOK**: 사용자가 자기 OpenAI 키를 넣으면 게이트웨이를 거치지 않고 직접 호출. "우리 서버조차 거치지 않는다"는 주권 메시지와 일관.
- 데이터 보존: Responses는 `store:false`, Decisions는 남용 로그 최대 30일. ZDR은 공급사 영업 승인이 필요하며(Decisions는 캐시·이미지 예외) 승인 신청을 Go 조건에 넣는다. 데이터 거주: 한국 리전 도메인은 저장만 가능하고 처리는 미국·EU에서 이뤄지므로 '국내 처리'라고 말하지 않는다.

### 6.3 사용자당 월 모델 비용 (가설)

Decisions API 단가는 입력 $0.10 per 1M 토큰, 출력 무료(정식 출시, 공식 가이드 기준). 캐시 적중 입력은 할인된다.

| 항목 | 가정 | USD |
|---|---|---|
| L1 화면 판정·스텝 판정 | 25회 실행 × 8질문 묶음 × 1.5k 입력 | ≈ 0.03 |
| L1 의도 라우팅·형식 검증 | 60회 × 2k 입력 | ≈ 0.01 |
| L2 대화·인자 채우기·요약 (Terra, low) | 40회 × 6k 입력/0.6k 출력 | ≈ 0.36 |
| L2 예외 복구 (Terra, medium) | 3회 × 40k 입력/3k 출력 | ≈ 0.17 |
| 캐시 효과 | 보수적으로 0 (명시 모드 적중 시 L1 −40%, L2 −30%) | 0 |
| **합계** | | **≈ 0.6~0.75 USD ≈ 850~1,050원** |

핵심 레버는 변함없이 **L2 개입률**이다. L1이 "이 화면은 예상대로다"를 싸게 확인해 줄수록 L2는 덜 불린다. 목표: 실행 100건당 L2 호출 ≤ 15건.

## 8. 리모트 컨트롤 프로토콜

1. 페어링: 데스크톱이 임시 키쌍과 QR(공개키+릴레이 룸 ID) 생성 → 모바일 스캔 → 양측 장기 키 교환, 지문 확인 문구 표시.
2. 세션: 모바일 → 릴레이 → 데스크톱으로 암호문 메시지. 릴레이는 룸 ID와 크기만 본다.
3. 명령 스키마: `{playbook_id, inputs, nonce, ts}`. 화이트리스트 외 명령 거부. 재전송 방지(nonce).
4. 승인: 비가역 단계의 user_gate는 요청한 쪽(폰)으로 승인 카드를 보내고, 로컬 화면에도 동일 표시. 둘 중 하나 승인.
5. 비밀 입력 중계: 보안카드 칸 번호·인증서 비밀번호는 폰에서 입력 → 암호문 → 데스크톱 메모리 → 사용 → 폐기. 데스크톱 디스크에 쓰지 않는다.
6. 결과 전달: PDF는 기기 키로 암호화해 블롭 저장소 경유 또는 직접 전송. 폰에서 복호화.
7. 오프라인: 데스크톱이 꺼져 있으면 릴레이가 "오프라인" 반환 → 모바일은 클라우드 조회 에이전트 모드로 전환 + "PC 켜지면 실행" 예약 큐(암호문으로 보관).

## 9. 데몬

- OS 로그인 시 시작하는 백그라운드 서비스(트레이). 작업 창·전원 조건·네트워크 조건 확인 후 실행.
- 무인 실행 가능 조건: (a) 사용자가 해당 서류의 자동 갱신에 동의 (b) 공동인증서 + 저장된 비밀번호 보유 (c) user_gate 사전 승인 규칙 존재("매월 1일 납세증명 자동 갱신 허용").
- 그 외는 반자동: 시작 전에 폰 알림 → 승인 → 실행 → 간편인증 PUSH 승인.
- 매 실행은 일반 플레이북과 동일한 감사 로그를 남긴다.

```
sovereign-ax/
  apps/
    desktop/        # Electron + TS: UI, 플레이북 엔진 호스트, 데몬, 리모트 수신기

  packages/
    playbooks/      # 포털별 플레이북 (서명 배포 단위)
    engine/         # 플레이북 런타임, 체크포인트, user_gate, 복구기

    redaction/      # 마스킹 규칙·사전·역치환
    protocol/       # 리모트/블롭 암호화 스키마
    docparse/       # PDF 텍스트 추출·유효기간 규칙표
  docs/             # 이 기획서, ADR, 법률 검토 메모
```

## 12. 지금 당장 검증해야 할 기술 가설 (스파이크 목록, 04 문서와 연결)

1. Playwright persistent Chromium으로 홈택스 **공동인증서 로그인 + 전자세금계산서 발급**이 보안 모듈 없이 끝까지 되는가 (Windows 11, macOS 각각).
2. 사업자용 **간편인증 PUSH** 흐름을 플레이북이 대기·재개할 수 있는가.
3. 정부24 **출력 → 가상 PDF 프린터**가 주요 5종 서류에서 모두 동작하는가 (출력 보안 모듈이 가상 프린터를 막는 서류 식별).
4. 발급 PDF에서 발급일·유효기간을 **규칙만으로** 95% 이상 뽑을 수 있는가.
5. 마스킹된 접근성 트리만으로 Terra가 셀렉터 실패를 **복구**하는 비율(목표 70%+).
6. 홈택스·정부24 사이트 개편 빈도와 영향 범위(지난 2년 변경 이력 조사).
7. Decisions API의 **화면 상태 판정 정확도**(로그인/오류/완료/세션만료/미지 5분류, 목표 98%+)와 실측 지연(목표 중앙값 1초 이하).
8. 사람 속도 설정으로 플레이북을 연속 50회 실행했을 때 포털의 경고·차단·추가 인증 요구가 0건인지(05 문서 운영 기준 검증).
