# 03. 기술 아키텍처


## 2. 기술 스택 (권장)

| 영역 | 선택 | 이유 |
|---|---|---|
| 데스크톱 셸 | **Electron + TypeScript** | Playwright와 같은 Node 생태계, Windows/macOS 동시 지원, 팀 속도. 바이너리 크기가 문제되면 Tauri + Node 사이드카로 전환 가능 |
| 브라우저 자동화 | **금고 프로세스가 사용자 설치 Chrome을 전용 프로필·최소 플래그 모드로 구동**(`ignoreDefaultArgs: true` + CDP 파이프, `--remote-debugging-port` 금지, `--no-sandbox`·`--disable-extensions` 없음), 엔진은 금고가 중계하는 CDP 사용 | 실제 Chrome이라 보안 모듈·간편인증 팝업 호환이 높다. | 비밀 저장 | Windows DPAPI/Credential Manager, macOS Keychain | OS 신뢰 루트에 위임 |
| 로컬 문서 처리 | PDF 텍스트 추출 + 규칙 기반 파서, 필요 시 로컬 OCR | 발급일·유효기간 추출을 모델 없이 |

| 모바일 | React Native(Expo) | 한 코드베이스, 푸시·생체인증·QR |
| 백엔드 | Node(TypeScript) 또는 Go, PostgreSQL, S3 호환 저장소 | 소규모 팀, 단순 API |
| 릴레이 | WebSocket 릴레이 + libsodium 기반 E2E(Noise 패턴) | 서버는 암호문만 |

## 3. 플레이북 엔진 (가장 중요한 부품)

플레이북 = 특정 포털 작업을 수행하는 **버전 관리된 선언적 IR**(코드가 아님). 모델 없이 끝까지 도는 것이 정상 경로. 상세 명세는 설계서 D02·D03이며, 여기서는 원칙만 적는다.

```
H-01 전자세금계산서 건별발급 (요약)
  로그인(간편인증 PUSH 또는 공동인증서 직접 입력) → 화면 판정(Decisions)
  → 건별발급 화면 입력 → 되읽기(readback) → 확인 카드(게이트, 단일 사용 토큰)
  → 발급 클릭(원장 armed → dispatched, 커밋 가드 무장) → 발급목록 조회(verify: committed / not_committed / unknown)
  → 승인번호 캡처 → PDF 저장 → 이메일 전송(후속 토큰) → 전송 상태 조회
  실패: 재시도 → Decisions로 상황 분류 → (커밋 구간 밖에서만) Terra 셀렉터 수리 → 사람 핸드오프
```

설계 원칙:
- **비가역성은 선언이 아니라 사전 속성**: 발급·제출 버튼은 셀렉터 사전에 `commits`로 표시되고, 정적 검증기가 커밋 구간 규칙(허가 게이트 유일·지배·구간 무결성·재진입 시 재게이트)을 강제한다. 런타임에는 단일 사용 게이트 토큰, 아이덴포턴시 원장(armed→dispatched→committed|in_doubt), 네트워크 커밋 가드가 겹친다.
- **결과는 조회로 확정**: 화면 판정이 아니라 포털 발급목록 조회로 제출 여부를 결정하고, 미확정이면 InDoubt 상태로 사람에게 넘긴다. 중복 발급을 막는 유일한 방법이다.
- **판단은 Decisions, 수리는 Terra**: 선택지가 정해진 질문은 Decisions API(출력이 선택지 밖으로 못 나감), 셀렉터 복구 같은 열린 문제만 Terra. 커밋 구간 안에서는 모델이 개입하지 않는다.
- **요청률 상한 유지**: 스텝 간 지연 범위, 세션·일일 상한, 재시도 상한을 서명된 운영 정책으로 집행한다. 행동 모사(타이핑 지터 등)는 하지 않는다.
- **텔레메트리**: 실패한 스텝·셀렉터·플레이북 버전만 수집(화면 내용 없음). 개편 감지 → 영업일 1일 임시 조치, 3영업일 핫픽스.
- **헤드풀 기본**: 사용자가 원하면 창을 볼 수 있다. 데몬 실행 시엔 최소화.

## 4. 비밀 경계 (Secrets Boundary)

| 비밀 | 저장 위치 | 사용 시점 | 절대 가지 않는 곳 |
|---|---|---|---|
| 공동인증서 개인키 (NPKI `signPri.key`) | 사용자 원위치(디스크). **하네스는 읽지 않는다** | 포털 브라우저 모듈이 서명 | 우리 서버, 모델, 릴레이 |
| 공동·금융인증서 비밀번호 | 저장하지 않는다(ADR-020 결정 2) | 사용자가 브라우저 서명 창에 직접 입력. 금고 타이피스트는 입력하지 않는다 | 〃 |
| 보안카드 번호표·홈택스 아이디·비밀번호 | 보안카드를 발급 인증으로 고른 경우에만 한 번 등록. AES-256-GCM 암호문, 열쇠는 DPAPI(위임 등급, ADR-020 결정 3, D05 §2) | 금고가 아이디 로그인과 요청된 칸만 입력 | 〃 |
| 간편인증 | 저장 없음(폰 앱이 보유) | PUSH 승인 | 〃 |
| 기기 키·백업 키 | OS 키체인(루트 키는 상주시키지 않음) + 사용자 복구 문구 | 블롭 암·복호화, 리모트 채널 | 서버(복구 문구도 서버 미보관) |

구현 규칙:
- **금고 프로세스가 Chrome 파이프를 소유**하고 비밀 입력을 직접 수행한다. 엔진·UI는 금고가 중계하는 CDP와 핸들만 본다. `--remote-debugging-port`는 금지한다.
- 이 장치의 범위는 정직하게 적는다: 평문이 엔진의 메모리·로그·크래시 덤프·모델 전송에 남지 않게 하는 **위생 장치**이며, 같은 PC 사용자의 악성코드나 엔진 침해에 대한 경계가 아니다. 사용자 고지에도 같은 문장을 쓴다.
- 비밀은 Buffer로만 다루고 사용 후 0으로 덮는다. 금고는 크래시 덤프를 끄고, 엔진·메인의 덤프는 업로드하지 않는다.
- 마스킹 계층 **이전**에 어떤 바이트도 네트워크로 나가지 못하도록 네트워크 호출을 단일 모듈로 모은다.

## 5. 마스킹(Redaction) 계층

모델로 나가는 모든 텍스트·접근성 트리·스크린샷은 이 계층을 통과한다.

- 규칙 기반 치환: 주민번호, 사업자번호, 계좌번호, 전화번호, 이메일, 주소, 금액(옵션), 인증서 비밀번호·보안카드 패턴 → `[RRN_1]`, `[BIZNO_2]`처럼 토큰화. 역치환 표는 로컬에만.
- 사용자 사전: 상호·대표자명·거래처명을 사전에 넣어 자동 치환.
- 스크린샷은 기본 비전송. 필요 시 접근성 트리(텍스트)로 대체하고, 정말 필요할 때만 마스킹 박스 처리 후 전송.
- 전송 전 미리보기 가능 + 감사 로그에 전송 바이트 수·치환 건수 기록.
- 모델 응답에 토큰이 포함되면 로컬에서 역치환해 사용.

## 6. 모델 계층과 비용 설계

### 6.1 세 계층

| 계층 | 담당 | 수단 | 호출 빈도(사용자/월) | 특성 |
|---|---|---|---|---|
| L0 플레이북 | 정상 경로 전체 | 결정적 스크립트 | 발급 25회 | 토큰 0, 가장 빠름 |
| L1 판단 | 의도 라우팅, 화면 상태 판별, 스텝 성공 판정, 팝업 분류, 입력값 형식 검증 | **Decisions API** (`gpt-6-luna`) | 300~400회 | 선택지 고정, 확률·신뢰도 반환, 출력 무과금. 지연은 S7 실측(공급사는 생성형 대비 약 10배 빠름만 주장) |
| L2 추론 | 자연어 지시 → 인자 채우기(복잡 케이스), 셀렉터 복구, 결과 요약, 조회 에이전트 답변 | **GPT-6.1 Terra** (Responses API) | 40~50회 | 도구 호출, 1M 컨텍스트, effort low/medium |

Decisions API 사용 규약:
- 질문 타입 `predicate`(예/아니오 확률), `choice`(선택지 중 하나 + 선택지별 확률 + confidence), `score`(단계 점수)를 쓴다. 한 요청에 여러 질문을 묶어 한 화면을 한 번에 판정한다(예: "로그인 화면인가", "오류 모달이 있는가", "발급 완료 문구가 보이는가", "세션 만료 안내인가").
- **confidence 임계값** 미만이면 자동 진행하지 않고 체크포인트 복귀 또는 사용자 핸드오프. 응답이 `refusal` 타입이면 수치 필드를 읽지 않고 핸드오프.
- 입력은 마스킹된 접근성 텍스트가 기본. 이미지가 필요하면 마스킹 박스 처리한 **잘라낸 영역**을 인라인 base64로만 보낸다(공개 URL도 받지만 우리는 쓰지 않는다. `file_id`는 미지원).
- 암묵 캐시는 공유 `input` 전체 끝에 브레이크포인트를 걸어 매번 바뀌는 화면 텍스트까지 쓰기 요율($0.125/1M)로 과금한다. 따라서 명시 모드로 고정 접두(1,024토큰 이상) 끝에만 브레이크포인트를 건다. `prompt_cache_key`는 계정별로 격리한다(공유 캐시는 적중 여부 오라클이 될 수 있다). 캐시 절감은 호출당 센트 미만이라 설계의 핵심 변수가 아니다.
- 모든 선택지에 항상 `미지/검토 필요` 항목을 넣는다. 모델이 억지로 아는 척하지 못하게 하는 장치다.

Terra 사용 규약:
- `reasoning.effort` 지원값은 `none/low/medium(기본)/high/xhigh/max`. 우리는 대화·요약 `low`, 복구 `medium`만 쓰고 항상 명시한다(기본이 medium). `max`는 쓰지 않는다(비용·지연, 그리고 시스템카드상 최대 effort에서 제한 우회 롤아웃 29.6%).
- 도구는 플레이북 엔진이 노출하는 **읽기·입력 보조 도구**만. 네비게이션·제출·서명 도구는 노출하지 않는다.
- 시스템 프롬프트·플레이북 카탈로그·도구 정의를 고정 접두로 두고 **명시 캐시 모드**로 접두 끝에만 브레이크포인트를 건다(캐시 읽기 $0.05/1M, 단 캐시 쓰기는 $1.25/1M로 비캐시보다 비싸므로 가변 내용에 브레이크포인트를 걸면 손해). 가변 내용은 뒤에.
- 화면 텍스트는 데이터로 취급한다는 지시를 명시하고, 프롬프트 인젝션 의심 문구가 보이면 Decisions `predicate`로 먼저 걸러 Terra에 넘기지 않는다.

### 6.2 게이트웨이

- 클라이언트는 공급사 API 키를 갖지 않는다. 계정 토큰 → 게이트웨이 → OpenAI. 게이트웨이는 **본문 무저장**이며 계량을 셋으로 나눈다: 결제 레코드(월 단위), 호출 단위 계정 연결 레코드(35일, 결제 대사), 운영 통계(계정·기기 ID 없음, 13개월). 질문·도구 정의는 서버가 주입하고 클라이언트 파라미터는 화이트리스트·크기 상한·HMAC 태그로 제한한다.
- 어댑터 구조: `decide()`와 `respond()` 두 인터페이스 뒤에 공급사를 숨긴다. `decide()`는 System One 계약(Upstage `solar-decide` 등)까지 포괄하도록 일반화했고, Phase 0에서 Upstage Decide를 같은 코퍼스로 병행 평가한다. 국산 모델·국내 CSP 전환 기준은 ADR-015(조달·계약 트리거, "완전 소버린" 표기 금지, 남는 외국 의존 공개).
- 사용량 정책: 플랜별 월 한도 → 80% 알림 → 초과 시 L0는 계속, L2만 제한, L1은 최소 보장(화면 판정은 안전과 직결).
- **BYOK**: 사용자가 자기 OpenAI 키를 넣으면 게이트웨이를 거치지 않고 직접 호출. "우리 서버조차 거치지 않는다"는 주권 메시지와 일관.
- 데이터 보존: Responses·Decisions 모두 ZDR 승인 전에는 공급사 남용 모니터링 보존(최대 30일, 공급사 정책)이 적용되고(`store:false`는 응답 객체 저장만 끈다), 공급사가 법적 보존 의무를 지면 더 길어질 수 있다. ZDR은 공급사 영업 승인이 필요하며(Decisions는 캐시·이미지 예외) 승인 신청을 Go 조건에 넣는다. 데이터 거주: 한국 리전 도메인은 저장만 가능하고 처리는 미국·EU·UAE에서 이뤄지므로 '국내 처리'라고 말하지 않는다.

## 8. 리모트 컨트롤 프로토콜 (요약, 상세는 설계서 D08)

1. 페어링: 데스크톱이 바이너리 QR(정적 공개키 + 1회용 PSK + 임시 룸 + 만료)을 표시 → 폰 앱 내 스캐너로 스캔 → `Noise_XXpsk0` 핸드셰이크 → 폰이 QR의 키와 계정 기기 목록으로 PC를 검증 → 사용자가 **폰의 6자리 코드를 PC에 입력**해야 완료.
2. 세션: `Noise_IK`, 연결마다 새 키. 릴레이는 우편함 ID·크기 버킷·시각만 보고 내용은 볼 수 없다.
3. 명령: 플레이북 ID + 입력만. 셀렉터·URL·스텝 같은 저수준 명령은 프로토콜에 없다.
4. 승인: 데스크톱이 되읽은 값으로 카드와 `actionHash`·챌린지를 만들고, 폰은 생체 인증 뒤 서명한 승인을 보낸다(비가역은 SE/StrongBox P-256 하드웨어 키만). 먼저 도착한 결정이 이긴다.
5. 비밀·캡차: 비밀은 금고 전용 키로 인증 봉인(챌린지·origin·종류 결속)되어 라이브 세션에서만 오가고, 엔진은 열 수 없다. 캡차 이미지는 폰으로 중계(포털별 정책이 허용할 때만). 홈택스 공동인증서 비밀번호(가상키패드)는 폰에서 대신 입력할 수 없다.
6. 결과: PDF는 E2EE 블롭 저장소 경유, 폰에서 복호화.
7. 오프라인: 의도 봉투만 72시간 큐에 두고, PC가 켜지면 실행이 아니라 **새 승인 요청**을 만든다. 비밀은 큐에 넣지 않는다.

## 9. 데몬

- OS 로그인 시 시작하는 백그라운드 서비스(트레이). 작업 창·전원 조건·네트워크 조건 확인 후 실행.
- Phase 2 출시 모드는 `notify`(알림)와 `semi_auto`(시작 동의 1회 + 비가역 직전 승인 1회, 폰). 무인 `auto`는 사람 없이 끝나는 로그인 경로(홈택스 공동인증서는 가상키패드, 간편인증은 폰 승인)와 법률 의견이 확보될 때까지 보류한다.
- 직전 실행에 미확정(in_doubt) 원장이 있으면 자동 재시도하지 않는다. 매 실행은 일반 플레이북과 동일한 감사 로그를 남긴다.
