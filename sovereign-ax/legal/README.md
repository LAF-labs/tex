## 2. 코드에서 찾은 불일치 (고칠 것)

1. **예상 밖 화면 판정·브라우저 에이전트 호출은 무보관(ZDR)·공급사 고정이 꺼져 있다.** → 게이트웨이에 `OPENROUTER_AGENT_PRIVACY=off|deny|zdr` 스위치를 넣었다(기본 off = 2026-11-13 결정 그대로). 실키로 판정이 막히지 않는지 본 뒤 `zdr`로 켜고 처리방침 예외 문구를 지운다. 게이트웨이 `ENV.md` `MODEL_AGENT` 행(대표 2026-11-13)과 `src/providers.ts`의 unpinned 경로. 처리방침 6항에 "공급사 정책을 따름"으로 정직하게 적어 두었지만, OpenRouter는 공급사를 고정하지 않고도 `zdr: true`·`data_collection: "deny"`만 보낼 수 있다. 이것만 켜면 처리방침의 예외 문구를 지울 수 있다. **권장: 출시 전에 켠다.**
2. ~~**앱 안 탈퇴(계정 삭제)가 없다.**~~ → 설정 > 기기 연결 [탈퇴] + 계정 API `/v1/account/delete-request`·`delete-cancel`·`deletion`(7일 유예, 구독 즉시 해지, 데스크톱 기기 토큰). 처리방침 9항을 앱 기준으로 고쳤다. 원래 지적: 계정 API에 계정 삭제 경로가 없고 앱에도 화면이 없다. 개인정보 보호법 §38④(동의 철회·탈퇴를 수집 절차보다 어렵게 하지 않음)과 약관 제15조(가입과 같은 경로로 해지)에 맞추려면 앱 설정에 [탈퇴]가 필요하다. 지금 처리방침은 "메일로 요청"으로 적었다.
3. **결제·해지 화면**은 결제 스레드 PR #384가 맡는다(체험은 카드 없이 가입일부터 1개월, 체험 뒤 AI 기능 잠금, 하루 사용 한도, 첫 결제 7일 전 메일, 동의 판 서버 기록). #384 머지 뒤 탈퇴 요청에서 `subscriptions.billing_key_sealed`도 비우거나 `cancelSubscription`을 부르게 맞춘다(지금도 canceled면 청구하지 않고, 계정 삭제 때 행이 CASCADE로 지워진다). 원래 지적: **결제·해지 화면이 없다.** `POST /v1/billing/checkout`·`/cancel` API만 있다. 결제 화면을 만들 때 결제 직전 고지(총액·부가세, 결제일·주기, 자동 갱신, 해지 방법·효력, 철회·환불 조건)를 그 화면에 넣고, 해지는 같은 화면에서 한 번에 되게 한다(약관 제11조③·제15조①). 고지 문구는 약관 제11조~제15조를 요약해 쓴다.
4. **모델 처리자 표에 OpenAI가 빠져 있었다.** 판정(L1 `decide`)은 OpenAI 직결이다. 이번 PR에서 `CONSENT_CONFIG`에 넣었다(판 `2026-11-16`).
5. **D09·D11은 Windows Hello를 전제로 쓴 곳이 있다.** 제품은 지금 Mac(키체인)이다. 처리방침은 Mac 기준으로 썼다.
6. **기기 2대 이상 계정의 공유 기록(대표 2026-11-16, ADR-046 결정 7·ADR-048 결정 5).** 발급 기록·밀린 일·거래처를 종단간 암호화해 서버에 둔다(서버는 종류·시각·크기만 봄). 처리방침 원칙·2항·3항에 `[출시 때 추가]` 표시로 자리를 잡아 두었다. 서버 PR이 올라올 때 표시를 지우고, 6항 Supabase 항목에도 "공유 기록 암호문"을 넣는다. 원칙의 "Mac에만 저장" 문장은 1대 계정에만 맞으므로 함께 고친다.

## 3. 변호사 확인 (EX-1, R13 Q7·Q8·Q9, R14 Q10에 더함)

- 무료 체험 1개월(대표 2026-11-16) → 유료 자동 전환: 체험 시작 때 받은 명시 동의로 전환해도 되는지, 전환 전 재통지 시점(첫 결제 7일 전 메일 1회, 약관 제12조)이 전자상거래법 §13④·시행령 기준을 채우는지.

- 약관 제14조②: 이용을 시작한 뒤 7일 안 철회 시 쓴 날짜만큼 공제하는 방식이 전자상거래법 §17②5호(디지털콘텐츠 제공 개시)의 요건과 맞는지. 개인사업자의 소비자 해당성.
- 약관 제17조 원인별 책임 배분, 제18조 면책 범위가 약관법 §7에 걸리지 않는지.
- 처리방침 5항·6항: 마스킹된 텍스트의 모델 전송을 §28의8①3호(계약 이행을 위한 처리위탁)로 공개만 하는 것으로 충분한지, 거래처·직원 정보가 섞일 때도 같은지(Q7). 지금 앱은 약관 화면에서 별도 동의 레코드도 남긴다(②).
- 공공데이터포털 상태조회로 거래처 사업자번호를 보내는 것의 성격(위탁·제공·해당 없음). 지금 처리방침은 5항 끝에 사실만 적었다.
- CODEF(헥토데이터) 위탁계약과 유료약관 제14조 9항 사전 동의(09 §4.6). 처리방침은 수탁자로 적었다.
- 접속 기록 보존 기간(통신비밀보호법 3개월, 안전성 확보조치 기준 적용 여부, D09 §10의 "법무 확인").
- 만 14세 미만 가입 제한으로 충분한지(사업자 서비스라 성인 제한이 필요한지).

## 4. 판과 동의 기록

- 약관 화면(④)의 판은 사이트 전문 판과 같이 간다: `terms-2026-11-30`. 전문을 바꾸면 `CONSENT_NOTICES.terms.version`을 올리고, 처리방침 14항·약관 제4조의 고지 기간을 지킨다.
- 처리자 표 판(`CONSENT_CONFIG.processorsVersion`)은 처리방침 6항 표와 같이 바꾼다.
- 서버의 `POST /v1/consents {version}`(계정 동의 이력)는 앱에서 아직 부르지 않는다. 결제 화면을 붙일 때 약관 판을 서버에도 남기는 것을 권한다(전자상거래법 계약 기록 5년).
- 폰 앱: Phase 1은 계정 로그인이 없어 앱 안 동의 화면이 없다. 스토어 제출 때 처리방침 URL(https://tax.laf-co.com/privacy)을 넣고, 개인정보 표시는 R14 I-8을 따른다(사진·현금매출은 E2EE라 '수집 안 함', 계정·기기 식별자·진단은 '수집').
