1. 관련
   가. 정부24 이용약관(2026. 3. 9. 시행) 제14조 제4항 제9호·제10호·제11호, 제16조 제4항
   나. 정부24 공지 「매크로 및 유사 프로그램 사용자 이용 제한 안내」(2024. 10. 15.)

2. 당사는 사업자가 **자기 PC에서, 자기 인증수단으로, 자기 명의의** 행정 서류를 발급하고 보관하도록 돕는 데스크톱 프로그램(가칭 「소버린 AX」)을 개발하고 있습니다. 위 약관 제14조 제4항 제9호는 사전 허락 없이 자동화된 수단으로 로그인하거나 로그인을 시도하는 행위를 금지하고 있습니다. 당사는 허락을 받기 전에는 정부24에서 어떠한 자동화도 하지 않으며, 이에 정부24 이용에 대한 **사전 허락을 요청**드리고 허락의 범위와 절차를 여쭙고자 합니다.

3. 서비스 개요
   가. 프로그램은 사용자 PC에서 사용자가 실행합니다. 포털 접속은 사용자 PC의 브라우저가 사용자 PC의 인터넷 주소(IP)로 합니다. 당사 서버는 정부24에 접속하지 않습니다.
   나. 사용자는 자기 명의의 서류만 다룹니다. 계정 하나에 프로필은 2개(개인 하나, 사업자 하나)까지만 등록할 수 있습니다. 여러 고객의 업무를 한 계정에 묶어 대신 처리하는 대리 사용은 이용약관으로 금지합니다(1단계 출시 때 적용).
   다. 당사는 세무 신고·장부 작성·세무 상담을 하지 않으며, 민원 신청을 대행하지 않습니다.
   라. 홈택스 이용에 대해서는 국세청에 별도로 알리고 질의하고 있습니다.

4. 허락 전 현재 운영 방식(후처리 모드)
   가. 프로그램은 정부24 페이지를 **사용자의 기본 브라우저로 열기만** 합니다. 자동화용 브라우저(Chrome 제어 채널)를 띄우지 않고, 프로그램이 정부24 서버에 요청을 보내지 않습니다.
   나. 로그인·입력·발급·출력은 사용자가 직접 합니다. 프로그램은 옆 화면에 단계 안내를 보여 주고, 사업자번호·주소처럼 비밀이 아닌 값을 복사할 수 있게 합니다. 복사한 값은 30초 뒤 클립보드에서 지웁니다. 비밀번호 같은 비밀 값은 복사 버튼을 만들지 않습니다.
   다. 사용자가 발급한 PDF를 저장하고 그 파일을 직접 고르면, 프로그램이 파일을 PC 안의 보관함으로 옮기고 발급일·유효기간을 추출해 만료 전에 알려 줍니다.
   라. 정부24 화면을 읽거나 기록하지 않고, 캡차를 중계하지 않으며, 값을 자동으로 입력하지 않습니다. 개발·시험 과정에서도 정부24 화면을 자동으로 조작하거나 녹화하지 않습니다.
   마. 정부24의 최대 운영 수준은 프로그램 안에 '후처리'로 고정돼 있습니다. 당사가 서명해 배포하는 운영 정책 파일만으로는 이 상한을 올릴 수 없고, 허락 회신을 받은 뒤 앱 업데이트로만 올립니다.
   바. 회신이 없는 것을 허락으로 보지 않습니다. 불허 회신을 받으면 위 후처리 방식을 계속 유지합니다.

5. 허락을 요청하는 범위
   가. 대상 서류

   | 구분 | 서류 | 대상 | 시기 |
   |---|---|---|---|
   | G-01 | 주민등록표 등본·초본 | 개인(대표자 등 본인) | 1단계 |
   | G-02 | 지방세 납세증명서(위택스 경로가 열리기 전까지) | 개인·법인 | 1단계 |
   | G-03 | 건강보험 자격득실확인서 | 개인 | 1단계 |
   | G-04 | 토지대장·건축물대장 | 개인·법인 | 2단계 |
   | G-05 | 지방세 세목별 과세증명(위택스 경로가 열리기 전까지) | 개인·법인 | 2단계 |

   나. 서류마다 하는 행위: 로그인(사용자 인증수단) → 해당 서류 메뉴 이동 → 신청 항목 입력 → 사용자 승인 → 발급 → 발급 결과를 사용자 PC에 저장. 저장 방식은 서류별로 귀 부의 기준에 따르겠습니다. 목록 화면을 반복해서 돌거나 대량으로 조회하는 행위는 하지 않습니다.

   다. 운영 수준: 아래 두 수준 가운데 허락하실 수 있는 범위를 여쭙습니다.
   - **보조**: 로그인과 발급(제출) 버튼은 사용자가 직접 누릅니다. 프로그램은 로그인 **뒤에** 비식별 입력값 채우기, 화면 상태 판정, 결과 파일 수집만 합니다.
   - **자동**: 위 나.의 흐름 전체를 프로그램이 진행합니다. 다만 인증(간편인증 승인, 인증서 비밀번호 입력)과 발급 직전 승인은 사용자가 합니다.

   라. 빈도 상한(프로필 하나 기준, 허락 후 적용할 현재 기준값): 하루 실행 20건, 그중 발급 5건, 로그인 세션 하나당 5건, 하루 로그인 6회, 분당 화면 이동 12회, 동시 세션 1개. 사용자 한 명의 실제 예상 빈도는 {{사용자 조사(PoC-11) 결과로 채움}}입니다.

6. 기술 방식(허락 후 적용하며, 홈택스에도 같은 방식을 씁니다)
   가. 사용자가 설치한 Chrome을 전용 프로필로 띄우고, 제어 채널(`--remote-debugging-pipe`)로 제어합니다. 원격 디버깅 포트(`--remote-debugging-port`)는 쓰지 않습니다.
   나. 이렇게 띄운 Chrome은 포털이 읽을 수 있는 **자동화 표식(`navigator.webdriver=true`)을 그대로 드러냅니다.** 당사는 이 값을 바꾸거나 숨기지 않습니다. 기동할 때마다 표식이 켜져 있는지 확인하고, 꺼져 있으면 자동화를 하지 않습니다.
   다. `--enable-automation` 플래그는 브라우저 상단에 표시줄을 띄우기 때문에 쓰지 않습니다. 이 플래그를 쓰지 않아도 위 표식은 그대로 남습니다.
   라. 화면 없는(헤드리스) 모드를 쓰지 않으며, 사용자가 창을 볼 수 있습니다. User-Agent·브라우저 지문·기기 정보를 바꾸지 않고, 프록시나 IP 변경을 쓰지 않습니다.
   마. 일반 입력칸은 값을 한 번에 넣고, 타이핑을 흉내 내지 않습니다. 키 입력 이벤트가 필요한 칸만 150ms 고정 간격으로 입력합니다. 화면 단계 사이에는 0.8~2.5초의 지연과 페이지 안정화 대기를 둡니다. 이 지연은 요청률 상한이며 사람의 행동을 흉내 내려는 것이 아닙니다.
   바. 단계마다 정해진 횟수(현재 2회) 안에서만 재시도하고, 그래도 안 되면 사용자에게 넘깁니다. 차단 안내 화면, 비정상 접근 경고, 연속 추가 인증 같은 차단 신호가 보이면 즉시 멈추고 사용자에게 알리며, 24시간 동안 다시 접속하지 않습니다.
   사. 캡차와 추가 인증은 사용자가 직접 풉니다. 캡차를 자동으로 해독하는 기능은 없습니다. 사용자가 PC 앞에 없을 때 캡차 화면을 사용자 본인의 휴대폰으로 보내 사용자가 입력하는 기능(2단계 예정, 종단간 암호화)은 정부24에서는 허락 전에 꺼져 있습니다. 이 기능을 켜도 되는지는 아래 9항 다.에서 따로 여쭙니다.
   아. 포털이 요구하는 보안 프로그램은 사용자가 설치한 그대로 둡니다. 키보드 보안이나 가상키패드가 적용된 칸은 사용자가 직접 입력하며, 이를 우회하지 않습니다.

7. 식별과 연락
   가. 운영 연락처: {{담당자 성명·직위}}, {{전화}}, {{이메일}}. 문의를 받으면 24시간 안에 응답하겠습니다. 【D-5】
   나. 귀 부가 정한 식별 방식(User-Agent 접미사, 등록 헤더, 허용 목록 등록 등)이 있으면 그대로 따르겠습니다. 요구가 없으면 임의로 식별자를 붙이지 않습니다. 프로그램은 실제 Chrome의 실제 User-Agent를 그대로 씁니다.
   다. 사용자 PC에는 세션별 시각, 작업, 플레이북 버전을 담은 감사 기록이 남습니다. 귀 부가 특정 접속에 대해 물으시면 사용자 동의를 받아 이 기록으로 소명하겠습니다(붙임 4).
   라. 귀 부가 중단이나 조정을 요청하시면 당사가 서명해 배포하는 운영 정책으로 해당 기능을 앱 업데이트 없이 즉시 끄거나 낮추겠습니다.

8. 준수 사항
   가. 정부24 이용약관을 지키며, 같은 조 제10호가 금지하는 IP 변경 접속과 외부 솔루션을 통한 캡차 우회를 하지 않습니다.
   나. 차단 신호가 보이면 즉시 멈추고, 귀 부가 요청하시면 기준을 조정하거나 기능을 중단합니다.
   다. 허락 범위를 넘는 변경은 미리 다시 협의하겠습니다.
   라. 인증서, 비밀번호 등 인증정보와 발급 서류 본문은 당사 서버로 보내지 않습니다. 당사 서버가 받거나 거쳐 가는 항목은 붙임 3에 모두 적었습니다.

9. 질의 사항
   가. 위 5항·6항의 방식으로 정부24를 이용하는 것을 허락해 주실 수 있는지, 허락하신다면 그 범위(서류, 운영 수준, 빈도, 시간대)를 알려 주십시오.
   나. 금지되는 행위나 따로 붙는 조건이 있는지 알려 주십시오.
   다. 사용자가 PC 앞에 없을 때 캡차 화면을 사용자 본인의 휴대폰에 종단간 암호화로 보여 주고 사용자가 직접 입력하는 방식이 약관 제14조 제4항 제10호의 "외부 솔루션 등을 통한 캡차 우회"에 해당하는지 알려 주십시오. 이 방식에서 당사 서버는 캡차 화면과 입력값을 볼 수 없고, 캡차 이미지는 인공지능 모델로 보내지 않습니다.
   라. 식별자 등록이나 허용 목록 절차가 있는지 알려 주십시오.
   마. 지켜야 할 기술 기준(요청 빈도, 시간대 등)이 있는지 알려 주십시오.
   바. 허락 전 운영 방식(4항: 기본 브라우저로 열기, 사용자가 저장한 파일 정리)이 약관상 문제가 없는지 알려 주십시오.
   사. 사전 허락을 이 공문과 다른 경로나 양식으로 신청해야 한다면 안내해 주시고, 앞으로 연락할 창구를 알려 주십시오.

10. 위택스 이용 관련 질의 【D-3】
   가. 당사는 지방세 납세증명서(W-01, 1단계 베타 중 추가 예정)와 지방세 세목별 과세증명(W-02, 2단계 예정)을 위택스에서 발급하는 기능을 계획하고 있습니다.
   나. 위택스 이용약관의 자동화 관련 조항을 확인하기 전에는 이 기능을 켜지 않습니다. 그동안 지방세 납세증명서는 위 4항의 정부24 후처리 방식으로만 제공합니다.
   다. 위택스에서 위 6항의 방식으로 자동화 수단을 이용하는 것이 허용되는지, 사전 허락이 필요한지, 필요하다면 그 절차와 담당 부서를 알려 주십시오. 빈도 상한은 5항 라.와 같은 수준 이하로 정하겠습니다.

## 작성 메모 (발송본에서 지운다)

- 9항 다.는 05 §3-1·D03 §7의 "정부24 캡차 중계는 허락 회신 전 비활성이고, 공문에 중계 방식을 명시한다"를 따른 것이다. 허락을 받더라도 캡차 중계 상한(`CAPTCHA_RELAY_CEILING`)은 앱 업데이트로만 올린다(ADR-011 결과).
- 5항 라.의 빈도 상한은 D03 §7 `limits.gov24` 값이다. `auto`·`assisted`를 허락받은 뒤에만 쓰인다.
- G-02·G-05는 위택스 경로(W-01·W-02)가 열리면 정부24 대상에서 빠진다(ADR-018 결정 3, 02 §10).
- 정부24 저장 경로(`page.pdf()`·전자문서지갑 자동화)는 허락 회신 뒤로 미뤄 두었다(04 S3a~c). 그래서 5항 나.에서 저장 방식은 "귀 부의 기준에 따른다"고만 썼다.
