1. 관련
   가. 정부24 이용약관(2026. 3. 9. 시행) 제14조 제4항 제9호·제10호·제11호, 제16조 제4항
   나. 정부24 공지 「매크로 및 유사 프로그램 사용자 이용 제한 안내」(2024. 10. 15.)
   다. 위택스 이용약관(2026. 7. 30. 시행) 제17조·제18조, 위택스 개인정보처리방침의 '대리인의 사전협의 방법'

2. 당사는 사업자가 **자기 PC에서, 자기 인증수단으로, 자기 명의의** 행정 서류를 발급하고 보관하도록 돕는 데스크톱 프로그램(가칭 「소버린 AX」)을 개발하고 있습니다. 정부24 이용약관 제14조 제4항 제9호와 위택스 이용약관 제17조 제2항은 사전 허락 없이 자동화된 수단으로 로그인하거나 로그인을 시도하는 행위(인증정보로 로그인한 뒤 개인정보를 수집하는 행위를 포함)를 금지하고 있습니다. 당사는 허락을 받기 전에는 두 사이트에서 접속·조작을 자동화하지 않으며, 이에 **사전 허락을 요청**드리고 허락의 범위와 절차를 여쭙고자 합니다. 아래 3~9항은 정부24에 관한 것이고, 위택스는 10항에 따로 적었습니다.

3. 서비스 개요
   가. 프로그램은 사용자 PC에서 사용자가 실행합니다. 포털 접속은 사용자 PC의 브라우저가 사용자 PC의 인터넷 주소(IP)로 합니다. 당사 서버는 정부24에 접속하지 않습니다.
   나. 사용자는 자기 명의의 서류만 다룹니다. 계정 하나에 프로필은 2개(개인 하나, 사업자 하나)까지만 등록할 수 있습니다. 여러 고객의 업무를 한 계정에 묶어 대신 처리하는 대리 사용은 1단계 출시 때 이용약관에 금지 조항을 둘 예정입니다.
   다. 당사의 서버나 직원은 민원을 신청하지 않습니다. 신청은 사용자 PC에서 사용자의 인증과 승인으로 이루어집니다. 당사는 세무 신고·장부 작성·세무 상담을 하지 않습니다.
   라. 홈택스 이용에 대해서는 국세청에 따로 알리고 질의하고 있으며, 당사가 개인정보 보호법령상 '대리인'에 해당하는지는 개인정보보호위원회에 질의하고 있습니다.

4. 허락 전 운영 방식(후처리 모드)
   현재 개발 검증 단계에서는 정부24 기능을 시험하지 않습니다. 1단계 출시 때부터 허락을 받기 전까지는 아래 방식으로만 제공합니다.
   가. 프로그램은 정부24 페이지를 **사용자의 기본 브라우저로 열기만** 합니다. 자동화용 브라우저(Chrome 제어 채널)를 띄우지 않고, 프로그램이 정부24 서버에 요청을 보내지 않습니다.
   나. 로그인·입력·발급·출력은 사용자가 직접 합니다. 프로그램은 옆 화면에 단계 안내를 보여 주고, 사업자번호·주소처럼 비밀이 아닌 값을 복사할 수 있게 합니다. 복사한 값은 30초 뒤 클립보드에서 지웁니다. 비밀번호 같은 비밀 값에는 복사 버튼을 만들지 않습니다.
   다. 사용자가 발급한 PDF를 저장하고 그 파일을 직접 고르면, 프로그램이 파일을 PC 안의 보관함으로 옮기고 발급일·유효기간을 추출해 만료 전에 알려 줍니다. 날짜를 고를 때 서류에서 날짜 주변의 짧은 텍스트를 식별 정보를 지운 뒤 인공지능 모델에 보냅니다(붙임 3).
   라. 정부24 화면을 읽거나 기록하지 않고, 캡차를 중계하지 않으며, 값을 자동으로 입력하지 않습니다. 개발·시험 과정에서도 정부24 화면을 자동으로 조작하거나 녹화하지 않습니다.
   마. 정부24의 최대 운영 수준은 프로그램 안에 '후처리'로 고정돼 있습니다. 당사가 서명해 배포하는 운영 정책 파일만으로는 이 상한을 올릴 수 없고, 허락 회신을 받은 뒤 앱 업데이트로만 올립니다.
   바. 회신이 없는 것을 허락으로 보지 않습니다. 불허 회신을 받으면 자동화하지 않으며, 위 방식에 대해서도 아래 9항 바.의 회신에 따르겠습니다.

5. 허락을 요청하는 범위
   가. 대상 서류

   | 구분 | 서류 | 대상 | 시기 |
   |---|---|---|---|
   | G-01 | 주민등록표 등본·초본 | 개인(대표자 등 본인) | 1단계 |
   | G-02 | 지방세 납세증명서(위택스 이용 허락 전까지) | 개인·법인 | 1단계 |
   | G-03 | 건강보험 자격득실확인서 | 개인 | 1단계 |
   | G-04 | 토지대장·건축물대장 | 개인·법인 | 2단계 |
   | G-05 | 지방세 세목별 과세증명(위택스 이용 허락 전까지) | 개인·법인 | 2단계 |

   나. 서류마다 하는 행위: 로그인(사용자 인증수단) → 해당 서류 메뉴 이동 → 신청 항목 입력 → 사용자 승인 → 발급 → 발급 결과를 사용자 PC에 저장. 저장 방식은 서류별로 귀 부의 기준에 따르겠습니다. 목록 화면을 반복해서 돌거나 대량으로 조회하는 행위는 하지 않습니다.

   다. 운영 수준: 아래 두 수준 가운데 허락하실 수 있는 범위를 여쭙습니다.
   - **보조**: 로그인과 발급(제출) 버튼은 사용자가 직접 누릅니다. 프로그램은 로그인 **뒤에** 비식별 입력값 채우기, 화면 상태 판정, 결과 파일 수집만 합니다.
   - **자동**: 위 나.의 흐름 전체를 프로그램이 진행합니다. 다만 인증(간편인증 승인, 인증서 비밀번호 입력)과 발급 직전 승인은 사용자가 합니다.

   라. 빈도 상한(프로필 하나 기준, 허락 후 적용할 현재 기준값): 하루 실행 20건, 그중 발급 5건, 로그인 세션 하나당 5건, 하루 로그인 6회, 분당 화면 이동 12회, 동시 세션 1개. 사용자 한 명의 실제 예상 빈도는 {{사용자 조사 결과로 채움}}입니다.

6. 기술 방식(허락 후 적용하며, 홈택스에도 같은 방식을 씁니다)
   가. 사용자가 설치한 Chrome을 전용 프로필로 띄우고, 제어 채널(`--remote-debugging-pipe`)로 제어합니다. 원격 디버깅 포트(`--remote-debugging-port`)는 쓰지 않습니다.
   나. 이렇게 띄운 Chrome은 포털이 읽을 수 있는 **자동화 표식(`navigator.webdriver=true`)을 그대로 드러냅니다.** 당사는 이 값을 바꾸거나 숨기지 않습니다. 기동할 때마다 표식이 켜져 있는지 확인하고, 꺼져 있으면 자동화를 하지 않습니다.
   다. `--enable-automation` 플래그는 브라우저 상단에 표시줄을 띄우기 때문에 쓰지 않습니다. 이 플래그를 쓰지 않아도 위 표식은 그대로 남습니다.
   라. 화면 없는(헤드리스) 모드를 쓰지 않으며, 사용자가 창을 볼 수 있습니다. User-Agent·브라우저 지문·기기 정보를 바꾸지 않고, 프록시나 IP 변경을 쓰지 않습니다.
   마. 일반 입력칸은 값을 한 번에 넣고, 타이핑을 흉내 내지 않습니다. 키 입력 이벤트가 필요한 칸만 150ms 고정 간격으로 입력합니다. 화면 단계 사이에는 0.8~2.5초의 지연과 페이지 안정화 대기를 둡니다. 이 지연은 요청률 상한이며 사람의 행동을 흉내 내려는 것이 아닙니다.
   바. 화면 요소를 찾지 못하면 한 단계에서 최대 3회까지 다시 시도합니다. 발급처럼 되돌릴 수 없는 단계는 다시 시도하지 않습니다. 그래도 안 되면 아래 자.의 방식으로 원인을 한 번 분류·복구해 보고, 그래도 안 되면 사용자에게 넘깁니다.
   사. 차단 안내 화면, 비정상 접근 경고, 연속 추가 인증 같은 차단 신호가 보이면 즉시 멈추고 사용자에게 알립니다. 차단 신호가 연속 두 번 확인되면 24시간 동안 다시 접속하지 않습니다.
   아. 캡차와 추가 인증은 사용자가 직접 풉니다. 캡차를 자동으로 해독하는 기능은 없습니다. 사용자가 PC 앞에 없을 때 캡차 화면을 사용자 본인의 휴대폰으로 보내 사용자가 입력하는 기능(2단계 예정, 종단간 암호화)은 정부24에서는 허락 전에 꺼져 있습니다. 이 기능을 켜도 되는지는 아래 9항 다.에서 따로 여쭙니다.
   자. 인공지능 모델은 화면 상태 판정(로그인 여부, 오류·차단·캡차 화면, 발급 직전 입력 오류 표시, 발급 직후 결과 화면)과, 화면이 예상과 다를 때의 복구에 씁니다. 이때 모델로 보내는 것은 현재 단계 화면의 구조 텍스트입니다. 보내기 전에 주민등록번호·사업자번호·이름·주소·연락처 같은 식별 정보와 금액을 찾아 기호로 바꾸고 입력칸의 값을 지우며, 당사 게이트웨이에서 한 번 더 검사합니다. 탐지 방식이라 일부가 남을 수 있습니다. 1단계에서는 화면 이미지를 보내지 않으며, 바꾸게 되면 미리 알리겠습니다. 캡차 이미지는 모델로 보내지 않습니다. 모델은 당사 게이트웨이를 거쳐 해외 공급사가 처리합니다(붙임 3). 발급 버튼을 누르는 단계에서는 모델이 판단하지 않습니다.
   차. 승인 없이 발급 요청이 나가지 않도록, 브라우저가 포털로 보내는 발급 요청을 PC 안에서 확인하고 사용자 승인이 없으면 보내지 않습니다. 요청 내용은 바꾸지 않습니다.
   카. 포털이 요구하는 보안 프로그램은 사용자가 설치한 그대로 둡니다. 키보드 보안이나 가상키패드가 적용된 칸은 사용자가 직접 입력하며, 이를 우회하지 않습니다.

7. 식별과 연락
   가. 운영 연락처: {{담당자 성명·직위}}, {{전화}}, {{이메일}}. 문의를 받으면 24시간 안에 응답하겠습니다. 【D-5】
   나. 귀 부가 정한 식별 방식(User-Agent 접미사, 등록 헤더, 허용 목록 등록 등)이 있으면 그대로 따르겠습니다. 요구가 없으면 임의로 식별자를 붙이지 않습니다. 프로그램은 실제 Chrome의 실제 User-Agent를 그대로 씁니다.
   다. 사용자 PC에는 세션별 시각, 작업, 플레이북 버전을 담은 감사 기록이 남습니다. 귀 부가 특정 접속에 대해 물으시면, 해당 사용자가 동의하는 경우 그 기록으로 확인해 드리겠습니다(붙임 4).
   라. 귀 부가 중단이나 조정을 요청하시면, 요청을 받은 날 당사가 서명한 운영 정책을 배포해 해당 기능을 앱 업데이트 없이 끄거나 낮추겠습니다. 배포한 정책은 켜져 있는 사용자 프로그램에 20분 안에 적용되고, 꺼져 있던 프로그램은 다시 켠 뒤 작업을 시작하기 전에 정책을 먼저 받아 적용합니다. 당사 서버에 연결되지 않으면 그 사실을 사용자에게 알립니다.

8. 준수 사항
   가. 정부24 이용약관을 지키며, 같은 약관 제14조 제4항 제10호와 위택스 이용약관 제17조 제2항이 금지하는 IP 변경 접속과 외부 솔루션을 통한 캡차 우회를 하지 않습니다.
   나. 차단 신호가 보이면 즉시 멈추고, 귀 부가 요청하시면 기준을 조정하거나 기능을 중단합니다.
   다. 허락 범위를 넘는 변경은 미리 다시 협의하겠습니다.
   라. 인증서·비밀번호 등 인증정보와 발급 서류의 원문은 당사가 볼 수 있는 형태로 당사 서버에 보내지 않습니다. 당사 서버나 외부로 가는 항목(식별 정보를 지운 화면·서류 텍스트 일부 포함)은 붙임 3에 모두 적었습니다.

9. 질의 사항
   가. 위 5항·6항의 방식으로 정부24를 이용하는 것을 허락해 주실 수 있는지, 허락하신다면 그 범위(서류, 운영 수준, 빈도, 시간대)를 알려 주십시오.
   나. 금지되는 행위나 따로 붙는 조건이 있는지 알려 주십시오.
   다. 사용자가 PC 앞에 없을 때 캡차 화면을 사용자 본인의 휴대폰에 종단간 암호화로 보여 주고 사용자가 직접 입력하는 방식이 약관 제14조 제4항 제10호의 "외부 솔루션 등을 통한 캡차 우회"에 해당하는지 알려 주십시오. 이 방식에서 당사 서버는 캡차 화면과 입력값을 볼 수 없고, 캡차 이미지는 인공지능 모델로 보내지 않습니다.
   라. 식별자 등록이나 허용 목록 절차가 있는지 알려 주십시오.
   마. 지켜야 할 기술 기준(요청 빈도, 시간대 등)이 있는지 알려 주십시오.
   바. 허락 전 운영 방식(4항: 기본 브라우저로 열기, 사용자가 저장해 고른 파일 정리)이 약관상 문제가 없는지 알려 주십시오.
   사. 사전 허락을 이 공문과 다른 경로나 양식으로 신청해야 한다면 안내해 주시고, 앞으로 연락할 창구를 알려 주십시오.

10. 위택스 이용 사전 허락 요청 【D-3】
   가. 당사는 지방세 납세증명서(W-01, 1단계 베타 중 추가 예정)와 지방세 세목별 과세증명(W-02, 2단계 예정)을 위택스에서 발급하는 기능을 계획하고 있습니다.
   나. 위택스 이용약관 제17조 제2항에 따라, 사전 허락을 받기 전에는 위택스에서 어떠한 자동화도 하지 않습니다. 그동안 지방세 납세증명서는 위 4항의 정부24 후처리 방식으로만 제공합니다. 위택스의 최대 운영 수준도 4항 마.와 같이 프로그램 안에 '후처리'로 고정해, 운영 정책 파일만으로는 올릴 수 없고 허락 회신을 받은 뒤 앱 업데이트로만 올립니다. 회신이 없는 것을 허락으로 보지 않습니다.
   다. 허락을 요청하는 방식은 위 6항(기술 방식)·7항(식별과 연락)·8항(준수 사항)과 같고, 빈도 상한은 5항 라.와 같은 수준 이하로 정하겠습니다. 캡차 중계는 위택스에서도 허락 전에 꺼 둡니다.
   라. 위 방식으로 위택스를 이용하는 것을 허락해 주실 수 있는지, 허락하신다면 그 범위와 조건을 알려 주십시오. 9항 나.~사.의 질의도 위택스에 대해 같이 여쭙니다.
   마. 위택스 개인정보처리방침은 자동화된 도구를 이용하는 대리인에게 사전협의 신청서를 따로 내도록 안내하고 있습니다. 당사가 그 대리인에 해당하는지는 개인정보보호위원회에 질의하고 있습니다. 이 공문과 별도로 사전협의 신청서를 내야 한다면 알려 주십시오.

## 작성 메모 (발송본에서 지운다)

- 9항 다.는 05 §3-1·D03 §7의 "정부24 캡차 중계는 허락 회신 전 비활성이고, 공문에 중계 방식을 명시한다"를 따른 것이다. 허락을 받더라도 캡차 중계 상한(`CAPTCHA_RELAY_CEILING`)은 앱 업데이트로만 올린다(ADR-011 결과).
- 5항 라.의 빈도 상한은 D03 §7 `limits.gov24` 값이다. `auto`·`assisted`를 허락받은 뒤에만 쓰인다.
- 6항 바.는 D03 §6 복구 계층(L0 재시도 ≤ 3, 비가역 스텝 0 → L1 `recovery_v1` → L2 `selector_repair` 1회 → L3 핸드오프)이다. 6항 사.는 D03 §7 `cooldown.positiveDetectionsForCooldown: 2`다.
- 6항 자.의 모델 호출 지점은 D04 §1 '호출 지점 전체 목록'과 §3 번들 카탈로그(`screen_state_v2`·`form_ready_v2`·`issue_result_v2`·`recovery_v1`)다.
- 7항 라.의 반영 시간은 ADR-023이다(앱이 켜져 있는 동안 15분마다 조회, 실행 직전 재조회, 켜진 앱 20분 안). 당사 서버에 닿지 못하는 PC는 마지막 유효 정책으로 돌며 경고를 띄우고, 정책 만료(발행 뒤 72시간 이하) 뒤에는 완화 금지·데몬 중지, 만료 168시간 뒤에는 전 포털 후처리로 내려간다(ADR-023 잔여 위험, [06 §3](06-design-crosscheck.md#3-설계-문서-사이의-불일치-후속) #17 해소).
- G-02·G-05는 위택스 경로(W-01·W-02)가 열리면 정부24 대상에서 빠진다(ADR-018 결정 3, 02 §10).
- 위택스 이용약관(2026. 7. 30. 시행, v1.1) 제17조 ①은 자동화된 도구를 쓰는 대리인에게 사전 협의 방식을 요구하고, ②는 사전 허락 없는 자동화 로그인, IP 변경 접속, 캡차 우회를 금지한다. 제18조는 대리인의 책임, 제20조 ②·③·④ 8호는 영리행위, 정보의 타인 제공, 안정 운영 저해를 정한다(위택스 약관 원문, 2026-11-02 조회). 그래서 10항을 '질의'에서 '사전 허락 요청'으로 바꿨다.
- 위택스 상한은 ADR-022로 D03 §7.1 `PORTAL_MODE_CEILING.wetax = postprocess`, `CAPTCHA_RELAY_CEILING.wetax = disabled_until_permission`이 됐다. 그래서 10항 나.에 4항 마.와 같은 '앱 내장 상한' 문장을 넣었다. 상향 순서는 허락 회신 → 앱 업데이트 → 정책이고, 상향 때 `limits.wetax`는 `limits.gov24` 이하다(ADR-022 결정 2·3, [06 §3](06-design-crosscheck.md#3-설계-문서-사이의-불일치-후속) #10 해소).
- 정부24 저장 경로(`page.pdf()`·전자문서지갑 자동화)는 허락 회신 뒤로 미뤄 두었다(04 S3a~c). 그래서 5항 나.에서 저장 방식은 "귀 부의 기준에 따른다"고만 썼다.
- 4항 첫 문장은 ADR-017 결정 2(PoC에서 정부24 제외, 목업만)다.
