## 붙임 1. 프로그램 구조 요약

```text
┌─ 사용자 PC (Windows) ────────────────────────────────────────────────┐
│  데스크톱 앱                                                          │
│   ├ 화면·승인 바(main): 사용자가 발급을 승인하는 곳                    │
│   ├ 엔진: 서명된 플레이북 실행, 요청률 상한, 중복 발급 방지 원장, 감사 기록 │
│   ├ 금고: 비밀 보관·입력, Chrome 기동과 제어 채널을 단독 소유           │
│   └ 문서 추출 샌드박스: 저장된 PDF에서 발급일·유효기간 추출(네트워크 차단) │
│                                                                      │
│  Chrome(사용자가 설치, 전용 프로필, 창이 보임) ── 사용자 IP ──▶ 홈택스   │
│  기본 브라우저(사용자가 직접 조작) ───────────────────▶ 정부24         │
│     (정부24는 허락 전 후처리: 프로그램은 페이지를 열고 저장 파일만 정리)  │
└──────────────────────────────────────────────────────────────────────┘
          │ 마스킹된 텍스트, 계정·계량                  ▲ 서명된 플레이북·운영 정책
          ▼                                            │
┌─ 당사 서버 ── 포털(홈택스·정부24)에 접속하지 않음 ───────────────────────┐
│  계정·구독 ─ 결제대행(국내), 메일 발송(국내)                              │
│  모델 게이트웨이 ─▶ 인공지능 모델 공급사(해외)                            │
│    └ 진위확인 프록시 ─▶ 공공데이터포털(국세청 진위확인·상태조회 API)         │
│  플레이북 레지스트리: 서명된 플레이북과 운영 정책 배포                      │
│  (2단계) 중계(종단간 암호화), 푸시, 암호문 백업, 서류 메타데이터           │
└──────────────────────────────────────────────────────────────────────┘
          ▲ 종단간 암호화(당사는 내용을 볼 수 없음)
┌─ 사용자 휴대폰 (2단계) ─┐
│  발급 승인, 캡차 입력    │
└─────────────────────────┘
```

- 포털 접속은 사용자 PC에서만 한다. 당사 서버는 포털에 접속하지 않는다.
- 프로그램이 다루는 비밀(홈택스 아이디·비밀번호, 보안카드 번호)은 금고 프로세스 안에만 있다. 공동·금융인증서 비밀번호는 사용자가 포털 화면에 직접 넣고 프로그램은 받지 않는다(붙임 2).
- 인공지능 모델은 화면 상태 판정과 복구, 대화 해석, 서류 날짜 확인에 쓰며, 식별 정보를 지운 텍스트만 받는다(붙임 3). 발급 버튼을 누르는 단계에서는 모델이 판단하지 않는다. 발급은 사용자가 승인 바에서 승인한 뒤에만 실행된다.
- 정부24의 최대 운영 수준은 앱 안에 '후처리'로 고정돼 있다. 서명된 운영 정책으로는 낮추거나 상한 안에서만 조정할 수 있고, 상한을 올리려면 앱 업데이트가 필요하다. 위택스는 사전 허락 회신 전에는 자동화하지 않는다.
- 홈택스용 Chrome은 자동화 표식(`navigator.webdriver=true`)을 그대로 드러낸다. 원격 디버깅 포트는 쓰지 않는다.
- 승인 없는 발급 요청이 나가지 않도록, 브라우저가 포털로 보내는 발급 요청을 PC 안에서 확인하고 승인이 없으면 보내지 않는다(요청 내용은 바꾸지 않는다).

## 붙임 2. 비밀 경계표

| 비밀 | 어디에 있는가 | 누가 쓰는가 | 당사 서버로 | 모델로 |
|---|---|---|---|---|

| 홈택스 아이디·비밀번호, 보안카드 번호(보안카드를 고른 사용자, 1단계) | PC 금고. 칸마다 AES-256-GCM으로 암호화하고 열쇠는 이 PC의 보안 칩(TPM)에 묶음(TPM이 없으면 Windows 로그인 계정에 묶어 보관, DPAPI). Windows 화면 잠금·15분 미사용 때 금고 잠금. 발급마다 Windows Hello 확인을 켤 수 있음(기본 꺼짐). PoC에서는 저장하지 않음 | 금고가 포털 칸에 직접 입력. 입력칸이 가상키패드면 사용자가 입력 | 가지 않음 | 가지 않음 |

| 간편인증 | 사용자 휴대폰(인증 앱) | 사용자가 휴대폰에서 승인 | 가지 않음 | 가지 않음 |

| 기기 키·앱 내부 키 | OS 키체인 | 금고(개인키는 금고 밖으로 나가지 않음) | 공개키만 | 가지 않음 |

**보호 범위(그대로 고지하는 문장)**: 이 구조는 비밀이 앱의 다른 부분, 로그, 크래시 덤프, 모델로 가는 데이터에 남지 않게 하는 장치다. **같은 PC의 같은 Windows 사용자 권한으로 실행되는 악성코드로부터는 보호하지 못한다.** 관리자·커널 권한을 가진 공격도 막지 못한다(보호 범위 밖).

## 붙임 4. 감사 기록 항목 예시

> **형식 예시이며 실제 기록이 아니다.** 사용자 PC에만 남고 당사 서버로 보내지 않는다. 운영기관이 특정 접속에 대해 물으면 사용자 동의를 받아 해당 실행의 기록을 낸다.

**실행 요약(실행 1건당 1행)**

| 필드 | 예시 | 뜻 |
|---|---|---|
| `id` | `run_01J…` | 실행 ID |
| `playbook_id` / `playbook_version` | `hometax.taxinvoice.issue` / `1.0.0` | 작업과 플레이북 버전 |
| `trigger` | `local` | 시작 경로(`local` PC, `remote` 휴대폰, `daemon` 정기 갱신) |
| `started_at` / `finished_at` | `2026-11-…T10:02:11+09:00` | 시각 |
| `status` | `succeeded` | 결과 |
| `l1_calls` / `l2_calls` / `handoffs` | `0` / `0` / `1` | 모델 호출 수, 사람에게 넘긴 횟수 |

**이벤트(값 없이 종류·해시·코드만, 앞뒤 해시로 묶음)**

```json
{"seq":1,"at":"…T10:02:11+09:00","type":"run.started","payload":{"mode":"auto"}}
{"seq":2,"at":"…T10:02:19+09:00","type":"secret.used","payload":{"kind":"portal_password","viaTypist":true}}
{"seq":7,"at":"…T10:03:40+09:00","type":"gate.bar_shown","payload":{"actionHash":"sha256:9c1e…"}}
{"seq":8,"at":"…T10:03:52+09:00","type":"gate.approved","payload":{"presence":"click"}}
{"seq":9,"at":"…T10:03:52+09:00","type":"ledger.armed","payload":{"intentId":"int_…","stepId":"issue"}}
{"seq":10,"at":"…T10:03:53+09:00","type":"secret.used","payload":{"kind":"security_card","viaTypist":true}}
{"seq":12,"at":"…T10:04:01+09:00","type":"ledger.dispatched","payload":{"intentId":"int_…","stepId":"issue"}}
{"seq":15,"at":"…T10:05:10+09:00","type":"ledger.committed","payload":{"intentId":"int_…","stepId":"issue"}}
{"seq":18,"at":"…T10:05:31+09:00","type":"run.finished","payload":{"status":"succeeded"}}
```

- 차단 신호가 보이면 `block.signal`과 `cooldown.*`가 남는다. 쿨다운이 끝나기 전에는 해당 포털에 접속하지 않는다.
- 사업자번호, 금액, 이메일, 비밀 값, 비밀의 길이, 화면 텍스트, URL은 기록하지 않는다.
- 각 이벤트는 앞 이벤트의 해시를 담는다(`prev_hash`·`hash`, 위 예시에서는 생략). 그래서 중간의 일부를 고치거나 지우면 드러난다. 1단계에서는 기록 전체를 다시 쓰거나 끝부분을 잘라 내는 것까지는 막지 못한다. 2단계에서 하루 한 번 서명한 체크포인트를 사용자 휴대폰에 보내 이것도 드러나게 한다.
