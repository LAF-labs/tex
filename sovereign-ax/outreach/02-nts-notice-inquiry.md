1. 관련
   가. 홈택스 이용약관(2015. 2. 23. 시행) 제15조
   나. 국세청 개인정보처리방침 제5조 제10항(대리인의 자동화된 도구를 통한 본인정보 전송 관련 사전협의 창구 안내)

2. 당사는 사업자가 **자기 PC에서, 자기 인증수단으로, 자기 명의의** 홈택스 업무(전자세금계산서 발급, 민원증명 발급)를 처리하도록 돕는 데스크톱 프로그램(가칭 「소버린 AX」)을 개발하고 있습니다. 귀청의 안정적인 서비스 운영에 맞추고자 프로그램의 이용 방식, 빈도, 연락처를 미리 알려 드리고, 허용 범위와 지켜야 할 기준을 여쭙습니다. 승낙이나 등록, 협의 같은 절차가 필요하면 안내에 따라 신청하겠습니다.

3. 서비스 개요
   가. 프로그램은 사용자 PC에서 사용자가 실행합니다. 홈택스 접속은 사용자 PC의 브라우저가 사용자 PC의 인터넷 주소(IP)로 합니다. **당사 서버는 홈택스에 접속하지 않습니다.**
   나. 사용자는 자기 명의의 업무만 처리합니다. 계정 하나에 프로필은 2개(개인 하나, 사업자 하나)까지만 등록할 수 있습니다. 세금계산서를 발급할 때 공급자 사업자번호가 프로필의 사업자번호와 같은지 확인합니다. 여러 고객의 업무를 한 계정에 묶어 대신 처리하는 대리 사용은 1단계 출시 때 이용약관에 금지 조항을 둘 예정입니다.
   다. 당사는 신고할 세액의 산정, 신고서 작성, 절세·공제 판단, 세무 상담을 하지 않습니다. 세금계산서 금액의 부가가치세 10% 분리는 홈택스 '계산' 버튼과 같은 산술로만 하고, 과세·영세·면세 구분은 사용자가 정합니다.
   라. 발급과 전송은 사용자가 내용을 확인하고 승인한 뒤에만 합니다(7항 라.).
   마. 프로그램은 월 구독료를 받는 유료 서비스로 제공할 예정입니다. 발급 건당 요금은 받지 않습니다.
   바. 정부24와 위택스는 행정안전부의 사전 허락을 받기 전까지 자동화하지 않습니다. 이 공문은 홈택스에 관한 것입니다.

4. 이용 범위
   가. 프로그램이 하는 작업은 당사가 서명해 배포하는 작업 목록(플레이북)으로 정해져 있으며, 목록 밖의 행위는 하지 않습니다.

   | ID | 작업 | 접근 화면과 행위 | 성격 | 시기 |
   |---|---|---|---|---|
   | H-01 | 전자세금계산서 건별발급과 이메일 발송 | 로그인 → 건별발급 화면 → 항목 입력(공급받는자 이메일 칸 포함) → 입력값 되읽기 → 발급목록 조회(발급 전 기준) → 사용자 승인 → 전자서명·발급(홈택스가 입력한 이메일로 발송) → 발급목록 조회로 결과 확인 → 발급분 PDF 저장 → 메일 발송 목록 조회로 전송 확인 | 발급(되돌릴 수 없음) | PoC·1단계 |
   | H-03 | 사업자등록증명 발급 | 민원증명 즉시발급 → PDF 저장 | 증명 발급 | PoC·1단계 |
   | H-04 | 납세증명서(국세) 발급 | 〃 | 증명 발급 | PoC·1단계 |
   | H-08 | 부가가치세 과세표준증명 / 면세사업자 수입금액증명 발급 | 〃 | 증명 발급 | 1단계 |
   | H-09 | 표준재무제표증명 발급 | 〃 | 증명 발급 | 1단계 |
   | H-02 | 전자(세금)계산서 발급분·수취분 조회와 PDF 저장 | 조회 화면 → PDF 저장 | 조회 | 1단계 베타 |
   | H-10 | 사실증명 신청·수령 | 신청 → 처리 대기 → 수령 | 증명 신청 | 1단계 베타 |
   | H-11 | 휴업·폐업사실증명 발급 | 민원증명 → PDF 저장 | 증명 발급 | 1단계 베타 |
   | H-06 | 수정세금계산서 발급 | H-01과 같은 흐름 | 발급(되돌릴 수 없음) | 2단계 |
   | H-07 | 매출·매입 합계표 조회(요약) | 조회 | 조회 | 2단계 |

   나. 하지 않는 일: 목록 화면 반복 순회, 대량 조회, 홈택스 화면에서 다른 사업자의 정보를 조회하는 일, 세무 신고.
   다. 거래처의 사업자등록 상태 확인은 홈택스 화면이 아니라 공공데이터포털에 공개된 국세청 진위확인·상태조회 API를 씁니다(진위확인 방식이면 API가 요구하는 대표자 성명·개업일자도 함께 보냅니다). 이 호출은 당사 게이트웨이를 거치거나(당사 서비스 키) 사용자가 자기 서비스 키로 직접 합니다.

5. 빈도와 상한(프로필 하나 기준 현재 기준값이며, 검증 결과와 귀청의 요청에 따라 더 보수적으로 조정할 수 있습니다)
   가. 하루 실행 40건, 그중 발급(되돌릴 수 없는 작업) 30건, 로그인 세션 하나당 15건, 하루 로그인 6회, 분당 화면 이동 12회, 동시 세션 1개
   나. 화면 단계 사이에 0.8~2.5초의 지연, 화면 이동 뒤 0.6~1.5초의 안정화 대기. 이 지연은 요청률 상한이며 사람의 행동을 흉내 내려는 것이 아닙니다.
   다. 재시도: 화면 요소를 찾지 못하면 한 단계에서 최대 3회까지 다시 시도합니다. 발급처럼 되돌릴 수 없는 단계는 다시 시도하지 않습니다. 그래도 안 되면 6항 아.의 방식으로 원인을 한 번 분류·복구해 보고, 그래도 안 되면 사용자에게 넘깁니다.
   라. 발급 결과 확인: 발급 뒤 발급목록을 조회해 결과를 확인합니다. 결과가 불분명하면 간격을 두고 다시 조회하며, 확인되기 전에는 다시 발급하지 않습니다(중복 발급 방지).
   마. 차단 신호: 차단 안내 화면, 비정상 접근 경고, 연속된 추가 인증 요구, 접속 거부 응답 급증이 보이면 즉시 멈추고 사용자에게 알립니다. 차단 신호가 연속 두 번 확인되면 24시간 동안 다시 접속하지 않습니다. 10분 안에 캡차가 3회 뜨면 속도를 낮추고 사용자에게 알립니다.
   바. 이중 로그인: 사용자가 다른 기기에서 홈택스에 로그인해 프로그램의 세션이 끊기면 멈추고 사용자에게 다시 시작할지 묻습니다. 다시 로그인해 상대 세션을 끊지 않습니다.
   사. 정기 갱신(2단계 예정): 사용자가 미리 등록한 민원증명만, 사용자가 정한 시간대에 갱신합니다. 시작할 때 사용자의 동의를 받고, 발급 직전에 다시 사용자 승인을 받습니다. 사람 없이 끝나는 무인 실행은 현재 하지 않으며, 하게 되면 그 전에 귀청에 알리겠습니다. 시작 시각은 여러 사용자의 실행이 한 시각에 몰리지 않도록 정한 시각 앞뒤 30분 안에서 나눕니다. 정기 갱신은 단계 사이 간격을 1.2~3.5초로 더 길게 둡니다.

6. 기술 방식
   가. 사용자가 설치한 Chrome을 전용 프로필로 띄우고, 제어 채널(`--remote-debugging-pipe`)로 제어합니다. 원격 디버깅 포트(`--remote-debugging-port`)는 쓰지 않습니다.
   나. 이렇게 띄운 Chrome은 포털이 읽을 수 있는 **자동화 표식(`navigator.webdriver=true`)을 그대로 드러냅니다.** 당사는 이 값을 바꾸거나 숨기지 않습니다. 기동할 때마다 표식이 켜져 있는지 확인하고, 꺼져 있으면 자동화를 하지 않습니다.
   다. `--enable-automation` 플래그는 브라우저 상단에 표시줄을 띄우기 때문에 쓰지 않습니다. 이 플래그를 쓰지 않아도 위 표식은 그대로 남습니다.
   라. 화면 없는(헤드리스) 모드를 쓰지 않으며, 사용자가 창을 볼 수 있습니다. User-Agent·브라우저 지문·기기 정보를 바꾸지 않고, 프록시나 IP 변경을 쓰지 않습니다.
   마. 일반 입력칸은 값을 한 번에 넣고, 타이핑을 흉내 내지 않습니다. 키 입력 이벤트가 필요한 칸만 150ms 고정 간격으로 입력합니다.
   바. 포털이 요구하는 보안 프로그램은 사용자가 설치한 그대로 둡니다. 키보드 보안이나 가상키패드가 적용된 칸은 사용자가 직접 입력하며, 이를 우회하지 않습니다.
   사. 캡차와 추가 인증은 사용자가 직접 풉니다. 캡차를 자동으로 해독하는 기능은 없습니다. 사용자가 PC 앞에 없을 때는 캡차 화면 부분을 사용자 본인의 휴대폰으로 종단간 암호화해 보내고, 사용자가 휴대폰에서 입력한 값을 PC가 넣습니다(2단계 예정). 당사 서버는 캡차 화면과 입력값을 볼 수 없고, 캡차 이미지는 인공지능 모델로 보내지 않습니다. 90초 안에 응답이 없으면 작업을 멈추고 자동으로 다시 시도하지 않습니다.
   아. 인공지능 모델은 화면 상태 판정(로그인 여부, 오류·차단·캡차 화면, 발급 직전 입력 오류 표시, 발급 직후 결과 화면)과, 화면이 예상과 다를 때의 복구에 씁니다. 이때 모델로 보내는 것은 현재 단계 화면의 구조 텍스트입니다. 보내기 전에 주민등록번호·사업자번호·이름·주소·연락처 같은 식별 정보와 금액을 찾아 기호로 바꾸고 입력칸의 값을 지우며, 당사 게이트웨이에서 한 번 더 검사합니다. 탐지 방식이라 일부가 남을 수 있습니다. 1단계에서는 화면 이미지를 보내지 않으며, 바꾸게 되면 미리 알리겠습니다. 캡차 이미지와 비밀번호·보안카드 값은 모델로 보내지 않습니다. 발급 버튼을 누르는 단계에서는 모델이 판단하지 않고, 발급 여부는 발급목록 조회로 확정합니다(붙임 3).
   자. 승인 없이 발급 요청이 나가지 않도록, 브라우저가 홈택스로 보내는 발급 요청을 PC 안에서 확인합니다. 사용자 승인이 없거나 요청의 주요 값이 승인한 값과 다르면 보내지 않습니다. 요청 내용은 바꾸지 않습니다.

7. 인증과 전자서명
   가. 사용자는 처음 설정할 때 발급 인증 수단 하나를 고르고, 이후 모든 발급에 같은 수단을 씁니다.
   - **사업자용 간편인증**: 로그인과 전자서명 때마다 사용자가 휴대폰에서 승인합니다.
   - **공동인증서·금융인증서**: 비밀번호는 사용자가 홈택스 화면에 직접 입력합니다. 프로그램은 이 비밀번호를 저장하거나 자동으로 입력하지 않습니다. 프로그램은 인증서 개인키 파일을 열지 않으며, 서명은 홈택스의 서명 모듈이 합니다.
   - **보안카드(아이디 로그인)**: 사용자가 홈택스 아이디·비밀번호와 보안카드 번호를 PC 안의 금고에 한 번 등록하면, 프로그램이 아이디 로그인을 하고 발급 때 전자서명 창이 요구하는 보안카드 번호를 입력합니다. 값은 PC 안에서 암호화해 보관하고(열쇠는 Windows가 사용자 로그인 계정에 묶어 보관), 인공지능 모델·대화 기록으로 보내지 않습니다. 당사 서버로도 보내지 않습니다(휴대폰에서 입력하는 경우는 아래 다.). 보안카드 입력칸이 가상키패드 같은 보안 장치를 쓰면 자동으로 입력하지 않고 사용자가 직접 입력합니다. **이 방식이 허용되는지 11항 다.에서 여쭙습니다.**
   나. 개발 검증(아래 10항)에서는 어떤 비밀도 저장하지 않습니다. 매번 사용자가 입력하며, 홈택스 화면에 직접 넣거나, 프로그램의 비밀 입력 창에 넣으면 프로그램이 홈택스 칸에 옮겨 넣습니다.
   다. 다른 기기에서의 승인(2단계 예정): 사용자가 휴대폰 앱에서 발급을 승인하면 사용자 PC가 발급합니다. 이 방식은 발급 인증이 간편인증이나 보안카드일 때만 쓸 수 있고, 공동·금융인증서는 PC에서만 발급합니다. 휴대폰에서 보안카드 번호나 홈택스 비밀번호를 입력하면 그 값은 PC 금고만 열 수 있게 암호화돼 당사 중계 서버를 거쳐 전달되고, PC 금고가 입력한 뒤 바로 지웁니다. 휴대폰 승인 발급은 하루 5건까지이고, 처음 거래하는 상대나 처음 보내는 이메일 주소에는 PC에서만 발급합니다.
   라. 발급 직전 승인: 프로그램은 홈택스 화면에서 되읽은 값(공급받는자, 금액, 이메일 등)을 사용자에게 보여 주고, 사용자가 [승인하고 발급]을 누른 뒤에만 발급 버튼을 누릅니다. 같은 발급이 두 번 실행되지 않도록 PC 안의 원장에 기록합니다.

8. 식별과 연락
   가. 운영 연락처: {{담당자 성명·직위}}, {{전화}}, {{이메일}}. 문의를 받으면 24시간 안에 응답하겠습니다. 【D-5】
   나. 귀청이 정한 식별 방식(User-Agent 접미사, 등록 헤더, 허용 목록 등록 등)이 있으면 그대로 따르겠습니다. 요구가 없으면 임의로 식별자를 붙이지 않습니다. 프로그램은 실제 Chrome의 실제 User-Agent를 그대로 씁니다.
   다. 사용자 PC에는 세션별 시각, 작업, 플레이북 버전을 담은 감사 기록이 남습니다. 귀청이 특정 접속에 대해 물으시면, 해당 사용자가 동의하는 경우 그 기록으로 확인해 드리겠습니다(붙임 4).
   라. 귀청이 중단이나 조정을 요청하시면, 요청을 받은 날 당사가 서명한 운영 정책을 배포해 해당 기능을 앱 업데이트 없이 끄거나 낮추겠습니다. 배포한 정책은 켜져 있는 사용자 프로그램에 20분 안에 적용되도록 하였고, 꺼져 있던 프로그램은 켤 때와 작업을 시작하기 직전에 정책을 다시 받습니다. 당사 서버에 연결되지 않는 프로그램은 마지막으로 받은 정책으로 동작하면서 작업마다 그 사실을 사용자에게 알립니다. 연결되지 않은 상태가 이어져 정책의 유효기간(최대 72시간)이 지나면 정기 실행을 멈추고, 그 뒤 7일이 더 지나면 모든 사이트를 후처리 방식(자동 조작 없이 안내만 하는 방식)으로만 운영합니다.

9. 정보 처리
   가. 홈택스 화면에서 얻은 정보와 발급 서류는 사용자 PC에 저장합니다.
   나. 당사 서버가 받거나 거쳐 가는 항목은 붙임 3에 모두 적었습니다. 주요 항목은 계정 이메일과 결제 참조, 6항 아.의 식별 정보를 지운 화면 텍스트, 사용자의 대화 지시(식별 정보를 지움), 저장된 서류에서 발급일·유효기간 후보 주변의 짧은 텍스트(식별 정보를 지움), 진위확인 때의 거래처 사업자번호, 사용자가 켠 경우의 발급 활동 표시(일방향 해시)입니다.
   다. 2단계의 서류 백업은 사용자 기기에서 암호화한 암호문만 보관하며 당사는 열 수 없습니다.
   라. 인공지능 모델 공급사는 현재 해외 사업자이며, 공급사가 고지한 처리 국가는 미국·EU·UAE입니다. 이 사실은 사용자에게 고지하고 동의를 받습니다.

10. 현재 진행 상황 【D-4】
   가. 당사는 2026. 10. 29.부터 4주간 개발 검증을 하고 있습니다. 검증은 관계사 법인 1곳의 계정을 검증 전용으로 정해 그 계정에서만 하며, {{검증 조작 주체}}가 그 법인의 인증수단으로 합니다. 【D-10】
   나. 범위
   - 로그인부터 발급 버튼 직전까지의 자동 구간 측정(10회 안팎, 발급하지 않음)
   - 실제 거래가 있는 소액 전자세금계산서 실발급 2~3건
   - 민원증명 2종(사업자등록증명, 납세증명서) 발급
   - 화면 상태 판정 정확도를 재기 위한 홈택스 화면 기록(약 100장)과 실발급 과정의 기록. 기록은 판정 시험에만 쓰며, 시험 때 모델에는 6항 아.처럼 식별 정보를 지운 텍스트만 보냅니다.
   - 조회성 작업 50회를 5항의 상한 안에서 여러 세션과 날에 나눠 실행해, 정상 이용 범위에서 경고나 추가 인증이 생기지 않는지 확인
   - 발급 요청의 형식을 확인하기 위해 PC 안에서 브라우저 통신 기록을 살펴보는 일(6항 자.의 확인 장치를 만들기 위한 것)
   다. 검증 중에도 5항의 상한과 6항 가.~바.·아.의 방식을 지킵니다. 차단이나 제재 신호가 한 번이라도 오면 검증을 멈추고 귀청에 연락하겠습니다.

11. 질의 사항
   가. 위 방식의 홈택스 이용이 허용되는지 알려 주십시오(이용약관 제15조와의 관계 포함).
   나. 금지되는 행위나 따로 붙는 조건이 있는지 알려 주십시오.
   다. 7항 가.의 보안카드 방식(사용자 PC에 보안카드 번호와 홈택스 아이디·비밀번호를 암호화해 저장하고, 프로그램이 아이디 로그인과 보안카드 번호 입력을 하는 것)이 허용되는지 알려 주십시오. 국세상담센터는 보안카드를 이용한 전자(세금)계산서 발급은 홈택스에서만 가능하고 민간사업자가 운영하는 시스템에서는 불가하다고 안내하고 있습니다. 이 프로그램은 별도 시스템으로 발급하지 않고 사용자 PC의 브라우저에서 홈택스 화면에 입력합니다. 이 방식에도 위 안내가 적용되는지 함께 알려 주십시오. 허용되지 않으면 사용자가 보안카드 번호를 직접 입력하는 방식으로 바꾸겠습니다.
   라. 6항 사.의 휴대폰 캡차 중계(사용자 본인의 휴대폰, 종단간 암호화, 사용자가 직접 입력)가 허용되는지 알려 주십시오.
   마. 당사가 이 프로그램을 유료 구독으로 제공하는 것(3항 마.)이 이용약관 제15조 제2항(사전 승낙 없는 영리행위 금지)과 관련해 따로 승낙을 받아야 하는 일인지 알려 주십시오.
   바. 식별자 등록이나 허용 목록 절차가 있는지 알려 주십시오.
   사. 지켜야 할 기술 기준(요청 빈도, 시간대 등)이 있는지 알려 주십시오.
   아. 이 프로그램이 개인정보처리방침 제5조 제10항의 사전협의 대상인지, 대상이라면 그 절차를 알려 주십시오. 당사가 개인정보 보호법령상 '대리인'에 해당하는지는 개인정보보호위원회에 따로 질의하고 있습니다.
   자. 앞으로 연락할 창구와, 운영 중 차단이 생겼을 때 연락할 곳을 알려 주십시오.

## 작성 메모 (발송본에서 지운다)

- 05 §4.1은 국세청 요청 내용을 "자동화 접근 허용 및 식별자 등록"으로 적었지만(2026-11-02 통지·질의로 고침, [06 §3](06-design-crosscheck.md#3-설계-문서-사이의-불일치-후속) #6 해소), 그 뒤 ADR-017 결정 1이 "공문은 통지·질의이며 허가 신청이 아니다"로 정했다. 그래서 이 초안은 허가를 청하지 않는다. 대신 등록 절차가 있으면 따르겠다고 썼다(05 §3).
- 7항 가.의 보안카드 방식은 ADR-020 결정 2·3이다. ADR-020 조건("보안카드 입력칸이 가상키패드면 완전 위임을 보류하고 사용자 직접 입력")을 같은 문단에 적었다.
- 7항 다.의 하루 5건과 '처음 거래·처음 보내는 주소는 PC에서만'은 D03 §7 `remote.irreversiblePerDay`·`newCounterpartyRequiresLocal`과 ADR-021 §4다.
- 6항 아.의 "금액"은 D06 §4의 기본 치환이다. 금액 원값은 대화 금액 확인 번들(`amount_parse_check_v1`) 하나에만 간다(D04 §3). 이 번들은 화면이 아니라 사용자 문장을 다루므로 6항에는 쓰지 않고 붙임 3에 적었다.
- 5항 다.는 D03 §6 복구 계층, 5항 마.는 D03 §7 `cooldown.positiveDetectionsForCooldown: 2`다. 05 §2의 "스텝 재시도 2회"·"차단·경고 감지 시 24시간 쿨다운"은 D03보다 단순한 옛 서술이었고, 2026-11-02 D03 기준으로 고쳤다([06 §3](06-design-crosscheck.md#3-설계-문서-사이의-불일치-후속) #2·#13 해소).
- 10항은 D14 §0의 PoC-3(S1)·PoC-6·PoC-7(화면 코퍼스 100장)·PoC-8·PoC-10(S8)이다. D14·04 S8의 "연속 50회"는 하루 40건·세션 15건 상한을 넘으므로, 이 초안은 "상한 안에서 여러 세션과 날에 나눠"로 썼다. PoC-10 보고서(PR #16, `poc/reports/PoC-10.md` §6)가 정책 예외 없이 이틀·세션을 나눠 돈다고 정했고, D14·04·D13도 그렇게 고쳤다([06 §3](06-design-crosscheck.md#3-설계-문서-사이의-불일치-후속) #14 해소).
- 【D-10】의 검증 조작 주체가 당사 임직원이면 법률 질의 Q5-3의 회신을 받은 뒤 발송한다.
- 3항 마.의 가격은 01 §5의 가설이다. 금액은 쓰지 않았다.
- 8항 라.의 반영 시간은 ADR-023이다. 켜진 앱 20분 안은 운영 목표(측정함)이고, 실행 직전 조회가 3초 안에 안 되면 마지막 유효 정책으로 진행하며 경고를 띄운다. 정책 만료(발행 뒤 72시간 이하) 뒤 데몬 중지·완화 금지, 만료 168시간 뒤 전 포털 후처리다(D03 §7.1). 레지스트리 동결 공격은 잔여 위험이다(ADR-023 결과).
