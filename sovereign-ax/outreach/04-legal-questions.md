## 0. 공통 사실관계

### 0.1 제품

- 사업자가 **자기 PC(Windows)에서, 자기 인증수단으로, 자기 명의의** 홈택스 전자세금계산서 발급과 민원증명 발급을 처리하도록 돕는 데스크톱 프로그램이다(가칭 「소버린 AX」). 사용자는 대화창에 한 줄로 지시하고, 확인 카드로 내용을 본 뒤 발급 직전에 화면 하단의 승인 바에서 승인한다. 발급한 서류는 PC 안의 보관함에 두고 만료일을 알려 준다.
- 포털 접속은 사용자 PC의 브라우저가 사용자 IP로 한다. **우리 서버는 홈택스·정부24에 접속하지 않는다.**
- 계정 하나에 프로필 2개(개인 1, 사업자 1)까지. 세금계산서 발급 때 공급자 사업자번호가 프로필의 사업자번호와 같은지 확인한다. 세무사·경리대행이 여러 고객을 한 계정에 묶는 대리 사용은 이용약관으로 금지할 예정이다(F-06).
- 가격은 월 구독(스타터 9,900원 / 비즈니스 29,000원, 가설)이다. 발급 건당 과금은 없다.

### 0.2 포털별 운영 수준

| 포털 | 수준 | 하는 일 |
|---|---|---|
| 홈택스 | `auto` | 플레이북 전체를 프로그램이 진행한다. 인증과 발급 직전 승인은 사용자가 한다. 요청률 상한과 차단 신호 즉시 중단이 전제이고, 국세청에 통지·질의 공문을 보낸다(공문 2) |
| 정부24 | `postprocess` | 사용자의 기본 브라우저로 페이지만 연다. 로그인·입력·발급·출력은 사용자가 한다. 프로그램은 사용자가 저장해 고른 PDF만 정리한다. 사전 허락 회신 전에는 이 수준을 넘지 못한다(앱 내장 상한, ADR-011·012). 행안부에 사전 허락 요청 공문을 보낸다(공문 1) |
| 위택스 | `postprocess` | 위택스 이용약관 제17조 제2항도 사전 허락 없는 자동화 로그인을 금지한다. 허락 회신 전까지 자동화하지 않는다(공문 1 10항) |

### 0.3 기술 방식(요약)

사용자가 설치한 Chrome을 전용 프로필로 띄워 제어 채널(`--remote-debugging-pipe`)로 제어한다. 포털이 읽을 수 있는 자동화 표식(`navigator.webdriver=true`)은 그대로 드러낸다. 헤드리스, User-Agent·지문 변경, 프록시, 타이핑 모사, 캡차 자동 해독은 하지 않는다. 상한은 프로필당 하루 홈택스 실행 40건(발급 30건), 로그인 세션당 15건, 하루 로그인 6회, 동시 세션 1개다. 자세한 내용은 공문 2 §5·§6에 있다.

### 0.4 인증 수단(ADR-020)

사용자는 처음 설정할 때 발급 인증 수단 하나를 고르고, 이후 모든 발급에 같은 수단을 쓴다.
- 사업자용 간편인증: 로그인과 전자서명 때마다 사용자가 휴대폰에서 승인한다.
- 공동·금융인증서: 비밀번호는 사용자가 홈택스 화면(가상키패드·키보드 보안)에 직접 입력한다. 프로그램은 저장하거나 자동으로 입력하지 않는다(Q4).
- 보안카드: 홈택스 아이디·비밀번호와 카드 번호 30개를 PC 금고에 한 번 등록하면 프로그램이 아이디 로그인과 번호 입력을 한다(Q6).

### 0.5 서버와 외부로 가는 정보

- 서버로 가지 않는 것: 인증서·비밀번호·보안카드 값, 발급 서류 본문, 포털 화면의 원문.
- 서버가 받거나 거쳐 가는 것: 계정 이메일·결제 참조, 화면 상태 판정·복구용 **마스킹된 화면 텍스트**, 마스킹된 대화 지시, 저장된 서류의 날짜 후보 주변 마스킹 텍스트(모두 게이트웨이를 거쳐 해외 모델 공급사로, 공급사 보존 최대 30일), 진위확인 때의 거래처 사업자번호(프록시 통과, 저장 안 함), 발급 활동 표시(해시, 1단계, 옵트인), 서류 메타데이터(2단계, 백업을 켠 경우), 2단계 암호문 백업(우리가 열 수 없음), 2단계 휴대폰 원격 메시지(종단간 암호문).
- 전체 목록은 [05-attachments.md](05-attachments.md) 붙임 3에 있다.

### 0.6 단계

- **PoC**: 2026-10-29~11-26. 관계사 법인 1곳의 계정에서만 한다(Q5).
- **1단계 MVP**: Windows, 초대 베타 50명.
- **2단계**: 휴대폰 원격 승인, 정기 갱신(승인형), 암호문 백업.

### 0.7 함께 드리는 자료

공문 1·2, 질의 3(개인정보위), 붙임 1~4. 저장소 설계 문서 경로는 각 질의의 '근거'에 적었다.

## Q1. 세무사법: 세무대리 해당 여부와 광고 규정

**쟁점**: 프로그램의 기능이 세무사법 제2조의 세무대리에 해당해 같은 법 제20조 제1항(등록하지 않은 자의 세무대리 금지)에 걸리는지, 그리고 2025. 12. 23. 개정으로 신설된 제20조 제3항(세무대리로 오인할 우려가 있는 표시·광고 금지, 2026. 6. 24. 시행, 벌칙 제22조의2)에 걸리는 표현이 있는지.

**사실관계**
1. 전자세금계산서(H-01): 사용자가 "거래처 B에 55만원 세금계산서"처럼 지시하면 프로그램이 홈택스 건별발급 화면에 입력하고, 되읽은 값을 승인 대기 카드와 승인 바로 보여 준다. 사용자가 승인하면 사용자 명의로, 사용자 PC에서, 사용자 인증수단으로 발급한다.
2. 금액: 입력창에 "계산서"가 보이면 부가가치세 [별도] [포함] 토글을 띄운다. 고르지 않으면 별도로 계산하고 추정 값으로 표시한다. 계산은 홈택스 '계산' 버튼과 같은 10% 산술뿐이다. 과세·영세·면세는 프로그램이 추측하지 않고 사용자가 고른다(ADR-020 결정 6).
3. 민원증명(사업자등록증명·납세증명서 등) 발급, 보관, 만료 알림.
4. 하지 않는 것: 세액 산정, 신고세액 계산, 절세·공제 판단, 신고서 작성, 세무 상담 답변(02 §12). 세무 질문에는 일반 정보만 주고, 개인에 맞춘 조언은 거절하고 세무사 상담을 안내한다(01 §8).
5. 2단계 후보: 전자세금계산서 발급·전송 기한 캘린더('이번 달 발급 미완료 거래처', D-day 알림). 가산세율 표시 여부는 이 자문 결과로 정한다(02 §14).
6. 사업 전략에 세무사 사무실과의 비경쟁 제휴가 있다(01 GTM 4).
7. 금지 표현 목록(초안): 세금환급, 세금신고 대행, 절세전문, 기장대행, 세무사·세무법인·세무대리 유사 표현, 세무사 제휴 허위 표시, 환급 보장·성공률(01 §8, D11 §6).

**질의**
1. 1~3의 기능이 세무사법상 세무대리에 해당합니까? 특히 사용자 지시에 따라 프로그램이 사용자 명의로 세금계산서를 발급하는 것이 '대리'로 평가될 여지가 있습니까?
2. 2의 부가세 분리 산술과 5의 기한 캘린더(가산세율 표시를 포함할 경우와 뺄 경우)는 세무 상담·자문의 경계를 넘습니까?
3. 7의 금지 표현 목록이 광고 규정에 비추어 충분합니까? 제품명·화면 문구에 '세무'·'세금'이라는 낱말을 어디까지 쓸 수 있습니까? 세무사 제휴를 표시할 때의 요건은 무엇입니까?
4. 국세기본법 일부개정법률안(의안번호 2217075, 2026. 2. 26. 제안, 2026. 10. 조세소위 계류)의 세무플랫폼 지도 근거 조항(안 제81조의20)이 입법되면 로컬 앱 배포자인 당사도 대상이 될 수 있습니까(리스크 R-13)? 법안이 쓰는 용어와 조문 원문은 저희가 확인하지 못했습니다.
5. 1단계 출시 전에 해야 할 조치(문구 심사, 고지, 약관 조항)가 있다면 알려 주십시오.

**당사 가설(단정하지 않음)**: 세무대리 기능이 없고 사용자 명의·기기·승인 구조이므로 세무대리에 해당하지 않을 가능성이 있다.

**근거**: 01 §8, 02 §4·§12·§14, D11 §6, ADR-020 결정 6, 04 R-2·R-13, 세무사법 제2조·제20조·제22조·제22조의2(시행 2026. 6. 24.), 국회 의안정보시스템 2217075

## Q2. 전자세금계산서 발급 시스템 사업자 지위

**쟁점**: 당사가 부가가치세법 제32조와 같은 법 시행령 제68조(전자세금계산서 발급), 같은 법 시행규칙 제50조, 국세청 고시 제2026-26호(「전자(세금)계산서 시스템을 구축·운영하는 사업자가 지켜야 할 사항 및 표준 인증에 관한 고시」, 2026. 8. 31. 시행)에 따라 발급 시스템 사업자(이른바 ASP)로서 등록이나 표준인증을 받아야 하는지.

**사실관계**
1. 전자세금계산서는 사용자 PC의 브라우저에서 **홈택스 화면**으로, 사용자 인증수단의 전자서명으로 발급한다. 국세청 전송은 홈택스가 한다.
2. 당사 서버는 홈택스에 접속하지 않고, 세금계산서 데이터를 저장하거나 국세청에 전송하지 않는다. 화면 상태 판정과 복구 때는 마스킹된 화면 텍스트가 게이트웨이를 거쳐 모델로 간다. 화면의 금액은 늘 지운다. 금액 원값은 사용자가 대화에 적은 금액을 바르게 해석했는지 확인하는 판정 하나에만 간다(D04 §3, D06 §4).
3. 이메일은 프로그램이 홈택스 발급 화면의 공급받는자 이메일 칸에 입력하고, 홈택스가 발급 때 그 주소로 보낸다. 프로그램은 메일 발송 목록을 조회해 전송을 확인한다(02 §4). 당사 메일 서버로 세금계산서를 보내지 않는다.
4. 당사는 국세청 표준인증을 받지 않았고 받을 계획이 없다. 국세청 공개 API에는 세금계산서 발행 API가 없다(R5 §2-A, 2026-09 기준). R5에 적힌 고시 제2023-17호는 현행이 아니며, 현행은 위 제2026-26호다.
5. H-02(1단계 베타): 발급분·수취분 조회와 PDF 저장(사용자 PC). 2단계 백업은 암호문만 저장한다.

**질의**
1. 1~3의 구조에서 당사가 발급 시스템 사업자 등록이나 표준인증 대상입니까?
2. 대상이 아니라면 이렇게 발급한 세금계산서가 '홈택스 발급분'으로서 효력·분류상 문제가 없습니까?
3. 프로그램이 공급받는자 이메일 칸을 채워 홈택스가 발송하게 하는 것과 관련해 지켜야 할 의무가 있습니까?
4. 5의 기능이 1·2의 판단을 바꿉니까?

**당사 가설**: 등록 대상이 아니다(01 §8). 법률 검토로 확정한다.

**근거**: 01 §8, 06 §2, R5 §2-A, D14 PoC-6, D06 §4, 국세청 고시 제2026-26호(국세청 누리집 2026-11-02 조회)

## Q3. 포털 이용약관과 관련 법령

**쟁점**: 홈택스·정부24·위택스 이용약관과 관련 법령에 비추어 프로그램의 이용 방식이 허용되는지, 위반이 된다면 그 책임이 누구에게 돌아가는지.

**사실관계**
1. 홈택스 이용약관(2015. 2. 23. 시행본)에는 자동화·매크로·스크래핑을 명시한 조항이 없다. 관련 포괄 조항은 다음과 같다(R2 §7-1). 제15조 제1항 ID·비밀번호를 제3자에게 이용하게 해서는 안 됨, 제2항 사전 승낙 없는 영리행위 금지, 제3항 얻은 정보를 사전 승낙 없이 사용하거나 타인에게 제공하는 것 금지, 제4항 안정적 운영에 지장을 주거나 줄 우려가 있는 행위 금지. 또 제9조 제4항은 위반 시 서비스 제한·중지를 정한다. 「홈택스 이용에 관한 규정」(고시)의 2026 개정본 본문은 확인하지 못했다.

## Q4. 공동·금융인증서 비밀번호: 사용자 직접 입력 구조의 적법성

> 원래 질의는 "인증서 비밀번호 저장"이었다. ADR-020 결정 2로 공동·금융인증서 비밀번호는 **사용자가 직접 입력하고 앱은 저장·자동 입력하지 않는다**로 바뀌어, 질의를 아래와 같이 조정했다.

**쟁점**: 인증서 비밀번호는 사용자가 직접 넣고 나머지 서명 흐름은 프로그램이 조작할 때, 이것이 전자서명법과 인증서 발급기관 이용약관상 '서명자 본인의 서명'으로서 문제가 없는지.

**사실관계**
1. 프로그램은 로그인 화면 이동과 인증서 선택 창 열기를 하고, 발급 직전에는 승인 화면(PC 앱 대화 열 하단의 승인 바)에 홈택스에서 되읽은 값을 보여 준다. 사용자가 [승인하고 발급]을 누르면 홈택스 전자서명 창이 뜬다.
2. 사용자는 비밀번호를 홈택스 서명 창(가상키패드·키보드 보안)에 직접 입력한다. 서명은 홈택스 서명 모듈이 한다. 프로그램은 인증서 개인키 파일(`signPri.key`)을 열지 않는다. 공개 인증서(`signCert.der`)만 읽어 주체와 만료일을 보여 준다(D05 §6).
3. 홈택스 브라우저 인증서 모드를 쓰는 경우(S1b), 사용자의 동작으로 인증서 파일을 업로드 칸에 넘겨 전용 Chrome 프로필의 브라우저 저장소로 가져온다. 프로그램은 파일 내용을 읽지 않지만, 전용 프로필에 사본이 생긴다(D05 §3.6·§6).
4. 휴대폰 원격 발급에서는 공동·금융인증서를 쓸 수 없고 PC에서만 발급한다.
5. 이전 설계안(D05 §2, 2026-11-02 고치기 전)에는 키보드 보안이 없는 칸에 한해 인증서 비밀번호를 옵트인으로 저장하는 안이 있었다. 현재 결정(ADR-020)은 저장하지 않는 것이고, 설계 문서에서 저장 기능을 지웠다. 플레이북 형식에 남은 관련 열거값의 정리는 후속 작업이다.

**질의**
1. 1~2의 구조(비밀번호는 사용자가 입력하고, 서명 대상 확인과 서명 창 호출은 프로그램이 함)가 전자서명법과 인증서 이용약관상 본인 서명으로서 문제가 없습니까? 관련 조문은 자문 측에서 특정해 주십시오.
2. 사용자가 서명 대상 내용을 홈택스 서명 창이 아니라 프로그램의 승인 바에서 확인하는 것이 서명 의사 확인으로 충분합니까? 부족하다면 무엇을 더 보여 주어야 합니까?
3. 3의 브라우저 인증서 사본에 대해 고지, 보관 위치 안내, 삭제 절차 등 지켜야 할 것이 있습니까?
4. 나중에 5의 비밀번호 저장(옵트인)을 다시 검토한다면 법적 요건(동의 방식, 고지, 보관 방식, 책임 범위)은 무엇입니까?

**당사 가설**: 비밀번호를 사용자가 직접 입력하고 서명은 포털 모듈이 하므로 본인 서명으로 볼 수 있다.

**근거**: ADR-020 결정 2, ADR-021, D05 §2·§3.6·§6, 01 §8

## Q5. 테스트 발급의 적법성

**쟁점**: 개발 검증(PoC)과 이후 회귀 시험에서 실제 세금계산서를 발급하는 방식이 부가가치세법, 조세범 처벌법 제10조 제3항(재화·용역의 공급 없이 세금계산서를 발급하는 행위의 처벌), 홈택스 약관상 문제가 없는지.

**사실관계**
1. 전자세금계산서는 발급 뒤 취소할 수 없고 수정세금계산서로만 고칠 수 있다. 재화·용역의 공급 없이 발급하면 조세범 처벌법 위험이 있으므로 '0원 발급'이나 '발급 후 취소'는 쓰지 않는다(06 Q12).
2. PoC(2026-10-29~11-26)는 관계사 법인 1곳의 계정을 PoC 전용으로 정해 그 계정에서만 한다. 계정 제한·정지 위험은 당사 대표가 수용하고 기록했다(ADR-017 결정 5). 관계사와의 관계는 {{지분·거래 관계}}이고, 조작하는 사람은 {{PoC 조작 주체: 관계사 임직원 / 당사 임직원}}이다. 【D-10】
3. 발급 없이 하는 시험: 로그인부터 발급 버튼 직전까지의 자동 구간 10회 안팎(드라이런), 조회성 작업 50회(하루 40건·세션 15건 상한 안에서 여러 날에 나눠 실행한다).
4. 실발급: 관계사 사이의 **실제 거래(소액 실용역)**에 대해서만 2~3건. 공급자는 {{공급자}}, 공급받는자는 {{공급받는자}}다. 민원증명 2종(사업자등록증명, 납세증명서)도 그 계정으로 발급한다.
5. 인증서 비밀번호와 보안카드 번호는 저장하지 않는다. 매번 사람이 홈택스 화면에 직접 넣거나, 프로그램의 비밀 입력 창에 넣으면 프로그램이 홈택스 칸에 옮겨 넣는다(D14 PoC-4). 시험 기록(실발급의 리플레이 기록)은 그 실거래에서만 만든다. 화면 상태 판정 시험용 홈택스 화면 약 100장도 그 계정에서 모은다.
6. 1단계 이후에도 포털 개편에 대응하려면 회귀 시험이 필요하다. 새 플레이북의 승인 기준은 '연속 20회 자동 구간 완주'다(05 §5).

**질의**
1. 4의 실거래 소액 발급을 시험 목적으로 쓰는 것이 부가가치세법·조세범 처벌법상 문제가 없습니까? 거래의 실질 요건과 남겨야 할 증빙은 무엇입니까?
2. 관계사(특수관계인일 수 있음) 사이의 거래라서 유의할 점이 있습니까?
3. 2의 조작 주체가 당사 임직원이라면 관계사 계정·인증수단을 쓰는 것이 홈택스 약관 제15조 제1항(ID·비밀번호 제3자 이용 금지)과 전자서명 관련 법령에 비추어 문제가 됩니까? 필요한 위임·동의 서류는 무엇입니까?
4. 3의 드라이런(발급 직전까지 입력 후 중단)과 조회 50회가 홈택스 운영상 문제(제15조 제4항)가 될 여지가 있습니까?
5. 5의 시험 기록에는 관계사의 거래 정보가 들어갑니다. 보관·폐기 기준은 무엇입니까?
6. 6의 회귀 시험을 적법하게 하려면 어떤 방식이 좋습니까(시험 전용 법인, 실거래 한정, 국세청 시험 환경 문의 등)?

**당사 가설**: 실제 공급이 있는 거래에 대한 발급은 적법하다. 다만 조작 주체와 위임 관계는 확인이 필요하다.

**근거**: 06 Q12, ADR-017 결정 5, D14 §0 PoC-3·6·8·10, 05 §5, REVIEW-C(A-04·A-05)

## Q6. 보안카드 번호와 홈택스 아이디·비밀번호의 저장과 자동 입력

> EX-1 스레드(10-31)와 ADR-020 결과에 따라 추가한 질의다.

**쟁점**: 사용자가 자기 PC에 보안카드 번호와 홈택스 아이디·비밀번호를 암호화해 저장하고 프로그램이 홈택스에 입력하는 것이 홈택스 이용 규정과 관련 법령상 허용되는지.

**사실관계**
1. 보안카드는 전자(세금)계산서 발급용 전자서명 수단이다. 2026-04 기준 발급 사업자 중 14%가 쓴다. 아이디 로그인일 때만 전자서명 창에서 고를 수 있다. 사업자 계정만 신청할 수 있고, 실물은 세무서에서 본인이 받는다(R2, NTS 보도참고자료 2026-04-22). 국세상담센터는 "보안카드를 이용한 전자(세금)계산서 발급은 홈택스에서만 가능하며, 민간사업자가 운영하는 시스템에서는 … 불가"하다고 안내한다(국세상담센터 '보안카드 발급방법', 2026-11-02 조회). 손택스·ARS 사용 범위는 2차 자료다(R2).
2. 설계(ADR-020 결정 2·3)
   - 사용자는 홈택스 아이디·비밀번호와 카드 번호 30개를 PC 금고 창에서 한 번 등록한다.
   - 번호는 JSON으로 묶어 AES-256-GCM으로 암호화하고, 열쇠는 Windows가 로그인 계정에 묶어 보관한다(DPAPI·자격 증명 관리자).
   - 발급마다 Windows Hello 확인을 켤 수 있다(기본 꺼짐).
   - 값은 금고 프로세스만 다루고 모델·서버·대화·활동 기록으로 보내지 않는다.
   - 같은 Windows 사용자 권한의 악성코드는 막지 못한다고 고지한다.
   - 카드 사진으로 등록하면 Windows 기본 OCR로 PC 안에서 숫자만 읽고 사진은 바로 지운다. 사용자가 확인·수정한다.
3. 프로그램은 아이디 로그인을 하고, 발급 때 전자서명 창이 요구하는 번호를 칸에 입력한다. 사용자는 발급 직전에 승인 바에서 승인한다.
4. 보안카드 입력칸이 가상키패드라면 자동 입력을 보류하고 사용자가 직접 입력한다. 이것은 PoC에서 확인한다(ADR-020 조건). 홈택스 아이디 로그인 2차 인증(2025-07, 2차 자료)의 방식도 확인 전이다.
5. PoC에서는 저장하지 않는다. 다만 PoC 금고에도 사람이 비밀 입력 창에 넣은 값을 홈택스 칸에 옮겨 넣는 기능이 있어, 보안카드를 고르면 저장 없이도 프로그램이 번호를 입력할 수 있다(D14 PoC-4).
6. 2단계 원격 발급: 휴대폰에서 승인하면 PC가 저장된 번호로 발급한다. 휴대폰에서 번호를 입력하는 경우에는 PC 금고만 열 수 있게 암호화돼 전달된다.

**질의**
1. 2·3의 방식이 홈택스 이용약관(제15조 제1항 포함)과 보안카드 이용 규정상 허용됩니까? 사용자가 자기 PC에 저장하고 자기 PC의 프로그램이 입력하는 경우에도 프로그램(또는 당사)이 '제3자'로 평가될 여지가 있습니까?
2. 1의 "민간사업자가 운영하는 시스템에서는 불가" 안내가, 별도 시스템이 아니라 사용자 PC의 브라우저에서 홈택스 화면 자체에 입력하는 이 방식에도 적용됩니까?
3. 프로그램이 보안카드 번호를 입력해 한 전자서명이 사용자 본인의 서명 의사로서 효력이 있습니까? 사용자가 승인 바에서 승인하는 것으로 충분합니까?
4. 악성코드 유출이나 무단 발급 같은 사고가 나면 책임은 어떻게 나뉩니까? 고지 문구와 동의 방식(F-06)의 요건은 무엇입니까?
5. 국세청에 따로 승인이나 협의가 필요합니까? 공문 2 §11 다.에서 이 질문을 국세청에 함께 보냅니다.
6. 6의 원격 발급이 1~4의 판단을 바꿉니까?

**당사 가설**: 판단을 미룬다. 허용되지 않는다는 의견이나 회신을 받으면 사용자 직접 입력으로 바꾼다.
